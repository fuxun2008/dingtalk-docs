### Menambah Peranti Dipercayai Peribadi Desktop

<Tabs>
  <Tab title="Tambah satu peranti">
    Admin boleh masukkan nama pekerja, pilih platform (Windows atau Mac), dan isikan alamat MAC peranti (format: xx:xx:xx:xx:xx:xx). Beberapa alamat MAC disokong tanpa had bilangan. **Setelah maklumat dimasukkan dan disimpan**, peranti tersebut menjadi dipercayai (berkuat kuasa serta-merta secara lalai), dan pekerja boleh menggunakannya untuk log masuk ke DingTalk.

    <Frame>
      <img src="https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/v9kqDejXV8oMMOVx/img/a67dd20a-ddfc-4139-810a-9d4eb5175b1b.png" alt="Tambah satu peranti dipercayai" />
    </Frame>
  </Tab>
  <Tab title="Tambah peranti secara pukal">
    Templat disediakan untuk admin **menambah peranti dipercayai peribadi desktop secara pukal**.

    1. **Eksport** templat import pukal.
    2. Ikut arahan dalam templat dan **masukkan data** mengikut format yang diperlukan.
    3. **Muat naik** templat dan **klik Sahkan** untuk melengkapkan import (muat naik semula disokong). Peranti yang disenaraikan dalam templat akan menjadi dipercayai (berkuat kuasa serta-merta secara lalai) dan boleh digunakan untuk log masuk ke DingTalk.

    <Note>
    Import pukal hanya menyokong alamat MAC pekerja yang telah berada dalam direktori organisasi. Untuk menambah pekerja baharu, jemput mereka menyertai organisasi terlebih dahulu daripada bahagian Kenalan.
    </Note>

### Menambah Peranti Dipercayai Peribadi Mudah Alih

Peranti mudah alih tidak boleh ditambah daripada admin console. Apabila pekerja cuba log masuk ke DingTalk pada peranti mudah alih yang tidak dipercayai, mereka akan digesa memohon status peranti dipercayai.

**Pihak pekerja:** **Klik "To apply"** untuk meneruskan ke Langkah 2. **Pilih jenis peranti, setuju dengan terma, dan hantar permohonan.** Ini melengkapkan permohonan peranti dipercayai peribadi.

<Note>
Pilihan "company device" di sini bukan merujuk kepada "peranti dipercayai kongsi." Ia sekadar menunjukkan bahawa peranti tersebut adalah milik syarikat.
</Note>

**Pihak admin:** Admin boleh **luluskan atau tolak** permohonan peranti dipercayai pekerja, sama ada daripada mesej kelulusan atau daripada admin console.

<Tabs>
  <Tab title="Lulus melalui mesej">
    Admin boleh **luluskan atau tolak** permohonan peranti dipercayai pekerja. Peranti yang telah diproses dalam admin console akan disegerakkan di sini secara automatik, jadi tiada tindakan berulang diperlukan.

    Medan berikut disediakan: syarikat, nama pekerja, ID pekerja, jabatan, nama peranti, masa permohonan, dan bilangan peranti dipercayai semasa. Admin boleh **luluskan atau tolak** setiap permohonan.

    - **Apabila diluluskan:** Peranti menjadi dipercayai, dan pekerja boleh menggunakannya untuk log masuk ke DingTalk.
    - **Apabila ditolak:** Peranti kekal tidak dipercayai, dan pekerja tidak boleh menggunakannya untuk log masuk ke DingTalk.

    <Frame>
      <img src="https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/v9kqDejXV8oMMOVx/img/8a3b648d-21a3-436c-89dc-349c964ba926.png" alt="Lulus melalui mesej" />
    </Frame>
  </Tab>
  <Tab title="Lulus dalam admin console">
    Dalam admin console, admin boleh **luluskan atau tolak** permohonan peranti dipercayai pekerja.

    - Kelulusan individu: **Approve** atau **Reject**.
    - Kelulusan pukal: **Batch Approve** atau **Batch Reject**.
    - **Apabila diluluskan:** Peranti menjadi dipercayai, dan pekerja boleh menggunakannya untuk log masuk ke DingTalk.
    - **Apabila ditolak:** Entri peranti dikeluarkan daripada senarai, dan pekerja tidak boleh menggunakannya untuk log masuk ke DingTalk. Admin juga boleh menyertakan sebab penolakan dan memilih sama ada membenarkan pekerja memohon semula.

### Mengurus Senarai Peranti Dipercayai Peribadi

- Anda boleh mencari senarai peranti dipercayai mengikut pelbagai dimensi, termasuk nama pekerja, status kepercayaan peranti (semua, menunggu kelulusan, dipercayai), jenis klien (semua, Windows, Mac, Android, iOS), alamat MAC (xx:xx:xx:xx:xx:xx, desktop sahaja), dan masa pendaftaran/permohonan.
- Anda boleh **melaporkan sebagai hilang, memadam, memadam secara pukal, atau menaikkan taraf kepada peranti dipercayai kongsi** (peranti yang dilaporkan hilang atau dipadam akan **dipaksa log keluar daripada DingTalk**). Senarai peranti juga boleh dieksport secara tempatan.

### Tetapan Penguatkuasaan

- **Luluskan secara automatik peranti mudah alih pertama dan kumpulkan maklumat:** Apabila diaktifkan, peranti mudah alih peribadi pertama pekerja diluluskan secara automatik dan menjadi peranti dipercayai.
- **Kumpulkan maklumat peranti mudah alih secara automatik:** Apabila diaktifkan, jika pekerja log masuk pada peranti mudah alih yang tidak dipercayai, maklumat peranti dikumpulkan secara automatik. Status kepercayaan kekal tidak berubah (masih tidak dipercayai), dan admin boleh meluluskannya daripada senarai peranti.
- **Luluskan secara automatik peranti desktop pertama dan kumpulkan maklumat:** Apabila diaktifkan, peranti desktop peribadi pertama pekerja diluluskan secara automatik dan menjadi peranti dipercayai.
- **Kumpulkan maklumat peranti desktop secara automatik:** Apabila diaktifkan, jika pekerja log masuk pada peranti desktop yang tidak dipercayai, maklumat peranti dikumpulkan secara automatik. Status kepercayaan kekal tidak berubah (masih tidak dipercayai), dan admin boleh meluluskannya daripada senarai peranti.

  <Accordion id="q1" title="S1: Apakah fungsi 'Remove users on untrusted devices' dalam tetapan dasar? Bukankah peranti tidak dipercayai sudah pun tidak boleh log masuk ke DingTalk?">
    *Bagaimanakah cara cold-start ciri peranti dipercayai jika organisasi saya sudah lama menggunakan DingTalk dan kemudian membeli ciri peranti dipercayai?*

    **J1:**

    Seorang pekerja telah log masuk ke DingTalk pada Peranti A pada 1 Januari 2022, sebelum organisasi membeli ciri peranti dipercayai.

    Organisasi membeli ciri peranti dipercayai pada 1 Januari 2023. Walau bagaimanapun, pekerja tersebut sudah pun log masuk pada peranti tidak dipercayai sejak 1 Januari 2022, jadi Peranti A berada di luar skop pengurusan peranti.

    Dengan menggunakan ciri "Remove users on untrusted devices," anda boleh memaksa DingTalk log keluar daripada Peranti A. Selepas log keluar dipaksa, anda boleh memulakan semula proses pendaftaran peranti dipercayai dari awal.

    <Note>
    Tetapan dasar peranti dipercayai semasa memerlukan pengimportan sebahagian data sebelum ia boleh digunakan. Ini akan dioptimumkan pada masa hadapan.
    </Note>
  </Accordion>
  <Accordion id="q2" title="S2: Bagaimanakah cara menetapkan beberapa alamat MAC untuk peranti desktop yang sama dalam templat import pukal?">
    **J2:** Ciri ini sedang dibangunkan. Nantikan kemas kini seterusnya.
  </Accordion>
  <Accordion id="q3" title="S3: Apakah logik pengesahan untuk beberapa alamat MAC pada peranti desktop?">
    **J3:** Selagi alamat MAC yang digunakan semasa log masuk sepadan dengan mana-mana satu alamat MAC yang didaftarkan dalam admin console, peranti tersebut boleh log masuk seperti biasa.
  </Accordion>
  <Accordion id="q4" title="S4: Bagaimanakah peranti dipercayai peribadi dikaitkan dengan pekerja tertentu?">
    **J4:** Peranti dipercayai peribadi dikaitkan dengan individu tertentu dalam organisasi. Contohnya, jika Syarikat A mengaktifkan modul peranti dipercayai, dan Pekerja A daripada Syarikat A memohon peranti dipercayai peribadi (Peranti X), maka tiada pekerja lain di Syarikat A boleh menggunakan Peranti X untuk log masuk.
  </Accordion>
  <Accordion id="q5" title="S5: Apakah yang berlaku jika pekerja menghantar permohonan selepas 'Kumpulkan maklumat peranti mudah alih secara automatik' diaktifkan?">
    **J5:** Apabila "Kumpulkan maklumat peranti mudah alih secara automatik" diaktifkan, jika pekerja log masuk ke DingTalk pada peranti mudah alih yang tidak dipercayai, permintaan tersebut tidak melalui aliran kelulusan — admin tidak akan menerima sebarang permohonan. Walau bagaimanapun, maklumat peranti akan dipaparkan dalam senarai peranti admin console, di mana admin boleh memilih untuk meluluskan atau menolaknya. Jika pekerja menghantar permohonan rasmi sebelum admin memprosesnya daripada console, admin akan menerima permohonan tersebut, dan senarai dalam console akan menggantikan maklumat peranti yang dikumpul secara automatik sebelum ini.
  </Accordion>
  <Accordion id="q6" title="S6: Selepas 'Kumpulkan maklumat peranti mudah alih secara automatik' diaktifkan, adakah maklumat peranti yang sudah log masuk ke DingTalk sebelum organisasi membeli ciri peranti dipercayai akan dikumpul?">
    **J6:** Tidak.
  </Accordion>
  <Accordion id="q7" title="S7: Adakah import pukal peranti dipercayai menggantikan data yang diimport sebelum ini? Apakah logik importnya?">
    **J7:** Pengimportan mengikut logik tambahan, bukan logik gantian.

    **Kes 1:** Jika admin console sudah mengandungi maklumat peranti dipercayai untuk Pekerja 1–5, dan admin menambah 10 entri untuk Pekerja 6–15 dalam templat, memuat naik templat tersebut akan menambah entri untuk Pekerja 6–15, menghasilkan sejumlah 15 entri.

    **Kes 2:** Jika Pekerja 1 sudah mempunyai satu peranti dipercayai Windows, dan admin menambah satu lagi peranti dipercayai Windows untuk Pekerja 1 dalam templat, selepas dimuat naik, Pekerja 1 akan mempunyai dua peranti dipercayai Windows.
  </Accordion>
