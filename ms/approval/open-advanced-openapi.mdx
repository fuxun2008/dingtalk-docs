## 1. Gambaran keseluruhan ciri

Bagi memenuhi keperluan pembangun untuk pembangunan aplikasi yang lebih diperibadikan, DingTalk OA Approval telah melancarkan satu set OpenAPI eksklusif untuk pelanggan Smart OA sejak 1 September 2024. OpenAPI eksklusif ini menyediakan keupayaan yang lebih kaya, menangani lebih banyak keperluan perniagaan yang diperibadikan, dan menyokong pembangunan aplikasi dalaman merentasi pelbagai senario. Kami menggalakkan pembangun menggunakan OpenAPI ini secara berkesan untuk membina ekosistem terbuka DingTalk yang lebih sihat.

## 2. Senario yang berkaitan

<Note>
DingTalk boleh menambah, mengubah suai, atau mengeluarkan skop atau ciri khusus API berikut bagi mematuhi undang-undang, peraturan, penyesuaian dasar, atau arahan pengawalseliaan, atau untuk melindungi keselamatan perkhidmatan DingTalk. API yang sebenarnya tersedia untuk pelanggan adalah tertakluk kepada kandungan yang diterbitkan di DingTalk Open Platform pada masa itu.
</Note>

Sesebuah organisasi mempunyai pelbagai sistem perniagaan (sama ada dibangunkan sendiri atau pihak ketiga) yang tugasan kelulusannya sudah bersepadu dengan Pusat Kelulusan DingTalk. ### 3. Integrasi pusat proses (kumpulan perniagaan tersuai)

### 4. Integrasi pusat proses (mod hosting halaman kelulusan)

Sesebuah organisasi mempunyai enjin proses sendiri dalam sistem perniagaannya dan ingin bersepadu menggunakan model kelulusan OA proprietarinya sendiri. Namun, organisasi tersebut tidak mempunyai halaman butiran H5 dan ingin menggunakan semula halaman butiran kelulusan OA rasmi DingTalk sambil menyesuaikan kawasan tindakan kelulusan. Ini menyatukan struktur dan gaya borang kelulusan merentasi pelbagai sistem perniagaan, memberikan pengguna pengalaman yang konsisten merentasi mudah alih, PC, dan tablet. Butang dalam kawasan tindakan kelulusan boleh disesuaikan (Terima, Tolak, serahkan, Cetak, dan lain-lain).

## 3. Langkah

Bagi OpenAPI eksklusif di atas, pelanggan Edisi Standard perlu **menaik taraf ke Smart OA** terlebih dahulu sebelum boleh memohon untuk menggunakannya. Sesetengah pelanggan yang menyertai beta awam sebelum 1 September 2024 sudah mempunyai akses untuk memanggil OpenAPI ini. Peraturannya adalah seperti berikut:

| Jenis pelanggan | Menyertai beta awam | Kesan |
| --- | --- | --- |
| Pelanggan Smart OA | Ya | Tidak terjejas; teruskan memanggil seperti biasa |
| Pelanggan Smart OA | Tidak | Boleh memanggil selepas memohon kebenaran API |
| Pelanggan Edisi Standard | Ya | Tidak boleh memanggil. Anda mesti menaik taraf ke Smart OA dan memohon kebenaran API untuk menyambung semula panggilan. Lihat langkah permohonan kebenaran di bawah |
| Pelanggan Edisi Standard | Tidak | Tidak boleh memanggil. Anda mesti menaik taraf ke Smart OA dan memohon kebenaran API sebelum memanggil. Lihat langkah permohonan kebenaran di bawah |

Laluan permohonan kebenaran: **Developer Backend** > App Development > DingTalk App > Cipta aplikasi baharu atau pilih aplikasi sedia ada > Klik aplikasi > [Urus kebenaran] > [Kelulusan OA], kemudian pilih kebenaran yang diperlukan:

## 4. Soalan Lazim

<AccordionGroup>
  <Accordion id="q1" title="Apakah peraturan pengebilan untuk OpenAPI eksklusif?">

Pelanggan DingTalk Edisi Standard tidak boleh menggunakan OpenAPI eksklusif Smart OA. Anda mesti **menaik taraf ke Smart OA** terlebih dahulu sebelum boleh memanggil API ini. Memanggil OpenAPI eksklusif menggunakan Kuota OpenAPI Smart OA anda.

  </Accordion>
  <Accordion id="q2" title="Bolehkah pelanggan Edisi Standard melihat OpenAPI eksklusif ini?">

Bermula 1 September 2024, pembangun boleh melihat OpenAPI eksklusif yang baharu dilancarkan dalam dokumentasi pembangun Open Platform dan **Developer Backend**.

  </Accordion>
</AccordionGroup>
