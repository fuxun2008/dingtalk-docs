## 1. Gambaran keseluruhan ciri

Seiring pendalaman digitalisasi perusahaan, semakin banyak organisasi perlu mengintegrasikan sistem OA mereka dengan sistem perniagaan pihak ketiga seperti ERP, CRM, dan sistem kewangan. **Integrasi proses dan halaman pihak ketiga** membolehkan pertukaran data, perkongsian proses, dan antara muka operasi yang bersepadu, sekali gus meningkatkan kecekapan pejabat secara keseluruhan dan kerjasama pengurusan. Panduan ini membimbing pembangun dan pentadbir sistem melalui konfigurasi **integrasi proses dan halaman pihak ketiga** pada platform OA, supaya anda dapat melaksanakan integrasi sistem dengan cepat.

## 2. Senario yang berkenaan

Mulakan proses daripada sistem perniagaan dan panggil API Kelulusan OA asli DingTalk untuk mencipta proses Kelulusan OA DingTalk. Kemudian, buka halaman butiran kelulusan sistem perniagaan di dalam DingTalk untuk memproses kelulusan tersebut.

### Gambaran keseluruhan aliran integrasi

Dokumen ini membimbing anda mencipta Aplikasi dalaman dan menggunakan API yang disediakan oleh Pusat Proses Kelulusan OA untuk mencipta, mengemas kini, dan memadam templat kelulusan pihak ketiga; mencipta dan mengemas kini instans kelulusan; mencipta, mengemas kini, dan membuat pertanyaan tugasan kelulusan tertunggak; serta membersihkan data Kelulusan OA. Ia menunjukkan cara sistem perniagaan memulakan kelulusan dan cara halaman butiran sistem perniagaan dibuka di dalam DingTalk bagi senario integrasi ini.

Prasyarat: Lengkapkan aliran **Cipta aplikasi**.

Langkah 1: Pergi ke halaman butiran aplikasi dan dapatkan Client ID dan Client Secret.

Langkah 2: Mohon Kebenaran API, khususnya kebenaran "Kelulusan OA".

Langkah 3: Dapatkan Kredensial akses aplikasi dengan **mendapatkan access token untuk Aplikasi dalaman**. Access token digunakan untuk mengesahkan identiti pemanggil semasa memanggil API.

Langkah 4: Panggil API berkaitan Kelulusan OA:

5.  Selepas instans kelulusan dicipta, pergi ke Pusat Kelulusan DingTalk untuk melihat empat senarai kelulusan (Belum Selesai, Telah Diproses, Dimulakan, Diterima), mencari data instans kelulusan, dan melaksanakan tindakan kelulusan.

6.  Segerakkan data tugasan kelulusan ke DingTalk: menggunakan `processInstanceId` instans kelulusan dan senarai tugasan `tasks`, panggil API **Create Process Center pending task** untuk menyegerakkan maklumat nod kelulusan daripada sistem pihak ketiga ke Kelulusan OA DingTalk, dapatkan `taskId` bagi setiap item tugasan, dan janakan tugasan DingTalk yang berkaitan. Nota: Dalam senario ini, tugasan kelulusan yang disegerakkan dikendalikan dengan membuka halaman butiran sistem perniagaan.

    ```json
    {
        "processInstanceId": "zG1X1zwFTEiwzI0JB5w38A0964172381_xxxx",
        "activityId": "activityId_xxx",
        "tasks": [
            {
                "userId": "manager9814",
                "url": "https://www.dingtalk.io"
            }
        ]
    }
    ```

7.  Selepas tugasan belum selesai dicipta, panggil API **Query OA approval tasks integrated via Process Center** untuk membuat pertanyaan tugasan kelulusan pengguna yang sedang berjalan.

8.  Segerakkan status tugasan kelulusan ke DingTalk: menggunakan `processInstanceId` instans kelulusan dan `taskId` tugasan kelulusan, panggil API **Update Process Center task status** untuk menyegerakkan kemas kini status bagi tugasan kelulusan anda sendiri. Dalam senario seperti kelulusan selari (OR-sign), panggil API **Batch cancel OA Approval pending tasks** untuk menetapkan semua item tugasan yang sedang berjalan di bawah satu instans kelulusan kepada CANCELED secara pukal.

9.  Segerakkan status instans kelulusan ke DingTalk: menggunakan `processInstanceId` instans kelulusan, `status` instans, dan `result` instans, panggil API **Update instance status** atau **Batch update instance status** untuk mengemas kini status instans.

10.  Akhir sekali, untuk membersihkan data templat kelulusan, panggil API **Delete template** untuk memadam templat kelulusan yang dicipta bagi organisasi tersebut. Instans dan tugasan yang dicipta di bawah templat itu turut dipadam.

## 6. API yang digunakan

### 1. Borang kelulusan

| API | Penerangan | Spesifikasi baharu (Server API baharu) |
| --- | --- | --- |
| Create or update approval template | Mencipta atau mengemas kini templat kelulusan. | **Create or update approval template** |
| Get template code | Membuat pertanyaan `process_code` berdasarkan nama templat. | **Get template code** |
| Delete template | Memadam templat kelulusan yang dicipta bagi organisasi, berserta semua instans dan tugasan yang dicipta di bawahnya. | **Delete template** |

### 2. Instans kelulusan

| API | Penerangan | Spesifikasi baharu (Server API baharu) |
| --- | --- | --- |
| Create instance | Mencipta instans kelulusan tanpa aliran proses. | **Create instance** |
| Update instance status | Mengemas kini status instans. | **Update instance status** |
| Batch update instance status | Mengemas kini status instans secara pukal. | **Batch update instance status** |

### 3. Tugasan Pusat Proses

| API | Penerangan | Spesifikasi baharu (Server API baharu) |
| --- | --- | --- |
| Create Process Center pending task | Mencipta tugasan Kelulusan OA yang belum selesai. | **Create Process Center pending task** |
| Query OA approval tasks integrated via Process Center | Membuat pertanyaan tugasan kelulusan pengguna yang sedang berjalan. | **Query OA approval tasks integrated via Process Center** |
| Update Process Center task status | Mengemas kini status tugasan yang belum selesai. | **Update Process Center task status** |
| Batch cancel Process Center pending tasks | Membatalkan tugasan Pusat Proses yang belum selesai secara pukal. | **Batch cancel Process Center pending tasks** |
