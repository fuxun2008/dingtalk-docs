---
title: "Kemas kini peraturan cuti"
description: "Panggil API DingTalk ini untuk mengemas kini peraturan cuti yang dicipta melalui API, termasuk nama cuti, unit permohonan, kaedah pengiraan tempoh dan skop."
---

Panggil API ini untuk mengemas kini peraturan bagi jenis cuti yang ditetapkan.

## Penerangan panggilan API

Peraturan cuti boleh dicipta melalui dua cara, iaitu dengan memanggil API atau dalam aplikasi rasmi DingTalk Kehadiran:

| Kaedah mencipta peraturan cuti | Menyokong kemas kini jenis cuti melalui API ini |
| --- | --- |
| Jenis cuti yang dicipta dengan memanggil API [Tambah peraturan cuti](/ms/open/development/add-holiday-rules). | Ya |
| Jenis cuti yang dicipta dalam aplikasi Kehadiran di Admin Console.   - Dicipta oleh sistem aplikasi Kehadiran secara lalai. - Dicipta di bahagian belakang aplikasi Kehadiran. | Tidak |

Pada halaman **Kehadiran** > **Pengurusan cuti** > **Peraturan cuti**, lihat empat peraturan cuti yang sedia ada.

- Jenis cuti ciptaan API 1 dan jenis cuti ciptaan API 2 dicipta melalui API. Panggil API ini untuk mengemas kini maklumatnya, seperti nama cuti, unit permohonan cuti, kaedah pengiraan tempoh cuti dan skop baki.
- Cuti peribadi dan Cuti ganti ialah jenis cuti lalai yang dicipta oleh sistem aplikasi Kehadiran. API ini tidak dapat mengemas kini jenis cuti tersebut dan akan mengembalikan mesej ralat berikut: errcode:880015,errmsg:leaveCode atau userId yang dinyatakan tidak wujud.

<Note>
Panggil API [Tanya senarai peraturan cuti](/ms/open/development/holiday-type-query) untuk menyemak peraturan cuti yang dicipta melalui API.
</Note>

Di DingTalk Admin Console, pergi ke **Pengurusan cuti** > **Peraturan cuti** untuk melihat senarai peraturan cuti. Klik **+ Tambah cuti** untuk mencipta peraturan baharu. Setiap peraturan memaparkan lajur berikut:

| Lajur | Penerangan |
| --- | --- |
| Nama cuti | Contohnya, Cuti peribadi, Cuti ganti, Jenis cuti ciptaan API 1/2 |
| Unit permohonan cuti | Mengikut jam atau Mengikut hari |
| Kaedah pengiraan tempoh cuti | Contohnya, Kira mengikut hari bekerja |
| Peraturan baki | Contohnya, Baki tanpa had |
| Skop | Contohnya, Seluruh syarikat |
| Tindakan | Sunting, Padam |

Dalam contoh yang ditunjukkan, jenis cuti lalai Cuti peribadi dan Cuti ganti ditetapkan dengan unit permohonan "Mengikut jam", manakala jenis cuti yang dicipta melalui API ditetapkan dengan "Mengikut hari".

### Isi permintaan

| Nama | Jenis | Wajib | Penerangan |
| --- | --- | --- | --- |
| leaveName | String | Tidak | Nama cuti. |
| leaveViewUnit | String | Ya | Unit permohonan cuti.   - **day**: Hari - **halfDay**: Separuh hari - **hour**: Jam |
| bizType | String | Ya | Jenis cuti.   - **general_leave**: Cuti biasa - **lieu_leave**: Kerja lebih masa ditukar kepada cuti ganti |
| naturalDayLeave | Boolean | Tidak | Menentukan sama ada tempoh cuti dikira mengikut hari kalendar.   - **true**: Ya - **false**: Tidak     Contohnya, pekerja Alex menghantar borang kelulusan permohonan cuti yang bermula pada 9:30, 11 Apr 2022 dan berakhir pada 18:30, 18 Apr 2022. 16 Apr dan 17 Apr ialah hari rehat Sabtu dan Ahad.   - Jika parameter ini true, borang kelulusan mengira 8 hari cuti, termasuk hari rehat tanpa jadual dan cuti umum. - Jika parameter ini false, borang kelulusan mengira 6 hari cuti, tidak termasuk hari rehat tanpa jadual dan cuti umum. |
| hoursInPerDay | Long | Tidak | Waktu kerja harian yang digunakan untuk penukaran, bersamaan dengan nilai parameter dibahagi 100.    Contohnya, jika syif pekerja mempunyai 8 jam waktu kerja, tetapkan parameter ini kepada 8\*100=800. |
| leaveCode | String | Ya | Pengecam peraturan cuti yang ditambah melalui API. leave_code mesti milik jenis cuti yang ditambah melalui API.   - Aplikasi dalaman: gunakan nilai leave_code yang dikembalikan oleh API Tambah peraturan cuti. - Aplikasi perusahaan pihak ketiga: gunakan nilai leave_code yang dikembalikan oleh API Tambah peraturan cuti. |
| extras | String | Tidak | Peraturan tempoh sah cuti ganti.   - **validity_type**: Jenis tempoh sah    - **absolute_time**: Masa mutlak   - **relative_time**: Masa relatif - **validity_value**: Tarikh lanjutan    - Jika validity_type ialah **absolute_time**, nilai ini tidak boleh kosong dan mesti menggunakan format "yy-mm".   - Jika validity_type ialah **relative_time**, nilai ini mesti integer yang lebih besar daripada 1. |

| visible | Array of String | Tidak | Senarai data dalam skop.   - Jika type=staff, hantar senarai userId pekerja. - Jika type=dept, hantar senarai ID jabatan. - Jika type=label, hantar senarai ID peranan. |
| type | String | Tidak | Jenis peraturan skop.   - **dept**: Jabatan - **staff**: Pekerja - **label**: Peranan |
| submitTimeRule | Object | Tidak | Peraturan penghantaran berhad masa. |
| timeValue | Long | Tidak | Nilai had.   - Jika timeUnit ialah **day**, julat sah ialah 0 hingga 30 hari. - Jika timeUnit ialah **hour**, julat sah ialah 0 hingga 24 jam. |

| timeType | String | Tidak | Jenis had.   - **before**: Hantar lebih awal - **after**: Hantar secara retroaktif |
| enableTimeLimit | Boolean | Tidak | Menentukan sama ada penghantaran berhad masa diaktifkan.   - **true**: Hidup - **false**: Mati |
| leaveCertificate | Object | Tidak | Sijil cuti. |
| unit | String | Tidak | Unit sijil cuti.   - **hour**: Jam - **day**: Hari |
| duration | double | Tidak | Tempoh cuti yang melebihinya memerlukan sijil cuti. |
| enable | Boolean | Tidak | Menentukan sama ada sijil cuti diwajibkan.   - **true**: Hidup - **false**: Mati |
