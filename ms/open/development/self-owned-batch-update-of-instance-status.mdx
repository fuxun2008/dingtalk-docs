Panggil API ini untuk mengemas kini status instans secara pukal.

## Penerangan panggilan API

Sebagai contoh, Pengguna A menghantar tugasan Tugasan yang mempunyai tiga peringkat nod pengendalian, dengan pelaksana B1, B2 dan B3. B1 telah menerima, tugasan kini berada di B2, dan B3 belum menerima tugasan Tugasan tersebut.

Selepas anda memanggil API ini, semak status Tugasan dalam **Pusat Kelulusan** dengan bertukar antara tab **Belum diproses**, **Telah diproses**, **Dimulakan** dan **Diterima**. Setiap baris menyenaraikan **Tajuk**, **Ringkasan**, **Pemohon**, **Masa mula**, **Masa selesai** dan **Status proses** (contohnya, **Diluluskan**). Jadual berikut menerangkan perubahan status.

Dalam contoh aliran kerja kelulusan ini, apabila status ditetapkan kepada **COMPLETED**, status aliran kerja kelulusan adalah seperti berikut:

| Penghantar/Pelaksana Tugasan | Sebelum kemas kini | Selepas kemas kini |
| --- | --- | --- |
| Pengguna A | Workbench > Tugasan > Dimulakan, Dalam kelulusan | Workbench > Tugasan > Dimulakan, Diluluskan |
| Nod kelulusan B1 | Workbench > Tugasan > Telah diproses, Diluluskan | Workbench > Tugasan > Telah diproses, Diluluskan |
| Nod kelulusan B2 | Tiada tugasan Tugasan sedemikian | Tiada tugasan Tugasan sedemikian |
| Nod kelulusan B3 | Tiada tugasan Tugasan sedemikian | Tiada tugasan Tugasan sedemikian |

Dalam contoh aliran kerja kelulusan ini, apabila status ditetapkan kepada **TERMINATED**, status aliran kerja kelulusan adalah seperti berikut:

| Penghantar/Pelaksana Tugasan | Sebelum kemas kini | Selepas kemas kini |
| --- | --- | --- |
| Pengguna A | Workbench > Tugasan > Dimulakan, Dalam kelulusan | Workbench > Tugasan > Dimulakan, Dibatalkan |
| Nod kelulusan B1 | Workbench > Tugasan > Telah diproses, Diluluskan | Workbench > Tugasan > Telah diproses, Dibatalkan |
| Nod kelulusan B2 | Tiada tugasan Tugasan sedemikian | Tiada tugasan Tugasan sedemikian |
| Nod kelulusan B3 | Tiada tugasan Tugasan sedemikian | Tiada tugasan Tugasan sedemikian |

## Permintaan

### Maklumat asas

| Medan | Nilai |
| --- | --- |
| URL HTTP | https://api.dingtalk.io/v1.0/workflow/processCentres/instances/batch |
| Kaedah HTTP | PUT |
| Jenis aplikasi yang disokong | appType-Aplikasi dalaman　appType-Aplikasi perusahaan pihak ketiga |
| Kebenaran yang diperlukan | permission-Workflow.Instance.Write-Kebenaran tulis instans aliran kerja |

### Pengepala permintaan

| Nama | Jenis | Wajib | Penerangan |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Ya | Kredensial akses untuk memanggil API ini. Dapatkannya seperti berikut:   - Aplikasi dalaman: Panggil API [Dapatkan access token aplikasi dalaman](/ms/open/development/obtain-the-access-token-of-an-internal-app). - Aplikasi perusahaan pihak ketiga: Panggil API untuk mendapatkan access token organisasi yang telah memberikan kebenaran kepada aplikasi pihak ketiga. |

### Isi permintaan

| Nama | Jenis | Wajib | Penerangan |
| --- | --- | --- | --- |
| updateProcessInstanceRequests | Array | Tidak | Senarai instans. Maksimum: 50. |
| processInstanceId | String | Ya | ID instans. Panggil API [Cipta instans](/ms/open/development/create-a-ticket-approval-instance) untuk mendapatkannya. |
| status | String | Ya | Status instans.   - **COMPLETED**: Menamatkan aliran kerja kelulusan. - **TERMINATED**: Menghentikan aliran kerja kelulusan. |
| result | String | Ya | Keputusan instans.   - Jika status instans ialah **COMPLETED**, tetapkan parameter ini kepada salah satu nilai berikut.    - **agree**: Terima   - **refuse**: Tolak - Jika status instans ialah **TERMINATED**, parameter ini wajib. Kedua-dua agree dan refuse akan membatalkan aliran kerja kelulusan. |
| notifiers | Array | Tidak | Senarai userId penerima CC. Maksimum: 30. |
| userId | String | Ya | userId penerima CC. |
