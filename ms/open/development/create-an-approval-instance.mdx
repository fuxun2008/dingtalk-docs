Panggil API ini untuk memulakan instans Kelulusan OA. Suite seperti Kehadiran & Cuti, HR, Kewangan & Cukai, Perundangan dan Perjalanan Perniagaan tidak menyokong permulaan instans kelulusan melalui API ini.

## Penerangan panggilan API

### Notis penting

API ini akan mengenakan pengesahan yang lebih ketat terhadap data yang dihantar. Tujuannya adalah untuk menghalang data tidak sah daripada dihantar ke Open API.

- Bagi kawalan pilih tunggal dan Pilih Banyak, setiap nilai pilihan yang dihantar mesti wujud dalam senarai pilihan yang dikonfigurasi.
- Bagi kawalan kenalan dalaman, setiap userID yang dihantar mesti milik pengguna aktif dalam organisasi semasa.
- Bagi kawalan jabatan, setiap ID jabatan mesti merupakan ID jabatan yang sah dalam organisasi semasa.
- Bagi kawalan borang kelulusan berkaitan, setiap ID instans yang dihantar mesti merupakan ID instans kelulusan yang wujud dalam organisasi semasa.

Borang kelulusan yang dimulakan dengan melanggar peraturan ini mungkin gagal dimulakan apabila pengesahan data borang yang lebih ketat berkuat kuasa kelak.

### Kes penggunaan

<Note>
Selepas instans kelulusan dimulakan, maklumatnya tidak boleh diubah suai melalui API.
</Note>

Terdapat 2 cara untuk memulakan instans kelulusan, bergantung pada sama ada penyokong ditetapkan. Tetapkan proses kelulusan baharu, atau guna semula proses kelulusan yang dikonfigurasi dalam Admin Console Kelulusan.

- Jangan tetapkan penyokong, dan guna semula proses kelulusan yang dikonfigurasi dalam Admin Console Kelulusan. Ambil perhatian perkara berikut:

  - Penyokong dan penerima CC menggunakan semula pengguna yang dikonfigurasi dalam Admin Console Kelulusan.
  - Semua reka bentuk aliran kerja yang disokong dalam Admin Console Kelulusan turut disokong. Contohnya kelulusan salah seorang, kelulusan bersama, kelulusan bersyarat dan penyokong dipilih oleh pemohon.

    Editor templat kelulusan mempunyai empat langkah konfigurasi: **Tetapan Asas** > **Reka Bentuk Borang** > **Reka Bentuk Aliran Kerja** > **Tetapan Lanjutan**. Dalam **Reka Bentuk Aliran Kerja**, bina aliran menggunakan jenis nod berikut:
    - **pemohon**
    - **penyokong**, contohnya dipilih oleh pemohon, kelulusan bersama atau kelulusan salah seorang
    - cabang bersyarat yang menghala mengikut nilai medan, contohnya amaun ≥ 100 berbanding < 100
    - **penerima CC**
- Tetapkan penyokong, dan jangan guna semula proses kelulusan yang dikonfigurasi dalam Admin Console OA.

  - Tetapan lanjutan templat kelulusan tidak disokong. Contohnya, Tandatangan dan kebenaran operasi borang tidak tersedia. **Tetapan Lanjutan** templat kelulusan (langkah 4) merangkumi pilihan proses berikut. Tiada satu pun pilihan ini terpakai apabila penyokong ditetapkan melalui API ini:
    - **Nyahpendua Automatik**: jika penyokong muncul lebih daripada sekali dalam aliran, mereka hanya meluluskan sekali dan selebihnya lulus secara automatik.
    - **Lulus Automatik**: apabila penyokong dan pemohon ialah orang yang sama, Kelulusan lulus secara automatik.
    - **Benarkan Penambahan Penyokong**: tambah penyokong sementara pada borang.
    - **Penarikan Balik Kelulusan**: pemohon boleh menarik balik borang.
    - **Kelulusan Berhad Masa**
    - **Tandatangan**
    - **Komen Kelulusan**
    - **Benarkan Penghantaran bagi Pihak Orang Lain**
  - Apabila penyokong ditetapkan, API ini tidak boleh digunakan untuk menetapkan penyokong sebagai dipilih oleh pemohon.

### Arahan

Senario 1: Jangan tetapkan penyokong, dan guna semula proses kelulusan yang dikonfigurasi dalam Admin Console Kelulusan.

### Nota

- Biarkan parameter approvers kosong. Proses kelulusan yang dikonfigurasi dalam Admin Console Kelulusan akan digunakan semula secara lalai.
- Parameter ccList dan ccPosition yang ditetapkan melalui API tidak berkuat kuasa. Penerima CC yang dikonfigurasi dalam Admin Console Kelulusan akan digunakan semula.

- Terdapat 2 kes, bergantung pada sama ada proses kelulusan mengandungi nod dipilih oleh pemohon.

  - Dengan nod dipilih oleh pemohon: panggil API [Dapatkan maklumat nod dalam proses borang kelulusan](/ms/open/development/approval-process-prediction). Nilai isTargetSelect bagi setiap nod yang dikembalikan ialah true.

### Nota

  Apabila memanggil API ini untuk memulakan instans kelulusan, biarkan approvers dan targetSelectActioners kosong.

  - Tanpa nod dipilih oleh pemohon: panggil API [Dapatkan maklumat nod dalam proses borang kelulusan](/ms/open/development/approval-process-prediction). Sesetengah nod yang dikembalikan mempunyai nilai isTargetSelect false.

### Nota

  Apabila memanggil API ini untuk memulakan instans kelulusan, biarkan approvers kosong. Hantar targetSelectActioners untuk menetapkan maklumat bagi nod dipilih oleh pemohon.

Senario 2: Tetapkan penyokong, dan jangan guna semula proses kelulusan yang dikonfigurasi dalam Admin Console OA. Gunakan parameter approvers untuk menetapkan penyokong baharu.
