## Apakah itu RDS Push

RDS Push ialah versi naik taraf yang menggantikan push protokol HTTP. Ia merupakan penyelesaian push yang dibangunkan secara bebas oleh DingTalk Open Platform bersama Alibaba Cloud.

Sambil memastikan keselamatan data, RDS Push memudahkan protokol push dengan ketara, mengurangkan bilangan pemindahan data, meningkatkan kelajuan pemindahan data, serta meningkatkan kestabilan push. RDS Push menyokong pemindahan data bukan sahaja antara DingTalk dan ISV, tetapi juga antara DingTalk dan pembangun Organisasi. Ia menyokong pembangunan dan penyahpepijatan secara tempatan serta penggunaan (deployment) dan operasi dalam talian, dengan itu memudahkan proses ISV dan Organisasi untuk berintegrasi dengan DingTalk secara ketara.

## Perbandingan Keupayaan Antara RDS Push dan HTTP Push

| **RDS Push** | **HTTP Push** |
| --- | --- |
| Menyokong protokol penyegerakan, memastikan data ditulis dengan boleh dipercayai ke RDS pembangun. Jika RDS pembangun mengalami kegagalan, data akan disimpan secara kekal dalam DingTalk. | Tidak menyokong protokol penyegerakan. Kehilangan data mungkin berlaku apabila rangkaian tidak normal atau perkhidmatan pembangun gagal. |
| Menghantar status akhir data perniagaan, membolehkan pembangun terus menggunakan data yang dihantar oleh DingTalk Cloud. Ini juga mengurangkan bilangan panggilan yang perlu dibuat oleh pembangun kepada DingTalk Open Platform, sekali gus mengelakkan had Sekatan kelajuan. | Menghantar ID perniagaan. Selepas menerima push, pembangun masih perlu memanggil API DingTalk Open Platform untuk menyoal status akhir data, yang mudah terkena had Sekatan kelajuan. |
| Menghantar data pada kadar berbeza berdasarkan spesifikasi dan keupayaan RDS pembangun yang menerima push. | Push boleh mencipta lonjakan seketika dalam permintaan HTTP, yang mungkin meningkatkan beban pada pelayan pembangun dan menyebabkannya ranap. |
| Data yang dihantar berbentuk teks biasa (plaintext), tanpa memerlukan pengesahan Tandatangan atau logik penyulitan/penyahsulitan. | Data yang dihantar berbentuk teks sifer (ciphertext), memerlukan pembangun mengesahkan Tandatangan serta melaksanakan penyulitan/penyahsulitan sendiri, dan melaksanakan logik pengesahan Tandatangan serta penyulitan/penyahsulitan dalam pelbagai bahasa pengaturcaraan. |
| Saluran data adalah saluran rangkaian dalaman tanpa kos trafik, dengan Tahap Keselamatan yang tinggi dan kecekapan yang tinggi. | Saluran data adalah saluran rangkaian awam dengan kos trafik, Tahap Keselamatan yang rendah dan kecekapan yang rendah. |

## Perbandingan Proses Antara RDS Push dan HTTP Push

| **Peringkat Pembangunan** | **RDS Push** | **HTTP Push** |
| --- | --- | --- |
| Cipta aplikasi/suite | Pembangun perlu menyediakan instans RDS untuk menerima push (semasa peringkat pembangunan, mana-mana instans MySQL dengan IP awam boleh digunakan). | Pembangun perlu menyediakan program dengan alamat awam untuk mengesahkan push. (Untuk pelancaran rasmi, program mesti digunakan (deploy) pada DingTalk Cloud.) |
| Organisasi memberi Kebenaran dan mengaktifkan aplikasi/suite | Pembangun perlu melaksanakan fungsi yang mengundi (poll) dan membaca jadual pangkalan data yang dihantar untuk mendapatkan maklumat Kebenaran bagi Organisasi yang telah mengaktifkan aplikasi tersebut. **Prosesnya ringkas dan isu mudah disiasat.** | Pembangun perlu melaksanakan empat fungsi berikut: 1) Menerima push kod Kebenaran sementara, 2) Menukar kod Kebenaran sementara kepada kod Kebenaran kekal, 3) Mengaktifkan aplikasi, dan 4) Mendapatkan maklumat Kebenaran bagi Organisasi yang telah mengaktifkan aplikasi. Prosesnya panjang dan isu sukar disiasat. |
| Memantau perubahan data masa nyata Organisasi | Pembangun perlu memilih data yang hendak dipantau pada halaman butiran aplikasi/suite, kemudian mengundi (poll) dan membaca jadual pangkalan data yang menerima push. **Satu tindakan sahaja, mudah dilaksanakan.** | Pembangun perlu mendaftarkan alamat pemantauan untuk setiap Organisasi. Selepas menerima push, mereka perlu menyoal semula DingTalk Open Platform untuk mendapatkan data akhir. Ini memerlukan pelbagai panggilan API dan menjadikan penyahpepijatan API rumit. |
