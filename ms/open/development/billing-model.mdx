## **Peraturan Pengukuran**

- Panggilan yang gagal disebabkan had kadar QPS aplikasi tunggal, had kadar QPS API global, ketidaksampaian rangkaian, dan sebab-sebab serupa tidak dikira dalam bilangan panggilan.
- Open API Asas tidak dikenakan bil. Untuk butiran, lihat Lampiran A: Senarai API Yang Tidak Termasuk Dalam Had Bilangan Panggilan Bulanan.
- Langganan peristiwa asas tidak dikenakan bil. Untuk butiran, lihat Lampiran B: Senarai Peristiwa Yang Tidak Termasuk Dalam Had Penggunaan Webhook dan Stream.

## **Cadangan Penggunaan**

Untuk memanggil endpoint API DingTalk dengan lebih cekap dan wajar, beri perhatian kepada perkara berikut:

1. **Optimumkan logik panggilan API**: Contohnya, jika sesuatu API membaca data DingTalk, elakkan memanggilnya secara pemasa gelung (polling). Jika perlu, integrasikan notifikasi callback DingTalk untuk mengurangkan bilangan panggilan dengan berkesan dan memastikan ketepatan masa data dengan lebih baik.
2. **Semak kod ralat API**: Contohnya, apabila panggilan API mengembalikan ralat, tentukan puncanya berdasarkan kod ralat tersebut. Jangan cuba semula tanpa had, dan kawal bilangan percubaan semula.
3. Untuk had kadar QPS peringkat aplikasi pada API, lihat Lampiran C: Cara Mengendalikan Had Kadar Pada Server API DingTalk.

Untuk menggunakan saluran mesej Webhook dan Stream DingTalk dengan lebih cekap dan wajar, beri perhatian kepada perkara berikut:

1. **Optimumkan penyelesaian langganan peristiwa anda dengan mengikut prinsip berikut**: Langgan hanya peristiwa yang perlu, nyahduplikasikan pengendalian acara, serta bertindak balas dan kembalikan respons dengan pantas. Untuk butiran, lihat Lampiran D: Cadangan Untuk Penggunaan Sumber Secara Wajar.
