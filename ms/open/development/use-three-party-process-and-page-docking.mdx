# Kelulusan OA sendiri: Integrasi aliran kerja dan halaman pihak ketiga

## Gambaran keseluruhan

### Latar belakang

Organisasi sering membangunkan sistem OA sendiri atau membeli sistem pihak ketiga. Sistem ini biasanya mempunyai proses dan halaman kelulusan tersendiri. Pekerja perlu bertukar antara beberapa sistem untuk mengendalikan kelulusan. Keadaan ini memecahkan aliran kerja dan menjejaskan kecekapan. Sambungkan proses kelulusan sistem sendiri anda kepada Pusat Kelulusan OA DingTalk. Pengguna kemudiannya boleh membuka halaman sistem perniagaan dan membuat kelulusan terus dalam DingTalk untuk pengalaman sehenti.

Organisasi lazimnya berdepan dengan masalah berikut:

- **Titik masuk kelulusan berselerak:** Pekerja mengendalikan kelulusan secara berasingan dalam beberapa sistem. Peringatan DingTalk To-Do tidak meliputi tugasan kelulusan daripada sistem sendiri, jadi penyokong mudah terlepas tugasan.
- **Pengalaman kelulusan tidak seragam:** Halaman kelulusan dalam sistem sendiri tidak sepadan dengan gaya DingTalk. Pengguna perlu menyesuaikan diri dengan antara muka yang berbeza, dan ini menambah keluk pembelajaran.
- **Capaian notifikasi To-Do yang rendah:** Sistem sendiri bergantung pada e-mel atau SMS untuk notifikasi kelulusan. Saluran ini lambat dan tidak dapat menggunakan Tolak mesej DingTalk atau Pusat To-Do.
- **Data kelulusan terasing:** Status kelulusan dan rekod pemprosesan tersebar merentas sistem. Pengurus tidak dapat melihat kemajuan kelulusan di satu tempat dalam DingTalk.

### Nilai teras

Penyelesaian ini menyambungkan sistem kelulusan pihak ketiga dengan halaman dalam aplikasi DingTalk. Penyelesaian ini memanggil API Pusat Proses Kelulusan di DingTalk Open Platform untuk menyegerakkan data kelulusan dua hala.

- **Penyegerakan templat kelulusan:** Segerakkan templat borang kelulusan daripada sistem sendiri anda ke DingTalk. Pengguna boleh melihat dan mengurus templat kelulusan pihak ketiga dalam Admin Console Kelulusan OA DingTalk.
- **Pautan instans kelulusan:** Apabila kelulusan bermula dalam sistem sendiri anda, DingTalk mencipta instans kelulusan yang sepadan secara automatik. Pengguna boleh melihat dan mengambil tindakan dalam empat senarai di Pusat Kelulusan DingTalk: Belum Selesai, Telah Diproses, Dimulakan dan Diterima.
- **Penolakan tugasan To-Do:** Selepas maklumat nod kelulusan disegerakkan ke DingTalk, DingTalk menjana tugasan To-Do secara automatik. Tugasan ini menggunakan peringatan To-Do dan Tolak mesej DingTalk yang seragam.
- **Penulisan semula status kelulusan:** Selepas pengguna menyelesaikan kelulusan dalam DingTalk, tulis semula keputusan (seperti Terima atau Tolak) ke sistem sendiri anda untuk memastikan data kekal konsisten di kedua-dua belah pihak.

### Kes penggunaan

Penyelesaian ini sesuai untuk senario perniagaan lazim berikut:

- **Integrasi kelulusan perolehan ERP:** Pekerja menghantar permohonan pembelian dalam sistem ERP. Permohonan disegerakkan ke DingTalk secara automatik. Penyokong menyelesaikan kelulusan dalam DingTalk, dan keputusan ditulis semula ke sistem ERP untuk mengemas kini status pesanan pembelian.
- **Pautan kelulusan cuti HR:** Permohonan cuti daripada sistem HR disegerakkan ke DingTalk. Pekerja menerima peringatan di Pusat To-Do DingTalk dan mengendalikannya di situ. Keputusan kelulusan mengemas kini modul kehadiran HR secara automatik.
- **Integrasi tuntutan perbelanjaan pengurusan projek:** Proses tuntutan perbelanjaan dalam sistem pengurusan projek disambungkan ke Pusat Kelulusan DingTalk. Pengurus projek membuat kelulusan dalam DingTalk, dan data tuntutan disegerakkan semula ke modul belanjawan projek.
- **Kolaborasi kelulusan kontrak CRM:** Proses kelulusan kontrak dalam sistem CRM disegerakkan ke DingTalk. Pasukan jualan menyelesaikan kelulusan berbilang peringkat dalam DingTalk, dan status kontrak dikemas kini dalam sistem CRM secara masa nyata.

## Senario perniagaan lazim

### Senario 1: CIMC Ruijiang menyatukan kelulusan daripada beberapa sistem perniagaan dalam DingTalk

#### Masalah

CIMC Ruijiang berperanan sebagai pusat perintis pembangunan IT dalaman CIMC Group. Syarikat ini telah membina lebih daripada sedozen sistem perniagaan bebas, seperti MES, IOT dan SRM. Setiap sistem mengendalikan data dan aliran kerja untuk fungsi tertentu. Model yang sangat khusus ini meningkatkan kecekapan unit perniagaan individu. Namun, model ini juga memecahkan dan mengganggu aliran maklumat dalam organisasi:

- Pekerja mengendalikan tugasan kelulusan secara berasingan dalam lebih daripada sedozen sistem. Prosesnya leceh, dan kelulusan segera mudah terlepas.
- Gaya halaman kelulusan berbeza antara sistem. Pengguna perlu menyesuaikan diri dengan antara muka yang berbeza, dan ini menambah keluk pembelajaran.
- Notifikasi kelulusan bergantung pada mesej dalaman setiap sistem dan tidak dapat menggunakan peringatan To-Do serta Tolak mesej DingTalk yang seragam.
- Pengurus tidak dapat melihat semua kemajuan kelulusan di satu tempat dalam DingTalk. Mereka perlu log masuk ke beberapa sistem untuk menyemak.

#### Nilai terbukti

- **Proses automatik**

  Aliran integrasi:

  1. Sistem **MES/IOT/SRM** memulakan Kelulusan.
  2. API Pusat **Kelulusan OA DingTalk** dipanggil untuk mencipta instans kelulusan.
  3. Tugasan kelulusan disegerakkan ke senarai **DingTalk To-Do**.
  4. Penyokong menyelesaikan Kelulusan dalam DingTalk.
  5. Keputusan kelulusan ditulis semula ke sistem perniagaan asal secara masa nyata.

  Kecekapan meningkat lebih **83%** berbanding kaedah tradisional yang memulakan dan meluluskan dalam setiap sistem satu demi satu.
- **Kelebihan utama**

  - **Akses seragam untuk kelulusan berbilang sistem:** Proses kelulusan, item To-Do dan Notifikasi Kerja penting daripada lebih sedozen sistem bebas, seperti MES, IOT dan SRM, semuanya berkumpul dalam DingTalk untuk dikendalikan secara seragam.
  - **Perkongsian data dan kolaborasi yang cekap:** Hapuskan silo maklumat antara sistem. Dayakan perkongsian data merentas sistem dan Automasi proses untuk meningkatkan responsif keseluruhan organisasi.
  - **Pengalaman kelulusan yang dipertingkatkan:** Pekerja tidak lagi perlu log masuk ke beberapa sistem satu demi satu. Sebaliknya, mereka membuka DingTalk dan mengendalikan semuanya dengan satu ketikan. Kerumitan operasi berkurangan dengan ketara, dan masa respons kelulusan menjadi jauh lebih singkat.

### Senario 2: Kelulusan cuti HR dipautkan dengan kehadiran DingTalk

#### Masalah

Sistem HR mengurus kelulusan cuti secara bebas, manakala data daftar masuk kehadiran berada dalam DingTalk. Data tidak mengalir antara kedua-dua sistem. Selepas bercuti, pekerja masih perlu menghantar permohonan daftar masuk susulan secara manual dalam DingTalk. Kakitangan HR perlu menyemak silang rekod cuti dan kehadiran merentas sistem.

#### Nilai terbukti

- **Proses automatik**

  Proses Automasi hujung ke hujung berjalan dalam lima langkah:

  1. Sistem **MES** mencipta pesanan kerja pengeluaran.
  2. **API Kelulusan OA DingTalk** dipanggil untuk mencipta instans kelulusan.
  3. Sistem **ERP** menyemak inventori bahan (bahan mentah, bahan tambahan, pembungkusan).
  4. Penyelia bengkel menyemak dalam DingTalk dan mengetik **Tolak** atau **Luluskan**.
  5. Keputusan kelulusan disegerakkan semula ke ketiga-tiga sistem: **MES** (status pesanan kerja), **ERP** (inventori) dan **QMS** (rekod kualiti).

  Berbanding cara tradisional log masuk ke MES, ERP dan QMS secara berasingan (kira-kira 15 minit setiap kelulusan), pendekatan bersepadu ini menyelesaikan kelulusan dalam masa 2 minit melalui satu titik masuk DingTalk, iaitu peningkatan kecekapan kelulusan sebanyak 87%.
- **Kelebihan utama**

  - **Integrasi kelulusan pesanan kerja pengeluaran:** Nod kelulusan pesanan kerja daripada MES, ERP dan QMS semuanya dipaparkan dalam Senarai tugasan DingTalk. Penyokong tidak lagi perlu bertukar antara sistem.
  - **Keterlihatan Proses kelulusan secara masa nyata:** DingTalk memaparkan data pesanan kerja lengkap yang dihimpunkan daripada ketiga-tiga sistem, termasuk senarai bahan, keperluan pemeriksaan kualiti dan data sejarah pesanan kerja. Kemajuan kelulusan jelas sepintas lalu.
  - **Penyegerakan data hujung ke hujung:** Keputusan kelulusan ditulis semula ke sistem perniagaan asal secara masa nyata. Apabila kelulusan ditolak, tugasan To-Do hiliran dibatalkan secara pukal. Ini memastikan data kekal konsisten dan boleh dikesan di kedua-dua belah pihak.

## Panduan pelaksanaan

### Seni bina teknikal

Penyelesaian ini menggunakan lima komponen teknikal teras berikut untuk menyambungkan sistem kelulusan sendiri anda dengan Pusat Kelulusan OA DingTalk:

- **Lapisan Pengesahan identiti:** Berasaskan protokol OAuth 2.0 DingTalk Open Platform. Lapisan ini menggunakan Kelayakan aplikasi untuk mendapatkan access token, yang menyediakan pengesahan identiti seragam bagi semua panggilan API serta memastikan keselamatan dan kesahihan panggilan.
- **Lapisan pengurusan templat kelulusan:** Menyegerakkan templat kelulusan sendiri ke Pusat Kelulusan OA DingTalk dan mendapatkan kod templat yang unik secara global sebagai pengecam. Lapisan ini menyokong penciptaan, pengemaskinian dan pemadaman templat untuk pengurusan awan seragam bagi struktur borang kelulusan.
- **Enjin instans kelulusan:** Mencipta instans kelulusan dalam DingTalk dan menjana pengecam instans yang unik. Enjin ini membawa data perniagaan kelulusan khusus, seperti pemohon, Kandungan kelulusan dan Lampiran, serta menyokong pengurusan kitaran hayat kelulusan sepenuhnya.
- **Lapisan penyegerakan tugasan To-Do:** Menyegerakkan tugasan kelulusan secara pukal ke Pusat Proses DingTalk, menjana pengecam tugasan dan mengikatnya kepada Pengguna DingTalk. Penyokong boleh melihat dan mengendalikan tugasan kelulusan daripada beberapa sistem perniagaan dalam satu Senarai tugasan DingTalk.
- **Lapisan penyegerakan status dua hala:** Menyegerakkan status kelulusan dalam kedua-dua arah. Apabila pengguna menyelesaikan kelulusan dalam DingTalk, status ditulis semula ke sistem perniagaan secara masa nyata. Apabila sistem perniagaan menamatkan atau menyelesaikan kelulusan, status tugasan DingTalk dikemas kini sewajarnya. Ini memastikan ketekalan data di kedua-dua belah pihak.

### Prasyarat

- **Penyediaan aplikasi**: Selesaikan [penciptaan dan konfigurasi aplikasi](/ms/open/dingstart/create-application).
- **Keperluan kebenaran**: Miliki kebenaran Admin Organisasi atau Sub Admin DingTalk, dan mohon kebenaran API berikut:

  - `Workflow.Form.Write` (kebenaran tulis templat aliran kerja)
  - `Workflow.Form.Read` (kebenaran baca templat aliran kerja), pilihan
  - `Workflow.Instance.Write` (kebenaran tulis instans aliran kerja)
  - `Workflow.Instance.Read` (kebenaran baca instans aliran kerja)
  - `qyapi_aflow` (kebenaran pengurusan data aliran kelulusan)
- **Persekitaran pembangunan**: Persekitaran pembangunan Java (JDK 1.6 atau lebih baharu) dan alat binaan Maven telah dipasang.
- **Penyediaan SDK**: Muat turun SDK Bahagian pelayan DingTalk, yang menyokong pelbagai bahasa seperti Java, Python dan Go.

### Pelaksanaan kod

Langkah 1: Dapatkan maklumat Kelayakan aplikasi, termasuk client ID dan Client Secret.

Langkah 2: Mohon kebenaran API untuk API berkaitan kelulusan.

Langkah 3: Dapatkan Kredensial akses. Rujuk [Dapatkan access token Aplikasi dalaman](/ms/open/development/obtain-the-access-token-of-an-internal-app). Apabila anda memanggil API, access token mengesahkan identiti pemanggil.

Langkah 4: Panggil API kelulusan Bahagian pelayan.

1. Panggil Server API baharu [Cipta atau kemas kini templat kelulusan](/ms/open/development/create-orupdate-the-approval-template-new) untuk mendapatkan kod templat unik `processCode`.
2. Jika anda tidak menyimpan `processCode`, panggil API [Dapatkan kod templat](/ms/open/development/obtain-the-template-code) untuk mendapatkannya semula.
3. Selepas templat kelulusan dicipta, pengguna boleh pergi ke Admin Console Kelulusan OA DingTalk untuk melihat templat Borang kelulusan sendiri pihak ketiga, melihat atau mencari data templat, serta mengeksport atau memadam data templat.
4. Menggunakan kod templat `processCode`, panggil Server API baharu [Cipta instans](/ms/open/development/create-a-ticket-approval-instance) untuk memulakan instans kelulusan dan mendapatkan ID instans kelulusan `processInstanceId`.
5. Selepas instans kelulusan dicipta, pengguna juga boleh membuka Pusat Kelulusan OA DingTalk untuk melihat empat senarai kelulusan (Belum Selesai, Telah Diproses, Dimulakan dan Diterima), mencari data instans kelulusan dan membuat kelulusan.
6. Menggunakan instans kelulusan `processInstanceId` dan senarai To-Do `tasks`, panggil API [Cipta tugasan belum selesai dalam Pusat Proses](/ms/open/development/create-pending-tasks-in-process-center). Ini menyegerakkan maklumat nod kelulusan daripada sistem pihak ketiga ke Kelulusan OA DingTalk, mengembalikan taskId bagi setiap item To-Do dan menjana tugasan DingTalk To-Do yang sepadan.
7. Selepas tugasan belum selesai dicipta, panggil API [Tanya tugasan kelulusan OA yang diintegrasikan melalui Pusat Proses](/ms/open/development/query-oa-approval-tasks-integrated-through-process-center) untuk menanya tugasan kelulusan pengguna yang sedang berjalan.
8. Menggunakan instans kelulusan `processInstanceId` dan taskId To-Do kelulusan, panggil API [Kemas kini status tugasan Pusat Proses](/ms/open/development/update-process-center-task-status) untuk menyegerakkan kemas kini status item To-Do kelulusan sendiri anda. Dalam senario seperti tandatangan-ATAU (mana-mana seorang penyokong boleh meluluskan), panggil API [Batalkan beberapa tugasan belum selesai dalam Pusat Proses](/ms/open/development/cancel-multiple-oa-approval-tasks) untuk menetapkan semua item To-Do yang sedang berjalan di bawah instans kelulusan kepada CANCELED secara pukal.
9. Menggunakan instans kelulusan `processInstanceId`, status instans `status`, keputusan instans `result` dan parameter lain, panggil API [Kemas kini status instans](/ms/open/development/update-instance-status) atau [Kemas kini status instans secara pukal](/ms/open/development/self-owned-batch-update-of-instance-status) untuk mengemas kini status instans.
10. Akhir sekali, untuk membersihkan data templat kelulusan, panggil API [Padam templat](/ms/open/development/self-owned-approval-deletion-template). Ini memadam templat kelulusan yang dicipta untuk Organisasi anda, bersama-sama instans dan tugasan To-Do yang dicipta di bawahnya.

## Langkah pelaksanaan

### **Langkah 1: Dapatkan kelayakan aplikasi**

1. Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.io/).
2. Pilih Aplikasi sasaran untuk membuka halaman butirannya.
3. Klik **Maklumat Asas** > **Kelayakan dan Maklumat Asas**.
4. Rekodkan `Client ID` dan `Client Secret` Aplikasi.

### Nota

   Simpan `Client Secret` dengan selamat dan jangan sekali-kali kongsi dengan pihak ketiga. Simpan dalam pemboleh ubah persekitaran atau sistem pengurusan kunci, bukan dikod keras.

### Langkah 2: Tambah kebenaran API

1. Pada halaman butiran Aplikasi, klik **Urus kebenaran**.
2. Dalam kotak carian kebenaran, masukkan pengecam kebenaran berikut dan mohon kebenaran tersebut:

   - `Workflow.Form.Write` (kebenaran tulis templat aliran kerja): Mencipta, mengemas kini dan memadam templat kelulusan.
   - `Workflow.Form.Read` (kebenaran baca templat aliran kerja): Mendapatkan kod templat. Pilihan.
   - `Workflow.Instance.Write` (kebenaran tulis instans aliran kerja): Mencipta instans kelulusan dan mengemas kini status instans.
   - `Workflow.Instance.Read` (kebenaran baca instans aliran kerja): Menanya tugasan kelulusan dan maklumat instans.
   - `qyapi_aflow` (kebenaran pengurusan data aliran kelulusan): Mengurus data Proses kelulusan secara menyeluruh.

<Note>
Senario perniagaan yang berbeza mungkin memerlukan gabungan kebenaran yang berbeza. Mohon berdasarkan keperluan sebenar anda. Contohnya, senario Import pukal juga memerlukan kebenaran untuk operasi Pengguna secara pukal.
</Note>

### Langkah 3: Dapatkan Kredensial akses (Access Token)

Gunakan Client ID dan Client Secret daripada Langkah 1 untuk mendapatkan Kredensial akses Aplikasi. Rujuk [Dapatkan access token Aplikasi dalaman](/ms/open/development/obtain-the-access-token-of-an-internal-app).

```java
public void getAccessToken() throws Exception {
  Config config = new Config();
  config.protocol = "https";
  config.regionId = "central";
  com.aliyun.dingtalkoauth2_1_0.Client client = new com.aliyun.dingtalkoauth2_1_0.Client(config);
  GetAccessTokenRequest accessTokenRequest = new GetAccessTokenRequest()
    .setAppKey("din*********hgn")
    .setAppSecret("9G_O************mBkhgGIO");
  GetAccessTokenResponse accessToken = client.getAccessToken(accessTokenRequest);
  System.out.println(JSON.toJSONString(accessToken.getBody()));
}
```

**Amalan terbaik**:

- **Strategi cache**: `accessToken` sah selama 2 jam. Simpan dalam cache memori atau Redis, dan muat semula secara proaktif 5 minit sebelumnya tamat tempoh.
- **Kawalan keserentakan**: Elakkan beberapa thread memuat semula token pada masa yang sama sehingga menyebabkan Konflik. Gunakan kunci teragih.
- **Cuba semula ralat**: Cuba semula secara automatik apabila berlaku gangguan rangkaian, sehingga 3 kali, dengan selang yang semakin meningkat (1s → 2s → 4s).

## Soalan lazim

- **S1: Parameter manakah yang wajib semasa mencipta templat kelulusan?**

  J: Parameter Wajib ialah:

  - `name`: Nama templat kelulusan.
  - `formComponents`: Senarai komponen borang. Senarai ini mesti mengandungi sekurang-kurangnya satu komponen.
  - Parameter Pilihan termasuk `description` (penerangan templat) dan lain-lain.
- **S2: Bagaimanakah cara mendapatkan processCode?**

  J: Gunakan salah satu kaedah berikut:

  - Selepas memanggil API Cipta atau kemas kini templat kelulusan, dapatkan `result.processCode` daripada respons.
  - Jika anda tidak menyimpan processCode, panggil API Dapatkan kod templat dan tanya berdasarkan nama templat.
- **S3: Apakah yang berubah dalam DingTalk selepas saya mencipta tugasan belum selesai?**

  J: Selepas anda mencipta tugasan belum selesai:

  1. Halaman butiran Borang kelulusan memaparkan butang Terima dan Tolak.
  2. Pusat Proses menyegerakkan tugasan kelulusan sebagai tugasan DingTalk To-Do.
  3. Penyokong melihat peringatan kelulusan di Pusat To-Do DingTalk.
- **S4: Bagaimanakah cara menyegerakkan data tugasan To-Do?**

  J: Ikut langkah berikut:

  1. Panggil API Cipta tugasan belum selesai dalam Pusat Proses untuk menyegerakkan maklumat nod kelulusan daripada sistem pihak ketiga ke DingTalk.
  2. Panggil API Tanya tugasan kelulusan OA untuk mengesahkan bahawa tugasan telah disegerakkan dengan betul.
  3. Apabila status kelulusan berubah, panggil API Kemas kini status tugasan Pusat Proses untuk menyegerakkan status terkini.
- **S5: Kebenaran manakah yang perlu saya mohon di DingTalk Open Platform?**

  J: Mohon kebenaran berikut untuk menyambung ke Pusat Proses Kelulusan OA:

  | **Kod Skop kebenaran** | **Nama Skop kebenaran** | **Penerangan** |
  | --- | --- | --- |
  | Workflow.Form.Write | Kebenaran tulis templat aliran kerja | Cipta, kemas kini dan padam templat kelulusan |
  | Workflow.Instance.Write | Kebenaran tulis instans aliran kerja | Cipta instans kelulusan dan kemas kini status instans |
  | Workflow.Instance.Read | Kebenaran baca instans aliran kerja | Tanya tugasan kelulusan dan maklumat instans |
  | qyapi_aflow | Kebenaran pengurusan data aliran kelulusan | Urus data Proses kelulusan secara menyeluruh |

  Senario perniagaan yang berbeza mungkin memerlukan gabungan kebenaran yang berbeza. Mohon berdasarkan keperluan sebenar anda.
