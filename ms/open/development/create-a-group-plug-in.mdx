Artikel ini menerangkan cara mencipta entri pintasan.

## Apakah itu entri pintasan (plugin kumpulan)

Apabila pengguna klik entri plugin di dalam kumpulan, parameter kumpulan berkaitan turut dibawa, membolehkan pembangun menentukan siapa yang mengklik plugin tertentu di kumpulan mana pada bila-bila masa. Berdasarkan ini, penyedia penyelesaian dapat menyampaikan perkhidmatan perniagaan yang sangat pintar dan bersasaran dengan jelas.

<Warning>
## Cipta plugin kumpulan
</Warning>

1. Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.io/#/index).
2. Pada halaman **Developer Console**, pilih **Scenario group** dan klik **Create group plugin**.
3. Cipta satu **plugin kumpulan**, klik **Create**, dan tunggu kelulusan.

   **Nota**
   - Kelulusan diselesaikan dalam masa 12 jam pada hari bekerja.

   Pelbagai pautan plugin kumpulan boleh dikonfigurasikan. Pautan boleh dibuka dalam workbench DingTalk, bar sisi, pelayar luaran, dan lain-lain:

   | Kaedah buka | Konfigurasi pautan |
   | --- | --- |
   | Buka plugin kumpulan dalam workbench DingTalk | dingtalk://dingtalkclient/action/openapp?corpid=dingxxxxxxxxxxx&**container_type=work_platform**&app_id=0_140444xxxxx&redirect_type=jump&redirect_url=https%3A%2F%2Fding-doc.dingtalk.io%2F |
   | Buka plugin kumpulan dalam bar sisi | dingtalk://dingtalkclient/action/openapp?corpid=dingxxxxxxxxxxx&**container_type=slide_panel**&app_id=0_140444xxxxx&redirect_type=jump&redirect_url=https%3A%2F%2Fding-doc.dingtalk.io%2F |
   | Buka plugin kumpulan dalam pelayar luaran | dingtalk://dingtalkclient/action/openapp?corpid=dingxxxxxxxxxxx&con**tainer_type=browser**&app_id=0_140444xxxxx&redirect_type=jump&redirect_url=https%3A%2F%2Fding-doc.dingtalk.io%2F |

## Bina pautan entri pintasan

Entri pintasan (plugin kumpulan) ialah pautan DingTalk yang mempunyai keupayaan perniagaan. Pembangun perlu menyusun pautan entri pintasan berdasarkan senario sebenar aplikasi mikro mereka dan keperluan khusus pengguna dalam kumpulan.

Nama entri pintasan menyokong sehingga empat aksara. Pautan entri pintasan menawarkan keupayaan yang luas, tetapi pembangun perlu menyusunnya melalui parameter pautan. Sebagai contoh, kaedah buka pada bahagian mudah alih (push halaman, pop halaman, dan sebagainya) dan logik navigasi halaman pada PC (buka bekas baharu atau geser halaman ke kiri) semuanya dilaksanakan melalui konfigurasi parameter pautan.

- **Alihkan ke halaman H5**

  link (bar sisi / bekas geser keluar)

  Contoh:

  ```text
  dingtalk://dingtalkclient/page/link?dd_mode=push&pc_slide=true&url=http%3a%2f%2fomsdevdingtalkf.zjk.taeapp.com%2findex.html%3fcorpid%3d$CORPID$%26dd_nav_bgcolor%3dffff943e%2f%23%2fgroup-plugin%3fcorpid%3d$CORPID$%26openConversationId%3d$DOUBLE_ENCCID$%26dd_nav_bgcolor%3dffff943e%26pluginType%3d3%26appid%3d6397
  ```

  Penerangan parameter:

  | Parameter | Penerangan |
  | --- | --- |
  | url | URL halaman. Pengekodan URL diperlukan. |
  | dd_mode | Digunakan pada iOS. - push: menolak (push) bekas dari kiri ke kanan pada iOS. - present: memaparkan (pop) bekas dari bawah ke atas pada iOS. |
  | pc_slide | Apabila pc_slide=true, URL dibuka di dalam aplikasi pada PC. |
- **Alihkan ke aplikasi mikro**

  openapp (seperti workbench, pelayar, atau panel geser kiri)

  Contoh:

  ```text
  dingtalk://dingtalkclient/action/openapp?corpid=$CORPID$&container_type=work_platform&app_id=3204&redirect_type=emit_params&params=&redirect_url=https%3A%2F%2Ftestt2.wmnetwork.cc%2Fmanage%2Findex%3Fmid%3Dwfp40mx9
  ```

  Penerangan parameter:

  | Parameter | Penerangan |
  | --- | --- |
  | container_type | Bekas tempat halaman dipaparkan: - browser: pelayar. - slide_panel: panel geser kiri. - work_platform: workbench. |
  | corpid | ID organisasi. |
  | app_id | - Untuk Aplikasi perusahaan pihak ketiga, isikan appId. Lihat cara melihat appId. - Untuk aplikasi dalaman, isikan 0_agentId, iaitu gabungan digit 0, Garis Bawah, dan agentId. agentId boleh dilihat dalam butiran aplikasi. |
  | redirect_type | Jenis pengalihan: - jump: membuka redirect_url secara terus. - emit_params: menggunakan kaedah penghantaran peristiwa (event-emitting). |
  | params | Parameter. Apabila dibuka buat kali pertama, tambahkan parameter ini ke dalam senarai parameter URL pengalihan. |
  | redirect_url | URL pengalihan. Pengekodan URL diperlukan. |
  | slide_panel_option | Parameter untuk panel geser kiri, khusus untuk versi PC. Contohnya: `{"width":500,"showAppPage":true}` (`width` ialah lebar bar sisi, dan `showAppPage` menunjukkan sama ada halaman web dipaparkan). |
- **Alihkan ke mini program**

  1. **Parameter umum (disokong oleh open_micro_app dan open_mini_app)**

     | Parameter | Wajib | Penerangan |
     | --- | --- | --- |
     | appId | Pilih salah satu antara appId dan agent_id. Jika kedua-duanya wujud, app_id diutamakan. | ID aplikasi mikro. Perhatikan ini bukan ID mini program. Aplikasi ISV menggunakan ID ini. |
     | page | Tidak | Laluan halaman mini program. Parameter GET boleh ditambah. Lalai kepada halaman utama mini program. |
     | query | Tidak | Parameter permulaan mini program, yang boleh diperoleh dalam callback App.onLaunch / onShow. Apabila mini program dilancarkan, bahagian klien menambah parameter corpId secara lalai. Oleh itu, pihak perniagaan tidak boleh menetapkan corpId kerana ia akan ditulis ganti. |
     | containerType | Tidak | Parameter khusus PC sahaja. Pilihan berikut tersedia: - browser: pelayar. - slide_panel (Lalai): panel geser kiri. - work_platform: workbench. - mobile: mengalihkan ke bahagian mudah alih. |
     | title | Tidak | Parameter khusus PC sahaja yang digunakan untuk memaparkan tajuk. |
     | source | Tidak | Sumber (digunakan hanya apabila pakej perlu ditarik daripada bahagian pelayan): - debug: versi nyahpepijat peranti sebenar. - trial: versi percubaan. |
     | version | Tidak | Nombor versi. |
     | ddMode | Tidak | Mod peralihan untuk melancarkan mini program. - push: mod push. - present: mod pop-up. - float: mod lapisan terapung. - pop: mod paparan pop. Jika tidak ditetapkan, bahagian klien melancarkan menggunakan mod peralihan lalai. Pelancaran grayscale bermula pada bahagian klien v4.5.8. float dan pop memulakan pelancaran grayscale pada v4.6.35 (20190624). |
     | mainTask | Tidak | Diperlukan hanya untuk **klien Android**. Nilai ialah "true" atau "false", dengan lalai false. Jika ditetapkan kepada "true", mini program berjalan dalam Task yang sama dengan Task utama DingTalk dan tidak lagi dikekalkan hidup (keep alive). Disokong dalam bahagian klien v4.6.3. |
     | ddJointNavi | Tidak | Mengkonfigurasi gaya bar navigasi. Jika dikonfigurasikan, ia menulis ganti logik ddMode. android & iOS: "0", "1", atau "1001". - 0: bar navigasi lama. - 1: bar navigasi baharu. - 1001: bar navigasi dengan hanya butang kembali dan tajuk. |
     | keepAlive | Tidak | Boleh ditetapkan kepada **true** atau **false**, dengan lalai **true**. Jika mainTask ditetapkan kepada true, kunci ini diabaikan. |
     | ddFocus | Tidak | Boleh ditetapkan kepada **true** atau **false**, dengan lalai **true**. Jika ditetapkan kepada **true**, bekas melumpuhkan elemen dalaman daripada mendapat fokus semasa permulaan. |
     | ddEnableWX | Tidak | Sama ada rendering Weex disokong. Apabila rendering Weex disokong, jika halaman dikonfigurasikan dengan mod rendering Weex, Weex boleh dilancarkan untuk memuatkan halaman. |
     | ddForceAsync | Tidak | Sama ada memaksa permulaan tak segerak (asynchronous). Dengan permulaan tak segerak dipaksa, jika pakej luar talian tempatan wujud, kemas kini segerak tidak dicetuskan dan aplikasi dimulakan dengan kemas kini tak segerak dipaksa (untuk menangani isu permulaan dalam persekitaran luar talian). |
     | animated | Tidak | Nilai ialah **0** atau **1**. Menunjukkan sama ada animasi peralihan digunakan untuk permulaan tak segerak (diabaikan untuk senario permulaan segerak). Lalai kepada **1**. Tersedia sejak v4.6.36. |

### Parameter yang disokong apabila ddMode=float (tetingkap terapung)

     | Parameter | Wajib | Penerangan |
     | --- | --- | --- |
     | panelHeight | Tidak | Ketinggian tetingkap terapung. Boleh berupa peratus (Percent) skrin atau ketinggian tetap. - percent50 bermaksud 50% daripada skrin. Nombor mesti dalam julat (0-100]. Nilai di luar julat akan dipendekkan ke sempadan. - 1000 bermaksud ketinggian tepat 1000 pt (bukan px). - Jika tidak ditetapkan atau ditetapkan kepada 0, tetingkap terapung dipaparkan dalam skrin penuh. |
     | containerType | Tidak | Dua nilai tambahan tersedia dalam senario ini: - miniApp (Lalai): mini program. - online: H5 dalam talian. |
     | miniAppId | Bergantung pada containerType | appId mini program. |
     | page | Bergantung pada containerType | Alamat halaman yang dikodkan URL. Untuk mini program, ini ialah halaman mini program. Untuk H5 dalam talian, ini ialah URL. |
     | coverVisible | Tidak. Dipaparkan secara lalai. Tetapkan kepada false untuk menyembunyikan. | - true (Lalai): menunjukkan lapisan topeng (mask layer). - false: menyembunyikan lapisan topeng. Dipaparkan secara lalai. |

### Parameter yang disokong apabila ddMode=pop (lapisan pop)

     | Parameter | Wajib | Penerangan |
     | --- | --- | --- |
     | width | Ya | Lebar lapisan pop. |
     | height | Ya | Ketinggian lapisan pop. |
     | clear | Tidak | Sama ada latar belakang telus. Legap secara lalai. |
     | containerType | Tidak | Dua nilai tambahan tersedia dalam senario ini: - miniApp (Lalai): mini program. - online: H5 dalam talian. |
     | miniAppId | Bergantung pada containerType | appId mini program. |
     | page | Bergantung pada containerType | Alamat halaman yang dikodkan URL. Untuk mini program, ini ialah halaman mini program. Untuk H5 dalam talian, ini ialah URL. |
  2. **Buka skema aplikasi mikro (skema khusus untuk mini program perusahaan)**

     Skema: `dingtalk://dingtalkclient/action/open_micro_app`

     `Parameter asas sama seperti dalam senarai parameter umum.`

     Logik kawalan grayscale hendaklah diletakkan dalam pelaksana (handler) skema ini.

     ​

     | Parameter | Wajib | Penerangan |
     | --- | --- | --- |
     | corpId | Ya | ID organisasi. **Penting** Parameter ini mempunyai keutamaan tinggi dan menulis ganti corpId dalam query. |
     | appId | Pilih salah satu antara appId dan agent_id. Jika kedua-duanya wujud, appid diutamakan. | ID aplikasi mikro. Perhatikan ini bukan ID mini program. Aplikasi ISV menggunakan ID ini. |
     | agentId | Pilih salah satu antara agentId dan app_id. | agent_id bagi aplikasi dalaman. |
     | fallbackUrl | Tidak. Tidak diperlukan untuk aplikasi mikro yang tidak menyokong H5. Diperlukan untuk aplikasi mikro dalam fasa grayscale antara H5 dan mini program. | Alamat H5. Aplikasi mikro yang tidak menyokong mini program menggunakan alamat ini secara terus. |
     | ddFocus | Tidak | Jika ditetapkan kepada true, bekas melumpuhkan elemen dalaman daripada mendapat fokus semasa permulaan. Lalai kepada false. |
     | ddForceAsync | Tidak | Sama ada memaksa permulaan tak segerak. Dengan permulaan tak segerak dipaksa, jika pakej luar talian tempatan wujud, kemas kini segerak tidak dicetuskan dan aplikasi dimulakan dengan kemas kini tak segerak dipaksa (untuk menangani isu permulaan dalam persekitaran luar talian). |

     Kes ujian bahagian PC:

     - Buka URL dalam panel geser tanpa tajuk.

       ```text
       dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io&container_type=slide_panel
       ```
     - Buka URL dalam panel geser tanpa tajuk.

       ```text
       dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io
       ```
     - Buka URL dalam pelayar.

       ```text
       dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io&container_type=browser
       ```
     - Buka URL dalam panel geser dengan tajuk.

       ```text
       https://www.dingtalk.io?micro_app_scheme=dingtalk%3A%2F%2Fdingtalkclient%2Faction%2Fopen_micro_app%3F%0AcorpId%3D11233%26app_id%3D123%26container_type%3Dslide_panel%26title%3Dtest_title
       ```
     - Buka URL dalam pelayar.

       ```text
       https://www.dingtalk.io?micro_app_scheme=dingtalk%3A%2F%2Fdingtalkclient%2Faction%2Fopen_micro_app%3F%0AcorpId%3D11233%26app_id%3D123%26container_type%3Dbrowser%26title%3Dtest_title
       ```
  3. Lancarkan skema mini program (skema khusus untuk mini program peribadi)

     Skema: `dingtalk://dingtalkclient/action/open_mini_app`

     Parameter asas sama seperti dalam senarai parameter umum.

     | Parameter | Wajib | Penerangan |
     | --- | --- | --- |
     | miniAppId | Ya | ID mini program. |
  4. **Skema nyahpepijat mini program**

     Skema: `dingtalk://dingtalkclient/action/dev_mini_app`

     Digunakan terutamanya untuk menyahpepijat mini program dan pembangunan dengan rangka kerja appx. Mini program yang dibuka dengan cara ini melancarkan dokumen utama secara terus melalui URL. Proses pengurusan pakej tidak dimasuki, dan logik keep-alive tidak dicetuskan. miniAppId digunakan hanya untuk pengesahan antara muka dan tujuan serupa.

### Penting

     Semua parameter telah dikodkan. Nyahkod sebelum digunakan.

     | Parameter | Penerangan |
     | --- | --- |
     | url | URL dokumen utama mini program yang dikodkan. Bahagian klien memanggil nebulaSDK untuk membuka pautan ini. |
     | miniAppId | appId mini program. |
     | isTinyApp | Sama ada ia mini program. Mesti ditetapkan kepada YES apabila dibuka melalui HTTP. |
     | enableDSL | Sama ada menggunakan mini program. Nilai ialah YES atau NO. |
     | enableWK | Sama ada menggunakan WK. Nilai ialah YES atau NO. |
     | packageManager | Perkhidmatan pengurusan pakej. - Lalai: antara muka DingTalk. - alipay_online: persekitaran produksi Alipay. - alipay_dev: persekitaran pembangunan Alipay. |
     | keepAlive | Sama ada dikekalkan hidup. Lalai kepada true. |

## Cara mendapatkan maklumat kumpulan sumber melalui pautan

- Nyatakan kaedah buka khas.

  Entri pintasan (plugin kumpulan) ialah pautan DingTalk yang mempunyai keupayaan perniagaan. Pembangun perlu menyusun pautan plugin kumpulan berdasarkan senario sebenar aplikasi mikro mereka dan keperluan khusus pengguna dalam kumpulan. Nama plugin menyokong sehingga empat aksara. Pautan plugin menawarkan keupayaan yang luas, tetapi pembangun perlu menyusunnya melalui parameter pautan. Sebagai contoh, kaedah buka pada bahagian mudah alih (push halaman, pop halaman, dan sebagainya) dan logik navigasi halaman pada PC (buka bekas baharu atau geser halaman ke kiri) semuanya dilaksanakan melalui konfigurasi parameter pautan.

  Berikut menggunakan entri pintasan bagi kumpulan projek sebagai contoh untuk menerangkan secara terperinci cara pautan entri pintasan disusun.

  `<dingtalk://dingtalkclient/page/link?url=https%3a%2f%2fding-doc.dingtalk.io%2fdoc%23%2fpqkq0u%2feluagw%2f$CORPID$%2f$DOUBLE_ENCCID$>`

  - **Alamat halaman sasaran pembangun**: https%3a%2f%2fding-doc.dingtalk.io%2fdoc%23%2fpqkq0u%2feluagw

    - Apabila anda menggunakan protokol pengalihan bersepadu DingTalk, bahagian ini digunakan sebagai parameter alamat "protokol pengalihan bersepadu DingTalk", jadi pengekodan URL diperlukan.
    - Apabila anda tidak menggunakan protokol pengalihan bersepadu DingTalk, anda boleh menggunakan URL asal secara terus sebagai alamat entri pintasan. Pengekodan URL tidak diperlukan.
  - **Protokol pengalihan bersepadu DingTalk (pilihan)** dingtalk://dingtalkclient/page/link?url=

    - Bahagian ini menentukan cara halaman yang anda tentukan dibuka. Kaedah yang disokong pada masa ini termasuk "buka dalam pelayar", "buka dalam bar sisi", dan lain-lain. Laluan protokol pengalihan bersepadu berbeza bagi setiap kaedah.
    - Sesetengah laluan protokol pengalihan bersepadu hanya tersedia pada klien platform tertentu. Sebagai contoh, "buka dalam bar sisi" hanya tersedia pada klien PC dan Mac.
  - **Parameter dinamik alamat entri pintasan (pilihan)** $CORPID$ $DOUBLE_ENCCID$

    - Apabila parameter dinamik ini ditetapkan, bahagian yang berkaitan dalam URL digantikan dengan maklumat Konteks kumpulan (seperti corpId dan openConversationId) apabila pengguna mengklik entri pintasan untuk mengakses alamat pembangun.

      Parameter dinamik yang disokong pada masa ini adalah seperti berikut:

      | Parameter | Penerangan |
      | --- | --- |
      | $CORPID$ | Digantikan secara dinamik dengan ID Organisasi (corpId). |
      | $ENCCID$ | Digantikan secara dinamik dengan ID kumpulan terbuka (openConversationId). Gunakan parameter dinamik ini hanya apabila protokol pengalihan bersepadu DingTalk tidak digunakan. |
      | $DOUBLE_ENCCID$ | Digantikan secara dinamik dengan ID kumpulan terbuka (openConversationId). Perbezaannya ialah ia dikodkan URL sebanyak dua kali, yang digunakan untuk penyahkodan URL semasa pengalihan pas-lalu (pass-through) protokol berganda. Gunakan parameter dinamik ini hanya apabila protokol pengalihan bersepadu DingTalk digunakan. |

      Sebab pengekodan/penyahkodan URL berganda bagi $DOUBLE_ENCCID$ adalah seperti berikut: DingTalk menggunakan protokol dalaman dengan awalan "dingtalk://", yang memerlukan satu pusingan pengekodan untuk dihuraikan. Protokol HTTPS perniagaan yang dilalukan (pass through) selepas parameter URL juga memerlukan satu lagi pusingan pengekodan/penyahkodan apabila digunakan oleh bekas hiliran (downstream container). Oleh kerana pengguna akhir perlu melakukan dua pusingan penyahkodan, dua pusingan pengekodan diperlukan semasa menjana URL.

      Contoh menjana URL: urlencode (URL DingTalk?xxx=xxx & url = urlencode (URL perniagaan))

      Contoh menghurai URL: a. urldecode (URL DingTalk) -> dapatkan URL perniagaan; b. urldecode (URL perniagaan) -> dapatkan parameter yang boleh digunakan.
