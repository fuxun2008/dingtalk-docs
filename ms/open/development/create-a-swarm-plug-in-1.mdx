---
title: "Konfigurasikan URL entri pintasan (plugin kumpulan)"
description: "Panduan mengonfigurasi URL entri pintasan plugin kumpulan DingTalk, meliputi lonjakan ke halaman biasa, mini app H5, dan mini program, serta cara mendapatkan maklumat kumpulan sumber daripada pautan."
---

Rujuk dokumen ini jika anda perlu mengonfigurasikan URL bagi plugin kumpulan.

## Alihkan ke halaman

```text
dingtalk://dingtalkclient/page/link?dd_mode=present&pc_slide=true&url=https%3A%2F%2Fwww.dingtalk.io
```

| Parameter | Penerangan |
| --- | --- |
| url | URL halaman. Pengekodan URL diperlukan. |
| dd_mode | Hanya untuk iOS.   - push: Menolak bekas dari kiri ke kanan pada iOS. - present: Memaparkan bekas secara timbul dari bawah ke atas pada iOS. |
| pc_slide | Apabila `pc_slide=true`, halaman dibuka dalam panel sisi pada PC. |

## Alihkan ke aplikasi web (mini app H5)

```text
dingtalk://dingtalkclient/action/openapp?corpid=$CORPID$&container_type=work_platform&app_id=0_1234&redirect_type=jump&redirect_url=https%3A%2F%2Fwww.dingtalk.io
```

| Parameter | Penerangan |
| --- | --- |
| container_type | Bekas untuk memaparkan halaman:   - browser: Pelayar. - slide_panel: Panel sisi. - work_platform: Workbench. |
| corpid | ID organisasi. |
| app_id | - Aplikasi perusahaan pihak ketiga: Masukkan `appId`. Lihat appId untuk butiran.   - Aplikasi dalaman: Masukkan `0_agentId`, yang terdiri daripada nombor `0`, Garis Bawah, dan `agentId`. Anda boleh dapatkan `agentId` pada halaman butiran aplikasi. |
| redirect_type | Jenis alihan:   - jump: Membuka `redirect_url` secara terus. - emit_params: Memancarkan satu Acara. |
| params | Parameter. Apabila dibuka buat kali pertama, parameter ini ditambahkan pada senarai parameter URL alihan. |
| redirect_url | URL alihan. Pengekodan URL diperlukan. |
| slide_panel_option | Parameter untuk panel sisi. Hanya tersedia pada PC. Contoh: `{"width":500,"showAppPage":true}` (`width` ialah lebar panel sisi; `showAppPage` menunjukkan sama ada halaman web dipaparkan). |

## Alihkan ke mini program

| Parameter | Wajib | Penerangan |
| --- | --- | --- |
| appId | `appId` atau `agentId` diperlukan. Jika kedua-duanya diberikan, `appId` diutamakan. | ID aplikasi. Perhatikan bahawa ini bukan `miniAppId` mini program. Gunakan ID ini untuk aplikasi perusahaan pihak ketiga. |
| agentId | `appId` atau `agentId` diperlukan. Jika kedua-duanya diberikan, `app_id` diutamakan. | ID aplikasi. |
| corpid | Ya | ID organisasi. |
| page | Tidak | Alamat halaman mini program. Anda boleh menambahkan parameter GET. Lalai kepada laman utama mini program. |
| query | Tidak | Parameter pelancaran mini program. Anda boleh mendapatkannya dalam callback `onLaunch` atau `onShow` bagi App. Semasa melancarkan mini program, Bahagian klien menambahkan parameter `corpId` secara lalai, jadi pihak perniagaan tidak boleh menetapkan `corpId`, jika tidak ia akan ditulis ganti. |
| containerType | Tidak | Parameter khusus PC. Nilai yang tersedia:   - browser: Pelayar. - slide_panel (lalai): Panel sisi. - work_platform: Workbench. - mobile: Alihkan ke mudah alih. |
| title | Tidak | Parameter khusus PC digunakan untuk memaparkan Tajuk. |
| source | Tidak | Sumber (hanya digunakan apabila pakej perlu diperoleh daripada Bahagian pelayan):   - debug: Versi Nyahpepijat Peranti. - trial: Versi Percubaan. |
| version | Tidak | Nombor Versi. |
| ddMode | Tidak | Gaya peralihan pelancaran mini program.   - push: Gaya Push. - present: Gaya timbul. - float: Gaya lapisan terapung. - pop: Gaya paparan timbul.   Jika tidak dinyatakan, Bahagian klien akan melancarkan dengan gaya peralihan lalai. Tersedia dalam klien v4.5.8 dan ke atas sebagai pelancaran berperingkat. `float` dan `pop` tersedia dalam v4.6.35 (20190624) dan ke atas sebagai pelancaran berperingkat. |
| mainTask | Tidak | Diperlukan **hanya untuk klien Android**. Tetapkan kepada `true` atau `false`. Lalai ialah `false`. Apabila ditetapkan kepada `true`, mini program berkongsi Task yang sama dengan Task utama DingTalk dan tidak lagi dikekalkan aktif. Disokong dalam klien v4.6.3 dan ke atas. |
| ddJointNavi | Tidak | Mengonfigurasikan gaya bar navigasi. Apabila ditetapkan, ini mengatasi logik `ddMode`. Android & iOS: `0`, `1`, atau `1001`.   - 0: Bar navigasi lama. - 1: Bar navigasi baharu. - 1001: Bar navigasi dengan hanya butang Kembali dan Tajuk. |
| keepAlive | Tidak | Tetapkan kepada **true** atau **false**. Lalai ialah **true**. Diabaikan apabila `mainTask` ditetapkan kepada `true`. |
| ddFocus | Tidak | Tetapkan kepada **true** atau **false**. Lalai ialah **true**. Apabila ditetapkan kepada **true**, bekas menghalang elemen dalaman daripada mendapat fokus semasa permulaan. |
| ddEnableWX | Tidak | Sama ada menyokong rendering Weex. Apabila rendering Weex disokong dan halaman dikonfigurasikan untuk menggunakan mod rendering Weex, Weex boleh dilancarkan untuk memuatkan halaman. |
| ddForceAsync | Tidak | Sama ada memaksa pelancaran tak segerak. Apabila dipaksa melancar secara tak segerak, jika pakej luar talian setempat wujud, kemas kini segerak tidak dicetuskan. Kemas kini tak segerak dipaksa (untuk menyelesaikan isu pelancaran dalam persekitaran luar talian). |
| animated | Tidak | Tetapkan kepada **0** atau **1**. Menunjukkan sama ada memainkan animasi peralihan semasa pelancaran tak segerak (diabaikan dalam senario pelancaran segerak). Lalai ialah **1**. Tersedia dalam v4.6.36 dan ke atas. |

1. **Parameter yang disokong apabila `ddMode=float` (tetingkap terapung)**

   | Parameter | Wajib | Penerangan |
   | --- | --- | --- |
   | panelHeight | Tidak | Ketinggian tetingkap terapung. Boleh berupa nilai Percent skrin atau ketinggian tetap.  - `percent50` bermaksud 50% daripada skrin. Nombor mesti antara (0, 100]. Nilai di luar sempadan akan dihadkan kepada sempadan tersebut. - `1000` bermaksud ketinggian tetap 1000 pt (bukan px). - Jika tidak ditetapkan atau ditetapkan kepada 0, tetingkap terapung dipaparkan dalam skrin penuh. |
   | containerType | Tidak | Dua nilai tambahan tersedia dalam senario ini:  - miniApp (lalai): Mini program. - online: H5 dalam talian. |
   | miniAppId | Ditentukan oleh `containerType` | `appId` mini program. |
   | page | Ditentukan oleh `containerType` | Alamat halaman yang dikodkan URL. Untuk mini program, ini ialah `page` mini program. Untuk H5 dalam talian, ini ialah alamat URL. |
   | coverVisible | Tidak. Dipaparkan secara lalai. Tetapkan kepada `false` untuk menyembunyikan. | - true (lalai): Tunjukkan lapisan overlay. - false: Sembunyikan lapisan overlay. Dipaparkan secara lalai. |

### Parameter yang disokong apabila `ddMode=pop` (lapisan timbul)

   | Parameter | Wajib | Penerangan |
   | --- | --- | --- |
   | width | Ya | Lebar lapisan timbul. |
   | height | Ya | Ketinggian lapisan timbul. |
   | clear | Tidak | Sama ada latar belakang telus. Lalai ialah legap. |
   | containerType | Tidak | Dua nilai tambahan tersedia dalam senario ini:  - miniApp (lalai): Mini program. - online: H5 dalam talian. |
   | miniAppId | Ditentukan oleh `containerType` | `appId` mini program. |
   | page | Ditentukan oleh `containerType` | Alamat halaman yang dikodkan URL. Untuk mini program, ini ialah `page` mini program. Untuk H5 dalam talian, ini ialah alamat URL. |
2. **Skema buka aplikasi (skema khusus untuk mini program perusahaan)**

   Skema: `dingtalk://dingtalkclient/action/open_micro_app`

   `Parameter asas adalah sama dengan senarai parameter umum.`

   Logik kawalan pelancaran berperingkat perlu diletakkan dalam pelaksana skema ini.

   | Parameter | Wajib | Penerangan |
   | --- | --- | --- |
   | corpId | Ya | ID organisasi.  **Penting**  Ini mempunyai keutamaan lebih tinggi dan mengatasi `corpId` dalam query. |
   | appId | `appId` atau `agent_id` diperlukan. Jika kedua-duanya diberikan, `appid` diutamakan. | ID Aplikasi mikro. Perhatikan bahawa ini bukan ID mini program. Gunakan ID ini untuk aplikasi ISV. |
   | agentId | `app_id` atau `agent_id` diperlukan. | `agent_id` bagi aplikasi dalaman. |
   | fallbackUrl | Tidak. Tidak diperlukan untuk aplikasi mikro yang tidak menyokong H5. Diperlukan semasa fasa pelancaran berperingkat H5-ke-mini-program. | Alamat H5. Untuk aplikasi mikro yang tidak menyokong mini program, alamat ini digunakan secara terus. |
   | ddFocus | Tidak | Apabila ditetapkan kepada `true`, bekas menghalang elemen dalaman daripada mendapat fokus semasa permulaan. Lalai ialah `false`. |
   | ddForceAsync | Tidak | Sama ada memaksa pelancaran tak segerak. Apabila dipaksa melancar secara tak segerak, jika pakej luar talian setempat wujud, kemas kini segerak tidak dicetuskan. Kemas kini tak segerak dipaksa (untuk menyelesaikan isu pelancaran dalam persekitaran luar talian). |

   Kes ujian untuk PC:

   - Buka URL dalam panel sisi tanpa tajuk.

     ```text
     dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io&container_type=slide_panel
     ```
   - Buka URL dalam panel sisi tanpa tajuk.

     ```text
     dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io
     ```
   - Buka URL dalam pelayar.

     ```text
     dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io&container_type=browser
     ```
   - Buka URL dalam panel sisi dengan tajuk.

     ```text
     https://www.dingtalk.io?micro_app_scheme=dingtalk%3A%2F%2Fdingtalkclient%2Faction%2Fopen_micro_app%3F%0AcorpId%3D11233%26app_id%3D123%26container_type%3Dslide_panel%26title%3Dtest_title
     ```
   - Buka URL dalam pelayar.

     ```text
     https://www.dingtalk.io?micro_app_scheme=dingtalk%3A%2F%2Fdingtalkclient%2Faction%2Fopen_micro_app%3F%0AcorpId%3D11233%26app_id%3D123%26container_type%3Dbrowser%26title%3Dtest_title
     ```
3. Skema buka mini program (skema khusus untuk mini program peribadi)

   Skema: `dingtalk://dingtalkclient/action/open_mini_app`

   Parameter asas adalah sama dengan senarai parameter umum.

   | Parameter | Wajib | Penerangan |
   | --- | --- | --- |
   | miniAppId | Ya | ID mini program. |
4. **Skema nyahpepijat mini program**

   Skema: `dingtalk://dingtalkclient/action/dev_mini_app`

   Digunakan terutamanya untuk menyahpepijat mini program dan untuk pembangunan rangka kerja appx. Mini program yang dibuka dengan cara ini akan melancarkan dokumen utama secara terus melalui URL. Ia tidak memasuki proses pengurusan pakej dan tidak mencetuskan logik kekal aktif. `miniAppId` hanya digunakan untuk pengesahan API dan tujuan yang serupa.

### Penting

   Semua parameter telah dikodkan. Pastikan anda menyahkodkannya.

   | Parameter | Penerangan |
   | --- | --- |
   | url | URL dokumen utama mini program yang dikodkan. Bahagian klien memanggil nebulaSDK untuk membuka Pautan ini. |
   | miniAppId | `appId` mini program. |
   | isTinyApp | Sama ada ia satu mini program. Mesti ditetapkan kepada `YES` apabila dibuka melalui HTTP. |
   | enableDSL | Sama ada menggunakan mini program. Tetapkan kepada `YES` atau `NO`. |
   | enableWK | Sama ada menggunakan WK. Tetapkan kepada `YES` atau `NO`. |
   | packageManager | Perkhidmatan pengurusan pakej.  - Default: API DingTalk. - alipay_online: Persekitaran produksi Alipay. - alipay_dev: Persekitaran pembangunan Alipay. |
   | keepAlive | Sama ada kekal aktif. Lalai ialah `true`. |

## Dapatkan maklumat kumpulan sumber melalui pautan

- Nyatakan kaedah pembukaan khas.

  Entri pintasan (plugin kumpulan) ialah Pautan `dingtalk` dengan keupayaan perniagaan. Pembangun perlu menyusun Pautan plugin kumpulan berdasarkan senario sebenar Aplikasi mikro mereka dan keperluan khusus pengguna dalam kumpulan. Nama plugin menyokong sehingga 4 aksara. Pautan menawarkan pelbagai keupayaan yang luas, tetapi pembangun perlu Tulis kesemuanya melalui parameter Pautan. Contohnya, kaedah pembukaan pada mudah alih (halaman push, halaman timbul, dan sebagainya) dan logik alihan halaman pada PC (buka bekas baharu atau gunakan panel sisi) semuanya dilaksanakan melalui konfigurasi parameter Pautan.

  Contoh berikut menggunakan entri pintasan kumpulan projek untuk menerangkan secara terperinci cara Pautan entri pintasan disusun.

  dingtalk://dingtalkclient/page/link?url=https%3a%2f%2fding-doc.dingtalk.io%2fdoc%23%2fpqkq0u%2feluagw%2f$CORPID$%2f$DOUBLE_ENCCID$

  - **Alamat halaman sasaran pembangun**: https%3a%2f%2fding-doc.dingtalk.io%2fdoc%23%2fpqkq0u%2feluagw

    - Apabila anda menggunakan protokol alihan bersatu DingTalk, bahagian ini dihantar sebagai parameter input kepada alamat "protokol alihan bersatu DingTalk" dan oleh itu mesti dikodkan URL.
    - Apabila anda tidak menggunakan protokol alihan bersatu DingTalk, anda boleh menggunakan URL asal secara terus sebagai alamat entri pintasan. Pengekodan URL tidak diperlukan.
  - **Protokol alihan bersatu DingTalk (pilihan)**: dingtalk://dingtalkclient/page/link?url=

    - Bahagian ini menentukan cara halaman yang dinyatakan dibuka. Pilihan yang disokong buat masa ini termasuk "Buka dalam pelayar" dan "Buka dalam panel sisi". Laluan protokol alihan bersatu berbeza bagi setiap pilihan.
    - Sesetengah laluan protokol alihan bersatu hanya tersedia pada platform tertentu. Contohnya, "Buka dalam panel sisi" hanya tersedia pada PC dan Mac.
  - **Parameter dinamik alamat** entri pintasan (pilihan): $CORPID$ $DOUBLE_ENCCID$

    - Apabila parameter dinamik ditetapkan, bahagian URL ini digantikan dengan maklumat Konteks kumpulan (seperti `corpId` dan `openConversationId`) apabila pengguna mengklik entri pintasan untuk mengakses alamat pembangun.

      Parameter dinamik yang disokong buat masa ini adalah seperti berikut:

      > Parameter dinamik berikut hanya dikenali apabila dibuka melalui entri pintasan (plugin kumpulan).

      | Parameter | Penerangan |
      | --- | --- |
      | $CORPID$ | Digantikan secara dinamik dengan ID Organisasi (`corpId`). |
      | $ENCCID$ | Digantikan secara dinamik dengan ID perbualan terbuka (`openConversationId`). Gunakan parameter dinamik ini hanya apabila protokol alihan bersatu DingTalk tidak digunakan. |
      | $DOUBLE_ENCCID$ | Digantikan secara dinamik dengan ID perbualan terbuka (`openConversationId`). Perbezaannya ialah ia dikodkan URL sebanyak dua kali, digunakan untuk penyahkodan URL merentasi pelbagai alihan pass-through protokol. Gunakan parameter dinamik ini hanya apabila protokol alihan bersatu DingTalk digunakan. |

      `$DOUBLE_ENCCID$` dikodkan URL dan dinyahkodkan sebanyak dua kali kerana DingTalk mempunyai lapisan protokol dalaman yang bermula dengan `dingtalk://`, yang memerlukan satu pusingan pengekodan semasa penghuraian. Protokol HTTPS perniagaan yang dihantar melalui parameter URL kepada bekas hiliran juga memerlukan satu pusingan pengekodan dan penyahkodan. Oleh kerana pengguna memerlukan dua pusingan penghuraian, dua pusingan pengekodan diperlukan semasa menjana URL.

      Contoh penjanaan URL: urlencode(URL DingTalk?xxx=xxx & url = urlencode(URL perniagaan))

      Contoh penghuraian URL: a. urldecode(URL DingTalk) -> Dapatkan URL perniagaan; b. urldecode(URL perniagaan) -> Dapatkan parameter yang boleh digunakan.
