# Integrasi kelulusan cuti dan kehadiran: Segerakkan data cuti dan kehadiran ke Kehadiran DingTalk secara automatik

## Gambaran keseluruhan

Penyelesaian ini menyegerakkan data daftar masuk kehadiran dari hujung ke hujung. Penyelesaian ini menggunakan API daftar masuk kehadiran di DingTalk Open Platform untuk menyegerakkan rekod daftar masuk pekerja daripada sistem Anda sendiri ke aplikasi Kehadiran DingTalk secara automatik.

### Latar belakang

Banyak organisasi telah menggunakan sistem kehadiran dalaman atau peranti kehadiran pihak ketiga, seperti pembaca kad akses, pengimbas cap jari atau terminal pengecaman wajah, untuk merekodkan daftar masuk pekerja. Namun, sistem ini tidak mempunyai antara muka data standard dengan Kehadiran DingTalk. Ini menimbulkan masalah berikut:

- **Daftar masuk susulan manual yang tidak cekap**: Selepas mendaftar masuk dalam sistem Anda sendiri, pekerja perlu menghantar daftar masuk susulan dalam DingTalk. Proses ini leceh dan pekerja kerap terlupa.
- **Data tidak selaras**: Data kehadiran terpisah antara sistem Anda sendiri dengan DingTalk. HR perlu menyemak silang rekod kehadiran merentas sistem.
- **Kurang tepat pada masanya**: Pekerja mahu melihat status kehadiran mereka dalam DingTalk sejurus selepas mendaftar masuk. Mereka tidak mahu menunggu penyegerakan berkelompok pada hari berikutnya.

### Nilai utama

Penyelesaian ini menyegerakkan data daftar masuk kehadiran dari hujung ke hujung. Penyelesaian ini menggunakan API daftar masuk kehadiran di DingTalk Open Platform untuk menyegerakkan rekod daftar masuk pekerja daripada sistem Anda sendiri ke aplikasi Kehadiran DingTalk secara automatik.

- **Penyegerakan daftar masuk automatik**: Rekod daftar masuk daripada sistem Anda sendiri dimuat naik ke DingTalk secara automatik tanpa kerja manual.
- **Satu titik masuk pengurusan**: Semua data kehadiran disalurkan ke DingTalk. HR mengendalikan statistik kehadiran dan analisis dalam satu platform.
- **Integrasi pantas dan kos rendah**: Hanya 2 API teras diperlukan, jadi kos pembangunan kekal rendah.

### Kes penggunaan

Penyelesaian ini sesuai untuk senario perniagaan berikut:

- **Integrasi dengan sistem kehadiran Anda sendiri**: Sambungkan sistem kehadiran dalaman atau peranti kehadiran pihak ketiga (pembaca kad akses, pengimbas cap jari, terminal pengecaman wajah dan lain-lain) ke Kehadiran DingTalk untuk menyegerakkan data daftar masuk secara automatik.
- **Penyatuan data daripada pelbagai peranti**: Organisasi Anda menggunakan peranti kehadiran yang berbeza di pelbagai lokasi kerja dan memerlukan semua rekod daftar masuk dalam DingTalk untuk pengurusan berpusat.
- **Status kehadiran masa nyata**: Pekerja mahu melihat status kehadiran mereka dalam DingTalk sejurus selepas mendaftar masuk, tanpa menunggu penyegerakan berkelompok pada hari berikutnya.
- **Tiada lagi semakan silang sistem untuk HR**: HR tidak perlu lagi membandingkan data antara sistem kehadiran Anda sendiri dengan DingTalk secara manual, sekali gus mempercepatkan statistik kehadiran.

## Senario perniagaan biasa

### Senario 1: Segerakkan data daftar masuk daripada sistem kehadiran Anda sendiri

#### Masalah

Secara tradisional, selepas pekerja mendaftar masuk dalam sistem kehadiran Anda sendiri (contohnya, menggunakan kad akses atau cap jari), mereka perlu menghantar daftar masuk susulan dalam DingTalk supaya status kehadiran mereka dipaparkan di sana. Bagi organisasi yang mencatatkan ribuan daftar masuk setiap hari, HR perlu memproses sejumlah besar permintaan daftar masuk susulan setiap hari. Proses ini memakan masa dan terdedah kepada kesilapan.

#### Nilai

- **Aliran kerja automatik**

  Aliran penyegerakan data daftar masuk masa nyata mempunyai 5 langkah:

  1. Pekerja mendaftar masuk dalam sistem Anda sendiri.
  2. Sistem kehadiran Anda memanggil API DingTalk untuk mewujudkan saluran data.
  3. Sistem Anda mendapatkan pengecam unik pekerja dalam DingTalk (**userId**) melalui API.
  4. Sistem Anda memuat naik rekod daftar masuk ke Kehadiran DingTalk.
  5. Aplikasi Kehadiran DingTalk memaparkan status daftar masuk dalam masa nyata.

  Contoh parameter untuk muat naik: **userid**, **userCheckTime**, **deviceId**.
- **Manfaat utama**

  - **Tiada kerja berulang**: Selepas pekerja mendaftar masuk dalam sistem kehadiran Anda sendiri, data disegerakkan ke Kehadiran DingTalk melalui API. Pekerja tidak perlu lagi menghantar daftar masuk susulan atau memasukkan semula data.
  - **Kurang semakan manual**: Rekod daftar masuk disegerakkan dalam masa nyata, jadi HR tidak perlu lagi menyemak permintaan daftar masuk susulan satu demi satu. Ini mengurangkan kerja semakan manual dengan ketara dan menjimatkan masa.
  - **Data lebih tepat**: Penyegerakan automatik menghapuskan campur tangan manual dan kesilapan kemasukan data. Data kehadiran kekal sahih, tepat dan boleh dikesan.
  - **Pengalaman pengguna lebih baik**: Pekerja melihat status daftar masuk mereka dalam masa nyata dan tidak perlu lagi bimbang tentang daftar masuk yang tertinggal atau daftar masuk susulan yang terlupa.

### Senario 2: Satukan data daripada pelbagai peranti kehadiran

#### Masalah

Organisasi besar lazimnya menggunakan beberapa jenis peranti kehadiran (pengimbas cap jari, terminal pengecaman wajah, lokasi GPS dan lain-lain) di lokasi kerja yang berbeza. Setiap peranti menyimpan data daftar masuknya secara berasingan. HR perlu log masuk ke beberapa sistem, mengeksport fail Excel dan menggabungkannya secara manual. Proses ini sangat tidak cekap dan data sering hilang.

#### Nilai

- **Aliran kerja automatik**

  Aliran data untuk menyatukan data daftar masuk daripada pelbagai peranti kehadiran ke dalam DingTalk:

  1. Pekerja mendaftar masuk menggunakan pelbagai peranti kehadiran.
  2. Setiap peranti memuat naik datanya dalam masa nyata ke sistem kehadiran Anda sendiri.
  3. Sistem Anda memanggil **API DingTalk Open Platform** untuk memuat naik data kehadiran secara pukal.
  4. DingTalk menerima semua data daftar masuk dan menyatukannya untuk storan dan pengurusan bersepadu.
  5. HR melihat laporan dan analisis kehadiran bersepadu dalam Workbench DingTalk.

  Pendekatan tradisional memerlukan log masuk ke beberapa sistem, mengeksport data Excel dan menggabungkan data secara manual untuk menyediakan laporan. Aliran ini pula mengumpulkan data ke dalam DingTalk secara automatik dan menjana laporan dengan satu klik.
- **Manfaat utama**

  - **Data pelbagai sumber yang bersepadu**: Satukan data daftar masuk daripada pengimbas cap jari, terminal pengecaman wajah, lokasi GPS dan peranti kehadiran lain ke dalam satu format standard dalam DingTalk untuk menghapuskan silo data.
  - **Pengurusan sehenti**: HR melihat rekod kehadiran setiap pekerja dalam DingTalk dalam masa nyata, tanpa perlu log masuk ke beberapa sistem, mengeksport fail Excel dan menggabungkannya secara manual.
  - **Statistik lebih pantas**: Sistem mengumpulkan data dan menjana laporan secara automatik, sekali gus memendekkan kitaran statistik kehadiran dengan ketara.
  - **Kurang kerja manual**: Automasi menggantikan kerja manual berulang seperti mengeksport, membersihkan dan menggabungkan data. Ini mengurangkan kos tenaga kerja dan risiko kesilapan manusia.

## Panduan pelaksanaan

### Seni bina teknikal

Penyelesaian ini dibina berdasarkan OpenAPI berkaitan kehadiran di DingTalk Open Platform. Komponen teknikal terasnya ialah:

- **Lapisan pengesahan**: Gunakan `Client ID` / `Client Secret` untuk mendapatkan `access_token` dan melindungi panggilan API.
- **Lapisan pengurusan kebenaran**: Mohon kebenaran API Kenalan dan kehadiran.
- **Lapisan pengambilan ID pengguna**: Panggil Server API Kenalan untuk mendapatkan butiran pengguna jabatan dan ID pengguna setiap pekerja dalam Struktur Organisasi DingTalk.
- **Lapisan muat naik daftar masuk**: Panggil Server API kehadiran untuk memuat naik rekod daftar masuk, termasuk tarikh dan masa daftar masuk daripada sistem Anda sendiri, ke aplikasi Kehadiran DingTalk.

### Prasyarat

Sebelum bermula, pastikan Anda memenuhi keperluan berikut:

- **Aplikasi**: Cipta dan konfigurasikan Aplikasi dalaman. Untuk butiran, lihat [Cipta dan konfigurasikan aplikasi](/ms/open/dingstart/create-application).
- **Kebenaran**: Miliki kebenaran Admin Organisasi atau Sub Admin DingTalk, dan mohon kebenaran API berikut:

  - `qyapi_get_department_member` (kebenaran baca untuk ahli jabatan Kenalan)
  - `Pro.AttendanceRecord.Write` (kebenaran tulis untuk rekod daftar masuk kehadiran)
- **Persekitaran pembangunan**: Pasang persekitaran pembangunan Java (JDK 1.6 atau lebih baharu) dan alat binaan Maven.
- **SDK**: Muat turun SDK bahagian pelayan DingTalk. Untuk butiran, lihat halaman muat turun SDK bahagian pelayan. SDK ini menyokong Java, Python, Go dan bahasa lain.

### Pelaksanaan kod

Langkah 1: Dapatkan Kelayakan aplikasi, termasuk client ID dan Client Secret.

Langkah 2: [Tambah kebenaran API](/ms/open/development/add-api-permission). Cari "Kenalan" dan "Kehadiran", kemudian mohon kebenaran API yang berkaitan.

Langkah 3: Dapatkan Kredensial akses. Lihat [Dapatkan access_token Aplikasi dalaman](/ms/open/development/obtain-orgapp-token). Apabila Anda memanggil API, access token mengesahkan identiti pemanggil.

Langkah 4: Panggil API Kenalan dan kehadiran:

1. Panggil Server API Kenalan [Dapatkan butiran pengguna jabatan](/ms/open/development/queries-the-complete-information-of-a-department-user) untuk mendapatkan ID pengguna setiap pekerja dalam Struktur Organisasi DingTalk.
2. Panggil Server API kehadiran [Muat naik rekod daftar masuk](/ms/open/development/upload-punch-records) untuk memuat naik tarikh, masa dan butiran daftar masuk lain pekerja daripada sistem Anda sendiri ke aplikasi Kehadiran DingTalk. Ini menyegerakkan data kehadiran.

## Langkah pelaksanaan

### **Langkah 1: Dapatkan Kelayakan aplikasi**

1. Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.io/).
2. Pilih aplikasi sasaran untuk membuka halaman butiran aplikasi.
3. Klik **Maklumat Asas** > **Kelayakan dan Maklumat Asas**.
4. Rekodkan `Client ID` dan `Client Secret` aplikasi.

### Nota

   Simpan `Client Secret` dengan selamat dan jangan sekali-kali kongsi dengan pihak ketiga. Simpan dalam pemboleh ubah persekitaran atau sistem pengurusan kunci, dan jangan tulis secara terus (hard-code) dalam kod.

### Langkah 2: Tambah kebenaran API

1. Pada halaman butiran aplikasi, klik **Urus kebenaran**.
2. Dalam kotak carian kebenaran, masukkan pengecam kebenaran berikut dan mohon kebenaran tersebut:

   - `qyapi_get_department_member` (kebenaran baca untuk ahli jabatan Kenalan): Mendapatkan butiran pengguna jabatan untuk memperoleh ID pengguna.
   - `Pro.AttendanceRecord.Write` (kebenaran tulis untuk rekod daftar masuk kehadiran): Memuat naik rekod daftar masuk ke aplikasi Kehadiran DingTalk.

<Note>
Senario perniagaan yang berbeza mungkin memerlukan gabungan kebenaran yang berbeza. Mohon kebenaran berdasarkan keperluan sebenar Anda. Contohnya, senario import pukal juga memerlukan kebenaran untuk operasi pengguna secara pukal.
</Note>

### Langkah 3: Dapatkan Kredensial akses (access_token)

Gunakan Client ID dan Client Secret daripada Langkah 1 untuk mendapatkan Kredensial akses. Lihat [Dapatkan access_token Aplikasi dalaman](/ms/open/development/obtain-orgapp-token).

```java
public void getAccessToken() throws ApiException {
  DingTalkClient client = new DefaultDingTalkClient("https://api.dingtalk.io/gettoken");
  OapiGettokenRequest req = new OapiGettokenRequest();
  req.setAppkey("dingxxxxxxxxxhgn");
  req.setAppsecret("9G_xxxxxxxxxxxxxxx1JDf0Qq3nexxxxxxxxGIO");
  req.setHttpMethod("GET");
  OapiGettokenResponse rsp = client.execute(req);
  System.out.println(rsp.getBody());
}
```

**Amalan terbaik**:

- **Cache**: `access_token` sah selama 2 jam. Simpan dalam cache memori atau Redis, dan muat semula token 5 minit sebelumnya tamat tempoh.
- **Kawalan keserentakan**: Elakkan beberapa thread memuat semula token pada masa yang sama sehingga menyebabkan konflik. Gunakan kunci teragih (distributed lock).
- **Cuba semula apabila ralat**: Cuba semula secara automatik apabila berlaku gangguan rangkaian, sehingga 3 kali, dengan selang masa yang semakin meningkat (1s → 2s → 4s).

### Langkah 4: Panggil API teras

1. **Dapatkan butiran pengguna jabatan**: Panggil Server API Kenalan [Dapatkan butiran pengguna jabatan](/ms/open/development/queries-the-complete-information-of-a-department-user) untuk mendapatkan ID pengguna setiap pekerja dalam Struktur Organisasi DingTalk.

   ```java
   public void deptInfo() throws ApiException {
       DingTalkClient client = new DefaultDingTalkClient("https://api.dingtalk.io/topapi/v2/user/list");
       OapiV2UserListRequest req = new OapiV2UserListRequest();
       req.setDeptId(1L);
       req.setCursor(0L);
       req.setSize(10L);
       req.setOrderField("entry_asc");
       req.setContainAccessLimit(false);
       req.setLanguage("zh_CN");
       OapiV2UserListResponse rsp = client.execute(req, "access_token");
       System.out.println(rsp.getBody());
   }
   ```
2. **Muat naik rekod daftar masuk**: Panggil Server API kehadiran [Muat naik rekod daftar masuk](/ms/open/development/upload-punch-records) untuk memuat naik tarikh, masa dan butiran daftar masuk lain pekerja daripada sistem Anda sendiri ke aplikasi Kehadiran DingTalk. Ini menyegerakkan data kehadiran.

   ```java
   public void attendanceRecordUpload() throws ApiException {
       DingTalkClient client = new DefaultDingTalkClient("https://api.dingtalk.io/topapi/attendance/record/upload");
       OapiAttendanceRecordUploadRequest req = new OapiAttendanceRecordUploadRequest();
       req.setUserid("01472825524039877041");
       req.setDeviceName("Mesin Kehadiran Pintu Timur");
       req.setDeviceId("dingTalk_one");
       req.setPhotoUrl("https://xxx.com/xxx.png");
       req.setUserCheckTime(1665363600000L);
       OapiAttendanceRecordUploadResponse rsp = client.execute(req, "access_token");
       System.out.println(rsp.getBody());
   }
   ```

**Senarai semak pelaksanaan**:

- Kelayakan aplikasi (Client ID / Client Secret) telah diperoleh.
- Kebenaran Kenalan dan kehadiran telah diberikan.
- access_token telah diperoleh.
- Panggilan API Dapatkan butiran pengguna jabatan berjaya dan mengembalikan senarai ID pengguna yang betul.
- Panggilan API Muat naik rekod daftar masuk berjaya, dan aplikasi Kehadiran DingTalk memaparkan data daftar masuk yang telah disegerakkan.

## Soalan lazim

- **S1: Apakah parameter yang wajib semasa memuat naik rekod daftar masuk?**

  J: Parameter wajib ialah:

  - `userid`: ID pengguna pekerja dalam Struktur Organisasi DingTalk
  - `userCheckTime`: Masa daftar masuk (Unix timestamp, dalam milisaat)
  - `deviceId`: ID peranti kehadiran
  - `deviceName`: Nama peranti kehadiran

    Parameter pilihan termasuk `photoUrl` (URL gambar yang dilampirkan pada rekod daftar masuk, yang mesti boleh diakses secara umum).
- **S2: Apakah punca biasa kegagalan penyegerakan data daftar masuk?**

  J: Punca biasa termasuk:

  - ID pengguna yang salah (ID mesti milik pekerja dalam Struktur Organisasi DingTalk)
  - Format userCheckTime yang tidak sah atau masa pada masa hadapan
  - access_token yang tidak sah atau telah tamat tempoh
  - Aplikasi belum memohon kebenaran kehadiran
  - Permintaan rangkaian tamat masa atau ralat pelayan
- **S3: Apakah amalan terbaik untuk memuat naik data daftar masuk berbilang pekerja secara pukal?**

  J: Pada masa ini, API hanya menerima satu rekod daftar masuk bagi setiap panggilan. Untuk memuat naik secara pukal, panggil API dalam gelung pada lapisan perniagaan dan kawal kekerapan panggilan supaya tidak melebihi had kadar. Anda juga boleh menghubungi sokongan teknikal DingTalk tentang pilihan muat naik pukal.
