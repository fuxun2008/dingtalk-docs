# Konfigurasikan peraturan kehadiran: Cipta kumpulan kehadiran secara pukal dan laraskannya secara dinamik

## Gambaran keseluruhan

Penyelesaian ini mengautomasikan pengurusan kumpulan kehadiran sepenuhnya. Penyelesaian ini menggunakan API pengurusan kumpulan kehadiran di DingTalk Open Platform untuk menyepadukan platform perniagaan seperti sistem HR dan OA dengan DingTalk Attendance.

### Latar belakang

Organisasi berdepan cabaran berikut dalam pengurusan kehadiran:

- **Peraturan kehadiran yang kompleks**: Kehadiran syif tetap, kehadiran berasaskan syif, waktu kerja fleksibel dan mod lain digunakan serentak. Konfigurasi manual lambat dan mudah tersilap.
- **Perubahan kakitangan yang kerap**: Kemasukan pekerja baharu, peletakan jawatan dan pertukaran memerlukan kemas kini manual pada ahli kumpulan kehadiran. Organisasi dengan lebih 1,000 pekerja menghabiskan beberapa jam setiap minggu untuk tugas ini.
- **Tiada penyegerakan rentas sistem**: Perubahan Struktur Organisasi dalam sistem HR tidak sampai ke kumpulan kehadiran DingTalk tepat pada masanya. Hal ini menyebabkan ralat data daftar masuk.
- **Tiada operasi pukal**: Admin tidak dapat mencipta atau mengemas kini beberapa kumpulan kehadiran sekali gus. Kemas kini satu demi satu sangat tidak cekap.

### Manfaat utama

Penyelesaian ini membantu organisasi mencapai perkara berikut:

- **Pengurusan kumpulan kehadiran secara automatik**: Cipta, buat pertanyaan, kemas kini dan padam kumpulan kehadiran melalui API tanpa campur tangan manual.
- **Perkaitan syif pintar**: Cipta syif baharu atau kaitkan syif sedia ada secara automatik untuk memastikan peraturan kehadiran tepat.
- **Pelaksanaan pukal yang cekap**: Dapatkan, cari dan kemas kini kumpulan kehadiran secara pukal untuk meningkatkan kecekapan operasi dengan ketara.
- **Data rentas sistem yang seragam**: Segerakkan data HR, OA dan DingTalk Attendance dalam masa nyata untuk menghapuskan silo data.

### Kes penggunaan

Penyelesaian ini sesuai untuk senario perniagaan biasa berikut:

- **Integrasi sistem HR**: Segerakkan peraturan kehadiran daripada sistem pengurusan HR ke kumpulan kehadiran DingTalk secara automatik.
- **Penggabungan dan pengambilalihan**: Cipta kumpulan kehadiran dan konfigurasi syif secara pukal dengan pantas untuk syarikat yang baru diambil alih.
- **Integrasi aliran kerja OA**: Cipta atau laraskan kumpulan kehadiran yang berkaitan secara automatik apabila Proses kelulusan tamat.
- **Pelarasan kebenaran dinamik**: Kemas kini ahli kumpulan kehadiran dan kebenaran Admin secara automatik berdasarkan perubahan Jabatan.

## Senario perniagaan biasa

### Senario 1: Segerakkan kumpulan kehadiran daripada sistem HR (penciptaan dan pengurusan pukal)

#### Masalah utama

Dalam model tradisional, selepas pihak HR merancang peraturan kehadiran baharu dalam sistem HR, mereka perlu log masuk ke Admin Console DingTalk dan mencipta setiap kumpulan kehadiran, mengkonfigurasikan syif serta menambah ahli secara manual. Organisasi dengan lebih 1,000 pekerja biasanya mempunyai 20 hingga 50 kumpulan kehadiran. Persediaan manual mengambil masa berjam-jam dan sering menyebabkan syif tersilap atau ahli tertinggal.

#### Pengesahan nilai

- **Aliran kerja automatik**

  Aliran Automasi berasaskan API dijalankan mengikut langkah berikut:
  1. Sistem HR merekodkan Pekerja baharu.
  2. Sistem mencari kumpulan kehadiran yang sepadan secara automatik berdasarkan Jabatan Pekerja tersebut.
  3. Sistem menambah ahli baharu secara pukal melalui API.
  4. Sistem mengesahkan dan memastikan hasilnya dalam masa nyata.
  5. Kebenaran daftar masuk berkuat kuasa serta-merta.
- **Kelebihan utama**

  - **Pencetus automatik sepenuhnya**: Panggilan API dijalankan secara automatik selepas HR memasukkan Pekerja baharu dalam sistem HR. Tiada sesiapa perlu log masuk ke Admin Console DingTalk atau memulakan tindakan secara manual. Kemasukan data dan penyegerakan berlaku serentak.
  - **Padanan tepat**: Sistem membuat pertanyaan dan memadankan `groupKey` kumpulan kehadiran secara automatik berdasarkan ID jabatan Pekerja. Ini mengelakkan ralat daftar masuk akibat tersilap memilih kumpulan kehadiran secara manual.
  - **Berkuat kuasa serta-merta**: Selepas API tambah pekerja secara pukal menambah ahli, API pertanyaan ahli mengikut ID mengesahkan hasilnya dengan segera. Pekerja boleh daftar masuk sebaik sahaja mereka menyertai kumpulan kehadiran.
  - **Jejak audit**: Setiap panggilan API merekodkan pengendali, cap masa, ID kumpulan kehadiran, `userId` Pekerja dan butiran lain untuk memenuhi keperluan audit pematuhan dan kebolehkesanan.

### Senario 2: Segerakkan kumpulan kehadiran secara automatik selepas perubahan Struktur Organisasi

#### Masalah utama

Apabila jabatan digabungkan atau dipecahkan, atau apabila pekerja bertukar, HR perlu mengemas kini senarai ahli dan peraturan penjadualan syif bagi setiap kumpulan kehadiran yang terjejas secara manual. Penstrukturan semula berskala besar boleh melibatkan berpuluh-puluh kumpulan kehadiran. Kemas kini manual memakan masa dan sering terlepas beberapa kumpulan. Hal ini menyebabkan ralat daftar masuk bagi pekerja.

#### Pengesahan nilai

- **Aliran kerja automatik**

  Aliran Automasi dijalankan dalam lima langkah:

  1. **Pencetus Kelulusan OA**: Apabila kelulusan bagi penggabungan atau pemecahan jabatan atau pertukaran kakitangan diluluskan, sistem menangkap **peristiwa** perubahan secara automatik.
  2. **Kenal pasti kumpulan kehadiran yang terjejas**: Sistem membuat pertanyaan bagi semua kumpulan kehadiran yang berkaitan secara automatik berdasarkan ID jabatan yang berubah.
  3. **Kemas kini pukal melalui API**: Sistem memanggil API kemas kini kumpulan kehadiran DingTalk untuk mengubah suai senarai ahli dan konfigurasi syif secara pukal.
  4. **Pengesahan data masa nyata**: Sejurus selepas kemas kini, sistem memanggil API pertanyaan untuk mengesahkan ketekalan data merentas semua kumpulan kehadiran.
  5. **Penyegerakan selesai**: Penyegerakan kumpulan kehadiran selesai dan peraturan kehadiran yang dikemas kini berkuat kuasa tanpa campur tangan manual.
- **Kelebihan utama**

  - **Pencetus automatik**: Sistem menangkap peristiwa perubahan dan menjalankan penyegerakan secara automatik apabila proses Kelulusan OA tamat. Tiada sesiapa perlu memulakan atau memantaunya. Kelulusan dan penyegerakan berlaku serentak.
  - **Pemprosesan pukal yang tepat**: Sistem mengenal pasti dan mengemas kini semua kumpulan kehadiran yang terjejas sekali gus. Ini mengelakkan keciciran akibat carian manual dan memastikan liputan 100% bagi perubahan organisasi.
  - **Pengesahan dan Maklum Balas masa nyata**: Sistem memanggil API pertanyaan sejurus selepas kemas kini untuk mengesahkan ketekalan data dan menghantar amaran secara automatik apabila berlaku ralat. Ini memastikan peraturan kehadiran berkuat kuasa dengan betul.
  - **Log audit lengkap**: Setiap panggilan API merekodkan pengendali, cap masa dan kandungan perubahan untuk memenuhi keperluan audit pematuhan dan kebolehkesanan.

## Panduan pelaksanaan

### Seni bina teknikal

Penyelesaian ini dibina berdasarkan Server API DingTalk Open Platform. Komponen teknikal terasnya ialah:

- **Lapisan pengesahan**: Menggunakan `Client ID` dan `Client Secret` untuk mendapatkan `access_token` dan melindungi panggilan API.
- **Lapisan pengurusan kumpulan kehadiran**: Menyediakan keupayaan API lengkap untuk mencipta, membuat pertanyaan, mengemas kini dan memadam kumpulan kehadiran. Menyokong kumpulan kehadiran syif tetap dan kumpulan kehadiran berasaskan syif.
- **Lapisan pengurusan syif**: Menyediakan keupayaan API untuk mencipta dan membuat pertanyaan syif, iaitu sumber prasyarat bagi kumpulan kehadiran.
- **Lapisan pengendalian ralat**: Menyediakan sistem kod ralat yang menyeluruh untuk membantu anda mengesan dan menyelesaikan isu dengan pantas.

**Versi API**: Server API mempunyai versi baharu dan versi lama. Utamakan versi baharu untuk prestasi dan sokongan ciri yang lebih baik.

### Prasyarat

Penuhi syarat berikut sebelum anda melaksanakan penyelesaian ini:

- **Penyediaan aplikasi**: Cipta dan konfigurasikan Aplikasi dalaman. Untuk butiran, lihat [Cipta dan konfigurasikan aplikasi](/ms/open/dingstart/create-application).
- **Keperluan kebenaran**: Miliki kebenaran Admin Organisasi atau Sub Admin DingTalk, dan mohon kebenaran API berikut:

  - `qyapi_attendance_group_manage` (kebenaran pengurusan kumpulan kehadiran)
  - `qyapi_attendance_group_read` (kebenaran pertanyaan kumpulan kehadiran)
- **Persekitaran pembangunan**: Pasang persekitaran pembangunan Java (JDK 1.6 atau lebih baharu) dan alat binaan Maven.
- **Penyediaan SDK**: Muat turun SDK Bahagian pelayan DingTalk. Untuk butiran, lihat Muat turun SDK Bahagian pelayan. SDK ini menyokong Java, Python, Go dan bahasa lain.

     - Panggil Server API [Dapatkan butiran kumpulan kehadiran secara pukal](/ms/open/development/batch-obtain-attendance-group-details) untuk mendapatkan butiran semua kumpulan kehadiran dalam Organisasi.
   - Panggil Server API [Cari ringkasan kumpulan kehadiran](/ms/open/development/attendance-group-search) untuk menjalankan pertanyaan kabur bagi kumpulan kehadiran mengikut nama.

     - Panggil Server API [Dapatkan butiran kumpulan kehadiran](/ms/open/development/query-a-single-attendance-group) dengan `id` kumpulan kehadiran untuk mendapatkan butiran satu kumpulan kehadiran.
     - Dapatkan butiran kumpulan kehadiran mengikut `groupKey`

       1. Panggil Server API [Tukar groupId kepada groupKey](/ms/open/development/groupid-to-groupkey) dengan `id` kumpulan kehadiran untuk mendapatkan `groupKey` kumpulan kehadiran.
       2. Panggil Server API [Buat pertanyaan maklumat kumpulan kehadiran mengikut groupKey](/ms/open/development/queries-attendance-group-information-by-id) dengan `groupKey` kumpulan kehadiran untuk mendapatkan maklumat kumpulan kehadiran.
3. Panggil Server API [Kemas kini kumpulan kehadiran](/ms/open/development/attendance-group-update-interface) dengan `id` kumpulan kehadiran untuk mengubah suai nama kumpulan kehadiran, syif dan maklumat lain.
4. Panggil Server API [Padam kumpulan kehadiran](/ms/open/development/delete-attendance-group) dengan `groupKey` kumpulan kehadiran untuk memadam kumpulan kehadiran.

## Langkah pelaksanaan

### **Langkah 1: Dapatkan kelayakan aplikasi**

1. Log masuk ke [Konsol Pembangun DingTalk](https://open-dev.dingtalk.io/).
2. Pilih aplikasi sasaran untuk membuka halaman butiran aplikasi.
3. Klik **Maklumat Asas** > **Kelayakan dan Maklumat Asas**.
4. Rekodkan `Client ID` dan `Client Secret` aplikasi.

### Nota

   Simpan `Client Secret` dengan selamat dan jangan sekali-kali kongsikannya dengan pihak ketiga. Simpan dalam pemboleh ubah persekitaran atau sistem pengurusan kunci, bukannya dikodkan terus dalam kod sumber.

### Langkah 2: Tambah kebenaran API

1. Pada halaman butiran aplikasi, klik **Urus kebenaran**.
2. Masukkan pengecam kebenaran berikut dalam kotak carian kebenaran dan mohon kebenaran tersebut:

   - `qyapi_attendance_group_manage` (kebenaran pengurusan kumpulan kehadiran): Digunakan untuk mencipta, mengemas kini dan memadam kumpulan kehadiran.
   - `qyapi_attendance_group_read` (kebenaran pertanyaan kumpulan kehadiran): Digunakan untuk membuat pertanyaan ringkasan dan butiran kumpulan kehadiran.

<Note>
Senario perniagaan yang berbeza mungkin memerlukan gabungan kebenaran yang berbeza. Mohon berdasarkan keperluan sebenar anda. Contohnya, senario Import pukal turut memerlukan kebenaran bagi operasi pengguna secara pukal.
</Note>

### Langkah 3: Dapatkan Kredensial akses (access_token)

Gunakan Client ID dan Client Secret daripada Langkah 1 untuk mendapatkan Kredensial akses aplikasi. Lihat [Dapatkan access_token bagi Aplikasi dalaman](/ms/open/development/obtain-orgapp-token).

```java
public void getAccessToken() throws ApiException {
  DingTalkClient client = new DefaultDingTalkClient("https://oapi.dingtalk.io/gettoken");
  OapiGettokenRequest req = new OapiGettokenRequest();
  req.setAppkey("dingxxxxxxxxxhgn");
  req.setAppsecret("9G_xxxxxxxxxxxxxxx1JDf0Qq3nexxxxxxxxGIO");
  req.setHttpMethod("GET");
  OapiGettokenResponse rsp = client.execute(req);
  System.out.println(rsp.getBody());
}
```

**Amalan terbaik**:

- **Strategi cache**: `access_token` sah selama 2 jam. Simpan dalam cache memori atau Redis dan muat semula secara proaktif 5 minit sebelumnya tamat tempoh.
- **Kawalan keserentakan**: Elakkan beberapa thread memuat semula token pada masa yang sama kerana ini menyebabkan konflik. Gunakan kunci teragih (distributed lock).
- **Cuba semula apabila berlaku ralat**: Cuba semula secara automatik apabila rangkaian tidak stabil, sehingga 3 kali, dengan selang masa yang meningkat (1s → 2s → 4s).

## Soalan lazim

- **S1: Apakah yang perlu saya lakukan jika saya menerima ralat "Shift does not exist" (Syif tidak wujud) semasa mencipta kumpulan kehadiran?**

  J: Kumpulan kehadiran syif tetap memerlukan syif yang sedia ada. Panggil API [Cipta syif](/ms/open/development/create-modify-shifts) terlebih dahulu, atau panggil API [Dapatkan ringkasan syif](/ms/open/development/enterprise-shift-query-in-batches) untuk mendapatkan ID syif sedia ada. Kemudian, cipta kumpulan kehadiran.
- **S2: Bagaimanakah saya mendapatkan maklumat semua kumpulan kehadiran secara pukal?**

  J: Ikut dua langkah. Pertama, panggil [Dapatkan ringkasan kumpulan kehadiran secara pukal](/ms/open/development/batch-query-of-simple-information-of-the-attendance-group) untuk mendapatkan maklumat ringkas (termasuk `id`) bagi semua kumpulan kehadiran. Kemudian, panggil [Dapatkan butiran kumpulan kehadiran secara pukal](/ms/open/development/batch-obtain-attendance-group-details) mengikut keperluan untuk mendapatkan butiran penuh.
- **S3: Apakah perbezaan antara id dan groupKey kumpulan kehadiran?**

  J: `id` ialah pengecam berangka kumpulan kehadiran, manakala `groupKey` ialah pengecam string kumpulan kehadiran. Sesetengah API, seperti Padam kumpulan kehadiran, memerlukan `groupKey`. Gunakan API [Tukar groupId kepada groupKey](/ms/open/development/groupid-to-groupkey) untuk menukar antara kedua-duanya.
- **S4: Adakah saya perlu menghantar semua medan semasa mengemas kini kumpulan kehadiran?**

  J: Tidak. Hantar hanya medan yang ingin diubah suai beserta `id` kumpulan kehadiran. Medan yang tidak dihantar akan mengekalkan nilai asalnya.
