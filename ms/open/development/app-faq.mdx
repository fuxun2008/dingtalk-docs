## **Apakah Aplikasi Berautoriti Organisasi**

Aplikasi berautoriti organisasi ialah aplikasi pada peringkat organisasi. Ia merupakan format aplikasi daripada versi awal DingTalk. Untuk menggunakan jenis aplikasi ini, anda perlu menjana Kelayakan API khusus berdasarkan pengecam unik organisasi anda (ID Organisasi, iaitu CorpId) dan kunci keselamatan (Organization Secret, iaitu CorpSecret). Dengan Kelayakan API yang dijana, anda boleh mengakses dan menggunakan keupayaan pembangunan seperti OpenAPI, Webhook, dan Stream.

**Nota**

Hanya Admin Organisasi boleh melihat dan menguruskan panggilan berautoriti organisasi. Ahli lain tidak boleh melakukan operasi tersebut.

## **Apakah Panggilan Berautoriti Organisasi**

Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.com/), kemudian klik **More** > **Basic Information** > [Development Information (Legacy)](https://open-dev.dingtalk.com/fe/old#/corpAuthInfo). Di situ, anda boleh mencari dan merekod ID Organisasi (CorpId) serta Organization Secret (CorpSecret). Dengan menggunakan kedua-dua nilai ini, anda boleh menjana Kelayakan API khusus untuk mengakses OpenAPI. Proses ini dipanggil panggilan berautoriti organisasi.

> Ini merupakan produk warisan daripada Open Platform versi awal. Jika perlu, kami mengesyorkan agar OpenAPI dipanggil melalui aplikasi dalaman. Untuk maklumat lanjut, lihat [Obtain the access_token of an internal app](/ms/open/development/obtain-the-access-token-of-an-internal-app).

## **Cara Menghentikan Panggilan Berautoriti Organisasi**

Apabila anda perlu menyahaktifkan ciri panggilan berautoriti organisasi, anda tidak boleh memadam Organization Secret (CorpSecret) secara terus. Jika anda ingin menghentikan penggunaan panggilan berautoriti, Super Admin yang mempunyai kebenaran pembangunan boleh melakukannya. Secara khusus, tukar alamat IP yang diikat kepada alamat yang tidak sah untuk menyahaktifkan panggilan berautoriti organisasi.

## Tidak Dapat Mencari Aplikasi Dalaman pada Workbench

Jawapan: Jika anda tidak dapat mencari aplikasi berkenaan pada Workbench, selesaikan masalah dengan mengikuti langkah berikut:

1. Sahkan bahawa organisasi Workbench semasa sepadan dengan organisasi milik aplikasi tersebut.
2. Sahkan bahawa aplikasi telah diterbitkan. Minta Admin pergi ke [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi sasaran > Version Management and Release** untuk mengesahkan sama ada aplikasi berada dalam status diterbitkan.
3. Sahkan skop ketersediaan aplikasi. Minta Admin pergi ke [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi sasaran > Version Management and Release** untuk mengesahkan sama ada pengguna yang tidak dapat mencari aplikasi berada dalam skop ketersediaan.

## Nyahpepijat Aplikasi Dalaman dalam Mini Program IDE Memaparkan Prompt "Sorry, You Are Not Within the Availability Scope of This App. Contact the Admin to Modify the Configuration"

Jawapan: Punca kemungkinan bagi prompt ini semasa menyahpepijat aplikasi dalaman termasuk, tetapi tidak terhad kepada, yang berikut:

1. Pengguna yang menyahpepijat aplikasi dalaman tidak berada dalam senarai pembangun. Tetapkan pembangun dalam [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi sasaran > User Management**.
2. Tiada versi telah dimuat naik untuk aplikasi dalaman tersebut. Pastikan anda memuat naik versi aplikasi dalam Mini Program IDE, kemudian keluarkan versi tersebut dalam [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi sasaran > Version Management and Release**.
3. Pengguna tidak ditetapkan dalam [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi sasaran > Version Management and Release > Availability Scope**.

   **Nota**

   Untuk mini program aplikasi dalaman, skop ketersediaan hanya dipaparkan selepas anda memuat naik versi dalam Mini Program IDE dan mengeluarkan versi tersebut dalam Version Management and Release.

## Aplikasi Mikro Dalaman atau Mini Program Tiada App Key atau App Secret

Jawapan: Sebab-sebab aplikasi yang dicipta tidak memaparkan App Key dan App Secret mungkin seperti berikut:

- Semasa anda mencipta aplikasi dalaman dalam Developer Console, seperti yang ditunjukkan dalam rajah di bawah, anda memilih **Development by an entrusted service provider** sebagai kaedah pembangunan, yang menyebabkan nilai tersebut tidak dipaparkan dalam App Management.

  **Nota**

  Jika anda sebenarnya tidak memerlukan pembangunan tauliah, pilih **In-house development**.

- Anda bukan pencipta aplikasi dan tidak mempunyai kebenaran berkaitan untuk melihat App Key dan App Secret. Hubungi Super Admin untuk menambah kebenaran App Management yang berkaitan pada halaman [DingTalk Admin Console](https://oa.dingtalk.com/#/welcome) **> Security and Permissions > Manage permissions**.
