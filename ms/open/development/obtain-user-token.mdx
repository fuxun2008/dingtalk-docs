## Kes penggunaan

API ini mendapatkan `accessToken` pengguna dan merupakan langkah penting dalam melaksanakan pengesahan identiti pengguna. Kes penggunaan biasa termasuk:

- Selepas pengguna log masuk, tukar kod kebenaran (`code`) kepada Kredensial akses yang sah.
- Sebelum `accessToken` tamat tempoh, gunakan `refreshToken` untuk memperbaharuinya secara automatik dan mengelakkan kebenaran semula yang kerap.
- Aplikasi perusahaan pihak ketiga menyepadukan dengan sistem log masuk bersatu DingTalk untuk melaksanakan Single Sign-On (SSO).
- Aplikasi perusahaan memanggil API yang dilindungi bagi pihak pengguna daripada perkhidmatan bahagian belakangnya.

Pembangun perlu menguruskan kitaran hayat `accessToken` dengan betul. Kami mengesyorkan menyimpannya dalam cache secara tempatan dan menyediakan mekanisme muat semula automatik untuk memastikan panggilan API yang stabil.

<Note>
Apabila menggunakan access token, ambil perhatian perkara berikut:
</Note>

- `accessToken` sah selama 7,200 saat (2 jam). Permintaan berulang dalam tempoh sah akan mengembalikan hasil yang sama dan memperbaharuinya secara automatik. Selepas tamat tempoh, `accessToken` baharu akan dikembalikan.
- `accessToken` bagi setiap aplikasi adalah bebas. Simpan token dalam cache mengikut aplikasi untuk mengelakkan kekeliruan.

## Permintaan

| **Maklumat asas** | |
| --- | --- |
| URL HTTP | https://api.dingtalk.io/v1.0/oauth2/userAccessToken |
| Kaedah HTTP | POST |
| Jenis aplikasi disokong | appType-Aplikasi dalaman appType-Aplikasi perusahaan pihak ketiga appType-Aplikasi peribadi pihak ketiga |
| Kebenaran diperlukan | permission-open_app_api_base-Kebenaran asas untuk mendapatkan kredensial akses pengguna bagi DingTalk Open API |

### Isi permintaan

| Nama | Jenis | Wajib | Contoh | Penerangan |
| --- | --- | --- | --- | --- |
| clientId | String | Ya | dingxxx | ID Aplikasi. Gunakan AppId aplikasi log masuk Imbas Kod QR atau mini program peribadi pihak ketiga.   - Untuk aplikasi dalaman, hantar **AppKey** aplikasi tersebut. - Untuk aplikasi perusahaan pihak ketiga, hantar **SuiteKey** aplikasi tersebut. - Untuk aplikasi peribadi pihak ketiga, hantar **AppId** aplikasi tersebut. |
| clientSecret | String | Ya | 1234 | App Secret aplikasi.   - Untuk aplikasi dalaman, hantar **AppSecret** aplikasi tersebut. - Untuk aplikasi perusahaan pihak ketiga, hantar **SuiteSecret** aplikasi tersebut. - Untuk aplikasi peribadi pihak ketiga, hantar **AppSecret** aplikasi tersebut. |
| code | String | Tidak | abcd | Kod kebenaran sementara OAuth 2.0. Aplikasi perusahaan pihak ketiga mesti menyepadukan dengan suite kebenaran bersatu atau [Dapatkan kredensial akses pengguna yang log masuk](/open/development/obtain-identity-credentials) untuk mendapatkan kod kebenaran sementara `authCode`. |
| refreshToken | String | Tidak | abcd | refresh token OAuth 2.0, diperoleh daripada respons API sebelumnya. Ia sah selama 30 hari. |
| grantType | String | Ya | authorization_code | - Untuk menukar kod kebenaran kepada token, hantar `authorization_code`. Dalam kes ini, parameter `code` diperlukan. - Untuk menukar refresh token kepada token baharu, hantar `refresh_token`. Dalam kes ini, parameter `refreshToken` diperlukan. |

### Contoh permintaan

```curl
curl -X POST 'https://api.dingtalk.io/v1.0/oauth2/userAccessToken' \
  -H 'Content-Type: application/json' \
  -d '{
    "clientId": "dingxxx",
    "clientSecret": "1234",
    "code": "abcd",
    "refreshToken": "abcd",
    "grantType": "authorization_code"
  }'
```

## Respons

### Isi respons

| Nama | Jenis | Contoh | Penerangan |
| --- | --- | --- | --- |
| accessToken | String | abcd | accessToken yang dijana, digunakan untuk Pengesahan dalam panggilan API seterusnya. |
| refreshToken | String | abcd | refresh_token yang dijana. Gunakan refresh token ini untuk mendapatkan accessToken pengguna secara berkala. |
| expireIn | Long | 7200 | Masa tamat tempoh, dalam saat. |
| corpId | String | corpxxxx | ID organisasi bagi organisasi yang dipilih. |

### Contoh respons

```text
HTTP/1.1 200 OK
Content-Type:application/json

{
  "accessToken" : "abcd",
  "refreshToken" : "abcd",
  "expireIn" : 7200,
  "corpId" : "corpxxxx"
}
```
