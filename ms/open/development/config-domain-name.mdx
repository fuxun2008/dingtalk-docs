**Penting** 

- Disebabkan naik taraf seni bina get laluan domain, domain keselamatan DingTalk tidak lagi menyokong akses SLB peribadi daripada DingTalk Cloud atau Jushita.
- Sebelum mencipta perkaitan, pastikan SLB peribadi telah dibeli di bawah akaun Alibaba Cloud (penggunaan Compute Nest) yang dikaitkan dalam konsol pembangun, bahawa SLB peribadi tersebut mempunyai port pendengar HTTP yang dikonfigurasikan, dan pengalihan HTTP-ke-HTTPS tidak dikonfigurasikan. Buat masa ini, hanya CLB disokong; ALB tidak disokong.
- Pilih SLB dan domain yang sah untuk diikat. Kami mengesyorkan menggunakan "app" + appId sebagai domain untuk mengelakkan pertindihan.
- Selepas anda mengikat domain keselamatan, satu nod perkhidmatan titik akhir PrivateLink dicipta secara lalai di bawah akaun awan untuk membina saluran peribadi daripada get laluan domain keselamatan DingTalk kepada SLB yang dikaitkan di bawah akaun awan tersebut. Nod perkhidmatan titik akhir PrivateLink adalah percuma di pihak ISV.
- Jika jenis push adalah SyncHttp, anda mesti menggunakan domain keselamatan DingTalk dalam alamat push bagi URL callback.
- Domain API bahagian pelayan aplikasi mestilah menggunakan domain keselamatan DingTalk.
- Wilayah dan zon yang disokong oleh SLB peribadi untuk kaedah penggunaan Compute Nest adalah seperti berikut:

  | **Wilayah** | **Zon** |
  | --- | --- |
  | China East 1 (Hangzhou) | Zone B, Zone E, Zone F, Zone G, Zone H, Zone I, Zone J, Zone K |
  | China East 2 (Shanghai) | Zone B, Zone E, Zone F, Zone G, Zone L, Zone M, Zone N, Zone I, Zone H |
  | China North 2 (Beijing) | Zone B, Zone C, Zone D, Zone E, Zone F, Zone G, Zone H, Zone I, Zone K, Zone L |
  | China North 3 (Zhangjiakou) | Zone A, Zone B, Zone C |
  | China South 1 (Shenzhen) | Zone D, Zone E, Zone F |

## Prosedur

1. Log masuk ke [Konsol Pembangun](https://open-dev.dingtalk.com/).
2. Cari aplikasi yang anda cipta. Pada halaman butiran aplikasi, klik **Domain Keselamatan DingTalk**.
3. Pilih SLB peribadi untuk dikaitkan dan domain yang hendak digunakan, pilih perjanjian kebenaran, kemudian klik **Kaitkan**.

   **Nota** 

   Selepas anda menghantar permintaan pengikatan domain keselamatan, tunggu semakan keselamatan DingTalk, yang biasanya mengambil masa 1 hingga 2 hari bekerja. Setelah diluluskan, proses tersebut secara automatik mengikat SLB peribadi kepada domain keselamatan, yang berkuat kuasa dalam masa 1 hingga 2 hari bekerja. Pantau kemas kini status. Jika permintaan ditolak, ubah suai dan hantar semula.

   - SLB peribadi: SLB peribadi telah dibeli di bawah akaun Alibaba Cloud yang diikat kepada Jushita, DingTalk Cloud, atau Compute Nest.

     **Nota** 

     SLB tersebut mesti mempunyai port pendengar HTTP yang dikonfigurasikan. Jangan gunakan port HTTPS biasa seperti 443 atau 8443.
   - Domain keselamatan: Kami mengesyorkan menggunakan "app" + appId sebagai domain untuk mengelakkan pertindihan.

## Kriteria Pengesahan untuk Pengaktifan Domain Keselamatan DingTalk

- Jika jenis push aplikasi perusahaan pihak ketiga ialah **HTTP** atau **syncHTTP**, domain alamat push mestilah domain keselamatan DingTalk.
- Jika aplikasi perusahaan pihak ketiga ialah mini program, API bahagian pelayan yang diminta oleh mini program tersebut mestilah menggunakan domain keselamatan DingTalk.
- Jika aplikasi perusahaan pihak ketiga ialah aplikasi mikro H5 dengan seni bina front-end dan back-end yang dipisahkan, API bahagian pelayan mestilah menggunakan domain keselamatan. Jika ia merupakan aplikasi front-end dan back-end bersepadu, alamat halaman utama aplikasi mestilah menggunakan domain keselamatan DingTalk.

## Soalan Lazim

### 1. SLB Telah Dibeli, tetapi Maklumat SLB Tidak Dipaparkan pada Peringkat "1 Kaitkan SLB"

**Jawapan:** Mula-mula, lakukan semakan kendiri berikut:

- Sahkan bahawa akaun awan telah dikaitkan dalam konsol pembangun.
- Sahkan bahawa SLB peribadi yang dibeli berada dalam julat wilayah yang disokong. Penggunaan Compute Nest menyokong China East 1 (Hangzhou), China North 3 (Zhangjiakou), China North 2 (Beijing), China East 2 (Shanghai), dan China South (Shenzhen). Penggunaan Jushita hanya menyokong China North 3 (Zhangjiakou), dan penggunaan DingTalk Cloud hanya menyokong China East 1 (Hangzhou).
- Sahkan bahawa anda membeli CLB dan bukannya ALB.
- Sahkan bahawa port pendengar SLB dikonfigurasikan dengan protokol HTTP dan bukannya protokol TCP.

Jika maklumat SLB masih tidak dipaparkan selepas semua semakan di atas, hantar tiket untuk maklum balas.

### 2. Pada Peringkat "2 Konfigurasi Domain", Status Semasa Menunjukkan "Domain Sedang Disemak, Sila Tunggu"

**Jawapan:** Dalam kes ini, domain keselamatan sedang disemak dan dikonfigurasikan. Biasanya, konfigurasi mengambil masa 1 hari bekerja untuk selesai. Tunggu 1 hari bekerja sebelum menyemak semula.

**Nota** 

Permintaan domain keselamatan untuk aplikasi bukan-produksi akan ditolak. Atas sebab kos di pihak DingTalk, domain keselamatan tidak lagi disediakan untuk aplikasi bukan-produksi seperti aplikasi ujian dan aplikasi staging. Jika anda perlu menguji domain keselamatan, mohon domain keselamatan untuk aplikasi produksi terlebih dahulu dan ikat kepada persekitaran ujian atau staging (tukar pengikatan dengan menggantikan kumpulan ECS yang dihala oleh SLB). Selepas pengesahan, tukar pengikatan kepada aplikasi produksi.

### 3. Pada Peringkat "3 Guna dalam Aplikasi", Status Semasa Domain Keselamatan Ialah "Pengikatan Domain Gagal, Admin DingTalk Sedang Memproses"

**Jawapan:** Dalam kes ini, konfigurasi domain keselamatan gagal. Anda boleh menghantar tiket untuk menghubungi sokongan teknikal DingTalk bagi campur tangan secara manual. Selepas campur tangan manual, pemprosesan biasanya mengambil masa 1 hari bekerja untuk selesai.

### 4. Pada Peringkat "3 Guna dalam Aplikasi", Status Semasa Domain Keselamatan Ialah "Pengikatan Domain Berjaya", tetapi Status Pengaktifan Domain Ialah "Domain Keselamatan Belum Diaktifkan"

**Jawapan:** Dalam kes ini, DingTalk telah menyelesaikan semakan dan konfigurasi domain keselamatan. Anda perlu melengkapkan konfigurasi domain keselamatan di pihak pembangun mengikut **Kriteria Pengesahan untuk Pengaktifan**. Selepas konfigurasi selesai, ia boleh dikesan berkuat kuasa dalam masa 1 hari bekerja.

### 5. SLB yang Asalnya Diikat Tidak Lagi Digunakan dan SLB Baharu Perlu Diikat

**Jawapan: Klik Ubah Suai** dan pilih SLB baharu untuk diikat:

- Jika anda tidak dapat melihat maklumat SLB yang perlu diikat semula, tangani dengan merujuk kepada Soalan Lazim pertama.
- Jika anda dapat melihat maklumat SLB yang hendak diikat semula, anda boleh mengubah suainya. Biasanya, operasi penukaran SLB menyokong peralihan tanpa gangguan, tetapi sedikit gangguan perkhidmatan mungkin berlaku semasa proses pengikatan semula. Alamat domain keselamatan tidak berubah selepas operasi penukaran.

### 6. Selepas Domain Keselamatan Dikonfigurasikan, Adakah Trafik Pengguna ke Aplikasi Akan Terus Dihalakan ke Domain Keselamatan?

**Jawapan:** Tidak. Selepas konfigurasi domain keselamatan berkuat kuasa, trafik akses tidak ditukar kepada domain keselamatan secara lalai. Anda perlu mengkonfigurasikan penghalaan trafik ke domain keselamatan di pihak aplikasi mengikut keperluan, dan mengaktifkan domain tersebut mengikut kriteria pengaktifan dalam Soalan Lazim 7, 8, dan 9.

### 7. Pengesahan Pengaktifan Domain Keselamatan: Gunakan Domain Keselamatan untuk Alamat Push

**Jawapan:** Gunakan domain keselamatan untuk domain dalam **Events and Callbacks > Callback Request Address** bagi ciri-ciri aplikasi.

### 8. Pengesahan Pengaktifan Domain Keselamatan: Gunakan Domain Keselamatan untuk Halaman Utama Aplikasi

**Jawapan:** Konfigurasikan domain keselamatan dalam **App Home Page Address** dan **PC Home Page Address** pada halaman **Development Management** bagi maklumat asas.

### 9. Pengesahan Pengaktifan Domain Keselamatan: Gunakan Domain Keselamatan untuk API Bahagian Pelayan Mini Program atau Aplikasi Front-End dan Back-End yang Dipisahkan

**Jawapan:** Konfigurasikan pengagihan trafik untuk domain keselamatan dalam perkhidmatan web nginx atau tomcat aplikasi anda. Untuk kaedah konfigurasi khusus, cari dokumentasi berkaitan dalam talian. Open Platform mengesan dan mengesahkan alamat domain API bahagian pelayan, yang biasanya berkuat kuasa secara T+1.

### 10. Cara Mengkonfigurasikan Sijil HTTPS untuk Domain Keselamatan

**Jawapan:** Domain keselamatan menyediakan akses HTTPS secara lalai. Anda tidak perlu mendapatkan sijil domain keselamatan atau mengkonfigurasikannya di pihak pembangun. Cukup konfigurasikan HTTP pada SLB awan; anda tidak perlu mengkonfigurasikan HTTPS. Get laluan domain keselamatan menghantar semula trafik HTTP melalui saluran khusus kepada SLB peribadi pembangun.

### 11. Pengalihan Berterusan Semasa Mengakses Domain Keselamatan

**Jawapan:** Semak konfigurasi SLB peribadi. Batalkan konfigurasi **Redirect to HTTPS:443** pada port 80 (atau port HTTP lain) SLB, hantar semula trafik ke port web pelayan bahagian belakang, dan konfigurasikan pelayan web perkhidmatan bahagian belakang dalam kumpulan pelayan. Untuk membatalkan konfigurasi pengalihan, rujuk [HTTP Redirect to HTTPS](https://help.aliyun.com/document_detail/89151.html).
