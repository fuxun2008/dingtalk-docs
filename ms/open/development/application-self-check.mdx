## Pengenalan kepada Pemeriksaan Kendiri Aplikasi

Selepas selesai membangunkan aplikasi perusahaan pihak ketiga, jalankan pemeriksaan kendiri aplikasi:

- Pemeriksaan kendiri fungsi, digunakan untuk menyemak tetapan asas seperti IP keluar pelayan aplikasi dan tetapan push.
- Semakan keselamatan, digunakan untuk menyemak aspek keselamatan.
- Pemantauan kestabilan, digunakan untuk menyemak kestabilan aplikasi, seperti kadar skrin kosong aplikasi dan kependaman API purata.

## Prosedur

1. Log masuk ke [Developer Console](https://open-dev.dingtalk.com/).
2. Pilih aplikasi perusahaan pihak ketiga yang anda cipta.
3. Klik aplikasi sasaran untuk membuka halaman butirannya, pilih **App Self-Inspection**, kemudian klik **Start Check**.

   - **Pemeriksaan Kendiri Fungsi**

     Digunakan untuk menyemak tetapan asas aplikasi, seperti IP keluar pelayan aplikasi, tetapan push, dan integrasi API. Butiran pemeriksaan adalah seperti berikut:

     | Item Pemeriksaan | Penerangan | Rujukan |
     | --- | --- | --- |
     | Sama ada IP keluar pelayan telah ditetapkan | Tetapkan IP keluar pelayan dalam maklumat pembangunan aplikasi. | Development Overview |
     | Sama ada jenis push yang sah telah ditetapkan | Lengkapkan tetapan push dalam maklumat pembangunan aplikasi. | Overview |
     | Sama ada organisasi penerimaan rasmi telah berjaya memasang aplikasi semasa | Pasang aplikasi semasa dalam organisasi penerimaan rasmi DingTalk untuk penerimaan produk seterusnya. Klik butang Start Check pada halaman pemeriksaan kendiri aplikasi, dan organisasi penerimaan rasmi (CorpId: ding0ed2f6a472ab48fef5bf40eda33b7ba0, Open Platform App Review Group) akan memasang aplikasi secara automatik.  **Nota**  Apabila anda klik butang Start Check, pastikan perkhidmatan push aplikasi berfungsi dengan baik. | — |
     | Sama ada integrasi Monitoring Center telah lengkap | Lengkapkan integrasi dalam Monitoring Center dan jana data pemantauan. | Monitoring Center |
     | Sama ada pelayan digunakan pada Alibaba Cloud atau Jushita | Pilih Alibaba Cloud atau Jushita sebagai kaedah penggunaan awan aplikasi. Untuk maklumat lanjut, rujuk dokumentasi penggunaan aplikasi. | Deployment Overview |
     | Sama ada versi mini program telah diterbitkan | Terbitkan versi mini program dalam pengurusan versi aplikasi. | Version Management and Publishing |
     | Sama ada domain gerbang keselamatan telah dimohon dan digunakan dalam aplikasi | Aplikasi yang disenaraikan di pasaran, iaitu aplikasi yang digunakan pada Jushita, mesti menggunakan domain keselamatan. | [DingTalk Security Domain](/zh/open/development/config-domain-name) |
4. Klik **Next** untuk membuka halaman **Security Review**.
5. Merujuk kepada Security Access Evaluation Guide, lengkapkan dan hantar bahan untuk item penilaian semakan keselamatan penyenaraian aplikasi.
6. Selepas anda menghantar, halaman **Stability Monitoring** akan dibuka.

   **Nota**

   Lengkapkan semakan kestabilan sebelum menyenaraikan aplikasi di DingTalk Marketplace. Selepas anda mengintegrasikan sistem pemantauan kestabilan, DingTalk akan mengumpul dan memaparkan data aplikasi berikut serta memaklumkan anda apabila data jatuh di bawah standard. Untuk maklumat lanjut, rujuk Stability Certification Standards.
7. Pilih **Integrate the Stability Monitoring System**.

   | Metrik Data | Penerangan | Keperluan Metrik |
   | --- | --- | --- |
   | Kadar kejayaan API dalam Monitoring Center | Lihat di Monitoring Center di bawah **Monitoring Metrics** -> **API Requests** -> **Success Rate**. | ≥98.99% |
   | Kependaman API purata dalam Monitoring Center | Lihat di Monitoring Center di bawah **Monitoring Metrics** -> **API Requests** -> **Request Latency**. | &lt;300 |
   | Kadar ralat JS dalam Monitoring Center | Lihat di Monitoring Center di bawah **Monitoring Metrics** -> **JS Errors** -> **Error Count to PV Ratio**. | &lt;1.99% |
   | Kadar skrin kosong dalam Monitoring Center | Lihat di Monitoring Center di bawah **Monitoring Metrics** -> **Blank Screen Errors** -> **Blank Screen Rate**. | &lt;1.99% |
   | Kadar kejayaan dd.config | Kadar kejayaan purata harian bagi panggilan JSAPI **dd.config**. | ≥98.99% |
   | Kadar kejayaan push HTTP | Jika jenis push adalah HTTP atau SyncHttp, kadar kejayaan adalah kadar DingTalk melakukan push ke URL callback dalam tempoh statistik (**push yang mengambil masa lebih daripada 1,500 ms dikira sebagai kegagalan tamat masa**). | ≥98.99% |

   Selepas aplikasi melengkapkan pemeriksaan kendiri, anda boleh menyenaraikannya di DingTalk Marketplace atau menjalankan aktiviti promosi luar talian.
