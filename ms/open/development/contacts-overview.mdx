Dokumen ini membantu anda memahami DingTalk Contacts secara menyeluruh. Dengan membaca dokumen ini, pengurus organisasi, ketua IT, dan pembangun dapat memahami dengan cepat sempadan keupayaan Contacts serta meletakkan asas untuk integrasi sistem dan inovasi perniagaan seterusnya.

## Apa itu DingTalk Contacts

DingTalk Contacts ialah infrastruktur teras untuk pengurusan bersepadu maklumat organisasi dalaman. Ia mewakili secara digital Struktur Organisasi dan maklumat pengguna sesebuah Organisasi, menyediakan pengguna keupayaan asas untuk mencari orang dengan cepat dan berkolaborasi secara cekap.

Untuk maklumat lanjut tentang ciri ini, lihat [Panduan Pengguna DingTalk - Kenalan Organisasi](https://docs.dingtalk.io/i/p/Y7kmbokZp3pgGLq2/docs/Y7kmbpxy30LLzLq2?dontjump=true#).

| **Dimensi** | **Penerangan** |
| --- | --- |
| Intipati | Pembawa perwakilan digital bagi Struktur Organisasi |
| Bentuk | Hierarki Jabatan berstruktur pokok + pangkalan data maklumat pengguna |
| Fungsi | Hab yang menghubungkan orang, urusan, dan sumber dalam sesebuah Organisasi, menyokong senario seperti aliran Kelulusan, penghalaan mesej, dan kawalan Kebenaran |

## Cara melihat Contacts

### Perspektif Admin Organisasi

Admin Organisasi boleh mengurus dan melihat Contacts melalui cara berikut:

- DingTalk Admin Console: Log masuk ke [DingTalk Admin Console](https://oa.dingtalk.io/), dan pergi ke modul **Kenalan Dalaman** untuk melaksanakan pengurusan dan konfigurasi penuh Contacts.
- Tetapan Contacts: Konfigurasikan ciri lanjutan seperti peraturan keterlihatan Contacts, Medan Tersuai, dan mod Eksekutif.

### Pengguna biasa

Pengguna Organisasi biasa boleh melihat Contacts melalui saluran berikut:

- **DingTalk for PC**: Dalam klien PC DingTalk, klik tab **Contacts** untuk melihat Struktur Organisasi dan butiran kenalan.
- **DingTalk Mobile**: Dalam Aplikasi mudah alih DingTalk, pergi ke halaman **Contacts** untuk melayari mengikut Jabatan atau mencari mengikut kata kunci.
- **DingTalk for Web**: Akses ciri Contacts melalui versi web DingTalk.

## Glosari

### ID Pekerja

Kod Medan yang sepadan dengan ID Pekerja ialah `job_number`. ID Pekerja bagi seorang Pekerja dalam sesebuah Organisasi tidak semestinya unik, jadi ID ini tidak boleh digunakan sebagai pengecam unik bagi Pekerja dalam Organisasi tersebut.

Admin Organisasi log masuk ke [DingTalk Admin Console](https://oa.dingtalk.io/), dan pada halaman Contacts, klik **Nama Pekerja** untuk melihat ID Pekerja. Medan ID Pekerja adalah Pilihan.

### unionId

Pengecam unik bagi seorang pengguna dalam skop akaun DingTalk Open Platform semasa. Satu akaun DingTalk Open Platform boleh mengandungi pelbagai Aplikasi terbuka, termasuk Aplikasi suite ISV dan Aplikasi dalaman.

unionId boleh diperoleh dengan memanggil API [Tanya butiran pengguna](/ms/open/development/query-user-details).

### Kumpulan peranan dan peranan

Kumpulan peranan dan Peranan ditakrifkan dalam Organisasi untuk memudahkan pengurusan maklumat identiti Pekerja. Seorang Pekerja boleh memegang pelbagai identiti Peranan pada masa yang sama.

Admin Organisasi log masuk ke [DingTalk Admin Console](https://oa.dingtalk.io/), pergi ke halaman **Contacts > Urus Kenalan Dalaman**, dan klik **Peranan** untuk melihat Kumpulan peranan dan Peranan.

### Medan lanjutan Contacts

Anda boleh menambah Medan lanjutan ke Contacts.

Admin Organisasi log masuk ke [DingTalk Admin Console](https://oa.dingtalk.io/), dan pergi ke **Tetapan Kenalan Dalaman > Maklumat Contacts > Tambah Medan Tersuai** untuk menambah Medan Tersuai.
