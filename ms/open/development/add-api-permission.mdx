Sebelum memanggil API bahagian pelayan DingTalk, tambah kebenaran panggilan API yang diperlukan. Selepas aplikasi dicipta, sistem secara lalai memberikan kebenaran API Pengesahan dan pemberitahuan Mesej. Kami menggalakkan aplikasi untuk menggunakan API sebanyak mungkin bagi mencapai interoperabiliti penuh dengan keupayaan teras DingTalk.

## Skop yang berkenaan

- **Aplikasi dalaman**: Aplikasi yang dibangunkan oleh organisasi untuk kegunaan dalamannya sendiri. Sesuai untuk senario integrasi sistem dalaman.
- **Aplikasi perusahaan pihak ketiga**: Aplikasi perkhidmatan yang dibangunkan oleh ISV (Vendor Perisian Bebas) untuk dipasang dan digunakan oleh pelbagai pelanggan perusahaan.
- **Aplikasi peribadi pihak ketiga**: Aplikasi yang dibangunkan oleh penyedia penyelesaian untuk pengguna peribadi di DingTalk.

Prosedur permohonan kebenaran, proses kelulusan, dan ketersediaan API mungkin berbeza mengikut jenis aplikasi. Rujuk arahan yang berkenaan dengan jenis aplikasi anda.

## Gambaran keseluruhan

Sebelum memanggil API bahagian pelayan DingTalk, tambah kebenaran panggilan API yang berkaitan pada aplikasi. Selepas aplikasi dicipta, sistem secara lalai memberikan sesetengah kebenaran asas. Mohon kebenaran API yang diperlukan berdasarkan keperluan perniagaan anda untuk mencapai integrasi mendalam dengan keupayaan teras DingTalk.

Kebenaran API diberikan **pada peringkat aplikasi**, dan kebenaran adalah bebas antara aplikasi. Walaupun beberapa aplikasi dalam organisasi yang sama perlu memanggil API yang sama, kebenaran mesti dimohon secara berasingan untuk setiap aplikasi.

Sebagai contoh, jika organisasi anda mempunyai dua aplikasi, A dan B, dan aplikasi A sudah mempunyai kebenaran Telah dibaca Kenalan, aplikasi B tetap perlu memohon kebenaran Kenalan secara berasingan untuk mengakses data Kenalan. Prosedurnya adalah sama seperti bagi aplikasi A.

<Warning>
Bukan semua API boleh diaktifkan secara terus. Sesetengah API adalah keupayaan bukan awam dan memerlukan kelulusan sebelum digunakan. API premium lain mungkin melibatkan bayaran atau keperluan kelayakan tertentu. Rujuk penerangan skop dalam setiap dokumen API untuk butiran lanjut.
</Warning>

## Prasyarat

Sebelum mengkonfigurasi kebenaran API, pastikan syarat berikut dipenuhi:

1. Jenis aplikasi ialah **Aplikasi dalaman**, **Aplikasi perusahaan pihak ketiga**, atau **Aplikasi peribadi pihak ketiga**, dan aplikasi tersebut telah dicipta dalam [Konsol Pembangun](https://open-dev.dingtalk.io/).
2. Akaun semasa mempunyai kebenaran pengurusan untuk aplikasi tersebut (biasanya Admin Organisasi atau pemilik aplikasi).
3. Organisasi telah menyelesaikan pengesahan (sesetengah API memerlukan pengesahan organisasi nama sebenar sebelum boleh dimohon).
4. `AppKey` dan `AppSecret` aplikasi telah diperoleh dan dikonfigurasi dengan betul untuk pengesahan API.

## Tambah kebenaran panggilan API standard

Prosedur ini terpakai untuk kebanyakan API awam bahagian pelayan dan boleh dimohon terus melalui Konsol Pembangun.

Prosedur:

1. Dalam dokumen API, salin skop kebenaran daripada bahagian Kebenaran API sasaran.

2. Log masuk ke [Konsol Pembangun](https://open-dev.dingtalk.io/).
3. Pada halaman **App Development**, klik aplikasi sasaran untuk masuk ke halaman butiran aplikasi.

4. Pada halaman butiran aplikasi, klik **Urus kebenaran**, cari skop kebenaran yang disalin, dan klik **Mohon kebenaran**.

## Tambah kebenaran panggilan API khas

Bagi API yang bukan awam, sensitif, atau khusus industri, kelulusan manual oleh DingTalk diperlukan sebelum ia boleh diaktifkan.

Prosedur:

1. Dalam dokumen API, salin skop kebenaran daripada bahagian Kebenaran API sasaran.

2. Log masuk ke [Konsol Pembangun](https://open-dev.dingtalk.io/) sebagai Admin.
3. Pada halaman **App Development**, klik aplikasi sasaran untuk masuk ke halaman butiran aplikasi.

4. Klik **Urus kebenaran**, pilih API khas yang hendak ditambah, dan klik **Mohon kebenaran**.
5. Masukkan penerangan permohonan dan klik **Mohon**.

   **Petua**
   - Permohonan kebenaran API disemak oleh pasukan DingTalk yang bertanggungjawab ke atas API berkaitan. Kelulusan biasanya diselesaikan dalam masa satu hari bekerja. Selepas diluluskan, status akan bertukar kepada **Diaktifkan**.
   - Jika permohonan ditolak, cari entri kebenaran dalam senarai **Requests**, arahkan kursor ke tag **Review Failed** untuk melihat sebab spesifik, dan hantar semula selepas membuat penambahbaikan berdasarkan maklum balas tersebut.

## Menyelesaikan masalah ralat kebenaran

<Note>
Penyelesaian ini pada masa ini hanya terpakai untuk panggilan yang dibuat kepada API bahagian pelayan yang baharu.
</Note>

Apabila panggilan API baharu mengembalikan ralat `403`, isi respons mengandungi maklumat terperinci tentang kebenaran yang tiada:

```json
{
  "Code": "Forbidden.AccessDenied.AccessTokenPermissionDenied",
  "StatusCode": 403,
  "Message": "code: 403, no permission to call this API request id: 8197EFxxxx59D33E58",
  "Data": "{\"AccessDeniedDetail\":{\"requiredScopes\":[\"Contact.Org.Read\"]},\"Code\":\"Forbidden.AccessDenied.AccessTokenPermissionDenied\",\"HostId\":\"dingtalk-inner.aliyuncs.com\",
            \"Message\":\"no permission to call this API\",\"Recommend\":\"https://next.api.aliyun.com/troubleshoot?q=Forbidden.AccessDenied.AccessTokenPermissionDenied\\u0026product=dingtalk\",
            \"RequestId\":\"8197Exxxx88C759D33E58\",\"statusCode\":403}",
  "Stack": null,
  "Description": "\u003cni\u003e",
  "AccessDeniedDetail": {
    "requiredScopes": [
      "Contact.Org.Read"
    ]
  }
}
```

Apabila aplikasi mengembalikan ralat "no permission to call this API", ikut langkah berikut:

1. Ekstrak nilai medan `requiredScopes` dalam `AccessDeniedDetail` pada respons ralat. Ini ialah kod skop kebenaran yang diperlukan oleh API sasaran.
2. Pada halaman Manage permissions bagi aplikasi semasa, cari kod skop kebenaran tersebut dan mohon kebenaran API yang berkaitan.
