Apabila aplikasi perlu memanggil DingTalk OpenAPI bagi pihak pengguna yang log masuk untuk mengendalikan sumber, ikut prosedur dalam topik ini untuk mendapatkan kredensial akses bagi memanggil API.

<Note>
Proses untuk aplikasi dalaman dan aplikasi perusahaan pihak ketiga adalah serupa. Topik ini menggunakan aplikasi dalaman sebagai contoh.
</Note>

## Langkah 1: Cipta aplikasi

1. Log masuk ke [DingTalk Developer Platform](https://open-dev.dingtalk.io/#/loginMan).
2. Buka halaman butiran aplikasi yang telah anda cipta. Pada halaman **Basic Information**, lihat **SuiteKey/SuiteSecret (Aplikasi perusahaan pihak ketiga) atau AppKey/AppSecret (Aplikasi dalaman)** aplikasi tersebut.

3. Pada halaman butiran aplikasi, klik **Development Configuration** > **Security Settings**, dan masukkan redirect URI (domain callback).

   > redirect URI ialah alamat yang anda jangkakan untuk dialihkan selepas kebenaran log masuk diberikan.

## Langkah 2: Kebenaran log masuk OAuth

Untuk menggunakan DingTalk OpenAPI bagi membaca dan menulis sumber bagi pihak pengguna, lengkapkan kebenaran melalui aliran Kebenaran OAuth 2.0. Aliran Kebenaran OAuth 2.0 digambarkan seperti berikut.

### Gunakan halaman kebenaran log masuk yang disediakan oleh DingTalk

Bina halaman kebenaran log masuk. Parameter halaman adalah seperti berikut:

### Penting

- Untuk kebolehbacaan, pemisah baris ditambah pada contoh parameter berikut. Pemisah baris tidak diperlukan dalam penggunaan sebenar.
- Nilai parameter mesti dikodkan URL (URL-encoded). Contoh berikut telah dikodkan URL.

```text
https://login.dingtalk.io/oauth2/auth?
redirect_uri=https%3A%2F%2Fwww.aaaaa.com%2Fa%2Fb
&response_type=code
&client_id=dingbbbbbbb
&scope=openid corpid
&state=dddd
&prompt=consent
```

| Name | Required | Description |
| --- | --- | --- |
| redirect_uri | Ya | URL callback selepas kebenaran diberikan atau ditolak.  **Penting**  Mesti sepadan dengan domain yang didaftarkan untuk aplikasi. |
| response_type | Ya | Nilai tetap iaitu code.  Mengembalikan authCode selepas kebenaran diberikan. |
| client_id | Ya | Diperoleh daripada butiran aplikasi yang dicipta dalam Langkah 1.   - Aplikasi dalaman: client_id ialah App Key aplikasi. - Aplikasi perusahaan pihak ketiga: client_id ialah SuiteKey aplikasi. |
| scope | Ya | Skop kebenaran. Maklumat kebenaran yang dipaparkan pada halaman kebenaran adalah berdasarkan konfigurasi semasa pendaftaran aplikasi.  Pada masa ini, hanya dua nilai disokong:   - **openid**: Selepas kebenaran diberikan, ID pengguna diperoleh. - **openid** corpid: Selepas kebenaran diberikan, ID pengguna dan ID organisasi yang dipilih oleh pengguna semasa log masuk diperoleh, dipisahkan dengan ruang. Perhatikan bahawa pengekodan URL diperlukan. |
| prompt | Ya | Apabila ditetapkan kepada consent, halaman pengesahan kebenaran dipaparkan. |
| state | Tidak | Dikembalikan seperti sedia ada bersama authCode. |
| org_type | Tidak | Mengawal output senarai organisasi bagi jenis tertentu. org_type=management menunjukkan hanya organisasi dengan kebenaran pentadbiran dikembalikan.  **Penting**  Parameter ini hanya bermakna apabila scope mengandungi corpid. |
| corpId | Tidak | Menentukan organisasi yang mesti dipilih oleh pengguna.  **Penting**   - Parameter ini hanya bermakna apabila scope mengandungi corpid. - corpId yang dihantar mestilah organisasi yang dimiliki oleh pengguna semasa. |
| exclusiveLogin | Tidak | Apabila ditetapkan kepada true, menunjukkan log masuk akaun eksklusif dan memaparkan halaman input Kod Organisasi. |
| exclusiveCorpId | Tidak | corpId bagi organisasi yang telah mengaktifkan ciri akaun eksklusif.  **Penting**  Parameter ini hanya bermakna apabila exclusiveLogin bernilai true,  dan ia akan mengalihkan terus ke halaman log masuk organisasi tersebut. |

Jika berjaya, mengalih ke: https://www.aaaaa.com/a/b?authCode=xxxx&state=dddd

Jika gagal, mengalih ke: https://www.aaaaa.com/a/b?error=yyyyyy&state=dddd

### Kebenaran log masuk Kod QR terbenam

<Warning>
Halaman yang membenamkan Kod QR mesti "sama asal" (same-origin) dengan halaman yang ditentukan oleh parameter redirect_uri. Jika tidak, mengimbas Kod QR tidak akan memberi kesan. "Sama asal" bermaksud protokol yang sama, domain peringkat kedua atau ketiga yang sama, nombor port yang sama, dan sebagainya. Untuk butiran lanjut, lihat [Dasar sama asal](https://developer.mozilla.org/zh-CN/docs/Web/Security/Same-origin_policy).
</Warning>

1. Sertakan JSSDK log masuk Imbas Kod QR DingTalk pada halaman.

   ```xml
   <script src="https://g.alicdn.com/dingding/h5-dingtalk-login/0.21.0/ddlogin.js"></script>
   ```
2. Panggil kaedah berikut di tempat log masuk Imbas Kod QR diperlukan.

   ```html
   <!-- STEP1: Add the wrapper container element in HTML -->
   <div id="self_defined_element" class="self-defined-classname"></div>
   <style>
       /* STEP2: Specify the CSS style for this wrapper container element. Pay special attention to width and height. */
       .self-defined-classname {
           width: 300px;
           height: 300px;
       }
   </style>
   <script>
       // STEP3: When needed, call the window.DTFrameLogin method to construct the sign-in QR Code and handle the success or failure callbacks.
       window.DTFrameLogin(
           {
               id: 'self_defined_element',
               width: 300,
               height: 300,
           },
           {
               redirect_uri: encodeURIComponent('http://www.aaaaa.com/a/b/'),
               client_id: 'dingxxxxxxxxxxxx',
               scope: 'openid',
               response_type: 'code',
               state: 'xxxxxxxxx',
               prompt: 'consent',
           },
           (loginResult) => {
               const {redirectUrl, authCode, state} = loginResult;
               // You can redirect directly here
               window.location.href = redirectUrl;
               // Or use the code for authorization without redirecting the page
               console.log(authCode);
           },
           (errorMsg) => {
               // Typically, display the specific reason for the sign-in failure here
               alert(`Login Error: ${errorMsg}`);
           },
       );
   </script>
   ```

   Penerangan parameter (dalam TypeScript):

   ```typescript
   // ********************************************************************************
   // Definition of the window.DTFrameLogin method
   // ********************************************************************************
   window.DTFrameLogin: (
     frameParams: IDTLoginFrameParams, // Parameters related to the DOM wrapper container
     loginParams: IDTLoginLoginParams, // Unified sign-in parameters
     successCbk: (result: IDTLoginSuccess) => void, // Callback function on successful sign-in
     errorCbk?: (errorMsg: string) => void,         // Callback function on failed sign-in
   ) => void;

   // ********************************************************************************
   // Parameters related to the DOM wrapper container
   // ********************************************************************************
   // Note! The width and height parameters only set the size of the QR Code iframe element and do not affect the size of the wrapper container.
   // The size and style of the wrapper container must be set by the integrator using CSS.
   interface IDTLoginFrameParams {
     id: string;      // Required. The ID of the wrapper container element, without '#'.
     width?: number;  // Optional. The width of the QR Code iframe element. Minimum 280. Default 300.
     height?: number; // Optional. The height of the QR Code iframe element. Minimum 280. Default 300.
   }

   // ********************************************************************************
   // Unified sign-in parameters
   // ********************************************************************************
   // The parameter meanings are identical to those in the "Construct a link to initiate sign-in authorization" integration method (with some parameters omitted).
   // The isPre parameter is added to set the runtime environment.
   interface IDTLoginLoginParams {
     redirect_uri: string;     // Required. Note that the URL must be encoded.
     response_type: string;    // Required. A fixed value of code.
     client_id: string;        // Required.
     scope: string;            // Required. If the value is openid+corpid, the org_type and corpId parameters below are required. Otherwise, sign-in will fail.
     prompt: string;           // Required. The value is consent.
     state?: string;           // Optional.
     org_type?: string;        // Optional. Required when scope is openid+corpid.
     corpId?: string;          // Optional. Required when scope is openid+corpid.
     exclusiveLogin?: string;  // Optional. To generate a QR Code dedicated to an exclusive organization, set this to true to restrict sign-in to organization accounts only.
     exclusiveCorpId?: string; // Optional. Required when exclusiveLogin is true. Specifies the corpId of the exclusive organization.
   }

   // ********************************************************************************
   // Sign-in result returned on successful sign-in
   // ********************************************************************************
   interface IDTLoginSuccess {
     redirectUrl: string;   // The redirect URL after successful sign-in. The integrator can use this URL directly for redirection.
     authCode: string;      // The authCode obtained after successful sign-in. The integrator can authenticate directly without redirecting the page.
     state?: string;        // The state obtained after successful sign-in.
   }
   ```

## Langkah 3: Dapatkan kredensial akses

Gunakan auth_code yang dikembalikan bersama maklumat aplikasi untuk memanggil API [Get user token](/open/development/obtain-user-token) bagi mendapatkan access_token.

Kod contoh:

```http
POST /v1.0/oauth2/userAccessToken HTTP/1.1
Host:api.dingtalk.io
x-acs-dingtalk-access-token:BE3xxxx
Content-Type:application/json

{
  "clientId" : "dingxxx",
  "clientSecret" : "1234",
  "code" : "abcd",
  "refreshToken" : "abcd",
  "grantType" : "authorization_code"
}
```

## Langkah 4: Panggil API dengan kredensial akses

Selepas mendapatkan access_token, anda boleh menggunakan kredensial ini untuk memanggil API [Get user contact profile](/open/development/dingtalk-retrieve-user-information).
