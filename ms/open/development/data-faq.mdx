Artikel ini merangkumi soalan lazim mengenai proses pembangunan dan urus kebenaran aplikasi dalaman. Ia disediakan untuk pembangun organisasi yang menggunakan DingTalk Open Platform untuk pembangunan aplikasi, terutamanya Organization Admin dan kakitangan teknikal yang mempunyai kebenaran pembangunan.

## Apakah aplikasi diberi kuasa organisasi

Aplikasi diberi kuasa organisasi ialah aplikasi peringkat organisasi, satu bentuk aplikasi daripada versi DingTalk yang lebih awal. Untuk menggunakan jenis aplikasi ini, anda perlu menjana Kelayakan API khusus berdasarkan pengecam unik organisasi (ID Organisasi, iaitu CorpId) dan kunci keselamatan (organization secret, iaitu CorpSecret). Dengan Kelayakan API yang dijana, anda boleh mengakses keupayaan pembangunan seperti OpenAPI, Webhook, dan Stream.

<Note>
Hanya Organization Admin boleh melihat dan mengurus panggilan API diberi kuasa organisasi. Pengguna lain tidak boleh melakukan tindakan ini.
</Note>

## Apakah panggilan API diberi kuasa organisasi

Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.io/), dan klik **More** > **Basic information** > [Development information (legacy)](https://open-dev.dingtalk.io/fe/old#/corpAuthInfo) untuk mencari dan merekod pengecam organisasi (CorpId) dan organization secret (CorpSecret). Gunakan kedua-dua nilai ini untuk menjana Kelayakan API khusus yang membenarkan akses kepada OpenAPI. Proses ini dipanggil panggilan API diberi kuasa organisasi.

> Ini adalah produk legasi daripada Open Platform peringkat awal. Kami mengesyorkan agar anda memanggil OpenAPI melalui aplikasi dalaman sebaliknya. Untuk maklumat lanjut, lihat [Get the access_token of an internal app](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app).

## Cara menghentikan panggilan API diberi kuasa organisasi

Oleh sebab organization secret (CorpSecret) tidak boleh dipadam secara terus, anda boleh menyahaktifkan ciri panggilan API diberi kuasa organisasi secara logik dengan mengubah suai senarai dibenarkan alamat IP keluar (egress IP allowlist).

**Laluan**: Log masuk ke Developer Console → App Management → aplikasi disasarkan → Security settings → Ubah suai alamat IP keluar.

**Langkah**:

1. Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.io/).
2. Pilih aplikasi disasarkan daripada senarai aplikasi untuk membuka halaman butirannya.
3. Klik **Security settings**.
4. Dalam medan "Egress IP address", masukkan alamat IP awam yang tidak sah (contohnya, `0.0.0.0`).
5. Klik **Save** untuk menerapkan tetapan.

> **Nota**: Selepas anda menetapkan IP yang tidak sah, perkhidmatan luaran tidak lagi boleh memanggil API dengan kelayakan sedia ada, sekali gus menghentikan panggilan API diberi kuasa secara berkesan.

## Penyelesaian masalah

### Semasa menyahpepijat aplikasi dalaman dalam Mini Program IDE, mesej "Sorry, you are not within the available scope of this app. Contact the admin to update the configuration" muncul

Jawapan: Kemungkinan punca mesej ini semasa penyahpepijatan termasuk, tetapi tidak terhad kepada:

1. Pengguna yang menyahpepijat aplikasi dalaman tidak berada dalam senarai pembangun. Tambah pengguna di bawah [Developer Console](https://open-dev.dingtalk.io/#/) **> aplikasi disasarkan > User management**.
2. Tiada versi telah dimuat naik untuk aplikasi dalaman. Pastikan versi aplikasi dimuat naik dalam Mini Program IDE, kemudian keluarkan versi tersebut di bawah [Developer Console](https://open-dev.dingtalk.io/#/) **> aplikasi disasarkan > Version management and release**.
3. Pengguna tidak dikonfigurasikan di bawah [Developer Console](https://open-dev.dingtalk.io/#/) **> aplikasi disasarkan > Version management and release > Available scope**.

### Nota

   Skop tersedia untuk mini program aplikasi dalaman hanya dipaparkan selepas versi dimuat naik dalam Mini Program IDE dan dikeluarkan di bawah Version management and release.

### Aplikasi mikro dalaman atau mini program tiada App Key atau App Secret

Jawapan: Kemungkinan sebab App Key dan App Secret tidak dipaparkan untuk aplikasi yang telah dicipta:

- Semasa aplikasi dalaman dicipta dalam Developer Console, kaedah pembangunan **Delegated ISV development** telah dipilih, jadi kelayakan tidak dipaparkan dalam App Management.

### Nota

  Jika pembangunan didelegasikan sebenarnya tidak diperlukan, pilih **Self-developed by the organization**.

- Pengguna bukan pencipta aplikasi dan tidak mempunyai kebenaran yang diperlukan untuk melihat App Key dan App Secret. Minta Super Admin memberikan kebenaran urus aplikasi berkenaan di bawah [DingTalk Admin Console](https://oa.dingtalk.io/#/welcome) **> Security and permissions > Manage permissions**.
