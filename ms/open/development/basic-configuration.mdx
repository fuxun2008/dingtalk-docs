## Prosedur

1. Log masuk ke [Developer Console](https://open-dev.dingtalk.com/) dan klik aplikasi yang disasarkan.
2. Pada halaman butiran aplikasi, klik **Development Management** untuk mengkonfigurasikan maklumat asas aplikasi.

   | Konfigurasi | Wajib | Penerangan |
   | --- | --- | --- |
   | Mod pembangunan | Wajib untuk aplikasi mikro H5 | Pilih mod pembangunan:  - **Develop app**: Membangunkan aplikasi mikro H5 baharu. - **Quick link**: Menambah aplikasi mikro H5 sedia ada. Sesebuah organisasi boleh mengintegrasikan aplikasi dalamannya ke dalam DingTalk melalui pautan pantas (quick link), membolehkan pekerja dalaman menggunakannya pada DingTalk Workbench. |
   | IP keluar server | Ya | Masukkan alamat IP yang digunakan semasa memanggil DingTalk Server API, iaitu alamat IP awam server organisasi. Pisahkan pelbagai alamat IP dengan koma (,). Format IP dengan satu aksara wildcard (\*) disokong. |
   | URL laman utama aplikasi | Wajib untuk aplikasi mikro H5 | Masukkan URL laman utama aplikasi. Mengetik ikon aplikasi pada Workbench mudah alih akan mengalihkan pengguna ke halaman ini.  Masukkan alamat IP atau domain server tempat perkhidmatan backend digunakan. Contohnya: `https://public-IP:8080`. |
   | URL laman utama PC | Tidak | Masukkan URL untuk membuka aplikasi pada DingTalk Workbench di PC. Pautan mesti bermula dengan http atau https.  **Nota**  Jika dibiarkan kosong, mengetik ikon aplikasi pada DingTalk Workbench di PC akan memaparkan mesej: "The PC version is not supported yet. Scan the QR code below with DingTalk on your phone to view." Aplikasi hanya boleh digunakan pada DingTalk Client-side di telefon bimbit. |
   | URL Admin Console | Tidak | Masukkan URL untuk admin mengakses aplikasi dalam [DingTalk Admin Console](https://oa.dingtalk.com/). |
   | Jenis push | Ya | Aplikasi perusahaan pihak ketiga **mesti** mendaftarkan Callback untuk menerima peristiwa pengaktifan aplikasi apabila sesebuah organisasi memberi kebenaran kepada aplikasi tersebut. Ini memberitahu aplikasi organisasi mana yang telah mengaktifkannya. Selepas backend aplikasi pihak ketiga menerima peristiwa ini, ia mesti memulakan (initialize) maklumat organisasi untuk melengkapkan pengaktifan. Untuk butiran lanjut, lihat Activate an authorized app.  Selain peristiwa pengaktifan aplikasi, DingTalk turut menghantar mesej peristiwa lain, seperti perubahan kebenaran aplikasi dan perubahan Jabatan. Dengan melanggan Peristiwa Callback ini, pembangun dapat mengintegrasikan aplikasi mereka dengan DingTalk secara lebih baik. Untuk butiran lanjut, lihat Data Push Overview.  DingTalk menyokong dua kaedah berikut untuk menerima Peristiwa Callback:  - Push data RDS - Push SyncHTTP |
