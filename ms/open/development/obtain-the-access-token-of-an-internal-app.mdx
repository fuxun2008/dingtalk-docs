Panggil API ini daripada aplikasi dalaman untuk mendapatkan kredensial akses (access token). Semasa memanggil DingTalk Server API, anda mesti menggunakan access token untuk pengesahan bagi memastikan permintaan datang daripada sumber yang sah dan mempunyai kebenaran yang diperlukan.

## Penerangan panggilan API

API ini direka untuk senario integrasi sistem perusahaan dalaman dan digunakan untuk mendapatkan kredensial akses yang diperlukan bagi memanggil keupayaan terbuka DingTalk. Aliran penggunaan biasa adalah seperti berikut:

- Panggil API ini untuk mendapatkan access token semasa aplikasi bermula atau sebelum panggilan API pertama.
- Cache access token yang diperoleh dalam storan tempatan (seperti Redis atau cache dalam memori) untuk mengelakkan permintaan berulang.
- Sertakan access token ini dalam semua panggilan API seterusnya yang memerlukan pengesahan.
- Tetapkan masa tamat tempoh cache sedikit lebih pendek daripada 7,200 saat (contohnya 7,000 saat) untuk melaksanakan mekanisme muat semula automatik dan mengelakkan tamat tempoh kredensial akibat perbezaan masa.
- Elakkan memanggil API ini secara kerap dalam tempoh masa yang singkat. Jika tidak, dasar had kadar mungkin tercetus dan menjejaskan kestabilan perkhidmatan.

## Permintaan

| **Maklumat asas** | |
| --- | --- |
| URL HTTP | https://api.dingtalk.io/v1.0/oauth2/accessToken |
| Kaedah HTTP | POST |
| Jenis aplikasi yang disokong | appType-Aplikasi dalaman |
| Kebenaran yang diperlukan | permission-qyapi_base-Kebenaran asas yang diperlukan untuk memanggil API perusahaan |

### Isi permintaan

| Nama | Jenis | Wajib | Contoh | Penerangan |
| --- | --- | --- | --- | --- |
| appKey | String | Ya | dingeqqpkv3xxxxxx | Client ID bagi aplikasi dalaman yang dicipta. Untuk maklumat lanjut cara mendapatkannya, lihat dokumen [Client ID/Client Secret](/ms/open/dingstart/basic-concepts-beta). |
| appSecret | String | Ya | GT-lsu-taDAxxxsTsxxxx | Client Secret bagi aplikasi dalaman yang dicipta. Untuk maklumat lanjut cara mendapatkannya, lihat dokumen [Client ID/Client Secret](/ms/open/dingstart/basic-concepts-beta).  **Nota**  Simpan Client Secret dengan selamat dan elakkan ia daripada bocor. |

### Contoh permintaan

```curl
curl -X POST 'https://api.dingtalk.io/v1.0/oauth2/accessToken' \
  -H 'Content-Type: application/json' \
  -d '{
    "appKey": "dingeqqpkv3xxxxxx",
    "appSecret": "GT-lsu-taDAxxxsTsxxxx"
  }'
```

## Respons

### Isi respons

| Nama | Jenis | Contoh | Penerangan |
| --- | --- | --- | --- |
| accessToken | String | fw8ef8we8f76e6f7s8dxxxx | Access token yang dijana.  **Nota**  Semasa menggunakan access token, ambil perhatian perkara berikut:   - Cache access token di pihak anda, dan simpan secara berasingan mengikut aplikasi, kerana access token bagi setiap aplikasi dalaman adalah bebas antara satu sama lain. - Elakkan memanggil API ini secara kerap untuk mendapatkan kredensial. Gunakan mekanisme cache untuk mengawal kekerapan panggilan dan elakkan daripada dikenakan had kadar oleh sistem. |
| expireIn | Long | 7200 | Masa tamat tempoh access token, dalam saat.  **Nota**  Access token sah selama 7,200 saat (2 jam). Permintaan berulang dalam tempoh sah mengembalikan hasil yang sama dan secara automatik melanjutkan tempoh sah. Selepas tamat tempoh, access token baharu akan dikembalikan. |

### Contoh isi respons

HTTP/1.1 200 OK
Content-Type:application/json

{
  "accessToken" : "fw8ef8we8f76e6f7s8dxxxx",
  "expireIn" : 7200
