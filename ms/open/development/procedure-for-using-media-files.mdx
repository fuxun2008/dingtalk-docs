title: "Hantar Notifikasi Kerja selepas memuat naik fail media"
description: "Panduan cara memanggil API storan fail dan notifikasi mesej DingTalk dalam aplikasi dalaman untuk memuat naik fail media dan menghantar Notifikasi Kerja hujung ke hujung."

Dokumen ini menerangkan cara memanggil API storan fail dan notifikasi mesej untuk melaksanakan aliran kerja fail media. Mula-mula, cipta aplikasi dalaman, kemudian gunakan API storan fail dan notifikasi mesej untuk memuat naik fail media dan menghantar Notifikasi Kerja.

## Pengenalan

### Apa yang akan anda pelajari

Tutorial ini menggunakan arahan langkah demi langkah dan contoh untuk membantu pembangun organisasi memuat naik fail media dengan cepat dan menghantar notifikasi kepada pengguna tertentu selepas muat naik berjaya.

### Objektif pembelajaran

Membantu pembangun membina aplikasi mereka sendiri dengan cepat serta menggunakan API asas DingTalk untuk memuat naik lampiran dan menghantar Notifikasi Kerja.

### Khalayak sasaran

Semua pembangun DingTalk.

## Prasyarat

- Anda telah mendapatkan kebenaran pembangun.
- Anda telah memasang IDE atau alat pembangunan lain.
- Anda telah memasang [Node.js](https://nodejs.org/en/download) dan melengkapkan [konfigurasi persekitaran](https://m.runoob.com/nodejs/nodejs-install-setup.html).
- Anda telah memasang [Maven](https://maven.apache.org/) dan melengkapkan [konfigurasi persekitaran](https://maven.apache.org/install.html).
- Anda telah memasang [JDK](https://www.oracle.com/java/technologies/downloads/?er=221886) dan melengkapkan [konfigurasi persekitaran](https://docs.oracle.com/en/java/javase/24/install/overview-jdk-installation.html).

## Aliran kerja pembangunan

1. Gunakan Log masuk senyap untuk mendapatkan nama, peranan, dan maklumat lain pengguna yang sedang log masuk. Untuk maklumat lanjut, lihat Log masuk senyap untuk aplikasi web (aplikasi mikro H5).
2. Panggil API [Muat naik fail media](/open/development/upload-media-files) untuk memuat naik fail tertentu (tutorial ini menggunakan fail tempatan; dalam praktiknya, pembangun boleh menggunakan sebarang fail) dan dapatkan `media_id` fail tersebut (pengecam unik fail).
3. Berdasarkan `media_id`, panggil Server API [Hantar Notifikasi Kerja](/open/development/asynchronous-sending-of-enterprise-session-messages) untuk menghantar Notifikasi Kerja (dokumen ini menyediakan dua jenis mesej: gambar dan tindakan, yang boleh anda tukar dalam kod).

## Langkah 1: Cipta aplikasi

1. Log masuk ke [Developer Backend](https://open-dev.dingtalk.io/#/).
2. Klik **App Development** > **Internal app** > **DingTalk App** > **Create App**.
3. Isikan maklumat aplikasi.

   | **Item** | **Wajib** | **Penerangan** |
   | --- | --- | --- |
   | Nama aplikasi | Ya | Masukkan nama aplikasi. Panjang minimum ialah 2 aksara. |
   | Penerangan aplikasi | Ya | Terangkan secara ringkas produk atau perkhidmatan yang disediakan oleh aplikasi. Panjang minimum ialah 4 aksara. |
   | **Ikon aplikasi** | Tidak | Muat naik ikon aplikasi. Ikon mesti dalam format JPG/PNG, sekurang-kurangnya 240 px \* 240 px, nisbah 1:1, tanpa sudut bulat, dan tidak melebihi 2 MB. |
4. Klik **Save** untuk masuk ke halaman butiran aplikasi. Klik **Basic Information** > **Credentials and Basic Information** untuk melihat Client ID, Client Secret, dan Agent ID aplikasi.

   > Nota: Simpan Client ID, Client Secret, dan Agent ID untuk kegunaan seterusnya.

## Langkah 2: Konfigurasikan aplikasi web

1. Pada halaman butiran aplikasi, klik **App Capabilities** > **Add App Capability**.
2. Pilih Add Web App.
3. Konfigurasikan maklumat aplikasi web (H5):

   | **Item** | **Penerangan** |
   | --- | --- |
   | URL halaman utama aplikasi | Masukkan URL halaman utama aplikasi. Contoh ini menggunakan `http://localhost:5173?corpid=$CORPID$` untuk pengujian seterusnya. Contoh ini hanya untuk pengujian tempatan. |
   | URL halaman utama PC | |
4. Selepas konfigurasi selesai, klik **Save**.

## Langkah 3: Tambah kebenaran API

Kebenaran diberikan secara lalai. Anda tidak perlu memohonnya.

## Langkah 4: Terbitkan aplikasi

1. Selepas mengkonfigurasikan aplikasi, anda perlu menerbitkannya. Pada halaman butiran aplikasi, klik **App Release** > **Version Management and Release**.
2. Klik **Create New Version** untuk masuk ke halaman butiran versi.
3. Konfigurasikan maklumat versi:

   | **Item** | **Penerangan** |
   | --- | --- |
   | Nombor versi aplikasi | Masukkan nombor versi aplikasi. Gunakan versi lalai. |
   | Penerangan versi | Masukkan penerangan untuk versi tersebut. Anda boleh menyesuaikannya. |
   | Kandungan untuk diterbitkan | Ciri aplikasi yang dipaparkan pada Workbench:  - Pilih aplikasi web |

   Selepas konfigurasi selesai, klik Save di bahagian bawah.
4. Dalam kotak dialog yang dipaparkan selepas menyimpan, klik Publish Directly.

   > *Jika anda bukan Admin Organisasi, penerbitan aplikasi memerlukan kelulusan daripada Admin Organisasi. Penerbitan untuk "Visible to me only" tidak memerlukan kelulusan admin.*

## Langkah 5: Bina perkhidmatan

1. Pastikan anda telah melengkapkan langkah-langkah di atas dan mendapatkan parameter yang diperlukan untuk menjalankan demo di bawah.
2. Muat turun demo [file-demo.zip](https://help-static-aliyun-doc.aliyuncs.com/file-manage-files/zh-CN/20250729/qrbdtr/file-demo.zip).
3. Buka IDE anda dan import demo yang telah dimuat turun.

   > Kod contoh dibahagikan kepada `backend` (direktori kod bahagian belakang) dan `frontend` (direktori kod bahagian hadapan).

4. Buka direktori kod bahagian belakang dan ubah suai fail `application.properties` dalam direktori `resources`. Isikan parameter seperti `clientId` (Client ID aplikasi), `clientSecret` (Client Secret aplikasi), `filepath` (laluan mutlak fail untuk dimuat naik), dan `agentId` (Agent ID aplikasi).

5. Klik untuk memulakan perkhidmatan bahagian belakang.

   **Nota**
   - Sebelum memulakan perkhidmatan bahagian belakang, pastikan Maven dan JDK dipasang dengan betul serta persekitaran berkaitan dikonfigurasikan. Jika anda memasang IDE buat kali pertama, anda perlu mengubah suai fail konfigurasi berkaitan dalam IDE.
   - Pastikan port 5173 dan 8080 tidak digunakan oleh proses lain.

6. Buka direktori kod bahagian hadapan dan ubah suai `vite.config.ts` untuk mengisi `clientId` (Client ID aplikasi) yang betul.

7. Klik kanan pada fail projek bahagian hadapan dan pilih **Terminal** untuk membukanya.

8. Dalam tetingkap terminal, jalankan arahan berikut:

   1. `npm install`
   2. `npm run dev`

      > Nota: Pada Windows, gunakan `npm run dev:raw` semasa memulakan.
9. Perkhidmatan bahagian hadapan dan bahagian belakang kini telah berjaya dimulakan.

### Langkah 6: Uji aplikasi

1. Log masuk ke DingTalk Bahagian Klien dan pilih organisasi tempat aplikasi berada.

2. Klik **Workbench** > **Add**, cari aplikasi organisasi yang anda cipta di atas, dan tambahkannya.

3. Buka aplikasi pada Workbench dan klik butang **Upload File** untuk memuat naik fail media.

   > *Saiz fail mesti kurang daripada 50 MB.*
