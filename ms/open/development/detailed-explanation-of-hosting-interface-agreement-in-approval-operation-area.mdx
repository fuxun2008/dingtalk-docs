## Gambaran keseluruhan kawasan tindakan kelulusan

Kawasan tindakan kelulusan terletak di bahagian bawah halaman butiran kelulusan dan mengandungi butang tindakan. Dalam contoh ini, kawasan tersebut mengandungi **Komen**, **Cipta perbincangan kumpulan**, **Padam**, **Kembali ke borang asal**, **Tolak** dan **Luluskan**. Aplikasi pihak ketiga boleh menyesuaikan butang dalam kawasan ini.

## Cara kawasan tindakan kelulusan berfungsi

Semasa mencipta templat kelulusan atau instans kelulusan, aplikasi pihak ketiga boleh mendaftarkan callback untuk memaparkan butang tersuai dalam kawasan tindakan kelulusan dan menghantar permintaan. Aplikasi perlu menyediakan dua API, iaitu satu untuk pemaparan yang dihoskan dan satu untuk memproses permintaan pengguna:

- **Pemaparan butang:** DingTalk memanggil semula aplikasi pihak ketiga untuk mendapatkan definisi butang bagi kawasan tindakan.
- **Operasi kelulusan:** DingTalk memanggil semula API pihak ketiga untuk menerima dan memproses tindakan kelulusan yang dihantar oleh pengguna.

Aliran integrasi bermula daripada **Aplikasi pihak ketiga** ke **Backend kelulusan: OA Open API**, kemudian ke **Frontend kelulusan**. Frontend kelulusan memaparkan hasilnya pada tiga permukaan: **To-Do**, **Pusat Kelulusan** dan **Kad interaktif IM**. Aplikasi pihak ketiga melengkapkan langkah berikut mengikut urutan:

1. Cipta templat
2. Cipta instans
3. Daftarkan callback Butang pemaparan tersuai & Hantar permintaan bagi kawasan tindakan kelulusan
4. Cipta tugasan

Semasa pemaparan dan penghantaran, Frontend kelulusan memanggil aplikasi pihak ketiga melalui **callback SPI (pemaparan / operasi kelulusan)**. **Backend kelulusan: Open gateway** menghalakan callback ini. Permukaan **To-Do** dan **Kad interaktif IM** mencetuskan callback operasi kelulusan.

## Definisi model teras

- **ProcessFeatureConfig: Konfigurasi integrasi Pusat Proses**

  Dalam mod integrasi Pusat Proses, konfigurasi ini membolehkan aplikasi pihak ketiga mentakrifkan logik tersuai bagi modul ciri perniagaan tertentu. Penyelesaian pengehosan halaman kelulusan dibina berdasarkan konfigurasi ini. Aplikasi pihak ketiga boleh menyesuaikan setiap butang dalam kawasan tindakan kelulusan pada halaman butiran. Konfigurasikan dua API callback tambahan:

  - CUSTOM_ACTION_DEFINITION: DingTalk memanggil semula aplikasi pihak ketiga untuk mendapatkan definisi butang bagi kawasan tindakan (pemaparan butang).
  - CUSTOM_ACTION_APPLY: DingTalk memanggil semula API pihak ketiga untuk menerima dan memproses tindakan kelulusan yang dihantar oleh pengguna (operasi kelulusan).

  ```text
  "featureConfig":{
    "features":  [
      {
        // URL callback untuk mendapatkan data kawasan tindakan (butang) (pemaparan butang)
        "name":"CUSTOM_ACTION_DEFINITION",  
        "runType":"OUTBIZ_CUSTOM",
        "callback":{
          "apiKey":"customActionDefinitionApiKey",
          "appUuid":"appUuid",
          "version":"1"
        }
      },
      {
        // URL callback yang dipanggil apabila tindakan kelulusan dilaksanakan (operasi kelulusan)
        "name":"CUSTOM_ACTION_APPLY",  
        "runType":"OUTBIZ_CUSTOM",
        "callback":{
          "apiKey":"customActionApplyApiKey",
          "appUuid":"appUuid",
          "version":"1"
        }
      }
    ]
  }
  ```

    - ##### **Butang umum**

      Platform pengehosan halaman butiran borang Kelulusan OA DingTalk menyediakan butang ini secara lalai. Gunakannya secara terus. Pihak yang berintegrasi tidak perlu mengembalikan sebarang data untuk butang ini. Pelaksanaan lalai mentakrifkan interaksinya. Pihak perniagaan boleh mengkonfigurasikan sama ada setiap butang dipaparkan.

      |  |  |  |  |
      | --- | --- | --- | --- |
      | ID butang [actionType] | Keupayaan | Jenis interaksi | Penerangan |

      | INSTANCE_DOWNLOAD | Muat turun borang kelulusan. DingTalk menghantar fail melalui Notifikasi Kerja. | Klik untuk menjalankan callback dan memaparkan prompt. | Pelaksanaan lalai mentakrifkan interaksi. Pihak perniagaan boleh mengkonfigurasikan sama ada butang dipaparkan. |
      | INSTANCE_PRINT | Cetak borang kelulusan | Klik untuk membuka kumpulan butang. | Pelaksanaan lalai mentakrifkan interaksi. Pihak perniagaan boleh mengkonfigurasikan sama ada butang dipaparkan. |
      | INSTANCE_DING | Peringatan: pemohon proses kelulusan menghantar peringatan kepada penyokong nod semasa | Klik untuk membuka komponen DING. | Pelaksanaan lalai mentakrifkan interaksi. Pihak perniagaan boleh mengkonfigurasikan sama ada butang dipaparkan. |
      | INSTANCE_IM_GROUP | Cipta perbincangan kumpulan berdasarkan instans | Klik untuk membuka pemilih pengguna. Dialog pengesahan dipaparkan selepas pemilihan. | Pelaksanaan lalai mentakrifkan interaksi. Pihak perniagaan boleh mengkonfigurasikan sama ada butang dipaparkan. |
      | INSTANCE_COMMENT | Beri komen pada borang kelulusan | Klik untuk membuka dialog pengesahan komen. | Pelaksanaan lalai mentakrifkan interaksi. Pihak perniagaan boleh mengkonfigurasikan sama ada butang dipaparkan. |
    - ##### **Butang pratakrif**

      Pengehosan borang mempratetapkan butang tindakan kelulusan ini dan melaksanakan mekanisme interaksi biasa untuknya secara automatik. Pihak perniagaan menghantar butang ini mengikut keperluan, berdasarkan proses dan pengguna semasa. Pihak yang berintegrasi melaksanakan keupayaan sebenar, jadi tingkah laku mungkin berbeza sedikit antara enjin proses.

      |  |  |  |
      | --- | --- | --- |
      | ID butang [actionType] | Keupayaan | Penerangan |
      | TASK_APPROVE | Terima tugasan kelulusan | Interaksi tetap. Teks butang dan logik callback boleh disesuaikan. |
      | TASK_REJECT | Tolak tugasan kelulusan | Interaksi tetap. Teks butang dan logik callback boleh disesuaikan. |
      | TASK_FORWARD | Serahkan tugasan kelulusan | Interaksi tetap. Teks butang, senarai pengguna yang boleh dipilih dan logik callback boleh disesuaikan. |
      | TASK_APPEND | Tandatangani permintaan | Interaksi tetap. Teks butang, penyokong yang boleh dipilih untuk Tandatangani permintaan, kaedah Tandatangani permintaan dan logik callback boleh disesuaikan. |
      | INSTANCE_REVERT | Kembalikan | Interaksi tetap. Teks butang, senarai nod untuk dikembalikan dan logik callback boleh disesuaikan. |
      | INSTANCE_MODIFY | Ubah suai borang kelulusan | Interaksi tetap. Teks butang, keadaan dikelabukan, sebab dikelabukan dan sifat yang serupa boleh disesuaikan. |
      | INSTANCE_TERMINATE | Buat asal borang kelulusan | Interaksi tetap. Teks butang, teks prompt pengesahan dan logik callback boleh disesuaikan. |
      | INSTANCE_DELETE | Padam borang kelulusan | Interaksi tetap. Teks butang, teks prompt pengesahan dan logik callback boleh disesuaikan. |
      | INSTANCE_EXTERNAL_DETAIL | Kembali ke borang asal: memaparkan butang pada halaman butiran kelulusan yang membuka halaman butiran luaran | Interaksi tetap. Teks butang dan keterlihatan boleh disesuaikan. |
    - ##### **Butang perniagaan tersuai**

      Sistem pihak ketiga yang berintegrasi mentakrifkan butang ini. Gunakan konfigurasi ringkas untuk memberikan gaya yang serupa dengan butang pratakrif. Apabila pengguna mengklik salah satu butang ini, DingTalk memanggil semula sistem pihak yang berintegrasi melalui API operasi kelulusan. Sistem tersebut kemudian menjalankan logik tindakan tersuai.

      |  |  |  |  |
      | --- | --- | --- | --- |
      | ID butang [actionType] | Keupayaan | Jenis interaksi | Penerangan |
      | CUSTOM_ACTION_xxx | Butang perniagaan tersuai | Jenis interaksi standard yang disokong oleh platform:  - link: ubah hala secara terus - confirm: dialog pengesahan - modal: buka dialog (pihak perniagaan boleh menyesuaikan komponen dalam dialog) | Tidak boleh sama dengan mana-mana ID yang dikhaskan oleh platform pengehosan. |
  - **Peraturan pengisihan dan pemaparan butang**

    Secara lalai, platform pengehosan mengisih dan memformat butang yang dihantar oleh pihak yang berintegrasi.

    - Platform pengehosan menyemak sama ada butang umum perlu ditambah dan menambahnya jika perlu.
    - DingTalk memanggil semula aplikasi pihak ketiga untuk mendapatkan definisi butang bagi kawasan tindakan (pemaparan butang). DingTalk kemudian memaparkan butang berdasarkan data yang dikembalikan. Jika callback mengembalikan ralat, DingTalk kembali menggunakan butang sedia ada penyelesaian pengehosan ORIGIN: Kongsi, Muat turun, Cetak, Terima, Tolak, Komen, Cipta perbincangan kumpulan, Padam dan Kembali ke borang asal.
    - Pengisihan semua butang:

      - Butang umum dipaparkan dahulu, dalam susunan tetap.
      - Butang pratakrif dan butang tersuai menyusul, mengikut susunan ia dihantar.

## Contoh langkah integrasi

### Langkah 1: Daftarkan callback butang tindakan tersuai

1. Daftarkan callback untuk butang tindakan kelulusan tersuai, seperti dalam contoh berikut.

   ```json
   {
     // URL callback untuk mendapatkan data kawasan tindakan (butang) (pemaparan butang)
     "name": "CUSTOM_ACTION_DEFINITION",
     "runType": "OUTBIZ_CUSTOM",
     "callback": {
       "apiKey": "getIntegratedCustomActionDefinitions",
       "appUuid": "dingecxxxx97fcb1e09",
       "version": "1"
     }
   },
   {
     // URL callback yang dipanggil apabila tindakan kelulusan dilaksanakan (operasi kelulusan)
     "name": "CUSTOM_ACTION_APPLY",
     "runType": "OUTBIZ_CUSTOM",
     "callback": {
       "apiKey": "applxxxxction",
       "appUuid": "dingecxxxxb1e09",
       "version": "1"
     }
   }
   ```
2. Pusat Proses mendapatkan senarai butang tersuai bagi kawasan tindakan kelulusan.

   - apiKey: getIntegratedCustomActionDefinitions
   - URL: https://connector.dingtalk.io/webhook/flow/d8c375d76acb7eb01019fe0b
   - Parameter: corpId,processInstanceId,activityId,taskId,operator,platform,locale,context,customData
   - apiSecret: getIntegratedCustomActionDefinitions

### Langkah 5: Kemas kini status tugasan kelulusan Pusat Proses

**Terima atau tolak tugasan kelulusan dengan logik tersuai:** Penyokong membuka halaman kelulusan tersuai dalam DingTalk dan memilih tindakan seperti Terima atau Tolak. DingTalk kemudian memanggil API callback yang dikonfigurasi dalam modul `CUSTOM_ACTION_APPLY` bagi Simpan templat kelulusan integrasi luaran Pusat Proses. Selepas aplikasi pihak ketiga menjalankan logik perniagaannya, aplikasi tersebut mesti menyegerakkan status tugasan ke DingTalk. Untuk mengemas kini status item To-Do kelulusannya sendiri, panggil API [Kemas kini status tugasan Pusat Proses](/ms/open/development/update-process-center-task-status) dengan ID instans kelulusan `processInstanceId` dan ID tugasan To-Do kelulusan `taskId`.

Dalam senario seperti tandatangan ATAU (OR-sign), panggil API [Batalkan berbilang tugasan belum selesai Pusat Proses](/ms/open/development/cancel-multiple-oa-approval-tasks). API ini menetapkan semua item To-Do yang sedang berjalan di bawah sesuatu instans kelulusan kepada CANCELED dalam satu kelompok.

```json
{
  "processInstanceId": "qZpLKAxxxx43810",
  "tasks": [
    {
      "taskId": 88094338042,
      "status": "COMPLETED",
      "result": "AGREE"
    }
  ]
}
```
