# Tetapkan ahli kehadiran: Penambahan pukal dan pengurusan yang tepat

## Gambaran keseluruhan

### Latar belakang

Organisasi sentiasa berubah. Pekerja menyertai organisasi, meninggalkannya, bertukar peranan atau berpindah jabatan. Setiap perubahan memerlukan HR atau Admin mengemas kini ahli kumpulan kehadiran satu demi satu dalam Admin Console DingTalk. Pekerja baharu perlu ditambah ke kumpulan kehadiran, pekerja yang berhenti perlu dikeluarkan dan pekerja yang dipindahkan perlu dialihkan ke kumpulan kehadiran lain. Organisasi dengan 1,000 pekerja atau lebih mungkin mengalami berpuluh hingga beratus perubahan setiap bulan. Kemas kini manual mengambil banyak masa dan tenaga. Ia juga menyebabkan keciciran dan kesilapan. Akibatnya, berlaku ralat daftar masuk dan data kehadiran menjadi tidak tepat.

### Faedah utama

Penyelesaian ini mengautomasikan keseluruhan kitaran hayat ahli kumpulan kehadiran. Operasi manual seperti penambahan pukal, pertanyaan, kemas kini dan pemadaman ditukar menjadi operasi standard yang dipacu API. Hasilnya, operasi sistem HR menjadi lebih cekap dan data kekal konsisten.

- **Pengurusan ahli pukal secara automatik**: Tambah, semak, kemas kini dan padam ahli melalui API tanpa campur tangan manual.
- **Pemilihan API yang tepat**: Pilih API pertanyaan yang paling sesuai untuk ahli individu, jabatan atau gabungan bagi mendapatkan data yang lengkap dan tepat.
- **Pengesahan masa nyata**: Semak sama ada pengguna milik kumpulan kehadiran tertentu. Sahkan hasil sejurus selepas setiap kemas kini untuk memastikan data kekal konsisten.
- **Data rentas sistem yang seragam**: Segerakkan data ahli kumpulan kehadiran secara masa nyata antara sistem HR, sistem OA dan DingTalk untuk menghapuskan silo data.

### Kes penggunaan

Penyelesaian ini sesuai untuk senario perniagaan biasa berikut:

- **Kemasukan pekerja baharu**: Selepas HR memasukkan pekerja baharu dalam sistem HR, tambah pekerja tersebut secara automatik ke kumpulan kehadiran jabatan yang berkaitan.
- **Pekerja berhenti**: Selepas kelulusan peletakan jawatan OA diluluskan, keluarkan pekerja daripada semua kumpulan kehadiran secara automatik.
- **Pertukaran peranan**: Apabila pekerja dipindahkan, keluarkan pekerja daripada kumpulan kehadiran asal dan tambahkannya ke kumpulan kehadiran jabatan baharu secara automatik.
- **Pelarasan ahli secara pukal**: Selepas Struktur Organisasi berubah, kemas kini senarai ahli beberapa kumpulan kehadiran secara pukal.

## Senario perniagaan biasa

### Senario 1: Tambah pekerja baharu ke kumpulan kehadiran secara automatik

#### Masalah utama

Dalam proses tradisional, HR perlu log masuk ke Admin Console DingTalk pada hari pertama setiap pekerja baharu, mencari kumpulan kehadiran jabatan yang berkaitan dan menambah setiap pekerja baharu secara manual. Jika 5 hingga 10 pekerja menyertai organisasi setiap hari, HR perlu mengulangi tugas ini berkali-kali. Keciciran atau pemilihan kumpulan yang salah sering berlaku, dan pekerja baharu tidak dapat mendaftar masuk seperti yang dijangka.

#### Nilai

- **Aliran automatik**

  Aliran automatik dijalankan dalam lima langkah:

  1. HR memasukkan rekod **Pekerja** baharu (nama, **Jabatan**, jawatan).
  2. Padankan **kumpulan kehadiran** sasaran berdasarkan ID jabatan pekerja dan dapatkan **groupKey** kumpulan tersebut.
  3. Panggil API **batch-add-employees** untuk menambah **userId** pekerja baharu ke **kumpulan kehadiran**.
  4. Panggil API **query-members-by-id** untuk mengesahkan bahawa pekerja berjaya ditambah.
  5. Kebenaran **daftar masuk** berkuat kuasa pada hari yang sama dan rekod kehadiran bermula.
- **Kelebihan utama**

  - **Pencetus automatik sepenuhnya**: Selepas HR memasukkan pekerja baharu, sistem HR memanggil API untuk menambah pekerja tersebut ke kumpulan kehadiran. Tiada tindakan manual diperlukan.
  - **Padanan tepat**: Sistem memadankan kumpulan kehadiran dengan jabatan pekerja secara automatik untuk mengelakkan pemilihan yang salah.
  - **Berkuat kuasa serta-merta**: Sistem mengesahkan hasil sejurus selepas penambahan, jadi pekerja baharu boleh mendaftar masuk pada hari pertama.
  - **Jejak audit**: Setiap tindakan merekodkan operator, cap masa dan ID kumpulan kehadiran untuk memenuhi keperluan pematuhan.

### Senario 2: Keluarkan pekerja yang berhenti daripada kumpulan kehadiran secara automatik

#### Masalah utama

Apabila pekerja berhenti, HR perlu mengeluarkan pekerja tersebut secara manual daripada setiap kumpulan kehadiran yang berkaitan. Jika pekerja menjadi ahli beberapa kumpulan kehadiran (contohnya, jabatan utama dan pasukan projek), pengeluaran manual mudah tercicir. Pekerja yang telah berhenti mungkin masih boleh mendaftar masuk. Data kehadiran menjadi tidak tepat dan pengiraan gaji mungkin salah.

#### Nilai

- **Aliran automatik**

  Aliran automatik dijalankan dalam lima langkah:

  1. Permohonan peletakan jawatan dalam **Kelulusan OA** diluluskan, dan sistem menangkap peristiwa tersebut untuk mencetuskan Automasi.
  2. Panggil API **queries-a-user-attendance-group** untuk mendapatkan ID semua kumpulan kehadiran yang dimiliki oleh Pekerja.
  3. Ulangi setiap kumpulan tersebut dan panggil API **batch-delete-employees** untuk mengeluarkan Pekerja secara pukal.
  4. Panggil API **query-members-by-id** untuk mengesahkan satu demi satu bahawa Pekerja telah dikeluarkan daripada setiap kumpulan kehadiran.
  5. Kebenaran daftar masuk Pekerja ditarik balik dan rekod kehadiran dihentikan.
- **Kelebihan utama**

  - **Pencetus automatik sepenuhnya**: Selepas kelulusan peletakan jawatan OA diluluskan, proses pengeluaran berjalan secara automatik tanpa campur tangan manual.
  - **Liputan menyeluruh**: Semak dan keluarkan pekerja daripada semua kumpulan kehadiran dalam satu proses untuk mengelakkan keciciran.
  - **Berkuat kuasa serta-merta**: Sistem mengesahkan hasil sejurus selepas pengeluaran, jadi pekerja yang telah berhenti tidak lagi boleh mendaftar masuk.
  - **Log audit yang lengkap**: Setiap pengeluaran merekodkan maklumat terperinci untuk memenuhi keperluan audit pematuhan dan kebolehkesanan.

## Panduan pelaksanaan

### Seni bina teknikal

Penyelesaian ini dibina berasaskan Server API DingTalk Open Platform. Komponen teknikal teras termasuk:

- **Lapisan pengesahan**: Dapatkan `access_token` menggunakan `Client ID` dan `Client Secret` anda untuk melindungi panggilan API.
- **Lapisan pengurusan ahli**: Menyediakan keupayaan API yang lengkap untuk menambah, menyemak, mengemas kini dan memadam ahli kumpulan kehadiran secara pukal.
- **Lapisan penghalaan pintar**: Memilih API pertanyaan terbaik berdasarkan jenis ahli (individu, jabatan atau gabungan) untuk mendapatkan data yang lengkap.
- **Lapisan pengendalian ralat**: Sistem kod ralat yang lengkap dan mekanisme cuba semula membantu anda mengenal pasti dan menyelesaikan isu dengan pantas.

**Nota versi API**: Server API mempunyai versi baharu dan versi lama. Utamakan versi baharu untuk prestasi dan sokongan ciri yang lebih baik.

### Prasyarat

Sebelum bermula, pastikan syarat berikut dipenuhi:

- **Persediaan aplikasi**: Cipta dan konfigurasikan Aplikasi dalaman. Untuk butiran, lihat [Cipta dan konfigurasikan aplikasi](/ms/open/dingstart/create-application).
- **Kebenaran**: Anda mempunyai kebenaran Admin Organisasi atau Sub Admin DingTalk, dan anda telah memohon kebenaran API berikut:

  - `qyapi_attendance_group_manage` (kebenaran pengurusan kumpulan kehadiran)
  - `qyapi_attendance_group_read` (kebenaran membaca kumpulan kehadiran)
- **Persekitaran pembangunan**: Persekitaran pembangunan Java (JDK 1.6 atau lebih baharu) dan alat binaan Maven telah dipasang.
- **SDK**: Muat turun SDK Bahagian pelayan DingTalk. Untuk butiran, lihat Muat turun SDK Bahagian pelayan. SDK menyokong pelbagai bahasa, termasuk Java, Python dan Go.

Langkah 1: Dapatkan Kelayakan aplikasi, termasuk client ID dan Client Secret.

Langkah 2: Mohon kebenaran API `qyapi_attendance_group_manage` dan `qyapi_attendance_group_read`.

Langkah 3: Dapatkan Kredensial akses. Untuk butiran, lihat [Dapatkan access_token Aplikasi dalaman](/ms/open/development/obtain-orgapp-token). Apabila anda memanggil API, access token mengesahkan identiti pemanggil.

Langkah 4: Panggil API kehadiran:

1. Panggil Server API [Tambah ahli kehadiran secara pukal](/ms/open/development/batch-add-employees-under-the-attendance-group) untuk menambah ahli kehadiran ke kumpulan kehadiran.
2. Panggil Server API [Dapatkan kumpulan kehadiran pengguna](/ms/open/development/queries-a-user-attendance-group) untuk mendapatkan maklumat kumpulan kehadiran yang dimiliki oleh pengguna.
3. Dapatkan maklumat ahli kehadiran bagi kumpulan kehadiran:

   - Panggil Server API [Dapatkan ID pengguna ahli kehadiran](/ms/open/development/query-attendance-group-personnel-information-in-batches) untuk mendapatkan ID pengguna ahli kehadiran.
   - Panggil Server API [Dapatkan ahli kehadiran](/ms/open/development/batch-query-of-attendance-group-members) untuk mendapatkan maklumat ahli kehadiran.
   - Panggil Server API [Semak senarai ahli kehadiran](/ms/open/development/batch-query-of-employees-in-the-attendance-group) untuk mendapatkan senarai ahli kehadiran.
4. Panggil Server API [Semak sama ada pengguna berada dalam kumpulan kehadiran](/ms/open/development/query-members-by-id) untuk menyemak sama ada jabatan atau pekerja milik kumpulan kehadiran.
5. Panggil Server API [Kemas kini ahli kehadiran](/ms/open/development/attendance-group-member-update) untuk mengemas kini ahli kehadiran bagi kumpulan kehadiran.
6. Panggil Server API [Padam ahli kehadiran secara pukal](/ms/open/development/batch-delete-employees-under-the-attendance-group) untuk memadam ahli kehadiran.

## Langkah pelaksanaan

### **Langkah 1: Dapatkan Kelayakan aplikasi**

1. Log masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.io/).
2. Pilih aplikasi sasaran untuk membuka halaman butirannya.
3. Klik **Maklumat Asas** > **Kelayakan dan Maklumat Asas**.
4. Rekodkan `Client ID` dan `Client Secret` aplikasi.

### Nota

   Simpan `Client Secret` anda dengan selamat dan jangan sekali-kali kongsikannya dengan pihak ketiga. Simpan dalam pemboleh ubah persekitaran atau sistem pengurusan kunci, bukan dikodkan terus dalam kod.

### Langkah 2: Tambah kebenaran API

1. Pada halaman butiran aplikasi, klik **Urus kebenaran**.
2. Masukkan pengecam kebenaran berikut dalam kotak carian kebenaran dan mohon kebenaran tersebut:

   - `qyapi_attendance_group_manage` (kebenaran pengurusan kumpulan kehadiran): Cipta, kemas kini dan padam kumpulan kehadiran.
   - `qyapi_attendance_group_read` (kebenaran pertanyaan kumpulan kehadiran): Semak ringkasan dan butiran kumpulan kehadiran.

<Note>
Senario perniagaan yang berbeza mungkin memerlukan gabungan kebenaran yang berbeza. Mohon kebenaran mengikut keperluan sebenar anda. Contohnya, senario import pukal turut memerlukan kebenaran untuk operasi pengguna secara pukal.
</Note>

### Langkah 3: Dapatkan Kredensial akses (access_token)

Gunakan Client ID dan Client Secret daripada Langkah 1 untuk mendapatkan Kredensial akses. Untuk butiran, lihat [Dapatkan access_token Aplikasi dalaman](/ms/open/development/obtain-orgapp-token).

```java
public void getAccessToken() throws ApiException {
  DingTalkClient client = new DefaultDingTalkClient("https://oapi.dingtalk.io/gettoken");
  OapiGettokenRequest req = new OapiGettokenRequest();
  req.setAppkey("dingxxxxxxxxxhgn");
  req.setAppsecret("9G_xxxxxxxxxxxxxxx1JDf0Qq3nexxxxxxxxGIO");
  req.setHttpMethod("GET");
  OapiGettokenResponse rsp = client.execute(req);
  System.out.println(rsp.getBody());
}
```

**Amalan terbaik**:

- **Cache**: `access_token` sah selama 2 jam. Simpan dalam cache memori atau Redis, dan muat semula 5 minit sebelumnya tamat tempoh.
- **Kawalan keserentakan**: Elakkan konflik akibat beberapa thread memuat semula token pada masa yang sama. Gunakan kunci teragih (distributed lock).
- **Cuba semula apabila ralat**: Cuba semula secara automatik semasa rangkaian tidak stabil, sehingga 3 kali, dengan selang yang semakin meningkat (1s → 2s → 4s).

## Soalan lazim

- **S1: Apakah perbezaan antara tiga API pertanyaan ahli?**

  J: Setiap API sesuai untuk senario jenis ahli yang berbeza:

  - [Dapatkan ID pengguna ahli kehadiran](/ms/open/development/query-attendance-group-personnel-information-in-batches): Hanya mengembalikan senarai ID pengguna. Gunakan API ini apabila anda hanya perlu menyemak sama ada ahli wujud dalam kumpulan kehadiran.
  - [Dapatkan ahli kehadiran](/ms/open/development/batch-query-of-attendance-group-members): Mengembalikan maklumat terperinci ahli (nama, jabatan dan lain-lain). Gunakan API ini apabila anda perlu memaparkan butiran ahli.
  - [Semak senarai ahli kehadiran](/ms/open/development/batch-query-of-employees-in-the-attendance-group): Menyokong pertanyaan dengan penomboran halaman. Gunakan API ini untuk mendapatkan ahli secara berkelompok apabila kumpulan kehadiran mempunyai ramai ahli.

  Apabila kumpulan kehadiran menyertakan ahli jabatan, ambil perhatian perkara berikut: pertanyaan menggunakan ID pengguna individu mengembalikan maklumat pekerja tersebut. Pertanyaan menggunakan ID jabatan tidak mengembalikan butiran pekerja dalam jabatan tersebut secara langsung. Panggil API pertanyaan ahli jabatan secara berasingan.
- **S2: Bagaimanakah cara mengendalikan kegagalan separa semasa menambah ahli secara pukal?**

  J: API tambah pukal menggunakan strategi "usaha terbaik" dan mengembalikan ahli yang berjaya dan gagal secara berasingan. Ikuti langkah berikut:

  1. Hurai respons untuk mendapatkan ID pengguna ahli yang gagal dan punca ralat.
  2. Log kegagalan dan analisis puncanya (contohnya, pengguna tidak wujud atau sudah berada dalam kumpulan kehadiran).
  3. Cuba semula ralat yang boleh dipulihkan (contohnya, pengguna yang baru dicipta belum disegerakkan).
  4. Langkau dan log ralat yang tidak boleh dipulihkan (contohnya, pengguna telah meninggalkan organisasi).
- **S3: Bagaimanakah cara memastikan pekerja yang berhenti dikeluarkan sepenuhnya?**

  J: Ikuti langkah berikut untuk memastikan pengeluaran yang lengkap:

  1. Selepas kelulusan peletakan jawatan OA diluluskan, panggil API [Dapatkan kumpulan kehadiran pengguna](/ms/open/development/queries-a-user-attendance-group) untuk mendapatkan ID semua kumpulan kehadiran yang dimiliki oleh pekerja.
  2. Ulangi semua kumpulan kehadiran dan panggil API [Padam ahli kehadiran secara pukal](/ms/open/development/batch-delete-employees-under-the-attendance-group) untuk mengeluarkan pekerja.
  3. Panggil API [Semak sama ada pengguna berada dalam kumpulan kehadiran](/ms/open/development/query-members-by-id) untuk mengesahkan bahawa pekerja telah dikeluarkan daripada semua kumpulan kehadiran.
  4. Log tindakan tersebut, termasuk senarai ID kumpulan kehadiran, masa tindakan dan operator.
