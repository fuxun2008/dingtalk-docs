Topik ini menerangkan jenis dan senario penggunaan pemberitahuan mesej, keupayaan API pemberitahuan mesej, dan cara mengintegrasikan API pemberitahuan mesej.

## Jenis pemberitahuan mesej

### Mesej notifikasi kerja

Mesej pemberitahuan yang di-Push kepada pekerja atas nama aplikasi mikro dalam sembang Notifikasi Kerja sesebuah organisasi. Contohnya termasuk ucapan hari lahir dan peringatan onboarding.

### Hantar notifikasi kerja menggunakan templat

### Penerangan

- Templat mesej hanya disokong oleh aplikasi perusahaan pihak ketiga, bukan oleh aplikasi dalaman.
- Hanya templat mesej yang telah lulus semakan boleh digunakan untuk push mesej notifikasi kerja.

- Templat **Markdown**

  Templat Markdown mengkonfigurasikan dan menghantar mesej menggunakan sintaks Markdown. Ia sesuai untuk mesej notifikasi tulen yang tidak memerlukan sebarang tindakan. Templat Markdown menyokong teks, imej, pautan, dan format paparan lain dengan mudah.
- Templat **ActionCard**

  Templat ActionCard menghantar mesej menggunakan jenis mesej ActionCard. Ia menyokong mesej yang menggabungkan kandungan dengan titik tindakan, sesuai untuk senario di mana penerima perlu memproses mesej dengan cepat melalui satu atau beberapa titik tindakan.

  Dibina berdasarkan templat Markdown, templat ActionCard menyokong kedua-dua gaya lompat keseluruhan dan lompat individu.
- Templat **Borang**

  Templat Borang menghantar mesej berdasarkan jenis mesej OA. Ia sesuai untuk memaparkan mesej seperti pesanan, dan menyokong lompat untuk melihat butiran mesej.

### Aliran integrasi

Seperti yang ditunjukkan dalam rajah berikut, menghantar notifikasi kerja menggunakan templat mesej memerlukan langkah-langkah berikut:

1. Cipta dan konfigurasikan templat mesej. Untuk maklumat lanjut, lihat Urus templat mesej.
2. Hantar templat untuk semakan.
3. Panggil API untuk menghantar notifikasi kerja menggunakan templat. Untuk maklumat lanjut, lihat [Hantar mesej notifikasi kerja menggunakan templat](/open/development/work-notification-templating-send-notification-interface).

## Gambaran keseluruhan keupayaan terbuka

Pemberitahuan mesej menyediakan pelbagai keupayaan API terbuka yang lengkap. Pembangun boleh menggunakan API untuk mengintegrasikan pemberitahuan mesej dengan sistem perniagaan organisasi.

| **API** | **Penerangan** | **Versi** |
| --- | --- | --- |
| [Hantar notifikasi kerja](/open/development/asynchronous-sending-of-enterprise-session-messages) | Menghantar mesej notifikasi kerja. | Legacy |
| [Kemas kini bar status notifikasi kerja](/open/development/update-work-notification-status-bar) | Mengemas kini status mesej notifikasi kerja OA. | Legacy |
| [Dapatkan kemajuan penghantaran mesej notifikasi kerja](/open/development/obtain-the-sending-progress-of-asynchronous-sending-of-enterprise-session) | Mendapatkan kemajuan penghantaran mesej notifikasi kerja. | Legacy |
| [Dapatkan hasil penghantaran mesej notifikasi kerja](/open/development/gets-the-result-of-sending-messages-asynchronously-to-the-enterprise) | Menanyakan hasil penghantaran mesej notifikasi kerja. | Legacy |
| Tarik Balik mesej notifikasi kerja | Menarik balik mesej notifikasi kerja. | Legacy |
| [Hantar mesej notifikasi kerja menggunakan templat](/open/development/work-notification-templating-send-notification-interface) | Menghantar notifikasi kerja menggunakan templat mesej. | Legacy |

## Glosari

### task_id

`task_id` ialah medan pengecam unik untuk mesej notifikasi kerja. Ia dikembalikan apabila anda memanggil API [Hantar notifikasi kerja](/open/development/asynchronous-sending-of-enterprise-session-messages).

Anda boleh menggunakan `task_id` untuk memanggil API [Dapatkan kemajuan penghantaran mesej notifikasi kerja](/open/development/obtain-the-sending-progress-of-asynchronous-sending-of-enterprise-session) dan API [Dapatkan hasil penghantaran mesej notifikasi kerja](/open/development/gets-the-result-of-sending-messages-asynchronously-to-the-enterprise) untuk menanyakan kemajuan dan hasil penghantaran mesej notifikasi kerja.
