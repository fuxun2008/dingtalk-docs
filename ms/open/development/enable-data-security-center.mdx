## **Maklumat Latar Belakang**

Data Security Center menyediakan keupayaan seperti pengenalpastian automatik data sensitif, pengelasan dan penggredan, pengauditan keselamatan data besar, dan penyamaran data. Ia menawarkan penyelesaian bersepadu merentasi domain penuh untuk pencegahan kebocoran data dan keselamatan di awan.

## **Prosedur**

1. Pada halaman produk [Data Security Center](https://www.aliyun.com/product/sddp?spm=ding_open_doc.document.0.0.784366c71seamX), klik **Beli Sekarang** untuk membuka halaman pembelian.
2. Tetapkan spesifikasi versi pada halaman pembelian:

   - [Wajib] Jenis Produk: Pilih **Data Security Center (Data Discovery, Classification and Grading, Masking, and Leak Prevention)**.
   - [Wajib] Versi: Pilih pelan **Asas**. Anda boleh memilih pelan **Business** bertahap lebih tinggi berdasarkan keperluan keselamatan anda.
   - [Wajib] Pengurusan Pangkalan Data: Anda mesti memilih **Aktif**.
   - [Wajib] Nombor Instans Pangkalan Data: Beli berdasarkan nombor sebenar instans pangkalan data yang menyimpan data DingTalk. Beli sekurang-kurangnya 1. Jika data yang diperoleh daripada DingTalk disimpan dalam 2 instans pangkalan data, beli 2.
   - [Pilihan] Pengurusan Data OSS: Jika **tiada fail sensitif disimpan**, anda boleh memilih **Tutup**. Jika fail sensitif seperti **gambar kad pengenalan atau hamparan senarai pengguna** disimpan, kami mengesyorkan anda memilih **Aktif** dan membeli berdasarkan penggunaan. Item ini adalah pilihan.
   - [Wajib] Tempoh Langganan: Pilih sekurang-kurangnya **1 tahun** dan pilih **Perbaharui Automatik selepas Tamat Tempoh**.

   **Penting**
   - Data Security Center menyokong pengenalpastian dan perlindungan produk data di wilayah domestik berikut: Hangzhou, Shanghai, Beijing, Shenzhen, Zhangjiakou, Hohhot, dan Qingdao. Pastikan instans pangkalan data anda dibeli dalam wilayah ini.

3. Selepas pembelian selesai, pergi ke konsol Data Security Center dan gunakan [Panduan Konfigurasi](https://yundun.console.aliyun.com/?spm=ding_open_doc.document.0.0.784366c71seamX&p=sddp#/taskGuide/WorkBench) untuk mengkonfigurasikannya.
4. Klik **Segerak** untuk menyegerakkan aset di awan secara automatik ke Data Security Center.

5. Untuk kebenaran aset, klik **Pergi ke Konfigurasi** untuk membuka halaman konfigurasi aset.

6. Pilih data berstruktur, dan konfigurasikan kebenaran untuk instans pangkalan data yang menyimpan data yang diperoleh daripada platform DingTalk (ditolak melalui RDS atau dipanggil melalui OpenAPI). Anda tidak perlu mengkonfigurasikan kebenaran untuk instans yang menyimpan data yang dikumpul oleh aplikasi perniagaan anda sendiri yang bukan di DingTalk.

   **Nota**

   Konfigurasi kebenaran adalah perlahan apabila terdapat banyak pangkalan data. Kami mengesyorkan anda menetapkan tidak lebih daripada 20 pangkalan data bagi setiap instans.

7. Selepas anda melengkapkan konfigurasi kebenaran, dalam lajur Tindakan di sebelah kanan instans yang diberi kebenaran, klik **Sambung Satu Klik** untuk mengikat aset yang diberi kebenaran.

8. Klik **Penyusunan Data** > **Konfigurasi Pengenalpastian**:

   - Konfigurasi Templat: Gunakan **templat pengelasan dan penggredan keselamatan terbina dalam Alibaba Group dan Ant Group**.
   - Butiran Templat: Tetapkan konfigurasi peraturan kepada keadaan **Aktif**.

## **Soalan Lazim**

1. Bagaimanakah kaedah penggunaan VPC + Data Security Center + Compute Nest melindungi data peribadi DingTalk? Bagaimanakah ia menghalang penyedia perkhidmatan daripada mengeksport data peribadi dalaman DingTalk?

   Jawapan:

   - Compute Nest boleh mengesan risiko keselamatan. Ia menolak amaran untuk konfigurasi berisiko tinggi, kelemahan, atau pencerobohan penggodam.
   - Data Security Center mengenal pasti data sensitif yang disimpan serta mengaudit dan memberi amaran terhadap operasi yang disyaki kebocoran data, seperti eksport data secara berkelompok.
2. Adakah Data Security Center mengubah data asal dalam pangkalan data?

   Jawapan: Tidak.
3. Adakah Data Security Center memintas dan menyamarkan data yang ditanya atau data yang sedang ditulis ke pangkalan data?

   Jawapan: Tidak. Versi yang disyorkan pada masa ini hanya mengenal pasti data sensitif. Ia tidak memproses data tersebut dan tidak menjejaskan perniagaan anda.
4. Bagaimanakah Data Security Center memantau pangkalan data?

   Jawapan:

   - Pemantauan adalah berdasarkan kebenaran. Data sensitif hanya dikesan apabila kebenaran diberikan. DingTalk Security memberi tumpuan kepada melindungi data yang disegerakkan keluar daripada platform. Penyedia penyelesaian produk hanya perlu memberi kebenaran untuk instans yang menyimpan data yang diperoleh daripada platform DingTalk, selaras dengan keperluan keselamatan platform.
   - Jika penyedia penyelesaian produk membatalkan kebenaran, atau jika DingTalk Security mendapati kebenaran yang dipalsukan melalui analisis audit dan penyedia enggan membuat pembetulan selepas notifikasi, penyedia akan dikenakan potongan mata dan penyingkiran aplikasi selaras dengan peraturan keselamatan.
5. Apabila Data Security Center memantau data dan mengesan risiko, bagaimanakah ia memberikan amaran? Apakah mekanisme pengendaliannya?

   Jawapan:

   - Log masuk ke konsol Data Security Center untuk memaparkan amaran risiko dan kandungan yang khusus.
   - Penyedia penyelesaian produk boleh mengendalikan risiko berdasarkan amaran risiko atau dengan berunding dengan DingTalk Security. Untuk amaran berisiko tinggi yang dipantau oleh DingTalk Security, ia menyediakan cadangan pengendalian.
   - DingTalk menerima notifikasi amaran berisiko tinggi yang ditolak. DingTalk Security memutuskan sama ada untuk membuat Tindakan Susulan dan memberitahu penyedia penyelesaian produk untuk mengendalikan risiko berdasarkan tahap keterukan yang ditunjukkan dalam notifikasi amaran.
6. Jika Issue tersebut tidak dikendalikan, adakah aplikasi akan disingkirkan atau adakah sebarang operasi penguncian akan dikenakan ke atas pangkalan data?

   Jawapan: Tiada operasi akan dilakukan ke atas pangkalan data. Walau bagaimanapun, jika amaran berisiko tinggi tidak dikendalikan dalam tempoh yang lama atau pelanggaran keselamatan ditentukan (contohnya, mengeksport data daripada platform DingTalk ke sistem perniagaan lain), aplikasi akan dikenakan potongan mata dan penyingkiran selepas komunikasi dengan penyedia perkhidmatan aplikasi, selaras dengan keperluan berkaitan peraturan keselamatan platform DingTalk.
7. Jika satu jadual dalam pangkalan data aplikasi penyedia penyelesaian produk menyimpan rekod data pengguna yang mengandungi kedua-dua data sensitif yang diperoleh daripada platform DingTalk dan data pengguna yang dikumpul oleh aplikasi penyedia sendiri, adakah mengeksport rekod pengguna ini mencetuskan amaran audit daripada Data Security Center?

   Jawapan:

   - Pada prinsipnya, mengeksport data pengguna memerlukan kebenaran dan persetujuan pengguna, dan data tersebut hanya boleh digunakan dalam skop yang dibenarkan. Oleh itu, penyedia penyelesaian produk harus mewujudkan mekanisme kelulusan dan audit untuk eksport data pengguna bagi mencegah data pengguna daripada disalahgunakan atau dibocorkan.
   - Pengenalpastian data sensitif serta pemantauan dan pengauditan pencegahan kebocoran data Data Security Center tidak membezakan antara data yang disegerakkan daripada platform dan data yang dikumpul sendiri.
   - Data Security Center mengaudit dan menjana amaran untuk operasi yang disyaki kebocoran, seperti eksport data secara berkelompok. Panggilan biasa oleh sesuatu aplikasi secara amnya tidak mencetuskan amaran.
8. Jika anda tidak lagi bersepadu dengan DingTalk pada masa hadapan, apakah yang perlu anda lakukan untuk memulihkan penggunaan rangkaian awam? Adakah anda perlu melakukan operasi seperti audit data?

   Jawapan: Selepas anda berhenti bersepadu dengan DingTalk, anda perlu memberitahu pelanggan organisasi yang menggunakan aplikasi rakan kongsi di DingTalk supaya mengeksport data mereka sendiri. Selepas anda memadam data pelanggan yang diperoleh daripada platform DingTalk dan data pelanggan organisasi DingTalk yang dikumpul, dan kakitangan DingTalk mengesahkan pemadaman tersebut, anda boleh menyahikat kebenaran dan keluar daripada platform Compute Nest.
