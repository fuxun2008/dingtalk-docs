Kebanyakan organisasi mempunyai peraturan pemberian cuti tersendiri. Contohnya, organisasi boleh memberikan baki cuti yang berbeza berdasarkan jawatan pekerja. Peraturan cuti DingTalk belum menyokong logik tersuai seperti ini. DingTalk menyediakan API cuti terbuka supaya organisasi boleh menyokong senario tersuai ini.

<Warning>
Sebelum memanggil API cuti, mohon Kebenaran API yang diperlukan dalam Developer Console.
</Warning>

## Mohon kebenaran

Mohon Kebenaran API sebelum memanggil API pengurusan cuti:

1. Log masuk ke [Developer Console](https://open-dev.dingtalk.io/#/appMgr/provider/eapp/53642/1) dan klik Aplikasi sasaran.
2. Klik **Urus kebenaran**, kemudian klik **Kehadiran**.
3. Tambah Kebenaran API pengurusan cuti, kemudian klik **Mohon kebenaran** atau **Mohon secara pukal**.

### Nota

   Jika permohonan kebenaran ditolak, cari Kebenaran API **pengurusan cuti** dalam lajur **Permintaan**. Letakkan tetikus pada **Ditolak** untuk melihat sebabnya.

   Dalam konsol Aplikasi, pergi ke **Maklumat Asas** > **Urus kebenaran** dan cari kebenaran pengurusan cuti dalam senarai:

| Kebenaran | Kod | API yang disertakan |
| --- | --- | --- |
| Pengurusan cuti DingTalk | `qyapi_holiday_manage` | Tambah peraturan cuti, Kemas kini peraturan cuti, Padam peraturan cuti |
| Pertanyaan cuti DingTalk | `qyapi_holiday_readonly` | Tanya senarai peraturan cuti, Tanya baki cuti, Tanya rekod perubahan baki cuti pekerja secara pukal |

Klik **Mohon kebenaran** di sebelah setiap kebenaran.

## Senario 1: Segerakkan peraturan cuti

Gunakan API cuti untuk menyegerakkan peraturan cuti sedia ada organisasi anda ke sistem pengurusan cuti DingTalk ([DingTalk Admin Console](https://oa.dingtalk.io) **> Workbench > Urus Aplikasi > Kelulusan OA**).

Dalam Admin Console **Kelulusan OA**, pergi ke **Pengurusan Cuti** > **Peraturan Cuti** dan klik **Tambah cuti** untuk menetapkan peraturan cuti. Konfigurasikan setiap peraturan dengan lajur berikut:

| Lajur | Penerangan |
|---|---|
| **Nama cuti** | Contohnya, Cuti Peribadi, Cuti Ganti, Cuti Sakit, Cuti Tahunan, Cuti Bersalin, Cuti Paterniti atau Cuti Perkahwinan |
| **Unit cuti** | Mengikut jam, setengah hari atau hari |
| **Pengiraan tempoh** | Contohnya, mengikut hari bekerja |
| **Bergaji** | Sama ada cuti tersebut bergaji |
| **Peraturan baki** | Contohnya, baki tanpa had |
| **Skop** | Contohnya, seluruh syarikat |
| **Tindakan** | Edit atau Padam |

Kemudian, dalam reka bentuk borang bagi Borang permohonan cuti, tambah kit kehadiran Kelulusan yang disediakan oleh DingTalk. Kit ini mengira baki cuti secara automatik dan menyegerakkannya ke Aplikasi Kehadiran DingTalk.

Editor Borang Kelulusan OA mempunyai empat langkah: **Tetapan Asas** > **Reka Bentuk Borang** > **Reka Bentuk Proses** > **Tetapan Lanjutan**. Pada langkah **Reka Bentuk Borang**, buka tab **Kit**. Di bawah **Kit kehadiran**, tambah **Kit Cuti/Cuti Ganti** ke Borang.

## Senario 2: Segerakkan baki cuti dalaman ke Kelulusan DingTalk

Jika organisasi anda mempunyai peraturan cuti tersendiri dan perlu menyegerakkan baki cuti dalaman ke Kelulusan DingTalk, gunakan API berikut (Aplikasi dalaman digunakan sebagai contoh):

1. Panggil API [Mulakan baki cuti](/ms/open/development/initialize-holiday-balance).
2. Sebagai Admin, pergi ke [DingTalk Admin Console](https://oa.dingtalk.io) **> Workbench > Urus Aplikasi > Kelulusan OA > Pengurusan Cuti > Baki Cuti Pekerja** untuk melihat baki Pekerja yang telah dikemas kini.

Pada halaman **Baki Cuti Pekerja**, klik **Tetapkan Peraturan Cuti Pekerja** atau **Edit Baki secara Pukal melalui Excel**. Tapis mengikut skop organisasi dan, jika perlu, pilih **Sertakan pekerja yang telah keluar dalam tempoh 90 hari**. Setiap rekod menyenaraikan seorang Pekerja dengan lajur berikut: **Nama**, **Jabatan**, **Tarikh Sertai**, **Tarikh Mula Bekerja**, **Cuti Peribadi (jam)**, **Cuti Ganti (jam)**, **Cuti Sakit (jam)**, **Cuti Tahunan (hari)** dan **Cuti Bersalin (hari)**.
