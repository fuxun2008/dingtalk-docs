Panduan ini menunjukkan cara menyumbang kepada **Pusat Pembangun YiDA**. Terdapat dua cara untuk menyumbang: Issues dan Pull Request.

## Issues

Kami menggunakan [GitHub Issues](https://github.com/dingtalk-yida/developer-site/issues) untuk menjejaki masalah dokumentasi di Pusat Pembangun. Jika anda menemui sebarang isu dalam dokumentasi, hantarkan isu tersebut menggunakan templat di bawah. Kami menyemak penyerahan secara berkala dan mengemas kini dokumentasi mengikutnya:

```
- Pautan dokumen: https://yida-developer.gitee.io/docs/api/yidaAPI
- Penerangan: Penerangan bagi this.setState() adalah tidak tepat—setState tidak menyokong fungsi Callback.
- Cadangan pembetulan: Alih keluar penggunaan Callback daripada API setState.
```

Sebelum melaporkan isu, cari isu sedia ada terlebih dahulu untuk mengelakkan pertindihan.

## Pull Request

Kami mengesyorkan penyumbangan melalui Pull Request untuk membantu menambah baik Pusat Pembangun YiDA. Klik butang **Edit this page** di bahagian bawah mana-mana dokumen untuk bermula. Langkah-langkahnya adalah seperti berikut:

* Klik **Edit this page** untuk membuka halaman GitHub (daftar akaun GitHub jika anda belum mempunyainya).

* Fork repositori Pusat Pembangun ke ruang GitHub peribadi anda (tindakan ini hanya sekali sahaja; edit seterusnya boleh langkau langkah ini):

* Pergi ke halaman penyuntingan dokumen, buat perubahan anda, dan commit perubahan tersebut:

* Sahkan perubahan dan hantar Pull Request tersebut:

Itu sahaja langkah untuk penyerahan Pull Request yang mudah. Pasukan YiDA memantau semua Pull Request. Kami akan menyemak dan menggabungkan (merge) perubahan anda, atau mungkin meminta anda membuat pembetulan atau memberikan penjelasan sekiranya perubahan tersebut tidak dapat diterima. Kami mengeluarkan versi patch daripada cabang master setiap minggu.

<Tip>
Anda juga boleh fork repositori Pusat Pembangun ke persekitaran tempatan anda, edit dokumen secara tempatan, dan hantar Pull Request. Jika anda baharu dalam menghantar Pull Request di GitHub, rujuk artikel berikut:

[Cara Menyumbang Kod di GitHub dengan Elegan](https://segmentfault.com/a/1190000000736629)

Cabang utama kami ialah master, jadi hantar Pull Request ke cabang master.
</Tip>

<Tip>
Apabila menghantar kandungan dokumentasi baharu, terangkan secara ringkas latar belakang dan kes penggunaan dalam Pull Request anda supaya kami dapat menyemak dan menambahkannya dengan cekap.
</Tip>

## Aliran Kerja Pembangunan Tempatan

Pusat Pembangun YiDA dibina menggunakan [Docusaurus 2](https://docusaurus.io/). Selepas anda clone repositori Pusat Pembangun dan memasang dependency menggunakan npm install, anda boleh menjalankan arahan biasa berikut:

### Mula Secara Tempatan

```
$ npm start
```

Selepas dimulakan, akses laman web secara tempatan di `http://localhost:3000/`.

> P.S.: Carian global tidak tersedia dalam mod pembangunan tempatan.

### Bina

```
$ npm run build
```

Output binaan akan ditulis ke dalam direktori build.

### Pratonton Binaan Produksi Secara Tempatan

```
$ npm run serve
```

Jalankan arahan ini hanya selepas `npm run build` selesai. Arahan ini memulakan pelayan statik tempatan berdasarkan direktori build, yang boleh diakses di `http://localhost:3000/`. Tingkah lakunya adalah sama seperti Produksi dan menyokong carian global.
