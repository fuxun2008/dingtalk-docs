Tiga pilihan storan object disokong: Alibaba Cloud OSS, Huawei Cloud OBS, dan Inspur Cloud OSS.

## Konfigurasi Produk

Dalam Admin Console YiDA, pergi ke **Pengurusan platform > Konfigurasi storan** untuk mengkonfigurasikan storan pangkalan data dan storan fail.

## Storan Object Fail

**Jenis storan**: Pilih Alibaba Cloud OSS, Huawei Cloud OBS atau Inspur Cloud OSS berdasarkan keperluan organisasi anda.

**Titik akhir storan**: Menggunakan format `bucket.endpoint` secara lalai.

**AccessKey (AK)**: AccessKey yang dikeluarkan oleh penyedia storan.

**SecretKey (SK)**: SecretKey yang dikeluarkan oleh penyedia storan.

### Mod Proksi Rangkaian Khusus DingTalk

YiDA Dedicated berfungsi dengan mod talian sewa khusus DingTalk. Melalui proksi rangkaian yang disesuaikan, OSS menyambung terus ke storan peribadi organisasi anda dan menyediakan penghantaran yang lebih selamat pada lapisan rangkaian.

### Senarai Semak Keperluan Persekitaran

| **Item** | **Konfigurasi** | **Penerangan** |
|---|---|---|
| **Jenis OSS** | Pilih Alibaba Cloud OSS, Huawei Cloud OBS atau Inspur Cloud OSS. | Tiga jenis storan object disokong pada masa ini: [Alibaba Cloud OSS](https://help.aliyun.com/zh/oss/?spm=a2c4g.11186623.0.0.5b4ede53HBHn6O), Huawei Cloud OBS, dan [Inspur Cloud OSS](https://console1.cloud.inspur.com/document/oss/index.html). |
| **Konfigurasi rangkaian** | Aktifkan akses rangkaian awam untuk OSS. |  |
| **Ujian sambungan** | Gunakan ujian sambungan pada halaman konfigurasi YiDA Dedicated untuk mengesahkan sambungan rangkaian. | Mengesahkan sambungan rangkaian. |
| **Tetapan cross-origin** | Benarkan permintaan cross-origin daripada domain organisasi anda pada YiDA. Tetapkan `Header` kepada `*`. | YiDA menyambung terus ke OSS untuk memuat naik dan memuat turun fail. Akses cross-origin mesti dibenarkan agar fungsi ini berfungsi. |
| **Semakan perlindungan hotlink** | Semak sama ada perlindungan hotlink diaktifkan. Jika ya, konfigurasikan senarai dibenarkan domain YiDA.<br />Referer senarai dibenarkan: im.dingtalk.com<br />IP keluar YiDA:<br />• 106.11.0.0/16<br />• 203.119.128.0/17<br />• 59.82.0.0/16<br />• 140.205.0.0/16 | Perlindungan hotlink menyekat sebarang permintaan yang tiada dalam senarai dibenarkan.<br /><br /> |
| **Semakan pelayan masa** | Jika organisasi anda menggunakan pelayan masa, sahkan bahawa masanya tepat. | Permintaan OSS sensitif terhadap masa. YiDA menggunakan tetingkap 30 saat, dan permintaan yang telah tamat tempoh dianggap tidak sah. |

## Soalan Lazim

<AccordionGroup>
<Accordion id="q1" title="S: Selepas saya mengkonfigurasikan storan object fail OSS organisasi sendiri, adakah masih terdapat had pada jumlah muat naik lampiran?">
  A:

  - Lampiran yang dimuat naik daripada aplikasi dengan storan Dedicated diaktifkan disimpan terus dalam storan Dedicated organisasi. (Jumlah lampiran keseluruhan untuk aplikasi yang menggunakan storan awan masih dihadkan, tetapi muat naik ke OSS Dedicated dikecualikan daripada pengiraan Kuota di pihak platform.) Ini melindungi data organisasi. Jumlah lampiran keseluruhan untuk aplikasi yang menggunakan storan Dedicated hanya dihadkan oleh kapasiti OSS organisasi sendiri.
</Accordion>
<Accordion id="q2" title="S: Apabila storan Dedicated diaktifkan dan data disimpan dalam pangkalan data Alibaba Cloud atau OSS organisasi sendiri, adakah platform YiDA membuat sandaran data ini?">
  Tidak. Data perniagaan disimpan terus dalam pangkalan data atau ruang OSS organisasi. YiDA tidak menyimpan atau membuat sandaran data ini, dan pelanggan bertanggungjawab untuk memastikan keselamatannya.
</Accordion>
<Accordion id="q3" title="S: Bolehkah item konfigurasi OSS Dedicated disunting atau dipadamkan?">
  OSS mengendalikan storan untuk fail perniagaan yang kritikal. Menukar medium storan OSS selepas konfigurasi berjaya tidak disokong pada masa ini. Konfigurasikan OSS Dedicated yang sah dengan teliti untuk mengelakkan ketidakkonsistenan penyegerakan data yang disebabkan oleh perubahan kerap pada titik akhir storan OSS.
</Accordion>
<Accordion id="q4" title="S: Selepas saya mengaktifkan OSS Dedicated, mengapakah muat naik lampiran mengembalikan Ralat URL tidak sah?">
  A: Semak sama ada domain storan Dedicated adalah sah. Konfigurasi OSS Dedicated hanya menyokong format `bucket + domain`. Menggunakan `bucket + IP` menyebabkan kegagalan muat naik lampiran.
</Accordion>
