Secara lalai, YiDA Dedicated edition tidak memerlukan konfigurasi khas untuk kegigihan data (data persistence). Jika anda mempunyai keperluan tambahan, YiDA Dedicated edition menyokong konfigurasi khusus untuk pangkalan data dan storan object fail. Artikel ini menerangkan sumber perkakasan dan perisian yang diperlukan semasa mengkonfigurasikan storan khusus.

## Pangkalan Data

Hanya pangkalan data **PostgreSQL** yang disokong buat masa ini. PostgreSQL v14 atau versi lebih baharu adalah disyorkan. Keperluan konfigurasi khusus adalah seperti berikut:

| **Item** | **Konfigurasi** | **Penerangan** |
|---|---|---|
| **Lokasi pangkalan data** | PostgreSQL Alibaba Cloud adalah disyorkan (kedua-dua versi RDS dan ADB disokong). | Pangkalan data Alibaba Cloud disyorkan kerana operasinya yang boleh dipercayai, rangkaian yang stabil, dan prestasi yang terjamin. |
| **Versi pangkalan data** | PostgreSQL 14 atau versi lebih baharu. | Versi lebih awal daripada 14 tidak dapat memberikan prestasi optimum. |
| **Spesifikasi pangkalan data** | 8C 16G SSD 200G atau lebih tinggi. | Berdasarkan jumlah data sebanyak 1,000,000 rekod, spesifikasi hos "8C 16G memori 200G SSD" atau lebih tinggi adalah disyorkan. |
| **Alamat pangkalan data** | Sediakan alamat berasaskan domain dan bukannya alamat IP. | Nama domain memudahkan penskalaan dan meningkatkan kedua-dua fleksibiliti konfigurasi serta ketersediaan perkhidmatan. |
| **Ujian sambungan pangkalan data** | Gunakan ciri ujian sambungan dalam konfigurasi khusus YiDA untuk mengesahkan kesambungan rangkaian. Aktifkan akses rangkaian awam dan konfigurasikan Senarai Dibenarkan IP keluar rangkaian. | Jika anda tidak mahu mendedahkan rangkaian awam, anda perlu membeli dan mengintegrasikan tambahan pintu masuk keselamatan khusus DingTalk (dedicated DingTalk security gateway).<br />Digunakan untuk mengesahkan kesambungan rangkaian dan sama ada Sumber Data boleh dimulakan (initialize). |
| **Kolam sambungan pangkalan data** | Minimum 1,000 sambungan tersedia. | YiDA menggunakan penggunaan kluster (cluster deployment). Untuk menjamin bilangan sambungan pada setiap mesin, tingkatkan bilangan sambungan Bahagian pelayan yang tersedia. |
| **Konfigurasi keep-alive sambungan** | tcp_keepalives_idle=30<br />tcp_keepalives_interval=5 | Tingkatkan kekerapan keep-alive sambungan pangkalan data untuk mengelakkan sambungan tidak sah yang disebabkan oleh isu rangkaian. |
| **Pemantauan pangkalan data** | Memudahkan penyelesaian masalah oleh DBA atau DevOps. | Memudahkan penyelesaian masalah harian. Tanpanya, isu prestasi tidak dapat dikesan dengan cepat. |
| **Lebar jalur pangkalan data** | Minimum 10M yang didedikasikan untuk YiDA adalah disyorkan. | Jika trafik perniagaan sangat tinggi dengan muat naik dan muat turun yang kerap, tingkatkan lebar jalur mengikut keperluan. |

| **Konfigurasi** | **Kapasiti pangkalan data (jadual tunggal)** | **Kapasiti pangkalan data (rekod instans data)** |
|---|---|---|
| 4-teras / 8G memori / 50G SSD | 50,000 | 1,000,000 |
| 8-teras / 16G memori / 100+ SSD | 100,000 | 2,000,000 |
| 16-teras / 32G / 100+ SSD | 300,000 | 5,000,000 |
| 32-teras / 64G / 200+ SSD | 500,000 | 10,000,000 |
| 64-teras / 128G memori / 200G+ SSD | 1,000,000 | 20,000,000 |

## Storan Object

Storan object menyokong tiga pilihan: [Alibaba Cloud OSS](https://help.aliyun.com/zh/oss/?spm=a2c4g.11186623.0.0.5b4ede53HBHn6O), Huawei Cloud OBS, dan [Inspur Cloud OSS](https://console1.cloud.inspur.com/document/oss/index.html).

Keperluan persekitaran storan object adalah seperti berikut:

| **Item** | **Konfigurasi** | **Penerangan** |
|---|---|---|
| **Jenis OSS** | Pilih Alibaba Cloud OSS, Huawei Cloud OBS, atau Inspur Cloud OSS. | Tiga jenis storan object disokong buat masa ini: [Alibaba Cloud OSS](https://help.aliyun.com/zh/oss/?spm=a2c4g.11186623.0.0.5b4ede53HBHn6O), Huawei Cloud OBS, dan [Inspur Cloud OSS](https://console1.cloud.inspur.com/document/oss/index.html). |
| **Konfigurasi rangkaian** | Aktifkan akses rangkaian awam untuk OSS. |  |
| **Ujian kesambungan** | Gunakan ciri ujian sambungan dalam konfigurasi khusus YiDA untuk mengesahkan kesambungan rangkaian. | Digunakan untuk mengesahkan kesambungan rangkaian. |
| **Tetapan CORS** | Konfigurasikan CORS untuk membenarkan domain organisasi pada YiDA. Tetapkan `Header` kepada `*`. | YiDA bersambung terus ke OSS untuk muat naik dan muat turun fail. CORS mesti dibenarkan untuk ia berfungsi. |
| **Semakan perlindungan hotlink** | Semak sama ada perlindungan hotlink diaktifkan. Jika diaktifkan, konfigurasikan Senarai Dibenarkan domain YiDA.<br />IP keluar YiDA adalah:<br />• 106.11.0.0/16<br />• 203.119.128.0/17<br />• 59.82.0.0/16<br />• 140.205.0.0/16 | Perlindungan hotlink menyekat sebarang permintaan yang tidak berada dalam Senarai Dibenarkan.<br /><br /> |
| **Semakan pelayan masa (time server)** | Jika organisasi menggunakan pelayan masa, sahkan bahawa masa adalah tepat. | Permintaan OSS mempunyai tempoh sah masa. YiDA menetapkannya kepada 30s, dan permintaan yang telah luput adalah tidak sah. |

## Sumber IT: Persediaan Storan

Pangkalan data setempat

- Pangkalan data PostgreSQL v14 atau versi lebih baharu.
- Domain pangkalan data, nama pangkalan data, akaun, dan kata laluan yang boleh diakses secara awam.
- Pelayan disyorkan: 8-teras 16G, cakera 2T.

Storan OSS fail setempat

- Domain baldi (bucket) OSS, kunci akses (AK), dan kunci rahsia (SK) yang boleh diakses secara awam.
