- Dalam persekitaran PostgreSQL awan VPC, import 50,000 baris dengan 100 medan asas mengambil masa 5-10 minit.
- Edisi Dedicated mengoptimumkan teknologi sambungan asas dan memberikan kelajuan import yang lebih pantas melalui teknologi sambungan pangkalan data Dedicated Storage.

## Import Edisi Dedicated

Untuk import data volum besar pada borang biasa, had import tunggal meningkat kepada 50,000 baris.

  ![](https://gw.alicdn.com/imgextra/i2/O1CN01bDY6BuemshC2QgMw_!!6000000000557-2-tps-1197-873.png)

Untuk import volum besar pada borang aliran kerja, had meningkat kepada 10,000 baris.

<Frame>
  ![](https://gw.alicdn.com/imgextra/i2/O1CN01R9bjCMcDK0J5qI8E_!!6000000001017-2-tps-2878-1560.png)
</Frame>

Integrasi & Automasi serta peraturan perniagaan (untuk pengambilan data, kemas kini, dan pemadaman) menyokong sehingga 2,000 rekod.

<Frame>
  ![](https://gw.alicdn.com/imgextra/i2/O1CN01QdPB2ZIaOgK4Neou_!!6000000000534-2-tps-2158-1646.png)
</Frame>

<Note>
- Dalam nod Kemas Kini, had yang lebih tinggi hanya berlaku untuk kaedah "Kemas kini melalui nod". Kaedah "Kemas kini terus" kekal terhad kepada 100 rekod.

<Frame>
  ![](https://gw.alicdn.com/imgextra/i4/O1CN01P3weSewpzGG4yAAC_!!6000000005580-2-tps-2448-1648.png)
</Frame>

- Jika anda menggunakan nod Pengambilan Data untuk mengambil 2,000 rekod dan memasukkannya ke dalam subborang melalui nod Sisip, had 500 rekod subborang masih berlaku, jadi hanya 500 rekod akan ditulis.
</Note>

## Import Edisi Bukan Dedicated (Perbandingan)

- Untuk import data volum besar pada borang biasa, had import tunggal ialah 5,000 baris, dan kelajuan import agak perlahan.

<Frame>
  ![](https://gw.alicdn.com/imgextra/i2/O1CN01F5QoKW3pUKJ2VqId_!!6000000003338-2-tps-1238-645.png)

## **Nota**

Jika Dedicated Storage diaktifkan untuk aplikasi, Integrasi & Automasi hanya dapat mengambil 100 rekod subborang pada satu masa.
