## **Gambaran Keseluruhan Ciri**

Selepas data dihantar melalui halaman proses YiDA, data tugasan akan dijana dalam pusat tugasan pada peringkat aplikasi dan peringkat organisasi. Tugasan dikategorikan mengikut status sebagai "Dicipta oleh saya", "Perlu diproses oleh saya", "Telah diproses oleh saya", dan "CC kepada saya". Semasa proses berjalan, data ini disimpan, dikemas kini, dan ditanya (query) oleh perkhidmatan YiDA sendiri.

Organisasi yang menggunakan Edisi Dedicated YiDA boleh menggunakan ciri integrasi mesej tugasan kelulusan perusahaan dalam Pusat Integrasi untuk menyambungkan perkhidmatan YiDA ke pusat tugasan atau sistem tugasan (to-do) mereka sendiri. Apabila proses aplikasi mencipta atau mengemas kini tugasan, YiDA akan memanggil perkhidmatan organisasi untuk push data tersebut.

Setelah penyambung dikonfigurasikan, setiap tugasan kelulusan daripada setiap aplikasi YiDA dalam organisasi akan di-push secara automatik ke alamat perkhidmatan berdaftar seperti yang ditunjukkan di bawah. Dalam callback perkhidmatan yang berkaitan, organisasi boleh memproses dan menggunakan peristiwa berkaitan kelulusan YiDA secara terpilih mengikut keperluan.

## **Cara Penggunaan**

### **Prasyarat**

1. Organisasi menggunakan Edisi Dedicated YiDA.
2. Organisasi mempunyai sistem perkhidmatan sendiri yang boleh mendedahkan perkhidmatan berasaskan HTTP untuk dipanggil oleh YiDA.
3. Perkhidmatan tersebut memenuhi keperluan format callback YiDA.
4. Perkhidmatan tersebut boleh diakses melalui rangkaian.

#### **Proses Tandatangan**

Tandatangan antara muka callback perkhidmatan menyulitkan parameter permintaan menggunakan MD5. Hasil penyulitan dihantar kepada penyedia perkhidmatan melalui parameter sign. systemToken aplikasi YiDA diperlukan sebagai kunci tandatangan.

1. Susun semua kunci parameter permintaan menggunakan String.CASE_INSENSITIVE_ORDER.
2. Gabungkan (concatenate) nilai parameter yang berkaitan mengikut turutan kunci untuk membentuk string yang akan disulitkan.
3. Tambahkan systemToken pada string yang dihasilkan dalam langkah 2.
4. Sulitkan string daripada langkah 3 menggunakan algoritma MD5 dengan set aksara UTF-8.

<Warning>
⚠️ Nota: systemToken ialah App Secret. Cari di Tetapan Aplikasi > Penyebaran dan Operasi > App Secret.
</Warning>

## Keputusan

Sebagai contoh, rajah di bawah menunjukkan cara seorang pelanggan industri menggunakan keupayaan integrasi dan pembangunan YiDA Dedicated untuk menyatukan tugasan kelulusan ke dalam pusat tugasan kelulusan yang dibina sendiri, menyeragamkan proses BPM merentasi pelbagai aplikasi sistem YiDA serta sistem perniagaan, produksi, dan pentadbiran organisasi sendiri pada pelbagai platform.

## FAQ

**S: Selepas Pusat Integrasi dikonfigurasikan, adakah ia terpakai untuk data sejarah (historical)?**

J: Tidak. Ia hanya terpakai untuk data baharu.

**S: Jika perkhidmatan yang di-push oleh Pusat Integrasi mengembalikan ralat akibat kegagalan dalam sistem pelanggan, adakah YiDA menyediakan cara untuk menanya (query) log yang berkaitan? Adakah terdapat mekanisme cuba semula sandaran apabila push gagal?**

J: Pusat Integrasi YiDA adalah dipacu peristiwa (event-driven). Tiada mekanisme sandaran disediakan pada masa ini, dan sistem tidak mengandungi logik cuba semula pada masa ini.
