| **Jenis pengesahan** | **Penerangan** |
|---|---|
| Tanpa pengesahan | Tanpa pengesahan bermaksud tidak diperlukan maklumat pengesahan, dan API boleh dipanggil terus. Biasanya digunakan untuk mengakses API awam. |
| Pengesahan Asas | Pengesahan Asas bergantung pada Pengepala permintaan Authorization bagi permintaan HTTP. Pengepala ini mengandungi kelayakan yang digunakan pelayan untuk mengesahkan identiti agen pengguna.<br />• **Format**: `Authorization: Basic <ciphertext>`.<br />Contohnya, tambah `Authorization: Basic YWxhZGRpbjpvcGVuc2VzYW1l` pada pengepala, iaitu akaun dan kata laluan yang dikodkan Base64.<br />Anda hanya perlu mengkonfigurasi label prompt untuk akaun dan kata laluan supaya pengguna tahu apa yang perlu dimasukkan semasa mendaftar maklumat pengesahan.<br />Contohnya:<br />• **label nama pengguna**<br />• **label kata laluan** |
| API Key | Merujuk kepada kaedah pengesahan **APIKey**. APIKey kekal sah untuk tempoh yang long (simpan dengan selamat). Pelawat mencipta kunci rahsia dalam sistem sasaran, dan pembangun kemudian boleh menggunakan kelayakan ini untuk memanggil API awam yang menyokong jenis pengesahan ini.<br />• **Label parameter**: dipaparkan sebagai Prompt semasa mengkonfigurasi maklumat pengesahan.<br />• **Nama parameter**: nama apiKey yang diperlukan oleh sistem.<br />• **Lokasi parameter**: pilih untuk melampirkan maklumat pengesahan pada Parameter pertanyaan atau pengepala, berdasarkan keperluan sistem sasaran. |
| Alibaba Cloud API Gateway | Selepas penyambung dicipta, tambah templat pengesahan. Setelah App Code dimasukkan dalam templat, anda boleh memanggil API Alibaba Cloud yang berkaitan.<br />Untuk maklumat lanjut, lihat [Memanggil API menggunakan pengesahan App Code](https://help.aliyun.com/document_detail/115437.html).<br />![](https://gw.alicdn.com/imgextra/i1/O1CN01UBzp7uCtaWL5q2U2_!!6000000001282-2-tps-2876-1410.png) |
| Pengesahan DingTalk Open Platform | Selepas penyambung dicipta, tambah templat pengesahan. Setelah `App Key` dan `App Secret` dimasukkan dalam templat, anda boleh memanggil API DingTalk Open Platform (termasuk beberapa API YiDA).<br />Selepas templat pengesahan ditambah, YiDA secara automatik menjana parameter pengesahan `access_token` dan menambahkannya pada parameter `x-acs-dingtalk-access-token` dalam `Header` semasa permintaan dibuat. Anda tidak perlu menjananya semula.<br />Untuk maklumat lanjut, lihat proses pembangunan aplikasi DingTalk. |
| DingTalk Zero Trust Gateway | Untuk maklumat tentang cara menggunakan DingTalk Zero Trust Gateway, lihat DingTalk Open Platform - Pengesahan Zero Trust Gateway. |

## Langkah 2: Cipta Tindakan Pelaksanaan

Pada halaman Tindakan Pelaksanaan, klik **Cipta tindakan pelaksanaan**, dan kemudian konfigurasikan tindakan tersebut seperti yang diterangkan di bawah.

| **Nama** | **Penerangan** |
|---|---|
| Maklumat asas | Konfigurasikan maklumat asas tindakan pelaksanaan semasa.<br />• **Pengecam unik**: digunakan untuk membezakan tindakan yang berlainan.<br />• Nama tindakan: nama tindakan pelaksanaan.<br />• Penerangan tindakan: penerangan tentang tindakan pelaksanaan. |
| Permintaan API | Konfigurasikan API yang akan dipanggil apabila tindakan pelaksanaan semasa dicetuskan.<br />• **URL permintaan**: pautan permintaan API. Domain permintaan diisi secara automatik dengan domain penyambung.<br />• **Kaedah HTTP**: GET, POST, DELETE, PUT, HEAD, OPTIONS, PATCH, dan kaedah lain disokong.<br />• **Query**: parameter permintaan, biasanya parameter yang ditambahkan selepas tanda soal `?` dalam URL. Klik tanda tambah untuk menambah satu.<br />• **Body**: untuk permintaan POST dan kes yang serupa, medan body juga boleh disertakan. Ia menyokong penghuraian menggunakan JSON permintaan.<br />• **Headers**: sesuaikan Pengepala permintaan tambahan di sini. Hanya konfigurasi statik disokong pada masa ini.<br />• **Path**: pemboleh ubah yang dilampirkan dalam kurungan dakap dalam URL, seperti `{pathParam}`, di mana `pathParam` ialah nama pemboleh ubah.<br />**Nota**: Parameter permintaan menyokong konfigurasi medan sistem seperti ID pengguna yang log masuk dan ID organisasi. |
| Respons API | Konfigurasikan Respons yang dijangka selepas API berjaya dipanggil. Penghuraian menggunakan JSON disokong.<br />**Nota**: Jika Respons API bukan object JSON, ia tidak boleh digunakan terus dalam Integrasi & Automasi. Huraikannya secara manual dalam nod skrip. |

Semua penyambung tersuai memerlukan skema pengesahan permintaan yang sepadan, walaupun untuk "**Tanpa pengesahan**".

1. Cipta akaun
