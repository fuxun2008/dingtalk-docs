**Langkah 1**: Untuk Aes_key penyulitan, sulitkan **systemToken** YiDA dengan kaedah **decrypt** di bawah dan gunakan hasilnya.

```text
private static final char[] HEX_ARRAY = "0123456789abcdef".toCharArray();

public static String bytesToHex(byte[] bytes) {
        char[] hexChars = new char[bytes.length * 2];
        for (int i = 0; i < bytes.length; i++) {
            int v = bytes[i] & 0xFF;
            hexChars[i * 2] = HEX_ARRAY[v >>> 4];
            hexChars[i * 2 + 1] = HEX_ARRAY[v & 0x0F];
        }
        return new String(hexChars);
    }

private static String decrypt(String input) throws NoSuchAlgorithmException {
        MessageDigest digest = MessageDigest.getInstance("SHA-256");
        byte[] hash = digest.digest(input.getBytes(StandardCharsets.UTF_8));
        // Convert the hash into a 43-character encrypted string
        return bytesToHex(hash).substring(0, 43);
}
```

Dapatkan systemToken YiDA daripada Tetapan aplikasi YiDA > Penerapan & Operasi.

**Langkah 2**: Token tandatangan ialah systemToken YiDA di atas.

**Langkah 3**: URL permintaan callback (https://www.yidaapps.com/saasAppCallback/\{appKey}), dengan appKey ialah kod aplikasi YiDA, contohnya "APP_XXX."

**Ciri-ciri berikut semuanya boleh diubah suai:**

> Logik umum: Setelah pengubahsuaian dibuat dan ISV kemudiannya menerbitkan versi baharu, konfigurasi tempatan pelanggan diutamakan untuk ciri yang terjejas. Perubahan pada aplikasi utama tidak disegerakkan turun ke aplikasi anak. Jika tiada pengubahsuaian dibuat, perubahan sumber inkremental dalam aplikasi utama disegerakkan ke aplikasi anak.
> 
> Logik perubahan proses kelulusan:
> 
> 1. Jika aplikasi anak melanggan V0 dan aplikasi utama mempunyai V1 yang belum diterbitkan, V1 tidak muncul dalam Sejarah Versi aplikasi anak.
> 2. Jika aplikasi anak melanggan V0 tanpa penyesuaian dan aplikasi utama kemudiannya menaik taraf ke V1, aplikasi anak terus memaparkan dan berjalan mengikut V0 yang dilanggan.
> 3. Jika aplikasi anak melanggan V0 dan menyesuaikannya, versi sejarah dalaman V0 dicipta bersama draf V1. Selepas aplikasi anak melanggan versi baharu, proses semasa tidak lagi mengikut naik taraf aplikasi utama.
> 4. Skop versi di atas merangkumi semua peraturan perniagaan dan formula dalam versi tersebut.

## 5 Operasi Aplikasi

### 5.1 Naik Taraf Versi

Selepas aplikasi SaaS yang dibina oleh ISV diterbitkan ke App Marketplace dan pelanggan melanggan, ISV boleh mengulangi ciri dan, di bawah "Workbench pembangunan SaaS YiDA > Tetapan aplikasi > Operasi jarak jauh," melancarkan naik taraf versi kepada organisasi tertentu secara individu atau berkelompok.

Nota ciri:

1. Secara lalai, pilihan naik taraf ialah iterasi terkini yang diterbitkan selepas versi yang sedang diterbitkan.
2. Naik taraf versi berkelompok merentasi pelbagai organisasi berbayar disokong.

> Operasi jarak jauh — akan datang.
