### S: Apabila Membuat Sumber Data, Ralat "Ujian Sambungan Tamat Masa. Semak Maklumat Sambungan dan Firewall, Kemudian Cuba Lagi" Muncul

- Apabila mengintegrasikan Sumber Data dengan sistem anda sendiri, pastikan pangkalan data atau sistem anda boleh diakses melalui rangkaian awam. Jika tidak, ralat ini akan berlaku.

### S: Apabila Menggunakan SQL Server (Versi Sebelum 2012), Ralat "Medan Xxx Bukan Nama Fungsi Terbina Dalam yang Dikenali" Muncul

- YiDA pada masa ini tidak serasi dengan versi SQL Server sebelum 2012. Data mungkin kadangkala dipaparkan dengan betul, tetapi versi ini tidak disyorkan.

### S: Bilakah Set Data Kehadiran Akan Tersedia?

J: Ia berada dalam pelan hala tuju dan akan dipertimbangkan untuk disampaikan dalam iterasi masa hadapan.

### S: Mengapa Saya Tidak Boleh Pratonton Data Terkini dalam Set Data Rasmi yang Saya Sambungkan?

J: Anda pada masa ini perlu mengklik butang ujian secara manual untuk memuat semula data. Butang muat semula untuk data pratonton akan ditambah kemudian.

### S: Adakah Data Real-Masa atau Dikemas Kini pada Hari Berikutnya?

J: Pada masa ini, hanya data Kelulusan OA adalah real-masa. Metrik Umum, senarai Pekerja, Smart HR (onboarding, serahkan, kenaikan pangkat, peletakan jawatan), dan set data serupa dikemas kini secara lalai pada 00:00 hari berikutnya.

### S: Selepas Admin dengan Kebenaran Data untuk Aplikasi Pihak Pertama Mencipta Set Data melalui Data Factory, Bagaimana Kebenaran Data Boleh Dikonfigurasikan Selanjutnya?

J: Data yang diproses melalui Data Preparation menjana set data bebas baharu berdasarkan kebenaran data penerbit terkini. Kebenaran baris dan lajur lalai bagi set data ini bergantung pada kebenaran penerbit terakhir. Berdasarkan ini, anda boleh mengkonfigurasikan kebenaran set data bebas.

<Accordion id="q9" title="S: Set data tidak dikemas kini selepas menambah komponen baharu?">
  Selepas menambah komponen baharu, klik ujian sekali lagi atau seret set data masuk semula untuk mengemas kininya.
</Accordion>
<Accordion id="q10" title="S: Hasil pratonton nod Data Preparation tidak sepadan dengan hasil kira tempatan?">
  Bilangan baris data yang ditunjukkan dalam pratonton data dalam Data Preparation adalah untuk rujukan sahaja. Ia tidak boleh digunakan untuk menilai bilangan baris set data output akhir, kerana caching pecutan perantaraan mungkin wujud.
</Accordion>
<Accordion id="q11" title="S: Dalam keadaan apakah pengubahsuaian jenis medan nod Data Preparation berkuat kuasa?">
  Sebagai contoh, jika nod distrukturkan sebagai A - B - C, pengubahsuaian jenis medan nod A hanya menjejaskan nod B dan C. Pengubahsuaian jenis medan nod B hanya menjejaskan nod C.
</Accordion>
<Accordion id="q12" title="S: Mengapakah ID medan nod output berubah?">
  Dalam penggunaan harian, elakkan tindakan padam atau tetapkan semula yang tidak boleh diterbalikkan pada nod operasi data.

  - Jika kandungan nod pemprosesan sebelumnya berubah (contohnya, ia mengandungi medan A dengan ID medan = xxx001), termasuk memadam dan menambah semula nod, ID medan yang sama sekali baharu akan dijana secara dinamik untuk medan seterusnya (ID medan A mungkin dijana semula secara rawak sebagai yyy789, sebagai ilustrasi). Ini menyebabkan konfigurasi ID nod sedia ada dalam senario penggunaan perniagaan hiliran seperti laporan dan papan pemuka gagal.
</Accordion>
<Accordion id="q13" title="S: Apabila Data Preparation mengambil data kehadiran DingTalk, 'masa daftar masuk pertama hari itu' menunjukkan null untuk sesetengah Pengguna walaupun mereka mempunyai rekod daftar masuk. Mengapa?">
  Dalam YiDA, medan yang didedahkan "masa daftar masuk pertama" menggunakan format: `yyyy-MM-dd HH:mm:ss`.

  Peraturan paparan:

  - Jika pengguna mempunyai jadual syif dan mendaftar masuk untuk syif kerja pertama, masa tersebut direkodkan sebagai masa daftar masuk pertama hari itu.
  - Untuk borang Kelulusan, luar pejabat, Tinggalkan, daftar masuk tambahan, dan rekod kerja luar tidak dikira.
  - Untuk rekod daftar masuk, kerja luar dan rekod yang diubah suai oleh Admin tidak dikira.
</Accordion>
