| **Jenis pengesahan** | **Penerangan** |
|---|---|
| Tiada pengesahan | Tiada kelayakan diperlukan untuk memanggil API. Ini biasanya digunakan untuk API awam. |
| Pengesahan asas | Kebenaran HTTP Standard. Pengepala permintaan mengandungi kelayakan yang digunakan oleh pelayan untuk mengesahkan identiti agen pengguna. Tambahkan akaun dan kata laluan yang dikodkan Base64 ke dalam pengepala, contohnya, `Authorization: Basic YWxhZGRpbjpvcGVuc2VzYW1l`.<br />Format pengekodan: `account:password`.<br />Anda hanya perlu mengkonfigurasi label untuk medan akaun dan kata laluan, yang memberitahu pengguna apa yang perlu dimasukkan semasa mendaftar kelayakan.<br />• **label nama pengguna**<br />• **label kata laluan** |
| API Key | Kaedah pengesahan **API Key**. API Key sah untuk jangka masa yang panjang (simpan dengan selamat). Pemohon menjana kunci rahsia dalam sistem sasaran, dan pembangun kemudian boleh menggunakan kelayakan ini untuk memanggil API awam yang menyokong kaedah pengesahan ini.<br />• **Label parameter**: Dipaparkan sebagai gesaan semasa mengkonfigurasi kelayakan.<br />• **Nama parameter**: Nama apiKey yang diperlukan oleh sistem.<br />• **Lokasi parameter**: Pilih sama ada untuk menghantar kelayakan sebagai Parameter pertanyaan atau dalam pengepala, berdasarkan keperluan sistem sasaran. |
| Alibaba Cloud API Gateway | Selepas anda mencipta penyambung, tambah templat kelayakan. Setelah App Code dimasukkan dalam templat, anda boleh memanggil API Alibaba Cloud yang berkaitan.<br />Untuk maklumat lanjut, lihat [Panggil API menggunakan pengesahan AppCode](https://help.aliyun.com/document_detail/115437.html).<br />![](https://gw.alicdn.com/imgextra/i1/O1CN01UBzp7uCtaWL5q2U2_!!6000000001282-2-tps-2876-1410.png) |
| Pengesahan DingTalk Open Platform | Selepas anda mencipta penyambung, tambah templat kelayakan. Setelah `App Key` dan `App Secret` dimasukkan dalam templat, anda boleh memanggil API DingTalk Open Platform (termasuk sebahagian API YiDA).<br />Selepas templat kelayakan ditambah, YiDA secara automatik menjana `access_token` melalui pengesahan dan menambahkannya ke parameter `Header` `x-acs-dingtalk-access-token` untuk setiap permintaan. Anda tidak perlu menjananya semula.<br />Untuk maklumat lanjut, lihat proses pembangunan aplikasi DingTalk. |
| DingTalk Zero Trust Gateway | Untuk butiran cara menggunakan DingTalk Zero Trust Gateway, lihat DingTalk Open Platform - Pengesahan Zero Trust Gateway. |

## Langkah 2: Cipta Tindakan

Pada halaman tindakan, klik **Cipta tindakan**, kemudian konfigurasikan tetapan berdasarkan maklumat berikut.

| **Nama** | **Penerangan** |
|---|---|
| Maklumat asas | Konfigurasikan maklumat asas untuk tindakan semasa.<br />• **Pengecam unik**: Digunakan untuk membezakan antara tindakan yang berbeza.<br />• Nama tindakan: Nama tindakan tersebut.<br />• Penerangan tindakan: Penerangan tindakan tersebut. |
| Permintaan API | Konfigurasikan titik akhir API yang dipanggil oleh tindakan semasa apabila dicetuskan.<br />• **URL permintaan**: Pautan permintaan API. Domain permintaan diisi secara automatik dengan domain penyambung.<br />• **Kaedah HTTP**: Menyokong kaedah GET, POST, DELETE, PUT, HEAD, OPTIONS, PATCH, dan lain-lain.<br />• **Query**: Parameter permintaan, biasanya ditambah selepas tanda soal `?` dalam URL. Klik tanda tambah untuk menambah satu.<br />• **Body**: Bagi permintaan POST dan kaedah seumpamanya, medan body juga boleh disertakan. Ia menyokong penghuraian menggunakan JSON.<br />• **Headers**: Sesuaikan pengepala permintaan tambahan di sini. Hanya konfigurasi statik disokong buat masa ini.<br />• **Path**: Pembolehubah dalam URL yang dilampirkan dalam kurungan dakap, seperti `{pathParam}`, dengan `pathParam` sebagai nama pembolehubah.<br />**Nota**: parameter permintaan menyokong medan sistem untuk ID pengguna yang log masuk dan ID organisasi. |
| Respons API | Konfigurasikan respons yang dijangka selepas panggilan API berjaya. Menyokong penghuraian JSON.<br />**Nota**: Jika API mengembalikan object bukan JSON, ia tidak boleh digunakan secara langsung dalam Integrasi & Automasi. Anda perlu menghuraikannya sendiri dalam nod skrip. |

## Langkah 3: Konfigurasikan Pengesahan

Setiap Penyambung data tersuai mesti mempunyai skema pengesahan permintaan yang sepadan, walaupun untuk **Tiada pengesahan**.

1. Cipta akaun

Pada penyambung yang dikonfigurasi, klik Uji untuk memilih akaun pengesahan. Anda juga boleh menambah akaun pengesahan baharu pada langkah ini.

<Frame>
  ![](https://gw.alicdn.com/imgextra/i3/O1CN01iDaxPtCrUBH5pXJy_!!6000000000239-2-tps-2872-1626.png)
</Frame>

2. Masukkan nama paparan akaun, App Key, App Secret, dan maklumat lain, kemudian klik Sahkan.
