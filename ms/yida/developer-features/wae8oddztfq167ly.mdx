## Syarat Pencetus

Untuk mengelakkan beban pelayan YiDA yang tidak normal disebabkan oleh ralat aplikasi, setiap endpoint YiDA Server API mempunyai had kadar lalai yang berbeza berdasarkan kerumitannya (untuk maklumat terperinci, hantar pautan dokumen API kepada sokongan teknikal). Melebihi had pada mana-mana dimensi mungkin mencetuskan had kadar. Kod ralat respons biasa: `failure.operation.requestTooFast` dan `failure.operation.tooManyVisitors`.

- Had kadar QPS aplikasi tunggal: Bagi setiap aplikasi, panggilan kepada endpoint tertentu yang melebihi kekerapan maksimum akan mencetuskan had kadar.
- Had kadar QPS organisasi tunggal: Bagi setiap organisasi, panggilan kepada endpoint tertentu yang melebihi kekerapan maksimum akan mencetuskan had kadar.
- Had QPS global bagi setiap endpoint: Disebabkan dasar perlindungan keselamatan endpoint YiDA, bilangan panggilan sesaat adalah terhad. Apabila semua aplikasi organisasi YiDA secara kolektif memanggil satu endpoint melebihi had sesaatnya, ralat respons akan dicetuskan.

Penyelesaian

- Umum: Oleh kerana tetingkap had kadar QPS ialah 1 saat, apabila anda menemui ralat had kadar, tangguhkan program anda selama 1 saat, kemudian Teruskan pelaksanaan.
- Strategi luar waktu puncak: Bagi program yang memanggil API YiDA mengikut jadual, elakkan waktu puncak pada waktu genap jam. Contohnya, jadualkan pelaksanaan pada minit ke-10 selepas setiap jam.

<Accordion id="q1" title="S: DingTalk Open Platform mengenakan caj untuk panggilan OpenAPI. Adakah endpoint berkaitan YiDA dikenakan caj lagi (caj berganda)?">
  J: Tidak, ia tidak dikenakan caj berganda. Butirannya adalah seperti berikut:

  Panggilan API perniagaan berkaitan YiDA terbahagi kepada 2 senario penggunaan:

  1. YiDA bertindak sebagai aplikasi SaaS dan memanggil endpoint DingTalk melalui ciri produk (iaitu, konektor rasmi YiDA, seperti mengambil data kehadiran DingTalk). Panggilan ini tidak tertakluk kepada had dasar tersebut.
  2. Pelanggan membina aplikasi dalaman pada DingTalk Open Platform dan terus memanggil kandungan dalam [senarai endpoint YiDA] daripada sistem luaran mereka sendiri (contohnya, sistem pelanggan sendiri memanggil endpoint openAPI YiDA untuk menyegerakkan data aplikasi yang dibina dalam YiDA ke sistem pelanggan sendiri). Panggilan ini mematuhi dasar bersepadu DingTalk Open Platform.

  
</Accordion>

  J: Tidak, ia tidak menggunakan bilangan panggilan DingTalk Open Platform, kerana panggilan API perniagaan berkaitan YiDA tidak tertakluk kepada had dasar tersebut.

<Accordion id="q3" title="S: Adakah had QPS yang diterbitkan oleh DingTalk Open Platform turut terpakai kepada endpoint YiDA?">
  J: Had QPS yang diterbitkan oleh DingTalk Open Platform membezakan antara aplikasi dalaman dan aplikasi perusahaan pihak ketiga. YiDA, sebagai aplikasi perusahaan pihak ketiga, turut tertakluk kepada had QPS. Bagi setiap endpoint DingTalk yang dipanggil sendiri oleh YiDA, kekerapan maksimum ialah 40 panggilan/saat. Untuk maklumat terperinci, lihat had kadar.

  
</Accordion>
<Accordion id="q4" title="S: Jika saya telah membeli kedua-dua DingTalk Edisi Profesional dan YiDA, standard had kadar QPS yang manakah terpakai?">
  J: Oleh kerana panggilan API perniagaan berkaitan YiDA tidak tertakluk kepada had dasar tersebut, tanpa mengira edisi DingTalk yang dibeli oleh pelanggan YiDA, standard QPS ialah kekerapan maksimum 40 panggilan/saat.
