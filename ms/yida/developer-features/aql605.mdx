## 1. Nota Penggunaan

### 1.1 Peraturan Penggabungan URL HTTP

API peringkat aplikasi kini disokong. Dalam sesebuah aplikasi (panggilan merentas aplikasi juga disokong), anda boleh mengakses API yang berkaitan menggunakan format berikut:

```text
${Domain YiDA}/dingtalk/web/${Kod aplikasi} + laluan API.
```

Sebagai contoh, untuk memanggil API perkhidmatan "Instans aliran kerja – Mula aliran kerja" daripada pelayar bagi aplikasi dengan kod APP_X1X2X3X4, URL Permintaan yang digunakan dalam panel data ialah (**laluan relatif sudah memadai**):

```text
/dingtalk/web/APP_X1X2X3X4/v1/process/startInstance.json
```

  ![](https://gw.alicdn.com/imgextra/i4/O1CN01wgArQ34ORwC1hk7A_!!6000000000530-2-tps-840-868.png)

Untuk demo langsung yang terperinci, lihat [II. Instans aliran kerja] → [1. Mula aliran kerja].

**Nota: Dalam versi semasa, medan searchFieldJson dan dynamicOrder memerlukan nilai jenis string. Contohnya:**

```javascript
const someJson = {
	"textField_kkm9o5cd":"123"
}

// Menghantar someJson terus ke searchFieldJson tidak memberi kesan. Gunakan JSON.stringify untuk menukar object kepada string.
const fieldJson = JSON.stringify(someJson); // '{"textField_kkm9o5cd":"123"}'
```

Tulis kod pengikatan di bawah. Perhatikan bahawa kita memasukkan nilai tetap `123` untuk kawalan Borang Teks satu baris (pengenal unik: `textField_kkm9o5cd`).

Anda boleh dapatkan parameter formUuid dan processCode di bawah [Tetapan Aplikasi] – [Data Aplikasi] – [XX aliran kerja] sebagai ID Borang dan Kod aliran kerja.

```javascript
export function onClick(){
  const params = {
    "processCode":"TPROC--CFYJ5HYUN89NJ1JW3IXBI7A95RXM3652O9MKK3",
    "formUuid": "FORM-CFYJ5HYUN89NJ1JW3IXBI7A95RXM3552O9MKK2",
    "formDataJson": '{"textField_kkm9o5cd":"123"}'
  }

  this.dataSourceMap.myDatasource.load(params).then((response) => {
    this.utils.dialog({
      method: 'alert', // atau confirm
      title: 'Permintaan berjaya',
      type: 'success', // Pada PC, info/success/error disokong
      content: `Respons: ${response}`,
    })
  })
  console.log('onClick');
}
```

### 5.2 Format Nilai Komponen untuk Carian Syarat Mengikut Nilai Komponen

- Setiap Komponen dalam Borang mempunyai ID unik (boleh dilihat dalam panel Premium di sebelah kanan Komponen dalam pereka bentuk halaman), dan format Carian setiap Komponen berbeza. Komponen Borang yang disokong pada masa ini untuk Carian ialah: Satu baris, pelbagai baris, Nombor, Pilih, Pilih Tunggal Dropdown, Pilih Banyak, Pilih Banyak Dropdown, Tarikh, Julat tarikh, Kotak carian pengguna, Pilih Wilayah, Pilih Jabatan, Pilih Berjenjang, dan Komponen subborang.

### 5.4 Format Data Borang sebagai Nilai Pulangan

Format Data Borang sebagai nilai pulangan pada dasarnya sama seperti dalam "Lampiran 1 – Format data Simpan/Kemas kini Borang". Perbezaannya ialah:

- Semasa penghantaran, nilai Komponen Wilayah ialah ["ID Wilayah", "ID Bandar", "ID Daerah"]. Sebagai nilai pulangan, ia ialah ["Nama Wilayah","Nama Bandar","Nama Daerah"].
- Pilih, Pilih Tunggal Dropdown, Pilih Banyak, dan Pilih Banyak Dropdown diantarabangsakan. Sebagai nilai pulangan, ia mengembalikan nilai data yang sepadan dengan parameter `language` yang anda hantar.
