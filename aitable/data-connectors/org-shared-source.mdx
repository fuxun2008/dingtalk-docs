## What is a shared data source

Use the org-shared data source to publish a data table as the org's source of truth. Other users in the org can sync the source into their own AI Tables for use and analysis — boosting data flow efficiency inside the org.

## Use cases

1. HR builds a "Company business contacts" basic info table and publishes it as a shared data source (updatable any time). Employees can sync the latest contact data and view it.
2. Procurement member C maintains "Factory info & monthly new product list" by aggregating partner factory info and recommended monthly products. After building the table, C publishes it as a shared data source visible only to 4 e-commerce ops members. The ops members can sync the shared table into their own AI Table for review and selection.

## Publish a shared data source

1. Click the icon on the right of the data table → pick **Publish as shared data source**.

2. Pick the specific view, set source title / description, and choose the share scope:
   - **Shared view**: only grid views are supported.

     ⚠️ Note: if the chosen grid view has filter conditions that hide some data, others syncing this shared source see only the filtered subset.
   - **Source title**: shown on the source card.
   - **Source description**: shown on the source card; keep it short — under 1 line is recommended.
   - **Share scope**: default is everyone in the org; you can set specific users / groups / departments.

## View published shared sources

1. In the AI Table left sidebar bottom, click **+ Add / Import** to open the Data sync center panel.
2. Click **Data sync center**.
3. In the left panel, expand Shared data source → click **Org shared sources / My published sources**.

## Use a shared source

1. Open **Data sync center** → **Org shared sources**.
2. Hover over the source you want → click **Use**.

3. Click **Use** to finish syncing the shared source.

## Edit sync settings after sync

- For the synced table, click the icon on its right → **Data sync settings**, **Refresh data**, **Detach sync**, etc.
- Edit **data sync settings** by toggling auto-sync hourly in the panel.

## Cancel sharing

1. Open **Data sync center**.
2. Click **My published sources**, find the source to cancel, click **Cancel** on the card's top-right, confirm to finish.
3. **Actively detach existing sync tables** means tables that referenced this shared source can no longer sync the latest data.

## FAQ

#### Q: Who can publish a shared data source?

A: Currently only the AI Table's admin can publish a data table as a shared source.

#### Q: When publishing a shared source, are the specified users / groups / departments added to the current AI Table directly?

A: Yes. Users, groups, departments — they're all really added to the current AI Table's permission group with **download** permission. If you set the publish scope to **everyone in the org**, the current AI Table's permission is changed to **public to org**.

#### Q: If the source table has advanced permissions enabled, can others in the org still sync data from it?

A: No. The permission rules for syncing a shared source follow the AI-Table-to-AI-Table data sync rules. If the source AI Table (call it A) has no advanced permissions, the syncer only needs **download** permission on A. If A has advanced permissions, the syncer needs **manage** permission on A.

#### Q: Can I cancel a published shared source?

A: Yes. Two cancel modes:
- Plain cancel (you didn't check "detach existing tables' sync") — the source no longer shows up in the data source center; tables that already established a sync relationship can still continue syncing the latest data.
- Detach cancel (you checked "detach existing tables' sync") — all tables with existing sync relationships are passively detached and can no longer sync the latest data.

Start syncing data from the shared source.
