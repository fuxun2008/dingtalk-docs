## Overview

With **view / download or edit permission**, DingTalk Spreadsheet data can be synced to AI Table via the AI Table Data sync center.

Synced fields can't be edited in AI Table, but you can still add custom fields. On top, you can use AI Table's automation, advanced permissions, dashboards, etc.

If you need to freely edit the sync table, you can detach sync at any time, or duplicate the sync table — the duplicate has no effect on the original DingTalk Spreadsheet.

## ⚠️ Must read before syncing: DingTalk Spreadsheet format requirements

When establishing the sync, the system maps fields and content between the two — to keep sync accurate, check and adjust the spreadsheet format first:

[Why must I follow these format requirements before sync?](/aitable/data-connectors/dingtalk-spreadsheet-sync/format-requirements)

| **First row of the spreadsheet** | **First column of the spreadsheet** |
| --- | --- |
| ⚠️ No empty cells   ⚠️ No duplicate names   ⚠️ After sync, don't modify the first cell of the first row   ⚠️ After sync, prefer not to modify the first row | ⚠️ No duplicates   ⚠️ Not multiple empties   ⚠️ After sync, the first column can't be deleted or moved |

### Must read 1: First row of the spreadsheet

The first row of the spreadsheet becomes AI Table fields at sync time. Since AI Table doesn't allow empty or duplicate field names, check and adjust the first row before syncing.

#### First-row cells preferably shouldn't be empty

If there are empty cells in the first row, **sync still proceeds**, but in AI Table the empty fields auto-rename to **Unnamed Column_X**.

If the first row has duplicates, **sync still proceeds**, but in AI Table duplicates auto-rename to **field-name_X**.

#### After sync, prefer not to modify first-row content

Once sync is established, don't modify any field name in the first row (which becomes AI Table fields). Renaming a field is the same as deleting + recreating — subsequent syncs write data to a new field. **This may break dashboards, automations, etc., that depend on the original field**.

### Must read 2: First column of the spreadsheet

#### After sync, the first column can't be deleted or modified

If the spreadsheet's **first-column data is deleted, the column name is changed, or a new column is inserted before the first column**, that's the same as removing the AI-Table sync table's primary key — sync fails with a red error in AI Table.

#### First-column data must not duplicate (incl. multiple empty cells)

If the first column has duplicate content, only the first record of each duplicate is kept, and AI Table shows a yellow warning.

If the first column has multiple empty cells (treated as duplicate content), only the first record is kept, and AI Table shows a yellow warning.

### Must read 3: Column-count limit

A single data source can sync up to **300 columns** from the source spreadsheet to AI Table — **including empty columns**. If the source has many empty columns, they count toward the limit; only the first 300 columns sync, with a yellow warning in AI Table.

**So before syncing, remove unnecessary empty columns to keep within the limit.**

### Must read 4: Locked regions in the spreadsheet

If the source DingTalk Spreadsheet has locked regions you can't view, those can't sync. Confirm and try again. (Action: open the source, check the usage notes.)

## Using sync in AI Table

| Once sync completes, a new AI Table is generated | Synced fields can't be edited; you can still add fields and content for management, and use dashboards, automations, advanced permissions, etc.   Note: if you duplicate the sync table, the duplicate becomes a regular table — content is freely editable, with no relationship to the source. |
| --- | --- |
| Edit sync settings | Open the synced table → click the ⋮ More icon next to the table name → **Data sync settings**. Change synced fields and sync mechanism, and turn auto-sync on / off. |
| Manual refresh | Click **Refresh data** to manually sync. |
| Detach sync | Click **Detach sync** — the sync table becomes editable and no longer follows the source. |

## FAQ

#### Q: Why did the sync fail with a red error: "first column deleted or moved"?

A: This means after syncing, you did one of the following to the spreadsheet's first column:

- Deleted the first column.
- Renamed the first column.
- Inserted another column before the first column.

#### Q: Why didn't some data sync? With a yellow warning: "Check whether the source's first column has duplicates (incl. multiple empty cells)"?

A: This is caused by **duplicate content or multiple empty cells in the first column** of the spreadsheet — please adjust the spreadsheet.

#### Q: Why does the spreadsheet need first-row / first-column format requirements?

[Why must I follow these format requirements before sync?](/aitable/data-connectors/dingtalk-spreadsheet-sync/format-requirements)

#### Q: Why did my spreadsheet field name change after syncing to AI Table?

A: Likely because the spreadsheet's first row has **empty field names** or **duplicates**:

- Empty field names auto-convert to **Unnamed Column_X**.
- Duplicate field names auto-rename to **field-name_X**.

#### Q: Is there a column-count limit for DingTalk Spreadsheet sync?

A: Yes — a single data source supports up to **300 columns (including empty columns)**.

#### Q: What permissions do I need to sync DingTalk Spreadsheet data to AI Table?

A: You need both:

- Copyable permission (view / download or above) on the DingTalk Spreadsheet.
- Manage permission (admin or owner) on the target AI Table.

#### **Q: Is there a row-count limit for cross-AI-Table sync?**

A: Yes — up to 20,000 rows. One AI Table can have at most 100 data tables.

#### Q: Can I edit the synced data?

A: No — read-only. You can't edit, delete, or add records, nor create a form view.

#### Q: Does deleting the data source affect sync?

A: After deleting the data source, already-synced data is retained, but no further sync.

#### Q: Why does it say "Source DingTalk Spreadsheet file too large"? What do I do?

This message means the source spreadsheet's overall content is too large for the sync to handle in this round.

It's usually not a single cell — it comes from the source having too much of:

- Many sheets.
- Many rows / columns.
- Lots of empty-but-occupied rows / columns.
- Lots of complex content, making the file large.

To make sync succeed, slim down the source spreadsheet first:

1. Delete sheets you don't need to sync.
2. Delete invalid empty rows / columns.
3. Keep only the data range you need to sync.
4. Split a large sheet into multiple smaller sheets and sync each.

If sync still fails after slimming, split the content further and retry.
