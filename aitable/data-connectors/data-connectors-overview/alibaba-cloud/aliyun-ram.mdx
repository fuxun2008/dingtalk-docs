AI Table supports the **Aliyun Resource Access Management (RAM) connector** to sync **RAM role info** and **RAM user info** under your Aliyun account — for unified management of cloud account permissions, members, and roles.

This guide walks you through:

- Sign in to the Aliyun console.
- Get AccessKey ID and AccessKey Secret.
- Create the Aliyun RAM data source in AI Table.
- Configure parameters and fields, complete the sync.

## 1. Prep

Before you start, confirm:

- A registered Aliyun account you can sign in to.
- The account has **RAM** enabled.
- You have read-or-above RAM permissions.
- You have AI Table access.

> ⚠️ Prefer a **RAM sub-account + AccessKey** rather than primary-account keys.

## 2. Get the Aliyun AccessKey

AI Table calls the Aliyun RAM API via AccessKey — create one in the Aliyun console first.

### 1. Sign in to the Aliyun console

1. Open Aliyun: [https://www.aliyun.com](https://www.aliyun.com "https://www.aliyun.com").
2. Click **Sign in** in the top-right.
3. Sign in with your Aliyun account.

### 2. Create or get the AccessKey (RAM user recommended)

1. After sign-in, open **RAM (Access Control)**.
2. Pick **Users** in the left menu.
3. Create or pick an existing RAM user.
4. Grant permissions (at minimum RAM read-only):
   - Example: `AliyunRAMReadOnlyAccess`.
5. Open **Authentication management**.
6. Create an AccessKey.
7. Copy and save:
   - **AccessKey ID**
   - **AccessKey Secret**

> ⚠️ AccessKey Secret is only shown once at creation — save it.

## 3. Create the Aliyun RAM data source in AI Table

### 1. Open the Data sync center

1. Open AI Table.
2. Click **Data sync center** at the top.
3. Search for **Aliyun**.
4. Pick **Aliyun RAM**.

## 4. Data source settings

Pick the data type to sync:

### Supported data source types

- **Aliyun RAM role list**

  Sync all RAM roles under the current account.
- **Aliyun RAM user list**

  Sync all RAM users under the current account.

Pick one (or create multiple data sources).

## 5. Account settings

Link your Aliyun account.

### Field reference

| Field | Description |
| --- | --- |
| Account name | Custom label to distinguish multiple Aliyun accounts in AI Table |
| AccessKey ID | From the Aliyun console |
| AccessKey Secret | From the Aliyun console |

Click **Confirm** when done.

> 🔒 AI Table encrypts AccessKey info at rest — used only for sync.

## 6. Parameters

### Endpoint (required)

Aliyun RAM service API endpoint.

- Default: `ram.aliyuncs.com`.
- Usually no need to change.

## 7. Fields

Pick which fields to sync into AI Table.

### 1. RAM role fields

| Field | Description |
| --- | --- |
| Role ID | Unique RAM role identifier |
| Role name | RAM role name |
| Role description | Role description |
| Created at | Role creation time |
| Updated at | Last update time |
| Max session duration | Role max session length |
| Resource descriptor | Role resource identifier info |
| Tags | Tags bound to the role |

### 2. RAM user fields

| Field | Description |
| --- | --- |
| RAM user ID | Unique user identifier |
| RAM user name | User name |
| Login name | User login name |
| User email | Bound email |
| Phone | Bound phone |
| Created at | User creation time |
| User updated at | Last update time |
| Notes | User notes |

You can:

- Check **Select all** to sync all fields.
- Or pick only business-relevant fields.

## 8. Sync settings

### Modes

- **Off (default)**

  Data updates only on creation or manual trigger.
- **On**

  System auto-syncs RAM data on the configured cadence.

> Recommended for scenarios with frequent permission churn.

## 9. Done — view data

1. Click **Create** in the bottom-right.
2. AI Table starts pulling Aliyun RAM data.
3. Once complete, view the role or user list in AI Table.
4. Use the data for filters, permission inventory, member management, or audit analysis.

## 10. FAQ

#### Q1: Permission denied or fetch failed?

- Confirm the RAM user has RAM permissions.
- Check the AccessKey was entered correctly.

#### Q2: Why are some users / roles missing?

-
- Confirm the resources actually exist under the account.
- Check whether the right AccessKey is in use.

#### Q3: Is the AccessKey safe?

- AI Table encrypts keys at rest.
- Used only by this data source — never exposed externally.
