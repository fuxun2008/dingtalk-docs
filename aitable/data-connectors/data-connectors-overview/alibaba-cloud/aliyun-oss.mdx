AI Table supports the **Aliyun Object Storage Service (OSS) connector** to sync your account's OSS bucket info to AI Table — for unified management and analysis.

This guide walks you through:

- Sign in to the Aliyun console.
- Get AccessKey ID and AccessKey Secret.
- Create the Aliyun OSS data source in AI Table.
- Configure parameters and fields, complete the sync.

## 1. Prep

Before you start, confirm:

- An **Aliyun account**.
- The account has **OSS service** enabled.
- The current account has **read or above** permission on OSS resources.
- You have AI Table access.

> ⚠️ Prefer a **RAM sub-account + AccessKey** rather than primary-account keys.

## 2. Get the Aliyun AccessKey

AI Table calls the Aliyun OSS API via AccessKey — create one in the Aliyun console first.

### 1. Sign in to the Aliyun console

1. Open Aliyun: [https://www.aliyun.com](https://www.aliyun.com "https://www.aliyun.com").
2. Click **Sign in** in the top-right.
3. Sign in with your Aliyun account.

### 2. Create / get the AccessKey

#### Option 1: RAM user (recommended)

1. After signing in, open **RAM (Access Control)**.
2. Pick **Users** in the left menu.
3. Create or pick an existing RAM user.
4. Grant the user permissions (at minimum OSS read-only, e.g. `AliyunOSSReadOnlyAccess`).
5. Open **Authentication management**.
6. Create an AccessKey.
7. Copy and save:
   - **AccessKey ID**
   - **AccessKey Secret**

> ⚠️ AccessKey Secret is only shown once at creation — save it.

#### Option 2: existing AccessKey

If you already have one, see **RAM → Users → AccessKey management** for the AccessKey ID, and re-create the Secret if needed.

## 3. Create the Aliyun OSS data source in AI Table

### 1. Open the Data sync center

1. Open AI Table.
2. Click **Data sync center** in the bottom-left.
3. Search for **Aliyun**.
4. Pick **Aliyun OSS**.

### 2. Pick the data source

Currently supported data source type:

- **Aliyun OSS bucket list**

  Sync basic info for all OSS buckets under the current account.

Confirm and continue.

## 4. Account settings

Link the Aliyun account info.

### Field reference

| Field | Description |
| --- | --- |
| Account name | Custom label to distinguish multiple Aliyun accounts in AI Table |
| AccessKey ID | From the Aliyun console |
| AccessKey Secret | From the Aliyun console |

Click **Confirm** when done.

🔒 AI Table encrypts keys at rest — used only for data sync.

## 5. Parameters

### 1. Region (required)

Specifies the OSS service region.

- Example: `cn-hangzhou`, `cn-shanghai`.
- Determines the OSS API endpoint.

> If your buckets span multiple regions, create one data source per region.

### 2. Prefix (optional)

Filter buckets by name pattern.

- Empty: sync all buckets under the account.
- With prefix: only sync buckets whose names start with the prefix.

Examples:

- `prod-`: only sync `prod-xxx` buckets.
- `test/`: sync resources under the path (where supported).

## 6. Fields

Pick which fields to sync into AI Table.

| Field | Description |
| --- | --- |
| Name | OSS bucket name |
| OSS-specific Region ID | Bucket's actual region |
| Aliyun common Region ID | Aliyun unified region identifier |
| Public access endpoint | Bucket's public access URL |
| Internal access endpoint | Bucket's internal access URL |
| Bucket storage class | Standard / Infrequent Access etc. |
| Bucket creation time | When the bucket was created |
| Notes | Reserved for extension |

You can:

- Check **Select all** to sync all fields.
- Or pick only business-relevant fields.

## 7. Sync settings

### Modes

- **Off (default)**:

  Data updates only on creation or manual refresh.
- **On**:

  System auto-syncs OSS data on the configured cadence.

> Pick based on data churn and use case.

## 8. Done — view data

1. Click **Create** in the bottom-right.
2. The system pulls OSS data.
3. Once complete, view the OSS bucket list in AI Table.
4. Use the data for filters, analytics, or linking with other tables.

## 9. FAQ

#### Q1: AccessKey says "no permission" — what's wrong?

- Confirm the RAM user has OSS permissions.
- At minimum, OSS read access.

#### Q2: Why are some buckets missing?

- Check the **Region** matches.
- Check whether a prefix filter is set.

#### Q3: Will my AccessKey leak?

- AI Table encrypts keys at rest.
- Used only by this data source — never exposed externally.
