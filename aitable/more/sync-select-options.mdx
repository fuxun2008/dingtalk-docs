AI Table's single- and multi-select fields can **sync options from another table** — reference single / multi-select options from the current table or any other table inside the same AI Table. The basic case: don't reconfigure the same options twice. The advanced case: build cascading dependencies between multiple single / multi-select fields.

## Reusing options

When configuring a single / multi-select field:

1. Check **Sync options from another table**.
2. Pick the source table.
3. Pick the source single / multi-select field.
4. Add filters (optional).

## Cascading dependencies

It's common to capture multi-level data in AI Table — for an address, you usually pick country → province → city → district one level at a time. Pick a province first and the city dropdown only shows that province's cities. Here's an employee picking an office location to walk through how cascading works.

A multinational has offices in Asia, North America, and Europe. Employees pick a region first, then an office. The office dropdown is restricted to offices in the chosen region.

It takes two steps to wire up:

### Set up the source table

Create a new table — say **Office directory** — with two single-select fields: **Region** and **Office**. List every office and its region:

Note: list every **Office** and its **Region**.

### Wire up the dependent fields

Create another table — say **Employee work location** — with two single-select fields: **My region** and **My office**.

Configure **My region**:

1. Check **Sync options from another table**.
2. Source table: **Office directory**.
3. Source field: **Region**.

Configure **My office**:

1. Check **Sync options from another table**.
2. Source table: **Office directory**.
3. Source field: **Office**.
4. Add a filter — source field: **Region**.
5. Current-table field: **My region**. The condition reads: **Office directory**'s **Region** equals **Employee work location**'s **My region**.

Once configured, the two single-select fields cascade in **Employee work location**.

For example, when Li Wei picks **Europe** as **My region**, **My office** is restricted to London and Paris.

## Add a province / city / district cascade

It's common to need a three-level cascade for province / city / district. Here's how to do it in AI Table.

### Add the China admin-region table

1. Click the **+** at the bottom-left of the AI Table > **Add / Import**.
2. Choose **Data Connector Center**.

   Learn more: [Cross-table sync between AI Tables](/aitable/data-connectors/cross-table-sync)

1. In the data-source center, pick **Org-shared data sources**.
2. Choose **China administrative regions**.

The synced table **China administrative regions — province / city / district** now shows up in your table list.

### Add province / city / district to your table

1. Add three single-select fields to your own table: **Province**, **City**, **District**.
2. Configure each one:

   **Province**: just check **Sync options from another table**. Source table: **China administrative regions — province / city / district**. Source field: **Province / Municipality / Autonomous Region**.

   **City**: a bit more involved — needs to filter by province.
   1. Check **Sync options from another table**.
   2. Source table: **China administrative regions — province / city / district**.
   3. Source field: **City**.
   4. Source filter field: **Province / Municipality / Autonomous Region**.
   5. Current-table field: **Province**.
      Meaning: the city dropdown pulls from **China administrative regions**, but it has every city — restrict to cities in the selected **Province**.

   **District**: similar — filter by city.
   1. Check **Sync options from another table**.
   2. Source table: **China administrative regions — province / city / district**.
   3. Source field: **District / County**.
   4. Source filter field: **City**.
   5. Current-table field: **City**.
      Meaning: the district dropdown pulls from **China administrative regions**, but it has every district — restrict to districts in the selected **City**.

Once configured, the three-level province / city / district cascade is live.

Note: if you're using **multi-select** instead, change the **City** and **District** filter operator from **equals** to **contains**.

## FAQ

#### Q: When syncing options from another table, what field types can I reference?

A: Only single-select or multi-select fields.

#### Q: Can I add multiple filter conditions when syncing options?

A: Yes, up to 5.
