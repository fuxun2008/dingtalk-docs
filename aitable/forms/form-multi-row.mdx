## What's a line-items question?

The **line-items** question is an advanced form question. It can hold multiple fields / questions and only works in form views. After the form admin sets it up, respondents can fill in multiple rows in a single submission and bulk-submit them to the table — fewer round-trips, faster and more accurate entry.

## When to use it

**Expense reports / financial detail**

Multiple expenses entered at once — travel reimbursement, project settlement. Respondents can enter line items (date, expense type, amount, invoice file) row by row and submit, generating multiple expense records in one go.

**Live-stream session category logging**

When one live stream covers multiple product categories. Ops adds line items for each category in the same form (category name, products, price range, on-shelf time, talking points, stock), and submits to create multiple category records at once.

**Procurement / inventory item lists**

When a procurement, receiving, or shipping run involves multiple items. Respondents log each item (name, spec, quantity, unit, notes) in line items and submit, generating multiple item records — clean for stock counting, in/out tracking, and management.

**Time tracking, tasks, or process logs**

When you need to enter many time-sheet or process entries at once — project hours, phased task records. Row-by-row entry (date, task, duration, notes), one submit creates many records, less repetitive filling.

**Education and bulk people entry**

When you need to enter info on multiple people at once — student grades, behavior records, visitor logs. Each row is one person; submitting creates that many independent records.

**More**

Line items also fit any business flow that needs to capture many same-shape records: equipment inspections, QC details, event participation, training sign-in, patrol logs, issue lists, process logs. Anywhere you have **same-structure, many-record, single-session** input, line items work.

## For form admins — adding and configuring line items

Line items are added by the **form admin** during form setup, to enable **bulk-entry submissions**. After setup, respondents can **add multiple rows in the same form and submit them all at once**.

**Open the form editor**

In AI Table, create a new form view and enter the form editor — you'll find **Line items** in the advanced question types on the left.

**Add the line-items question**

Select **Line items** from the advanced question types and add it to the form. Line items can mix with other question types — put it where it makes sense for your flow. After adding, you can edit the title and description.

Note: only one line-items question per form.

**Add questions / fields inside line items**

You can drag available questions / new question types from the left, or existing form questions, into the line items. For each one, set required, format, default value, etc.

Option 1: drag or click an existing field at the top-left.

Option 2: drag from the bottom-left, or click to add a new field.

Option 3: drag an existing form field into the line items.

Option 4: insert a question / field directly to the left or right inside the line items.

Notes:

1. Fields inside line items are for **multiple same-shape records** — different entries row by row in one submission. For example: in a single expense submission with multiple invoices, fields like "Date" and "Amount" belong inside line items.
2. Field types supported in line items match the form view — workflow, button, Created by, Updated by, Last updated time are not supported.

**Configure questions / fields inside line items**

Set title, field type, format, required, default value — these **sync to the table's fields**.

**Reorder questions / fields inside line items**

Drag to reorder. You can also drag a field out of the line items to make it a regular form question.

Note: reordering fields inside line items only affects how the form is shown — it doesn't change the actual field order in the table. Grouping fields inside line items doesn't generate a corresponding group in the grid view either.

**Remove a question / field from line items**

Removing a question / field puts it back in the **Available questions / fields** area at the top-left.

**Note: if you also check "Delete the field from the table", the field is removed from the table.**

**Other line-items settings**

Set **Max rows** (up to 100). After setup, respondents can submit up to that many records per submission.

Toggle **Required** for the line items as a whole — if on, respondents must fill at least one field value before submitting. If any single question / field inside is required, the line items as a whole becomes required.

**Remove line items**

Remove the line items — the inner questions / fields go back to the **Available questions / fields** area at the top-left.

When removing, you can also choose to delete the fields from the table. **If checked, the corresponding fields are deleted from the table.**

## For respondents — filling out line items

When the form contains line items, respondents can enter multiple same-shape records in one submission and submit them all at once.

After submission, multiple rows are created in the table.

## FAQ

**Q: What kinds of fields belong inside line items?**

A: Fields you fill in row-by-row — different content per row in a single submission.

**Q: What kinds don't belong?**

A: Fields you fill once that apply to the whole submission — applicant, department, project name, overall notes.

**Q: Does each row in line items become its own record in the table?**

A: Yes. Each row is saved as an independent record. Other fields in the form auto-fill across the rows, producing complete multi-row data.

**Q: Is the line items thing itself a field? Do its title and description show in the table?**

A: No. Line items isn't a field — it's a form question type for batch entry. Its title and description are for respondents only and don't appear in the table.

**Q: How many line items can a form have?**

A: One. This keeps the form structure clear and avoids ambiguous data combinations from multiple expanding line-item groups.

**Q: How is data sorted after submission?**

A: Submission order. The view's current sort rules apply on top.

**Q: How many rows can a respondent add in one submission?**

A: Up to **10 rows** at the moment.
