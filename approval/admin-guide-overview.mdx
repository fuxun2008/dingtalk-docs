## 1. Product Introduction

DingTalk OA Approval is an official DingTalk app that delivers an out-of-the-box OA Approval product. With simple configuration, it flexibly meets an organization's day-to-day approval needs, improves team management and business efficiency, helps enforce management policies, and reduces operational risk.

## 2. Usage Instructions

##### 3.2 Form Settings

Configure the Approval form Content — that is, what submitters see and fill out when submitting an Approval.

1) Available control library

Includes multiple controls such as options, Number, Text, and Date. Click or drag a control from the left panel to add it to the form; long-press and drag a control to reorder it freely.

<Frame>

![Available control library panel](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/YdgOk2b0JJJNXq4B/img/32056a2b-c180-49ac-bbf3-0802ecb7f2b9.png)

2) Available control groups

DingTalk Approval also provides **attendance/HR control groups such as leave request, overtime, hiring, and offboarding; finance control groups such as reimbursement and payment; and legal control groups such as contract and seal use**. These control groups are linked with Attendance clock-in / Smart HR / Smart Finance / Smart Contract, so when an Approval containing a control group is used, the employee's attendance, on/offboarding, reimbursement/payment, and contract/seal-use data are synchronized automatically to the Attendance clock-in / Smart HR / Smart Finance / Smart Contract systems.

You can **click** or **drag** the desired control group to add it, then configure it on the right. **Each form can contain at most one control group.**

<Frame>

![Available control groups panel](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/jP2lRYjZmyDkLO8g/img/173e7c4e-5661-4ccc-82f9-1b5e3f81efac.png)

3) Basic Settings

Basic Settings typically include: control title, hint text, control rules (such as option settings for a Select control or Type settings for a Date control), and whether the control is printable and Required.

2) Approval Step types

| **Step type** | **Description** | **Details** |
| --- | --- | --- |
| initiator | The initiator Step is the starting point of an Approval process. On this Step, you can configure who can submit this Approval form and which Fields the initiator can fill out |   Default Step<br />    <br />The Step name cannot be modified<br />    <br />After submission, view it in the "Submitted by me" category of the process center<br />    <br />Field permissions on the form can be configured — editable, Read-only, and hidden are supported |
| approver | Can perform Accept, Decline, transfer, return, sign request, and Comments actions on the Approval form |   Optional Step<br />    <br />The Step name can be modified<br />    <br />Before approval, view it in the "To Do" category of the process center; after approval, view it in the "To Do" category of the process center<br />    <br />Field permissions on the form can be configured — editable, Read-only, and hidden are supported |
| CC recipient | When the process routes to this Step, this role has no review capability but receives the Approval form and can view and comment on it |   Optional Step<br />    <br />The Step name can be modified<br />    <br />After the process routes to this Step, view it in the "CC'd to me" category of the process center<br />    <br />Field visibility on the form can be configured — Read-only and hidden are supported |
| handler | Can perform Submit, transfer, return, sign request, and Comments actions on the Approval form |   Optional Step<br />    <br />The Step name can be modified<br />    <br />Before handling, view it in the "To Do" category of the process center; after handling, view it in the "To Do" category of the process center<br />    <br />Field permissions on the form can be configured — editable, Read-only, and hidden are supported |
| conditional branch | This Step routes different situations to different Approval branches<br />See >>> [How to set up conditional approval](/approval/set-conditional-approval) |   Optional Step<br />    <br />Branch names can be modified<br />    <br />Branches can be copied<br />    <br />Conditions can be added — different conditions within a set have an "AND" relationship<br />    <br />Condition groups can be added — different Condition groups have an "OR" relationship<br />    <br />At runtime, branches are **evaluated in priority order**<br />    <br />Once any branch's rules pass, the remaining branches are not tried — **at most one conditional branch executes** |
| parallel branch | This Step routes multiple Approval branches simultaneously. |   Optional Step<br />    <br />Branch names can be modified<br />    <br />Branches can be copied<br />    <br />Conditions can be added — different conditions within a set have an "AND" relationship<br />    <br />Condition groups can be added — different Condition groups have an "OR" relationship<br />    <br />Multiple branches can **execute simultaneously** based on the rules you configure |
| Connector | This Step invokes a Connector configured in "My integrations" |   Optional Step |
| Automation | This Step |   Optional Step |

| **Approver type** | **Description** | **Details** |

5) When multiple people participate in the same Step, sequential approval, joint sign-off, single sign-off, and Vote are supported.

<Frame>

![Multi-approver modes for a single Step](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/jP2lRYjZmyDkLO8g/img/7b7a0f94-b657-46d1-b5df-47c4a248133f.png)

| **Approval mode** | **Description** | **Details** |
| --- | --- | --- |
| Sequential approval | Multiple approvers approve in sequence | Approvers act one after another, and the Approval passes only when all Accept |
| Joint sign-off | The Step passes only when all approvers Accept | Approvers act simultaneously, and the Approval passes only when all Accept |
| Single sign-off | The Step passes when any one approver Accepts | Approvers act simultaneously; when any one Accepts, the Approval passes; when any one Declines, the Approval does not pass |
| Vote | Passes when the configured number of Accept votes is reached | Approvers act simultaneously; the Approval passes once the required number of Accept votes is reached |

Selecting another type — such as manager or Role — replaces the manager or Role settings, and the approvers in the Approval process are then replaced automatically.
