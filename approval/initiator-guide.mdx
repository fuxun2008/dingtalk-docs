## 1. Role overview

<Note>
In DingTalk OA Approval, organization members who submit approval requests are collectively called initiators.

Initiator permissions:

*   Search for and view forms they are allowed to initiate (such as leave request, business trip, and reimbursement).

*   Fill in Form Fields by typing or selecting, following the rules set on the form.

*   Submit the form once the entered information is correct and every Required field is complete; when approvers must be picked manually, select approvers from the organization according to the rules set on the form.

*   Track approval progress at any point during the Approval process.

*   Undo or modify the Approval form during the Approval process, subject to the rules set on the form.

*   Download details of Approval forms within their management scope.

**Note**: Form initiation Permissions, Form Fields, Required rules, Approval process, Undo, and modification rules are all configured by the organization's Approval Admin.
</Note>

## 2. Core actions

Initiator core actions are organized into the following 8 steps in order of use — jump to any step as needed:

| **Action** | **Description** |
| --- | --- |
| Open the Approval app | Find the **OA Approval** app on the Workbench or in the sidebar |
| Open the Approval form | Find the Approval form you need on the Workbench, in OA Approval, or in the sidebar |
| Fill in the Approval form | Enter or select values to fill in the form as required |
| Submit the Approval form | Submit the request once it meets the requirements; if submission fails, check against the common cases |
| View approval Progress | Track Progress at any time in **OA Approval** — **Initiated by Me** |
| Undo the Approval form | The initiator can Undo an Approval form once the Admin has turned On Allow Undo |
| Modify the Approval form | The initiator can modify an approved Approval form once the Admin has turned On Allow Modify |
| Download approval details | Download Approval form details from the approval detail Page |

#### Common submission failure cases

If Submit shows a message saying the form cannot be initiated, check against these 6 common cases:

<Steps>
<Step title="Case 1: A Required Field is empty">

<Frame>

![Tips that a Required Field is empty](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/8K4nyeZ9azDejnLb/img/9a32e851-a2e1-4c10-b690-4a6a05ebb733.png)
</Frame>

Cause: One or more Required fields are empty.

Fix: Follow the red Tips to complete the fields, then Submit.

</Step>
<Step title="Case 2: Initiating Department not selected">

<Frame>

![Tips that an initiating Department must be selected](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/8K4nyeZ9azDejnLb/img/85f69cc7-694f-4632-8f52-d34780064978.png)
</Frame>

Cause: The organization User belongs to multiple departments, but no Department was selected when initiating.

Fix: Select the Department this approval belongs to, then Submit.

</Step>
<Step title="Case 3: An Approval form already exists for the same time range">

<Frame>

![Tips that an Approval form already exists in the same time range](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/8K4nyeZ9azDejnLb/img/2e28c511-db5d-4a53-9acb-a0957341a010.png)
</Frame>

Cause: For certain business types, an Approval form was already initiated for the same time range.

Fix:

1. View History, locate the existing request for the same time range, Undo it, then Submit again.

2. If there is no Undo Button (the Admin has set the form as non-undoable), contact the Approval Admin to Delete the time-Repeat Approval form in the Admin Console (this also deletes the related system Data).

You can forward the how-to to the Admin: [Admin managing form Data](/approval/admin-manage-form-data)

3. If you cannot find the existing request, the Admin has already deleted the Approval form but removed only the form itself, not the associated system Data. Ask the Admin to first restore the Trash Data, delete the associated system Data, and then submit again.

</Step>
<Step title="Case 4: Manually-selected approver not chosen">

<Frame>

![Tips that an approver must be selected](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/8K4nyeZ9azDejnLb/img/70d4fa43-5635-4285-afa8-38186789d618.png)
</Frame>

Cause: An Approval process node is set to "initiator selects", but the initiator submitted without picking an approver.

Fix:

1. Select an approver and Submit again.

2. Contact the Admin to configure the approver.

You can forward the how-to to the Admin: [Admin performing process design](/approval/admin-process-design)

</Step>
<Step title="Case 5: The process could not find an approver">

<Frame>

![Tips that the process engine could not find an approver](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/8K4nyeZ9azDejnLb/img/3ada7932-eea2-42e6-9edc-4f1e12953095.png)
</Frame>

Cause: An Approval process node is misconfigured — the process engine could not find an approver.

Fix: Contact the Admin to review the Approval process settings and configure the approver correctly.

You can forward the how-to to the Admin: [Admin performing process design](/approval/admin-process-design)

</Step>
<Step title="Case 6: No branch condition matches">

<Frame>

![Tips that no branch condition matches](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/8K4nyeZ9azDejnLb/img/f7418fd7-b1fb-4a94-89e5-aae92c19788a.png)
</Frame>

Cause: The Approval form uses conditional approval, and the branch conditions do not cover what the current initiator filled in.

Fix: Contact the Admin to review the conditional approval settings.

You can forward the how-to to the Admin: [Troubleshooting conditional approval errors](/approval/conditional-troubleshooting)

</Step>
</Steps>
