In some business scenarios, data view permissions must be assigned based on business attributes, such as the region or project department a User is responsible for.

Before this feature was available, the only way to handle such scenarios was to manually configure a dozen or more permission groups using "Custom User + Custom Condition" based on business needs. When multiple forms required the same permission setup, the same configuration had to be repeated manually. Both the initial creation and ongoing maintenance were tedious.

With this feature, you only need to maintain the basic information in a permission matrix once, and then configure a single permission group in the form permission settings by combining "Reference matrix users" with "Configure matrix condition."

The details are as follows.

## Prerequisites: Maintain a Permission Matrix and Upgrade to the New Data View

1. Maintain a permission matrix

In the permission matrix, maintain the assignment conditions and the matrix table for the corresponding roles. When responsibilities or Users change, update the matrix accordingly. Data permissions take effect in real time after the update.

For details on how to use a permission matrix, see [Permission matrix](/yida/platform-admin/bqc0fgwy5usglvrn).

2. Use the new data view (This feature is currently in gray release. To enable it, contact YiDA support.)

Upgrade the data view to the new version. Upgrade entry:

For an introduction to the new data view, see [New data view](https://docs.aliwork.com/docs/yida_updates/hqlg7m5vvlgs0d6k/zmztxwhgl5bbggw4).

## Reference a Permission Matrix in Form Data View Permissions

When configuring a permission group:

- For permission Users, select "From permission matrix": choose the target matrix and the role column that represents the Users in the current permission group.

- For the data range, select "By matrix condition": use the condition matching rules between form fields and matrix fields to determine the data range visible to each User.

**Tips:**

The condition column of the matrix supports two value types: Department or Custom text. To prevent incorrect matching rules, this release supports only basic text components in the form **(Single-line text, Multi-line text, Select, Multiselect, Dropdown Select, Dropdown Multiselect) and the Department component** in matrix condition settings for data view permissions.
