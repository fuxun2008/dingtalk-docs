<Note>
The OA Approval connector is currently available only on **DingTalk Professional edition** paired with **YiDA Professional edition (Premium)** or higher.
</Note>

This article walks you through using the OA Approval connector in YiDA, using a payment request triggered by a YiDA form as an example.

## Overview of the Approval Connector

- Form event triggers

The connector is invoked automatically when a YiDA form is created, edited, deleted, or commented on, enabling data to flow between YiDA and DingTalk OA.

- App event triggers

The connector fires when a new event occurs in an app — for example, when an employee submits a new overtime request through DingTalk OA Approval.

App event triggers let users fill in and submit an approval directly in DingTalk OA Approval. By configuring an **app event trigger**, you bind a DingTalk OA Approval to a YiDA form so that a new record is added automatically to the YiDA form whenever a request is submitted.

<Note>
**Configuration notes:**

1. Select a connector action: enter a name in the search box, or click to browse and locate the connector action you need.
2. Select a workflow form: first choose an approval app in DingTalk (such as OA Approval in the image above); this app must be created by the user in DingTalk. Then select the corresponding YiDA form (such as the overtime approval test in the image above).
3. Configure the action: bind the YiDA form to the DingTalk app through point-and-click configuration.
</Note>

### Step 2: Configure the Connector in Integration & Automation

1. Sign in to the YiDA workbench. Select the target app and open its Integration & Automation page.
2. Select the integration & automation flow you have created and click Edit.
3. Move the cursor to the connecting line between steps to bring up the **+** button, click **+**, and select Connector.
4. In the Attribute panel on the right, search for and select the Submit Instance connector.
