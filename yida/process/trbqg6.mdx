The table below summarizes each step type in a workflow form and links to its detailed configuration guide.

| **Step type** | **Description** |
|---|---|
| **Start Step** | The start step marks the beginning of a workflow. Every approval process includes a default start step, which cannot be deleted. On this step, you can configure the form field permissions available to the workflow initiator. |
| **Human Step** | Human steps include approver steps, operator steps, and CC recipient steps.<br />• [**Approver Step**](/yida/process/rq8i94): The approver processes the approval task on this step and must make decisions such as Accept or Decline. A workflow must contain at least one approver step.<br />• [**Operator Step**](/yida/process/bl1oq2): The operator does not make decisions. They only complete the assigned work, then return the workflow to the approver to continue processing. The operator's work is unrelated to approval.<br />• [**CC recipient Step**](/yida/process/cntvp8): Sends Message notifications to CC recipients after the approver completes approval. CC recipients do not need to approve or execute the task. |
| **Branch Step** | Branch steps include conditional branch steps, parallel branch steps, and sub-workflow steps.<br />• [**Conditional branch Step**](/yida/process/yv8dnv): A conditional branch step splits a workflow design into multiple branches. When the rule conditions are met, the execution actions of the corresponding branch steps run in full.<br />• [**Parallel branch Step**](/yida/process/row1axsz4s0ix2vl): A parallel branch step runs two or more branch tasks in parallel. Unlike conditional branches, when data is submitted, all task lines under the logical branches are triggered as long as the condition rules are met.<br />• [**Sub-workflow Step**](/yida/process/xgy1wgc95g65fusy): YiDA workflows allow you to add a sub-workflow step while designing the current workflow. A sub-workflow step is a special step. It supports multiple parameter-triggered modes to trigger another existing approval workflow form, which helps decouple and organize approval workflows. |
| [**Data Step**](/yida/integration/mmwrzb5agf5i9lvb) | The data step in a workflow form is the same as the data step in integration & automation. For details, see [Data Step](/yida/integration/nl4abrm791inlvm2). |
| [**Script Step**](/yida/process/ywnn9itpk2e52332) | YiDA workflows allow you to add a script developer step when designing the current workflow or integration & automation. |
| **Message Step** | Message steps include Message notifications steps and Mail Notification steps.<br />• [Message notifications](/yida/process/kvm0wu): Sends DingTalk Work Notifications or group notifications to specified users through a configured notification type when the workflow reaches a specific step.<br />• [Mail Notification](/yida/process/obvnvx): Sends Mail Notifications to specified users through a configured Mail Template when the workflow reaches a specific step. |
