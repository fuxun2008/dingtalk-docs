## **バージョン要件**

DingTalk 統合認可スイート SDK は、DingTalk バージョン **6.3.35 以降**が必要です。それより前のバージョンの場合は、ユーザーにクライアントのアップグレードを促してください。DingTalk のバージョンを確認するには、次の方法を使用します。

```
import { getENV, } from 'dingtalk-jsapi/lib/env';
import { compareVersion, } from 'dingtalk-jsapi/lib/sdk/sdkLib';

const { platform, version, appType, } = getENV();
/**
 * 現在のアプリバージョンが SDK をサポートしているか確認する
 * @return {boolean}
 */
function isAuthSDKSupport() {
  return compareVersion(version, '6.3.35');
}
```

## **1. 認可スイート SDK のインストール**

1. 次のコマンドを実行して SDK をダウンロードおよびインストールします（dingtalk-design-libs はバージョン 0.1.0 以降である必要があります）。

   ```
   npm install dingtalk-design-libs --save
   ```
2. ダウンロード完了後、SDK をコードに直接インポートします。

   ```
   import { openAuth } from 'dingtalk-design-libs/biz/openAuth';
   ```

## **2. App 認可の組み込み**

以下の手順に従い、DingTalk 統合認可スイートを使用して、ユーザーに関連情報の認可を案内します。

1. DingTalk 統合認可スイート SDK をインポートします。

   ```
   import { openAuth } from 'dingtalk-design-libs/biz/openAuth';
   ```
2. ユーザー認可が必要な場合は、**openAuth** を直接呼び出します。リクエスト例は次のとおりです。

   ```
   openAuth({
     clientId:'dingwlanwxxx', // アプリ ID（固定の識別子）
     corpId:'', // 現在の組織の組織 ID
     rpcScope:'Calendar.Event.Write,Calendar.Event.Read,Contact.User.Read', 
     fieldScope:'Contact.User.mobile',
     type:0 // 0 はプロフィールの認可、1 は組織情報の認可を示す
   }).then((res)=>{
   // 返却されたデータを処理する
   })
   ```

### **リクエストパラメータ**

| **パラメータ** | **タイプ** | **必須** | **例** | **説明** |
| --- | --- | --- | --- | --- |
| client | string | はい | f1dLkxxx | アプリ ID：   - 社内アプリは **Appkey** を使用 - サードパーティ社内アプリは **SuiteKey** を使用 - サードパーティ個人アプリは **AppId** を使用 - カスタムアプリは **CustomKey** を使用 |
| corpId | string | はい | ding123xxxx | 現在の組織の組織 ID。 |
| rpcScope | string | いいえ | Contact.User.Read | インターフェーススコープのリスト。  **注意**   - 複数のスコープはカンマで区切ります。 - rpcScope と fieldScope のうち、少なくとも一方を指定してください。 |
| fieldScope | string | いいえ | Contact.User.mobile | フィールドスコープのリスト。  **注意**  複数のスコープはカンマで区切ります。  rpcScope と fieldScope のうち、少なくとも一方を指定してください。 |
| type | string | はい | 0 | 認可タイプ：   - **0**：個人認可をリクエスト - **1**：組織認可をリクエスト |
| from | string | いいえ | alicloud | リクエスト元。  **注意**  呼び出し元が設定する場所の識別子です。 |

## **3. レスポンス情報**

#### **レスポンス例は次のとおりです。**

- 認可完了

  ```
  {
   status: 'ok',
   result: {
   authCode:'xxxxxxx' // 組織認可（type=1）ではこの値は返却されない
   }
  }
  ```
- 認可辞退

  ```
  {
      status: 'cancel',
      result: null
  }
  ```
- 管理者に認可リクエストを送信し、認可待ち（組織認可のシナリオでのみ発生）

  ```
  {
      status: 'toAdmin',
      result: null
  }
  ```
- 認可エラー

  ```
  {
      status: 'failed',
      result: null
  }
  ```

### **レスポンスパラメータ**

| **フィールド名** | **タイプ** | **例** | **説明** |
| --- | --- | --- | --- |
| status | string | ok | 認可結果：   - **ok：** 認可成功 - **toAdmin：** 管理者に認可リクエストを送信し、認可待ち - **failed：** 認可エラー - **cancel：** 認可を自発的にキャンセル |
| result | Object |  | 返却される結果。 |
| result.authCode | string | mrtjjwdmxxx | 一時的な個人認可コード。  **注意**  type=0 で認可が成功した場合に返却されます。 |

## **エラーコード**

### **パラメータエラー**

| **エラーコード** | **原因** |
| --- | --- |
| 400001 | 空のリクエストです。 |
| 400006 | clientId パラメータは必須です。 |
| 400007 | corpId パラメータは必須です。 |
| 400008 | uid が空です。DingTalk にお問い合わせください。 |

### **権限スコープエラー**

| **エラーコード** | **原因** |
| --- | --- |
| 500201 | 無効な権限スコープコードです。 |
| 500202 | rpcScope パラメータには rpc タイプの権限スコープを含める必要があります。 |
| 500203 | fieldScope パラメータには field タイプの権限スコープを含める必要があります。 |
| 500204 | 組織認可には組織タイプの権限スコープを含める必要があります。 |
| 500205 | 個人認可には個人タイプの権限スコープを含める必要があります。 |

### **アプリエラー**

| **エラーコード** | **原因** |
| --- | --- |
| 500101 | アプリが存在しません。 |
| 500102 | アプリに権限スコープが追加されていません。 |
| 500103 | アプリ情報の取得に失敗しました。 |
| 500104 | アプリにこの権限スコープがありません。開発者コンソールで追加してください。 |
| 500105 | アプリプロバイダーの組織情報の取得に失敗しました。 |

### **認可エラー**

| **エラーコード** | **原因** |
| --- | --- |
| 500401 | 認可者のロールの取得に失敗しました。 |
| 500402 | 現在の組織の管理者ではありません。 |
| 500403 | 組織がこのアプリの認可を有効にしていません。 |
| 500404 | 認可レコードの更新に失敗しました。 |

## **認可の有効期間**

ユーザーが明示的に認可を許可すると、その認可関係は、ユーザーが自発的にキャンセルするまでバックエンドに記録されます。
