本記事では、連絡先データを含む組織の機密データを保護するために、データセキュリティセンターを購入、有効化、設定する方法を説明します。

## **背景情報**

データセキュリティセンターは、機密データの自動識別、分類・格付け、ビッグデータのセキュリティ監査、データマスキングなどの機能を提供します。クラウド上でのデータ漏洩防止とセキュリティを実現する、統合的かつ全ドメインのソリューションを提供します。

## **手順**

1. [データセキュリティセンター](https://www.aliyun.com/product/sddp?spm=ding_open_doc.document.0.0.784366c71seamX)の製品ページで、**Buy Now** をクリックして購入ページを開きます。
2. 購入ページでバージョン仕様を設定します。

   - [必須] 製品タイプ：**Data Security Center（データ検出、分類・格付け、マスキング、漏洩防止）** を選択します。
   - [必須] バージョン：**ベーシック** プランを選択します。セキュリティのニーズに応じて、より上位の **Businessプラン** を選択できます。
   - [必須] データベース管理：**On** を選択する必要があります。
   - [必須] データベースインスタンス数：DingTalkのデータを保存する実際のデータベースインスタンス数に基づいて購入します。最低 1 つは購入してください。DingTalkから取得したデータが 2 つのデータベースインスタンスに保存されている場合は、2 つ購入します。
   - [任意] OSS データ管理：**機密ファイルを保存していない場合** は、**Close** を選択できます。**身分証明書の写真やユーザー名簿のスプレッドシート** などの機密ファイルを保存している場合は、**On** を選択し、使用量に応じて購入することをお勧めします。この項目は任意です。
   - [必須] 契約期間：**1 年** 以上を選択し、**Auto-renew on Expiration**（期限切れ時の自動更新）を選択します。

   **重要**
   - データセキュリティセンターは、以下の国内リージョンでのデータ製品の識別と保護をサポートしています：杭州、上海、北京、深圳、張家口、フフホト、青島。データベースインスタンスがこれらのリージョン内で購入されていることを確認してください。

3. 購入完了後、データセキュリティセンターのコンソールにアクセスし、[設定ガイド](https://yundun.console.aliyun.com/?spm=ding_open_doc.document.0.0.784366c71seamX&p=sddp#/taskGuide/WorkBench) を使用して設定します。
4. **Sync** をクリックして、クラウド上のアセットをデータセキュリティセンターに自動的に同期します。

5. アセットの権限付与では、**Go to Configure** をクリックしてアセット設定ページを開きます。

6. 構造化データを選択し、DingTalkプラットフォームから取得したデータ（RDS 経由でプッシュされる、または OpenAPI 経由で呼び出される）を保存するデータベースインスタンスに対して権限付与を設定します。DingTalk上にない独自の業務アプリで収集したデータを保存するインスタンスに対しては、権限付与を設定する必要はありません。

   **注意**

   データベースが多数ある場合、権限付与の設定に時間がかかります。1 インスタンスあたり 20 個以下のデータベースに設定することをお勧めします。

7. 権限付与の設定が完了したら、権限付与済みインスタンスの右側にある操作列で **One-Click Connect** をクリックし、権限付与済みアセットをバインドします。

8. **Data Sorting** > **Identification Configuration** をクリックします。

   - テンプレート設定：**Alibaba Group と Ant Group の組み込みセキュリティ分類・格付けテンプレート** を使用します。
   - テンプレート詳細：ルール設定を **On** の状態にします。

## **よくある質問**

1. VPC + データセキュリティセンター + Compute Nest のデプロイ方式は、どのようにしてDingTalkのプライベートデータを保護しますか？サービスプロバイダーがDingTalkの内部プライベートデータをエクスポートするのをどのように防止しますか？

   回答：

   - Compute Nest はセキュリティリスクを検出できます。高リスクの設定、脆弱性、またはハッカーによる侵入に対してアラートをプッシュします。
   - データセキュリティセンターは、保存されている機密データを識別し、一括データエクスポートなどのデータ漏洩の疑いのある操作を監査してアラートを発します。
2. データセキュリティセンターは、データベース内の元データを変更しますか？

   回答：いいえ。
3. データセキュリティセンターは、クエリされたデータやデータベースに書き込まれるデータを傍受・マスキングしますか？

   回答：いいえ。現在推奨されているバージョンでは、機密データの識別のみを行います。データを処理することはなく、業務に影響を与えることもありません。
4. データセキュリティセンターは、どのようにデータベースを監視しますか？

   回答：

   - 監視は権限付与に基づいて行われます。権限が付与されている場合にのみ、機密データが検出されます。DingTalk Security は、プラットフォームから同期されたデータの保護に重点を置いています。製品ソリューションプロバイダーは、プラットフォームのセキュリティ要件に従って、DingTalkプラットフォームから取得したデータを保存するインスタンスに対してのみ権限を付与する必要があります。
   - 製品ソリューションプロバイダーが権限付与を取り消した場合、または DingTalk Security が監査分析を通じて改ざんされた権限付与を発見し、通知後もプロバイダーが是正を拒否した場合、プロバイダーはセキュリティ規定に従ってポイント減点およびアプリの削除の対象となります。
5. データセキュリティセンターがデータを監視してリスクを検出した場合、どのようにアラートを提供しますか？対応の仕組みはどうなっていますか？

   回答：

   - データセキュリティセンターのコンソールにログインすると、具体的なリスクアラートとその内容を確認できます。
   - 製品ソリューションプロバイダーは、リスクアラートに基づいて、または DingTalk Security に相談して、リスクに対応できます。DingTalk Security が監視している高リスクのアラートについては、対応の推奨事項を提供します。
   - DingTalk はプッシュされた高リスクのアラート通知を受信します。DingTalk Security は、アラート通知に示された深刻度に基づいて、フォローアップして製品ソリューションプロバイダーにリスクへの対応を通知するかどうかを判断します。
6. イシューが未対応のまま放置された場合、アプリは削除されますか、またはデータベースに対して何らかのロック操作が適用されますか？

   回答：データベースに対する操作は行われません。ただし、高リスクのアラートが長期間未対応のまま放置された場合、またはセキュリティ違反（例：DingTalkプラットフォームから別の業務システムへのデータのエクスポート）が判明した場合、アプリはDingTalkプラットフォームのセキュリティ規定の関連要件に従い、アプリサービスプロバイダーとの協議のうえ、ポイント減点および削除の対象となります。
7. 製品ソリューションプロバイダーのアプリデータベースのテーブルに、DingTalkプラットフォームから取得した機密データとプロバイダー自身のアプリで収集したユーザーデータの両方を含むユーザーデータのレコードが保存されている場合、このユーザーレコードをエクスポートすると、データセキュリティセンターから監査アラートがトリガーされますか？

   回答：

   - 原則として、ユーザーデータのエクスポートにはユーザーの権限付与と同意が必要であり、データは権限付与された範囲内でのみ使用できます。したがって、製品ソリューションプロバイダーは、ユーザーデータの不正利用や漏洩を防ぐため、ユーザーデータのエクスポートに関する承認・監査の仕組みを確立する必要があります。
   - データセキュリティセンターの機密データ識別およびデータ漏洩防止の監視・監査では、プラットフォームから同期されたデータと自己収集したデータを区別しません。
   - データセキュリティセンターは、一括データエクスポートなどの漏洩の疑いのある操作を監査してアラートを生成します。アプリケーションによる通常の呼び出しでは、通常アラートはトリガーされません。
8. 今後 DingTalk との連携を行わなくなった場合、パブリックネットワークのデプロイを復元するには何をする必要がありますか？データ監査などの操作を実行する必要がありますか？

   回答：DingTalk との連携を停止した後、DingTalk上でパートナーアプリを使用している組織の顧客に、自身のデータをエクスポートするよう通知する必要があります。DingTalkプラットフォームから取得した顧客データと、収集したDingTalk組織の顧客データを削除し、DingTalk のスタッフが削除を検証・確認した後、権限付与のバインドを解除し、Compute Nest プラットフォームから退出できます。
