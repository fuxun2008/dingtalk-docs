本記事では、アプリ開発プラットフォームの課金モデルについて説明します。

アプリ開発プラットフォームは、企業のデジタルトランスフォーメーションを支援するために、エンタープライズ開発者に多様なアプリタイプと豊富なアプリ機能を提供します。社内アプリ開発で消費する Open API の使用量はメータリングの対象となり、イベントサブスクリプションやカスタムボットによる Webhook および Stream メッセージングの利用は課金対象となります。

## **アプリ開発プラットフォームの課金モデル**

アプリ開発プラットフォームは、DingTalk のエディションごとに、API 呼び出し、Webhook および Stream 呼び出しのクォータ、ならびに API 呼び出し同時実行 QPS の月間上限を、それぞれ異なる値で提供します。詳細は以下をご覧ください。

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **機能サービス** | | **標準版 DingTalk** | **プロフェッショナル版 DingTalk** | **専用版 DingTalk** |
| **API 呼び出し回数** | | 10,000 回/暦月 | 500,000 回/暦月 | 5,500,000 回/暦月 |
| **Webhook および Stream 呼び出し回数** | | 5,000 回/暦月 | 50,000 回/暦月 | 100,000 回/暦月 |
| **QPS 上限** | | 20 qps | 40 qps | 60 qps |
| **料金** | | **フリー** | **9,800 CNY/年** | **営業へお問い合わせ** |

開発者は [開発者コンソール - リソース管理](https://open-dev.dingtalk.com/?hash=%23%2F#/) にログインすると、組織のすべての使用クォータを確認できます。使用量に関するアラートを受け取った場合、または呼び出しクォータがニーズを満たせない場合は、[アプリ開発アドオンパッケージ（単独購入）](dingtalk://dingtalkclient/page/link?pc_slide=true&redirect_type=jump&url=https%3A%2F%2Fh5.dingtalk.com%2F40plan%2Fh5-official-order%2Forder-form.html%23%2FplaceOrder%3FarticleCode%3DDT_GOODS_EPopenapi001) を購入することで、当月の合計呼び出しクォータを増やせます。

## **メータリングルール**

- 単一アプリの QPS レート制限、グローバル API QPS レート制限、ネットワーク到達不可などの理由で失敗した呼び出しは、呼び出し回数にカウントされません。
- ベーシックな Open API は課金対象外です。詳細は 付録 A：月間呼び出し回数の上限に含まれない API の一覧 をご覧ください。
- ベーシックなイベントサブスクリプションは課金対象外です。詳細は 付録 B：Webhook および Stream の使用量上限に含まれないイベントの一覧 をご覧ください。

## **利用の推奨事項**

DingTalk の API エンドポイントをより効率的かつ合理的に呼び出すために、以下の点にご注意ください。

1. **API 呼び出しロジックを最適化する**：例えば、API が DingTalk のデータを読み取る場合、タイマーによるループ呼び出し（ポーリング）は避けてください。必要に応じて DingTalk のコールバック通知を組み込むことで、呼び出し回数を効果的に削減し、データのタイムリー性をより確実に確保できます。
2. **API のエラーコードを確認する**：例えば、API 呼び出しがエラーを返した場合は、エラーコードに基づいて原因を判断してください。無制限にリトライせず、リトライ回数を制御してください。
3. API のアプリレベル QPS レート制限については、付録 C：DingTalk サーバー API のスロットリングへの対処方法 をご覧ください。

DingTalk の Webhook および Stream メッセージングチャンネルをより効率的かつ合理的に利用するために、以下の点にご注意ください。

1. **次の原則に従ってイベントサブスクリプションのソリューションを最適化する**：必要なイベントのみをサブスクライブし、イベント処理を重複排除し、迅速に応答して返却してください。詳細は 付録 D：リソースの合理的な利用に関する推奨事項 をご覧ください。
