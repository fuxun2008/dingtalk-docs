この API を呼び出して、OA承認インスタンスのステータスを更新します。

## API 呼び出し説明

たとえば、ユーザー A が提出したタスクに、B1、B2、B3 の 3 つの処理段階があるとします。B1 はすでにタスクを承認済みです。現在タスクは B2 にあり、B3 はまだタスクを受け取っていません。

この API を呼び出した後、DingTalk の**承認**コンソールでタスクのステータスを確認してください。ステータスの変化は次の表のとおりです。

コンソールでは、承認記録が**未処理**、**処理済み**、**提出済み**、**受信済み**の 4 つのタブに分かれて表示されます。各記録の進捗状況は**フローステータス**列に表示されます（例：**承認済み**）。

上記の承認フローでステータスを **COMPLETED** に設定すると、承認フローは次のように変化します。

| 提出者/タスクの処理担当者 | 更新前 | 更新後 |
| --- | --- | --- |
| ユーザー A | ワークベンチ > タスク > 提出済み、承認中 | ワークベンチ > タスク > 提出済み、承認済み |
| 承認ノード B1 | ワークベンチ > タスク > 処理済み、承認済み | ワークベンチ > タスク > 処理済み、承認済み |
| 承認ノード B2 | 該当するタスクなし | 該当するタスクなし |
| 承認ノード B3 | 該当するタスクなし | 該当するタスクなし |

上記の承認フローでステータスを **TERMINATED** に設定すると、承認フローは次のように変化します。

| 提出者/タスクの処理担当者 | 更新前 | 更新後 |
| --- | --- | --- |
| ユーザー A | ワークベンチ > タスク > 提出済み、承認中 | ワークベンチ > タスク > 提出済み、取り消し済み |
| 承認ノード B1 | ワークベンチ > タスク > 処理済み、承認済み | ワークベンチ > タスク > 処理済み、取り消し済み |
| 承認ノード B2 | 該当するタスクなし | 該当するタスクなし |
| 承認ノード B3 | 該当するタスクなし | 該当するタスクなし |

## リクエスト

### ベーシック情報

| フィールド | 値 |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processCentres/instances |
| HTTP メソッド | PUT |
| 対応するアプリタイプ | appType-社内アプリ　appType-サードパーティ社内アプリ |
| 必要な権限 | permission-Workflow.Instance.Write-ワークフローインスタンスの書き込み権限 |

### リクエストヘッダー

| 名前 | タイプ | 必須 | 説明 |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | はい | この API を呼び出すためのアクセス認証情報です。次の方法で取得します。   - 社内アプリ：[社内アプリのアクセストークンを取得](/ja/open/development/obtain-the-access-token-of-an-internal-app) API を呼び出します。 - サードパーティ社内アプリ：サードパーティアプリが承認された組織のアクセストークンを取得する API を呼び出します。 |

### リクエストボディ

| 名前 | タイプ | 必須 | 説明 |
| --- | --- | --- | --- |
| processInstanceId | String | はい | 承認インスタンス ID です。[インスタンスを作成](/ja/open/development/create-a-ticket-approval-instance) API を呼び出して `processInstanceId` の値を取得します。 |
| status | String | はい | インスタンスのステータスです。   - **COMPLETED**：承認フローを完了します。 - **TERMINATED**：承認フローを終了します。 |
| result | String | はい | インスタンスの結果です。   - インスタンスのステータスが COMPLETED の場合は、次のいずれかの値を設定します。    - **agree**：承認   - **refuse**：却下 - インスタンスのステータスが **TERMINATED** の場合も、この値は必須です。agree と refuse のどちらを指定しても、承認フローは取り消されます。 |
| notifiers | Array | いいえ | CC受信者のユーザー ID リストです。最大 30 件まで指定できます。 |
| userId | String | はい | CC受信者のユーザー ID です。[部門のユーザー ID リストを取得](/ja/open/development/query-the-list-of-department-userids) API を呼び出して取得します。 |
