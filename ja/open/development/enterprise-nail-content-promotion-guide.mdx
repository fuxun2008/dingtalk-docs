## **1. DingTalk 連携レベルとは**

DingTalk 連携レベルは、アプリと DingTalk の連携の深さを測る指標です。アプリは DingTalk API・コネクタ・クールアプリなどを通じて DingTalk と深く連携します。連携レベルの高いアプリを利用する組織では、アプリのアクティビティが 35% 向上することがデータで示されています。

## **2. DingTalk 連携レベルが重要な理由**

- 連携レベルの高いアプリは、より豊富な機能とより大きな価値を提供し、ビジネスのデジタル化を誰もが取り組みやすいものにします。
- 連携レベルの高いアプリは、ライブデータを安全に流通させ、流れるデータがアプリにより多くの活力をもたらします。
- 連携レベルの高いアプリは、多様なシナリオベースの形態をとり、より没入感のある環境でシームレスに利用できます。
- 連携レベルの高いアプリは、エンタープライズアプリと公式アプリの間の壁を取り払い、両者が連携してより良いユーザー体験を実現します。

## **3. エンタープライズアプリの DingTalk 連携レベルのスコアリングルール**

|  |  |  |  |
| --- | --- | --- | --- |
| **連携レベルのスコアリング項目** | | **項目の定義** | **スコアリングルール** |
| **能力項目** | **API** | L3 以上のレベルで日次アクティブな API の数をカウントします | 日次アクティブな API 1 件につき **4** ポイント |
| **コネクタ** | 連携済みかつアクティブなコネクタの数をカウントします（アクションはコネクタの中核コンポーネントであり、API に類似します） | 日次アクティブなコネクタのアクション 1 件につき **5** ポイント |
| **プロダクト項目** | **クールアプリ** | メインアプリに拡張クールアプリがあるか、およびクールアプリの各シナリオ（トップバナー、ボット、メッセージメニューなど）での連携状況とアクティビティを確認します | 日次でアクティブなシナリオ 1 件につき **8** ポイント |

## **5. DingTalk 連携レベルを高める方法**

### **より多くの** [**L3 以上の API**](https://open.dingtalk.com/developer/old) **を連携し、DingTalk で人事・財務・資産・オペレーション・本番環境・供給・販売を強化して連携レベルを高める**

- **導入前**

  - DingTalk 上のアプリは、単に **ワークベンチにピン留めされたクイックリンク** にすぎず、DingTalk をエントリポイントとしてしか扱っていません。ブラウザで開くのと変わりません。
  - アプリは **DingTalk のアカウントによるサイレントログイン** と、連絡先・組織構造を取得するインターフェースのみを連携し、DingTalk を権限センターとしてしか扱っていません。これは DingTalk が提供する最も基本的な能力にすぎません。
  - アプリは **DingTalk のメッセージ通知インターフェースのみを連携** し、メッセージの多様性やユーザーへの到達方法を考慮していません。これもまた、DingTalk の最も基本的な能力の 1 つを使っているにすぎません。
- **導入後**

  - **IM API 連携、ボット、インタラクティブなカード** を通じて、アプリは多次元的なグループ管理を実現し、コミュニケーションをビジネスに、ビジネスをコラボレーションに変えます。
  - **イベント API** 連携を通じて、アプリは社内のイベント管理プロセスを DingTalk と深く統合します。
  - **勤怠、承認、タスクなどの API** 連携を通じて、アプリは社内の人事・財務・資産・オペレーションの管理を DingTalk 上でより容易にします。
  - DingTalk の **データ資産** を連携し、データで駆動して DingTalk アプリを活性化させます。

### [**DingTalk コネクタ**](https://open.dingtalk.com/developer/connector) **を連携し、異種システム間のデータサイロを解消して連携レベルを高める**

- **導入前**

  - アプリを DingTalk 上に公開した後、その **データは独立して保存・アクセスされ**、サイロが生まれます。
  - エンタープライズアプリ間でデータを共有するには、アプリ間の共同開発以上の方法はありません。連携がなければサイロが再発し、同じデータを繰り返し入力せざるを得なくなります。
  - 社内システムで ERP の承認フォームを提出するには、関係する承認者に別途通知して ERP システムで確認してもらう必要があり、煩雑です。
- **導入後**

  - DingTalk コネクタは、DingTalk 公式アプリ、サードパーティ SaaS アプリ、Kingdee や Yonyou などの大規模外部システムを連携します。**一度連携すれば、データがつながります。**
  - **コネクタを社内システムに連携** します。経費精算フォームが提出されると、コネクタが自動的に DingTalk に承認タスクを作成します。承認者が確認すると、フォームの証憑がコネクタを通じて財務システムへ自動的に還流します。コネクタにより、精算プロセスはシンプルかつ効率的になります。

### [**DingTalk クールアプリ**](https://open.dingtalk.com/coolapp) **を連携し、高頻度シナリオで低頻度アプリを駆動して連携レベルを高める**

- **導入前**

  - アプリを DingTalk 上に公開した後、**利用したい** たびに、企業のワークベンチでアプリアイコンを探し、クリックして開き、必要な機能を見つける必要があり、**長い経路** になります。
  - 採用グループで履歴書をやり取りする際、面接官が良さそうな履歴書だと判断して HR に伝えます。HR はその後、採用システムに戻り、履歴書をアップロードし、候補者を作成し、面接官と時間を確認し、面接を設定する必要があります。HR は **一見ルーティンに見えるものの、実際にははるかに効率化できる作業を繰り返し行っています**。
- **導入後**

  - DingTalk クールアプリを連携します。アプリがワークベンチに公開されると、**よく使う機能、メッセージメニュー、プロフィールページなどの高頻度エントリポイントにワンクリックで配信** することもできます。
  - 採用グループで履歴書をやり取りする際、**履歴書は自動的に候補者カードに変換されます**。面接官が良さそうな履歴書だと判断して **[良さそう] をタップ** すると、**ハーフスクリーンのフローティングウィンドウが開き**、面接官は空いている時間枠を選択して確定します。**カードはリアルタイムで更新** され、HR は面接官のやり取りをフォローし、候補者に直接連絡して面接を設定します。迅速かつ効率的です。

## **6. DingTalk 連携レベルのベンチマーク事例**

- [**デバイスディレクトリを構築し、製造設備を DingTalk に取り込んで効率的なデバイス管理を実現**](https://open.dingtalk.com/abilities/189)

  デバイスを DingTalk に取り込むと、各設備にデバイスアカウントが作成され、デバイスのデジタル化を通じてデバイス・組織・ビジネスがつながります。
- [**店舗ディレクトリを構築し、「ストアコネクト」で標準化された小売店舗運営を実現**](https://open.dingtalk.com/abilities/191)

  「ストアコネクト」は DingTalk の IM とタスクの能力を活用して店舗の課題を素早く特定し、標準化された改善を推進することで、標準化された店舗運営を支援します。
