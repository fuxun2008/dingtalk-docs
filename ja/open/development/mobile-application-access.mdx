モバイルアプリ向け DingTalk ログインは、[OAuth 2.0 プロトコル標準](https://oauth.net/2/)に基づいて構築された DingTalk OAuth 2.0 認可ログインシステムです。

**注意**

- 現在、モバイルアプリでの DingTalk ログインはネイティブログイン方式のみに対応しており、ユーザーは DingTalk クライアントサイドをインストールする必要があります。
- Android アプリの場合、DingTalk ログインボタンを常に表示してください。ユーザーの端末に DingTalk クライアントサイドがインストールされていない場合は、ダウンロードとインストールを案内してください。

## ユースケース

社員が組織内部で開発したアプリを使用する際は、アカウントとパスワードでログインする必要があります。ログインを簡略化するため、ログインページに直接 DingTalk ボタンを追加すれば、社員は DingTalk アカウントを使ってアプリにログインできます。

以下の画像は、BOC International クライアントのログインページです。DingTalk アカウントを持ち、DingTalk クライアントサイドをインストール済みのユーザーは、アカウントとパスワードを入力せずに、DingTalk 権限付与で直接ログインできます。

## 手順

アプリで DingTalk ログインを利用する場合は、まず **DingTalk Open Platform** で DingTalk アプリを追加し、次に DingTalk Open Platform が提供する SDK を使って認可ログインリクエストを連携します。SDK を正しく連携し、関連する認可スコープ（権限付与の範囲。現在、DingTalk は認可ログインとユーザーのベーシック情報の取得のみに対応しています）を取得すると、開発者のモバイルアプリが端末上でローカルに DingTalk アプリを起動して認可ログインを行います。DingTalk ユーザーが確認すると、DingTalk が開発者のモバイルアプリを起動し、一時的な認可チケット `code` パラメータを渡します。その後、DingTalk 個人ユーザー情報 API を呼び出して、ログインしたユーザーのベーシック情報（携帯番号、DingTalk 名前、DingTalk プロフィール写真 URL など）を取得します。
