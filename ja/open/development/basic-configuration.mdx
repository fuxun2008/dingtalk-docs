サードパーティ社内アプリの作成後、サーバーのアウトバウンドIPアドレスなどのベーシック設定を完了し、データのプッシュ方式を指定します。

## 手順

1. [開発者コンソール](https://open-dev.dingtalk.com/)にログインし、対象のアプリをクリックします。
2. アプリ詳細ページで**開発管理**をクリックし、アプリのベーシック情報を設定します。

   | 設定 | 必須 | 説明 |
   | --- | --- | --- |
   | 開発モード | H5マイクロアプリでは必須 | 開発モードを選択します。  - **アプリを開発**：新しいH5マイクロアプリを開発します。 - **クイックリンク**：既存のH5マイクロアプリを追加します。組織は内部アプリをクイックリンク経由でDingTalkに統合でき、社内従業員はDingTalkのワークベンチ上で利用できます。 |
   | サーバーのアウトバウンドIP | はい | DingTalkのサーバー APIを呼び出す際に使用するIPアドレス、すなわち組織サーバーのパブリックIPアドレスを入力します。複数のIPアドレスはカンマ（,）で区切ります。1つのワイルドカード（\*）を含むIP形式に対応しています。 |
   | アプリのホームページURL | H5マイクロアプリでは必須 | アプリのホームページURLを入力します。モバイルのワークベンチでアプリアイコンをタップすると、このページにリダイレクトされます。  バックエンドサービスがデプロイされているサーバーのIPアドレスまたはドメインを入力します。例：`https://public-IP:8080`。 |
   | PCのホームページURL | いいえ | PC版DingTalkのワークベンチでアプリを開くためのURLを入力します。リンクはhttpまたはhttpsで始まる必要があります。  **注意**  空欄のままの場合、PC版DingTalkのワークベンチでアプリアイコンをタップすると、「PC版はまだサポートされていません。以下のQRコードをスマートフォンのDingTalkでスキャンして表示してください。」というメッセージが表示されます。このアプリはモバイルのDingTalkクライアントサイドでのみ利用できます。 |
   | 管理コンソールURL | いいえ | 管理者が[DingTalk管理コンソール](https://oa.dingtalk.com/)でアプリにアクセスするためのURLを入力します。 |
   | プッシュタイプ | はい | サードパーティ社内アプリは、組織がアプリを認可した際にアプリのアクティベーションイベントを受信するため、コールバックを登録**しなければなりません**。これにより、どの組織がアプリをアクティベートしたかをアプリに通知します。サードパーティアプリのバックエンドはこのイベントを受信した後、組織情報を初期化してアクティベーションを完了する必要があります。詳細は認可済みアプリのアクティベートを参照してください。  アプリのアクティベーションイベントに加えて、DingTalkはアプリの認可変更や部門変更など、その他のイベントメッセージもプッシュします。これらのコールバックイベントを購読することで、開発者はDingTalkとより適切に統合できます。詳細はデータプッシュの概要を参照してください。  DingTalkは次の2つの方式でコールバックイベントの受信をサポートしています。  - RDSデータプッシュ - SyncHTTPプッシュ |
