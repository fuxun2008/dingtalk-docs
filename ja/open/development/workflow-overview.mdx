## OA承認とは

OA承認（スマート作業フロー）は、組織向けの DingTalk 公式アプリです。休暇申請や出張など、承認フローをすばやく設定できます。OA承認の API を使用すると、承認インスタンスなどのリソースを操作できます。これにより、組織の既存の業務システムと DingTalk OA承認を連携できます。その他の機能については、[DingTalk 使い方ガイド - OA承認](https://alidocs.dingtalk.io/i/p/Y7kmbokZp3pgGLq2/docs/lo1YvX0prG98keM3X7aqVPw7xzbmLdEZ)を参照してください。

OA承認との連携に対応しているアプリの種類は次のとおりです。

- 社内アプリ
- サードパーティ社内アプリ

## OA プレミアム版とは

OA プレミアム版は、DingTalk OA承認チームが新たにリリースした有償エディションです。詳細については、[OA プレミアム版の全特典](dingtalk://dingtalkclient/page/link?url=https%3A%2F%2Fpage.dingtalk.io%2Fwow%2Fdingtalk%2Fdefault%2Fdingtalk%2FEYs6dgD4wlLHABzOAGksE%3Fdd_mini_app_id%3D5000000004997171&pc_slide=true)を参照してください。

DingTalk OA承認では、[OA承認プレミアム版](dingtalk://dingtalkclient/page/link?url=https%3A%2F%2Fpage.dingtalk.io%2Fwow%2Fdingtalk%2Fdefault%2Fdingtalk%2FlnfR8GaRSWqNncZHSvLLx%3Fdd_mini_app_id%3D5000000004997171&web_wnd=general&width=480&height=800)のお客様向けに専用の OpenAPI とソリューションを追加し、カスタムアプリ開発における開発者のニーズに応えています。これらの専用 OpenAPI とソリューションは、より豊富な機能を提供し、個別性の高い業務ニーズにも対応します。また、さまざまなシナリオでの社内アプリ開発にも対応しています。OpenAPI を適切かつ効果的に活用し、より健全な DingTalk オープンエコシステムの構築にご協力ください。

専用オープン機能の詳細については、「OA承認プレミアム版の新しい専用 OpenAPI とソリューションの説明」を参照してください。

- OA プレミアム版では、一括承認・却下を効率的に行う API をはじめ、30 以上の専用オープン API を提供しています。
- OA プレミアム版では、2 種類の専用プロセスセンター連携ソリューションを提供しています。サードパーティのフローを DingTalk OA のページと連携したり、DingTalk OA承認を自社開発アプリに組み込んだりして、業務に合わせてカスタマイズできます。

### AppLink

**AppLink は、DingTalk のアプリ向け標準リンクプロトコルです。リンクから DingTalk のアプリや機能に直接アクセスできます**。たとえば、承認ページへの遷移、承認詳細ページや申請ページの表示などに使用します。

- 承認ホームページを開く
- 承認のフィルターページを開く
- 承認を申請する
- 承認の詳細を開く

<Warning>
AppLink プロトコルは現在、OA承認プレミアム版でのみ利用できます。OA承認標準版では利用できません。
</Warning>

### 連携オプション

#### 説明

DingTalk OA承認のオープン機能では、業務システムと DingTalk OA承認を連携するための 4 つのソリューションを提供しています。業務システムで承認を申請し、DingTalk で処理できます。また、DingTalk のチャット、ToDo、通知などの機能ともシームレスに連携します。これにより、すべての業務プロセスの承認を一元化し、効率的なコラボレーションを実現できます。

その他の機能については、[DingTalk 使い方ガイド - OA承認](https://alidocs.dingtalk.io/i/p/Y7kmbokZp3pgGLq2/docs/lo1YvX0prG98keM3X7aqVPw7xzbmLdEZ)を参照してください。

DingTalk OA承認では、業務システムから承認を申請するための 4 つの連携方式を提供しています。

1. **DingTalk OA承認のフロー + ページ**
2. **サードパーティのフロー + ページ**
3. **サードパーティのフロー + DingTalk OA承認のページ**
4. **DingTalk OA承認を組み込んだ自社開発アプリ**

連携後、OA承認は **ToDo**、**ドキュメント**、**連絡先**、**メッセージカード**、**DING**、**カレンダー**、**日報**、**承認アシスタント**、**IM / ワンクリックでのグループ作成**などの DingTalk 機能と連動します。

#### 連携方式

DingTalk OA承認では、さまざまな業務管理・連携ニーズに対応するため、4 つのフロー連携ソリューションを提供しています。

## 用語集

### 承認フォーム

承認フォームは、複数のフォームコントロールを含めることができる事前定義のテンプレートです。社員がフォームに入力して送信すると、承認インスタンスが生成されます。DingTalk では、休暇申請や出張などの一般的な承認フォームも用意しています。**新規フォームを作成** をクリックすると、これらをそのまま利用できます。管理者は [OA承認管理コンソール](https://aflow.dingtalk.io/dingtalk/web/query/dashboard?dinghash=aflowSetting#/aflowSetting)ですべての承認フォームを確認できます。

**新規フォームを作成** をクリックすると、2 種類のフォームを選択するダイアログが表示されます。**フローフォーム**（承認が必要なシナリオ向け）と**データフォーム**（承認を伴わないデータ収集向け）です。テンプレートから作成するには、**クラシックテンプレートを使用**、**他のアプリのテンプレート**、**既存のテンプレートをコピー** の 3 つのタブのいずれかを使用します。組み込みのクラシックテンプレートには、休暇申請、シフト交換、残業、出張、外出、採用申請、業績自己評価、異動申請、車両申請、物品申請、一般承認があります。

### 承認フォームコントロール

DingTalk では、承認フォームをすばやくカスタマイズするための多様な承認フォームコントロールを提供しています。承認フォームを新規作成するか既存のフォームを編集し、**フォーム設計** をクリックしてコントロールを追加または変更します。以下では、休暇申請フォームのコントロールについて説明します。

承認フォームの作成画面は、**基本設定** > **フォーム設計** > **フロー設計** > **高度な設定** の 4 ステップで構成されています。**フォーム設計** で **コントロールライブラリ** を開き、コントロールを追加または変更します。コントロールは次のようにグループ化されています。

| グループ | コントロール |
| --- | --- |
| レイアウト | 列 |
| 基本 | 一行テキスト、複数行テキスト、数値、ラジオボタン、チェックボックス、日付、期間、説明テキスト、身分証明書、電話番号 |
| 拡張 | 階層選択/カテゴリ、画像、明細/表、金額、添付、手書き署名、外部連絡先、連絡先 |

デフォルトの休暇申請フォームには、**休暇タイプ**、**開始時刻**、**終了時刻**、**期間**、**休暇理由**、**画像** のフィールドが含まれています。

### 承認フロー

承認者や承認条件の設定など、ニーズに合わせて承認フローを設計します。

承認フローは、**基本設定** > **フォーム設計** > **フロー設計** > **高度な設定** の 4 ステップのウィザードで設定します。**フロー設計** のキャンバスで、**申請者** とフローの終了の間にノードを追加します。利用可能なノードの種類は次のとおりです。

| ノードの種類 | 用途 |
| --- | --- |
| **承認者** | 申請を承認する担当者 |
| **CC受信者** | 申請の通知を受け取る担当者 |
| **操作** | タスクを処理する担当者 |
| **条件分岐** | 条件に基づいてフローを分岐させる |

各ノードの処理担当者を設定します（例：**申請者が選択**）。

### 承認インスタンス

組織内のユーザーが承認を申請すると、承認インスタンスが生成されます。各承認インスタンスには、申請時にユーザーが入力したフォームデータ、承認者、承認者の操作ログなどのデータが含まれます。

### 承認ステップ

承認フローには複数の承認ステップを設定できます。各ステップには 1 人以上の承認者を設定します。ステップの承認者に応じて、次の 2 つのケースがあります。

- **1 つの承認ステップに承認者が 1 人のみの場合**：承認者がこのステップで承認または却下すると、ステップは即時に終了し、承認は自動的に次のレベルへ進みます。
- **1 つの承認ステップに複数の承認者がいる場合**：承認者ごとに 1 つの承認タスクが対応します。承認者の承認方法に応じて、次の 3 つのケースがあります。

  - **順次承認**：1 人の承認者が処理を完了すると、承認タスクは順番に従って次の承認者に自動的に送信されます。
  - **全員承認（全員の承認が必要）**：現在のステップのすべての承認者が承認した場合にのみ、フローは次のステップに進みます。それ以外の場合、フローは却下されます。
  - **いずれか 1 人の承認**：現在のステップの承認者のうち 1 人が操作するだけで、現在のステップは即時に終了します。

### 承認タスク

1 つの承認ステップから 1 つ以上の承認タスクが生成されます。各承認タスクは承認者を識別します。承認者はタスクを受け取ると、承認、却下、またはその他の操作を行えます。

### processCode

承認フォームを一意に識別する固定値のコードです。承認フォームの編集画面にある **基本設定** ページの下部で確認できます。
