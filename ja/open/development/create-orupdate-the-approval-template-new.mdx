この API を呼び出して、承認テンプレートを作成または更新します。

## API 呼び出し説明

- 1 つの組織がプロセスセンターで作成できるテンプレートは最大 200 個です。上限に達すると、この API の呼び出しはエラーを返します。
- DingTalk クライアントの承認リストには、テンプレートフォームの先頭 3 つのフィールドのみが表示されます。
- 自社構築の承認作業フローテンプレートを作成したら、テンプレート名と、この API が返す processCode を保存してください。これらの値は他の API で必要になります。
- 自社 OA 承認テンプレートでサポートされる承認コンポーネントは、本ドキュメントに記載されているもののみです。その他のコンポーネントはサポートされません。

## リクエスト

### 基本情報

| フィールド | 値 |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processCentres/schemas |
| HTTP メソッド | POST |
| サポートされるアプリタイプ | appType-社内アプリ　appType-サードパーティ社内アプリ |
| 必要な権限 | permission-Workflow.Form.Write-作業フローテンプレートの書き込み権限 |

### リクエストヘッダー

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | はい | この API を呼び出すためのアクセス認証情報です。次の方法で取得します。   - 社内アプリ：社内アプリのアクセストークンを取得する API を呼び出します。 - サードパーティ社内アプリ：サードパーティアプリを承認した組織のアクセストークンを取得する API を呼び出します。 |

### リクエストボディ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| processCode | String | いいえ | フォームの ProcessCode です。フォームテンプレートを更新する場合に指定します。processCode の値は、[テンプレートコードの取得](/ja/open/development/obtain-the-template-code) API を呼び出して取得します。      ProcessCode を渡してフォームコンポーネントを変更・更新する場合、ワークフロー設計で条件分岐として使用済みのコントロールは削除・変更できません。たとえば、元のフォームで単一選択コントロール【社員区分】を分岐条件として使用している場合、このフォームを更新する際に【社員区分】フィールドのコントロールタイプを変更したり、削除したりすることはできません。     - 新しいテンプレートを作成する場合は、このパラメータを空のままにします。 - このパラメータを指定すると、渡した値に一致する承認テンプレートが更新されます。 |
| name | String | はい | フォームテンプレート名です。最大 200 文字です。 |
| description | String | いいえ | フォームテンプレートの説明です。最大 300 文字です。 |
| formComponents | Array | はい | フォームコントロールのリストです。サポートされるコントロールは以下のとおりです。1 つのフォームに含められるコンポーネントは最大 200 個です。 サポートされるコントロールタイプの詳細は、本ドキュメントの **FormComponent パラメータの補足説明** を参照してください。   - **TextField**：単一行入力 - **TextareaField**：複数行入力 - **NumberField**：数値入力 - **DDSelectField**：単一選択 - **DDMultiSelectField**：複数選択 - **DDDateField**：日付コントロール - **DDDateRangeField**：期間コントロール - **TextNote**：説明テキストコントロール - **DDPhotoField**：画像コントロール - **MoneyField**：金額コントロール - **TableField**：明細コントロール（テーブルコントロール） - **DDAttachment**：添付 - **InnerContactField**：連絡先コントロール - **RelateField**：関連承認フォーム - **AddressField**：省/市/区コントロール - **StarRatingField**：評価点コントロール - **DepartmentField**：部門コントロール |
| FormComponent | FormComponent | はい | フォームコントロールです。サポートされるコントロールについては、[FormComponent パラメータの説明](/ja/open/development/oa-formcomponent-message) を参照してください。1 つのフォームに含められるコンポーネントは最大 200 個です。 |
| processFeatureConfig | Object | いいえ | プロセスセンター連携の設定です。 |
| features | Array | いいえ | 設定リストです。 |
| name | String | いいえ | サードパーティがカスタマイズできる機能モジュールの名前です。指定できる値：   - **TASK_EXECUTE**：タスク実行モジュール。詳細ページの「承認」ボタンと「却下」ボタンを指します - **SYNC_BOXSTER**：タスクを To-Do に同期する方法 - **CUSTOM_SHORTCUT**：To-Do 項目およびカード通知内のショートカットアクションボタン - **AFFILIATION_DIR**：To-Do の業務グループを指定します |
| pcUrl | String | いいえ | PC 版のサードパーティカスタムリダイレクトリンクです。最大 1,024 文字です。 |
| mobileUrl | String | いいえ | モバイル版のサードパーティカスタムリダイレクトリンクです。最大 1,024 文字です。 |
| runType | String | いいえ | 実行モードです。features.name が `TASK_EXECUTE` の場合、指定できる値：   - **ORIGIN**：ネイティブ実行。公式の承認アプリ内で機能が実行され、callback に設定したコールバック API がトリガーされます。 - **REDIRECT**：外部リダイレクト実行。サードパーティのアドレスで機能が実行され、ユーザーは pcUrl または mobileUrl に設定したアドレスにリダイレクトされます。   features.name が `SYNC_BOXSTER` の場合、指定できる値：   - **DEFAULT**：デフォルトで承認タスクを To-Do に同期します。 - **OUTBIZ_CUSTOM**：To-Do に同期しません。業務側でカスタム処理を実装します。   features.name が `CUSTOM_SHORTCUT` の場合、指定できる値：   - **ORIGIN**：ネイティブ実行。To-Do の詳細ページを開くと、公式の承認アプリの詳細ページにリダイレクトされます。 - **REDIRECT**：外部リダイレクト実行。To-Do の詳細ページを開くと、pcUrl または mobileUrl に設定したアドレスにリダイレクトされます。   features.name が `AFFILIATION_DIR` の場合、指定できる値：   - **OUTBIZ_CUSTOM**：To-Do のグループを指定します。業務側で To-Do 項目のカテゴリを指定します。 |
| callback | Object | いいえ | ゲートウェイのコールバック設定です。runType が ORIGIN の場合は必須です。 ゲートウェイがコールバックするすべての外部データ API は、「データソース管理」でゲートウェイとして登録してください。詳細は「データソースの作成」を参照してください。 |
| appUuid | String | いいえ | ゲートウェイの appUuid です。runType が ORIGIN の場合は必須です。 データソースを作成した組織の組織 ID（corpId）を渡します。 |
| apiKey | String | いいえ | ゲートウェイの apiKey です。runType が ORIGIN の場合は必須です。作成済みのデータソースから `apiKey` を取得します。       - ゲートウェイが外部 API を呼び出す際、DingTalk は業務シナリオに応じて業務処理に必要なパラメータを返します。コールバックリクエストの受信後にこれらのパラメータを解析するため、ISV はデータソースの作成時に対応するパラメータキーを設定する必要があります。   たとえば、TASK_EXECUTE モジュール（詳細ページの「承認」ボタンと「却下」ボタン）にコールバックを設定した場合、DingTalk は次の固定パラメータを返します：`&#123;"outResult":"agree","processInstanceId":"xxx","activityId":"xxx","corpId":"dingxxx","data":[],"remark":"同意します","title":"xxx が提出した備品受領申請","taskId":111,"operator":"manager0001"&#125;`。 - ISV はデータソースの作成時に、業務要件に応じて解析に必要な次のキーを設定してください：outResult,processInstanceId,activityId,corpId,remark,title,taskId,operator |
| version | String | いいえ | ゲートウェイ API のバージョンです。       - runType が ORIGIN の場合は必須です。 - デフォルト：1。 |
| config | String | いいえ | サードパーティがカスタマイズする機能モジュールの設定です。 |
| templateConfig | Object | いいえ | プロセスセンターのテンプレート設定です。 |
| hidden | Boolean | いいえ | テンプレートを非表示にするかどうか：   - **true**：非表示テンプレート - **false**：非表示テンプレートではない |
| createInstanceMobileUrl | String | いいえ | フォーム作成用のモバイル版 URL です。最大 1,024 文字です。 |
| createInstancePcUrl | String | いいえ | フォーム作成用の PC 版 URL です。最大 1,024 文字です。 |
| templateEditUrl | String | いいえ | テンプレート編集用の URL です。最大 1,024 文字です。 |
| disableSendCard | Boolean | いいえ | プロセスセンターで保留中のタスクを作成する際に、メッセージカード通知を無効にするかどうか：   - **true**：無効。メッセージカード通知は送信されません。 - **false**：デフォルト。無効にしません。メッセージカード通知が送信されます。 |
