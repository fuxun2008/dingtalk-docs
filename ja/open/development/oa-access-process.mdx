このトピックでは、承認プロセスセンターの背景と概要、統合後のユーザー体験、開発者向けの統合ガイドについて説明します。

## 承認プロセスセンターの背景

中国企業のデジタルトランスフォーメーションは新たな段階に入りました。業務のデジタル化、システム間の相互接続、産業チェーンの上流から下流までをつなぐデジタルコラボレーションへの需要が高まっています。DingTalk はこうした顧客ニーズに応えるため、PaaS プラットフォームとしての位置付けを打ち出しました。この位置付けのもと、DingTalk にはより高い開放性が求められています。

OA承認は、DingTalk の機能の中でも特に PaaS モデルに適した機能です。この方針に沿って、OA承認は PaaS 製品として再構築されました。フォームとプロセスの機能が開放され、さまざまなビジネスモデルのパートナーのニーズに応えるプロセスセンター統合ソリューションが提供されています。

**プロセスセンター**は、**ローコードプロセス**、**契約**、**カスタムプロセス**、**入社/異動/退職**、**購買**、**資産**、**経費精算**など、組み込み済みおよび拡張可能なさまざまな承認フローのカテゴリをサポートしています。また、サードパーティのプロセスプロバイダーやフォームプロバイダーとの統合にも対応しています。

プロセスセンターとの統合により、3 つの統一された機能が提供されます。**統一されたチャット体験**（開発者のアプリでリアルタイムにコミュニケーションとコラボレーションが可能）、**統一されたタスク**（すべての業務タスクを 1 か所で処理）、**統一されたデータインサイト / 効率診断**（データ資産の蓄積）です。

## 承認プロセスセンターとは

DingTalk のOA承認は、社内で構築したシステムやサードパーティから購入したシステムなど、外部システムからプッシュされた承認タスクを DingTalk の承認アプリで受け取れます。承認タスクは PC、モバイル、タブレットにリアルタイムで届き、DingTalk 承認に埋め込まれたフォームのサイドパネルで開きます。ユーザーは DingTalk 承認上ですべての承認を 1 か所で確認・処理でき、ワンストップの承認体験を得られます。さらに、チャットのメッセージプッシュ、チャットへのワンタップ転送、毎日のタスクリマインダー、効率カンバンと組み合わせることで、申請・処理・レポートの各段階で承認効率が向上します。

### ユースケース

中規模から大規模の組織では、承認がさまざまな業務システムに分散しているケースがよく見られます。承認者は毎日システムを切り替えながら承認を処理する必要があり、手間がかかり非効率です。また、承認者が保留中の承認を忘れがちになり、業務処理の遅延や管理効率の低下を招きます。上級管理職は承認の種類も件数も多いため、この問題はさらに深刻になりがちです。

**プロセスセンターはアプリシステムに分散した承認フォームを集約し、「ワンストップ」のOA承認を実現**

### 統合の価値

**ユーザーにワンストップのOA承認を提供し、自社構築およびサードパーティの承認タスクでもファーストパーティと同等の体験を実現**

**統合のメリット：**

| メリット | 詳細 |
| --- | --- |
| ワンストップの承認体験 | 複数システムの承認タスクを DingTalk に集約し、システム間を行き来する必要がありません |
| 承認効率の向上 | タスクリマインダーや承認効率ダッシュボードなどの機能強化 |
| デバイス間で統一された体験 | デスクトップ、モバイル、タブレットで一貫した体験 |

- DingTalk のプロセスセンターは分散した承認フォームを集約し、複数の入口による不便さを解消して、「ワンストップ」の承認管理センターを構築します。

  - 統合により、**組織の OA、人事、財務**などのシステムのフォームが DingTalk のプロセスセンターの一覧に取り込まれ、**承認データの表示、通知（IM のアクティビティカードや DingTalk のタスクを含む）、操作、検索、フィルター、エクスポート、印刷、管理を統一的かつ便利に行えます。**
  - DingTalk のプロセスセンターは、サードパーティまたは自社構築システムの承認データを埋め込み、**DingTalk 承認内のサイドドロワーで開きます**。これにより承認者のページ切り替えが減り、スムーズで途切れのない承認体験を実現します。
  - ページ構成とデザインはシンプルで、PC、モバイル、タブレットに対応しています。**デバイス間をシームレスに切り替えられるため、導入と定着のハードルが低くなります**。

    **プロセスセンター**の**承認センター**の一覧には、**未処理** > **処理済み** > **申請済み** > **受信済み**のタブがあり、**検索**ボックス、**種類**と**プロセスステータス**のフィルター、**詳細フィルター**が用意されています。一覧には次の列が表示されます。

    | 列 | 説明 |
    | --- | --- |
    | **タイトル** | 承認フォームのタイトル |
    | **概要** | フォームの主要な内容 |
    | **申請者** | 申請を送信した人 |
    | **送信日時** | 送信日 |
    | **完了日時** | 完了日 |
    | **プロセスステータス** | 例：承認済み |

    フォームを選択すると、サイドドロワーに詳細が表示され、**コメント**、**グループチャットを作成**、**その他**、**修正**、**却下**、**承認**の操作を実行できます。
- DingTalk のプロセスセンターと統合することで、業務効率が向上し、承認フローが迅速化します。

  - 統合後は、**OA承認アシスタントが保留中の承認タスクについて毎週タスクのサマリーをプッシュ**します。これにより承認のターンアラウンドが短縮され、承認タスクの停滞を防げます。
  - 統合後は、承認フローのデータが承認効率カンバンに集約され、管理効率の向上がひと目で把握できます。**組織の管理者は組織の承認効率レポートを毎週受け取り**、処理時間が異常に長い承認者、部門、承認フローを確認できます。これにより**プロセスのボトルネックを早期に発見**し、組織の実行力を高められます。
  - 統合後は、承認をチャットへすばやく転送でき、**承認と IM のメッセージフローを連携**させることで、承認者は会話の中で承認を完了できます。
  - **ワンタップでのグループ作成**により、プロセスの他の参加者をワンタップでディスカッショングループに追加できます。情報を効率的に共有し、コンテキストを明確にすることで、迅速な承認判断を支援します。
- DingTalk のプロセスセンターと統合すると、一部の高度な機能が開放され、管理者が必要に応じて設定できるようになります。

  - **統合前**：DingTalk 承認には承認フロー向けの高度な機能が多数用意されており、管理者は承認テンプレートにカスタム設定を適用できます。ただし、外部システム、サードパーティの OA システム、またはスイートから申請されたプロセスでは、これらの高度な機能はデフォルトで無効になっています。
  - **統合後：** プロセスセンターと統合すると、ネイティブの承認機能で一部の高度な機能が開放され、管理者が必要に応じて設定できるようになります。
  - **管理コンソールのフォーム管理で外部システムから申請されたプロセスを表示**：外部システムのフォームテンプレートを表示・編集できます。API で作成したフォームテンプレートは、デフォルトで「フォーム管理 - システムまたはその他のアプリのフォーム」に配置されます。

    承認テンプレートエディターでは、**高度な設定**はウィザードの手順 4 にあたります（**基本設定** > **フォーム設計** > **プロセス設計** > **高度な設定**）。管理者は**プロセスの高度な設定**で次のオプションのオン/オフを切り替えられます。

    | オプション | 説明 |
    | --- | --- |
    | **自動重複除去** | 同じ承認者がプロセス内に複数回登場する場合、承認は 1 回のみで、残りは自動的に通過します |
    | **承認者の追加を許可** | 承認フォームに一時的な承認者を追加します |
    | **取り消し/修正** | 申請者が送信済みの承認を取り消せます |
    | **期限付き承認** | 承認期限を設定し、自動リマインダー、転送、または承認を行います |
    | **手書き署名** | 承認者は承認時に手書きで署名する必要があります |
    | **承認コメント** | コメントを必須にするかどうかと、その公開範囲を設定します |
    | **代理送信を許可** | 指定した人が他の人に代わって承認を送信できます |

    API で作成したフォームテンプレートは、管理コンソールの**フォーム管理**に表示され、表示・編集できます。

## ユーザー側の統合体験

### 社員ビュー

- 詳細ページ

  - **公式 OA 承認の詳細ページが表示され、サードパーティの承認フォームのデータが同期されるとともに、CC ノードと承認ノードが表示されます**
  - **OA承認内で直接承認または却下でき、承認の操作を 1 か所で完了できます**
  - **開発者のブランドロゴが表示され、エコシステムパートナーのブランド露出を高めます**
  - サードパーティシステムへのリダイレクトによる転送と取り消し
  - エクスポート/ダウンロード
  - グルチャ作成
  - 共有
  - サードパーティの元の承認フォームへのリダイレクト
  - コメント

  承認の詳細ページには、送信された**フォームフィールド**（一行テキスト、複数行テキスト、数値、日時、金額など）と、その下に**プロセス**のタイムラインが表示されます。タイムラインには各ノードが順番に、ステータスとタイムスタンプとともに表示されます。**申請を送信**（申請者）、**CC**（「1 人が既読」などの既読状況を表示）、1 つ以上の**承認者**ノード（「承認済み」や「いずれか 1 人の承認、承認中」などの結果を表示）です。画面下部の操作バーには、**コメント**、**グループディスカッションを開始**、**元のフォームに戻る**、**取り消し**、**却下**、**承認**があります。
- エコシステムパートナーのブランドを表示した承認メッセージカード

- スマートワークアシスタントが未完了の承認を毎日プッシュ

- 承認センターの 4 つの一覧ページで、統合された承認を表示・検索

  **承認センター**では、承認が**未処理**、**処理済み**、**申請済み**、**受信済み**の 4 つの一覧タブに表示されます。**検索**ボックスで一覧を絞り込めるほか、**種類**と**詳細フィルター**のオプションも利用できます。各一覧には、**タイトル**、**概要**、**申請者**、**開始日時**、**完了日時**、**プロセスステータス**の列が表示されます。
- CC の受信者には CC カードが届きます

- DingTalk のタスク通知を統一：すべての業務タスクを 1 か所で処理

  統一された**タスク**センターでは、項目が左側のサイドバーに**すべて**や**OA承認**などのソース別にまとめられます。一覧から**却下**または**承認**ボタンを使って、各タスクを直接その場で処理できます。

### 管理者ビュー

- 管理コンソールでプロセスセンターのテンプレートを表示・検索

  OA承認の管理コンソールで、**フォーム管理** > **システムの非表示フォーム**を開くと、他のアプリから統合された承認フォームを確認できます。管理コンソールでは、各フォームについて承認フォームの**検索**と承認インスタンスの**データ表示**が可能です。**データ表示**ページでこれらのデータをエクスポート・管理できます。
- 管理コンソールでプロセスセンターのテンプレートの承認インスタンスデータを表示・検索
- 管理コンソールでプロセスセンターの承認フォームを削除/エクスポート

  OA承認の**管理コンソール**で**データ表示**ページを開き、プロセスセンターのデータを管理します。**フォーム名**、**承認ステータス**、**申請者**、**承認番号**、**申請日時**、**完了日時**で一覧を絞り込み、**照会**、**リセット**、**詳細フィルター**を使用します。一括操作として、**一括エクスポート**、**添付ファイルの一括ダウンロード**、**一括削除**が用意されています。各承認フォームの行でも**エクスポート**と**削除**を実行できます。

## 開発者向け統合ガイド

詳細な統合ソリューションについては、[自社 OA 承認：サードパーティのプロセスとページの統合](/ja/open/development/use-three-party-process-and-page-docking)を参照してください。

- 従来の自社構築プロセス API と比較したプロセスセンター API の変更点

  - 従来の自社構築プロセスの Open API は、すべて新しいプロセスセンターの Open API に移行されました
  - 一部の API パラメーターが新たに追加され、既存のパラメーターは引き続き互換性があります
- OA承認の保留中タスクを照会する新しい API が追加されました。この API を呼び出してデータの整合性を確認できます

### プロセスセンターの統合ソリューション

DingTalk のプロセスセンターは、複数の入口から統合できます。

1. **DingTalk ネイティブの承認**（プリセットテンプレート、カスタムフォーム、組み込みの業務プロセス、スイート）は直接接続します。
2. **自社構築システム**は、**API** 経由で**プロセスエンジン**を通じて接続するか、**API** で直接接続するか、サービスプロバイダーを通じて接続します。
3. **サードパーティアプリ**（Landray、Weaver、Kingdee など）は、**公式コネクタ**を通じて接続します。

**プロセスセンター**は、**承認センター**、**IM ダイナミックカード**、**DingTalk のタスク**、**検索/フィルター**、**データ管理（インポート/エクスポート）**、**プロセス効率**、**承認タスクの削除/取り消し**、**プロセスへの介入**の機能を提供します。

### プロセスセンター統合のシーケンス図

統合のシーケンスには、**DingTalk ユーザー**、**開発者**、**DingTalk オープンプラットフォーム**、**DingTalk OA承認**の 4 者が関与します。

1. **承認テンプレートの作成/更新**：開発者がオープンプラットフォームを呼び出すと、オープンプラットフォームはテンプレートをOA承認に保存し、**承認テンプレートの Code** を返します。
2. **承認テンプレートの管理**：OA承認の管理コンソールで、開発者はテンプレートの表示、データの表示/検索、データのエクスポート/削除を行えます。
3. **承認インスタンスの作成**：開発者がオープンプラットフォーム経由でインスタンスを作成すると（オープンプラットフォームは**承認インスタンス ID** を返します）、CC カードが DingTalk ユーザーに送信されます。
4. **承認フォームの管理**：DingTalk のプロセスセンターで、DingTalk ユーザーは 4 つの承認一覧の表示、データの検索、承認の実行を行えます。
5. **元のフォームにリダイレクトする承認タスクの作成**（DingTalk 承認からサードパーティのフォームページにリダイレクトして実行）：オープンプラットフォームが**承認タスク ID** を返し、タスクカードが送信され、元のフォームでタスクが実行された後、タスクカードが更新されます。
6. **DingTalk 承認内で実行する承認タスクの作成**（統合実行）：実行後、DingTalk が実行メッセージを送信し、結果が **RDS** または **HTTPSYNC** でプッシュされ、タスクカードが更新されます。
7. **承認インスタンスの更新**：開発者がオープンプラットフォーム経由でインスタンスを更新し、更新結果を取得すると、CC カードが更新されます。

### 統合方法

社内アプリとサードパーティアプリは、DingTalk オープンプラットフォームの自社 OA 承認にあるプロセスセンター API を呼び出し、承認データを DingTalk 承認のプロセスセンターに同期します。これにより、組織は承認処理のための統一された入口を利用できます。詳細な統合ソリューションについては、[自社 OA 承認：サードパーティのプロセスとページの統合](/ja/open/development/use-three-party-process-and-page-docking)を参照してください。

1. 承認フォームを作成します。

   **社内アプリ**は、**テンプレートの作成または更新**と**テンプレートの削除**の 2 つの操作を通じて **DingTalk 承認**とやり取りします。
2. データを同期します。

   統合フローは**社内アプリ**と **DingTalk 承認**の間で実行されます。アプリは、**インスタンスの作成**、**タスクの作成**、**タスクステータスの同期**、**インスタンスステータスの同期**の 4 つのやり取りを通じて DingTalk 承認を操作します。
