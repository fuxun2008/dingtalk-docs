イベントサブスクリプションのプッシュサービスを開発するには、Stream モードプッシュ、HTTP モードプッシュ、SyncHTTP の 3 つのプッシュモードから 1 つを選択できます。本ドキュメントの手順に従って開発を進めてください。

## Stream モードの開発（推奨）

    ### サンプルコード

    ここでは Bot コールバックとインタラクティブカードコールバックを例に、開発者向けのサンプルコードを示します。

    **Bot コールバック**

    ```java
    public static void main(String[] args) throws Exception {
      OpenDingTalkStreamClientBuilder
        .custom()
        .credential(new AuthClientCredential("${clientId}", "${clientSecret}"))
        //Bot リスナーを登録
        .registerCallbackListener("${topic}", robotMessage -> {
          log.info("receive robotMessage, {}", robotMessage);
          //開発者は自身の業務ニーズに応じて Bot コールバックを処理
          return new JSONObject();

        })
        .build().start();
    }
    ```

    | パラメーター名 | 説明 |
    | --- | --- |
    | `clientId` | DingTalk 企業内部アプリおよび DingTalk サードパーティ企業アプリの一意の ID。詳細は [Client ID/Client Secret](/ja/open/dingstart/basic-concepts-beta) を参照してください。Client ID は旧版アプリの AppKey/SuiteKey に対応します。 |
    | `clientSecret` | DingTalk 企業内部アプリおよび DingTalk サードパーティ企業アプリの呼び出しシークレット。詳細は [Client ID/Client Secret](/ja/open/dingstart/basic-concepts-beta) を参照してください。Client Secret は旧版アプリの AppSecret/SuiteSecret に対応します。 |
    | `topic` | Bot コールバック名。固定値：`/v1.0/im/bot/messages/get`。 |

    **カードコールバック**

                        //your code is here

                        //開発者は自身の業務ニーズに応じてカード内容を変更し、response を返す
                        CardCallbackResponse resp = new CardCallbackResponse();
                        return resp;

                    .build().start();
    }

### エラーコード

イベント受信時に次のエラーコードが表示された場合は、解決策に従って対処してください。

| エラーコード（errCode） | エラーメッセージ（errMsg） | 説明 | 解決策 |
| --- | --- | --- | --- |
| 20001 | 呼び出し量の超過により、現在「マイメッセージ」サービスは一時停止しています。所属組織の管理者に連絡して対処してください。受信メッセージに、エラー情報を表示するための `errMsg` フィールドが追加されます。 | 受信メッセージに内容がなく、`text` および `content` フィールドの内容がありません。[開発者コンソール](https://open-dev.dingtalk.com/){target="_blank"}にログインすると呼び出し量を確認できます。 | DingTalk Professional Edition へのアップグレード、または増量パッケージの購入が必要です。 |

### よくある質問

<AccordionGroup>
  <Accordion title="1 つのアプリケーションで複数のイベントリスナーを起動できますか？">
    複数のイベントリスニングサービスを起動できます。必要に応じて複数の Stream クライアント設定を起動してください。

    1. **企業内部アプリ**：1 つの企業につき、Stream クライアントを 1 つ設定するだけで済みます。
    2. **サードパーティ企業アプリ**：当該サードパーティ企業アプリをリッスンするだけで、現在認可されている企業のイベントサブスクリプション内容を取得できます。
  </Accordion>
</AccordionGroup>
