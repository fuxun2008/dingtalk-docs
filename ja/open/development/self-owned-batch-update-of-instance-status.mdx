この API を呼び出して、インスタンスのステータスを一括更新します。

## API 呼び出し説明

例として、ユーザー A が 3 段階の処理ノードを持つタスクを提出したとします。処理担当者は B1、B2、B3 です。B1 はすでに承認しており、タスクは現在 B2 にあります。B3 にはまだタスクが届いていません。

この API を呼び出した後、**承認センター**で **未処理**、**処理済み**、**申請済み**、**受信済み** の各タブを切り替えて、タスクのステータスを確認します。各行には **タイトル**、**概要**、**申請者**、**開始時間**、**完了時間**、**フローステータス**（例：**承認済み**）が表示されます。ステータスの変化は次の表のとおりです。

この承認作業フローの例で、ステータスを **COMPLETED** に設定した場合、承認作業フローのステータスは次のようになります。

| 提出者/タスク処理担当者 | 更新前 | 更新後 |
| --- | --- | --- |
| ユーザー A | ワークベンチ > タスク > 申請済み、承認中 | ワークベンチ > タスク > 申請済み、承認済み |
| 承認ノード B1 | ワークベンチ > タスク > 処理済み、承認済み | ワークベンチ > タスク > 処理済み、承認済み |
| 承認ノード B2 | 該当するタスクなし | 該当するタスクなし |
| 承認ノード B3 | 該当するタスクなし | 該当するタスクなし |

この承認作業フローの例で、ステータスを **TERMINATED** に設定した場合、承認作業フローのステータスは次のようになります。

| 提出者/タスク処理担当者 | 更新前 | 更新後 |
| --- | --- | --- |
| ユーザー A | ワークベンチ > タスク > 申請済み、承認中 | ワークベンチ > タスク > 申請済み、取り消し済み |
| 承認ノード B1 | ワークベンチ > タスク > 処理済み、承認済み | ワークベンチ > タスク > 処理済み、取り消し済み |
| 承認ノード B2 | 該当するタスクなし | 該当するタスクなし |
| 承認ノード B3 | 該当するタスクなし | 該当するタスクなし |

## リクエスト

### ベーシック情報

| フィールド | 値 |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processCentres/instances/batch |
| HTTP メソッド | PUT |
| 対応アプリタイプ | appType-社内アプリ　appType-サードパーティ社内アプリ |
| 必要な権限 | permission-Workflow.Instance.Write-ワークフローインスタンス書き込み権限 |

### リクエストヘッダー

| 名前 | タイプ | 必須 | 説明 |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | はい | この API を呼び出すためのアクセス認証情報です。取得方法は次のとおりです。   - 社内アプリ：[社内アプリのアクセストークンを取得](/ja/open/development/obtain-the-access-token-of-an-internal-app) API を呼び出します。 - サードパーティ社内アプリ：サードパーティアプリを承認済みの組織のアクセストークンを取得する API を呼び出します。 |

### リクエストボディ

| 名前 | タイプ | 必須 | 説明 |
| --- | --- | --- | --- |
| updateProcessInstanceRequests | Array | いいえ | インスタンスのリストです。最大 50 件です。 |
| processInstanceId | String | はい | インスタンス ID です。[インスタンスを作成](/ja/open/development/create-a-ticket-approval-instance) API を呼び出して取得します。 |
| status | String | はい | インスタンスのステータスです。   - **COMPLETED**：承認作業フローを完了します。 - **TERMINATED**：承認作業フローを終了します。 |
| result | String | はい | インスタンスの結果です。   - インスタンスのステータスが **COMPLETED** の場合は、次のいずれかの値を設定します。    - **agree**：承認   - **refuse**：却下 - インスタンスのステータスが **TERMINATED** の場合も、このパラメーターは必須です。agree と refuse のいずれを指定しても、承認作業フローは取り消されます。 |
| notifiers | Array | いいえ | CC受信者の userId のリストです。最大 30 件です。 |
| userId | String | はい | CC受信者の userId です。 |
