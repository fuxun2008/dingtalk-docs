DingTalk は、連絡先の変更やアプリ認可の変更など、購読したコールバックイベントをアプリにプッシュします。開発者はデータをリアルタイムで同期し、業務システムをより効率的に統合できます。

## RDS プッシュとは

RDS プッシュは、HTTP プロトコルプッシュを置き換えるアップグレード版です。DingTalk Open Platform が Alibaba Cloud と連携して独自に開発したプッシュソリューションです。

RDS プッシュは、データの安全を確保しながら、プッシュプロトコルを大幅に簡素化し、データ転送の回数を削減し、データ転送速度を向上させ、プッシュの安定性を高めます。RDS プッシュは、DingTalk と ISV の間だけでなく、DingTalk と企業開発者の間のデータ転送もサポートします。ローカルでの開発とデバッグ、およびオンラインでのデプロイと運用の両方に対応し、ISV や組織が DingTalk と統合するプロセスを大幅に簡素化します。

## RDS プッシュと HTTP プッシュの機能比較

| **RDS プッシュ** | **HTTP プッシュ** |
| --- | --- |
| 同期プロトコルをサポートし、データが開発者の RDS に確実に書き込まれることを保証します。開発者の RDS に障害が発生した場合でも、データは DingTalk に永続的に保存されます。 | 同期プロトコルをサポートしません。ネットワークの異常や開発者のサービス障害が発生した際に、データが失われる可能性があります。 |
| 業務データの最終状態をプッシュするため、開発者は DingTalk Cloud がプッシュしたデータを直接利用できます。これにより、開発者が DingTalk Open Platform を呼び出す回数も削減され、スロットリング制限を回避できます。 | 業務 ID をプッシュします。プッシュを受信した後、開発者はデータの最終状態を照会するために DingTalk Open Platform API を呼び出す必要があり、スロットリング制限を受けやすくなります。 |
| プッシュを受信する開発者の RDS の仕様と能力に応じて、異なるレートでデータをプッシュします。 | プッシュにより HTTP リクエストの瞬間的なピークが発生し、開発者のサーバーの負荷が増大してクラッシュを引き起こす可能性があります。 |
| プッシュされるデータは平文であり、署名検証や暗号化・復号のロジックは不要です。 | プッシュされるデータは暗号文であり、開発者は自身で署名を検証し暗号化・復号を行い、さらに異なるプログラミング言語で署名検証と暗号化・復号のロジックを実装する必要があります。 |
| データチャンネルは内部ネットワークチャンネルであり、トラフィックコストがなく、セキュリティレベルが高く、効率も高くなります。 | データチャンネルはパブリックネットワークチャンネルであり、トラフィックコストが発生し、セキュリティレベルが低く、効率も低くなります。 |

## RDS プッシュと HTTP プッシュのプロセス比較

| **開発ステージ** | **RDS プッシュ** | **HTTP プッシュ** |
| --- | --- | --- |
| アプリ/スイートの作成 | 開発者は、プッシュを受信するための RDS インスタンスを構築する必要があります（開発ステージでは、パブリック IP を持つ任意の MySQL インスタンスを使用できます）。 | 開発者は、プッシュを検証するためにパブリックアドレスを持つプログラムを準備する必要があります（正式リリースでは、プログラムを DingTalk Cloud にデプロイする必要があります）。 |
| 組織によるアプリ/スイートの認可と有効化 | 開発者は、プッシュされたデータベーステーブルをポーリングして読み取り、アプリを有効化した組織の権限付与情報を取得する機能を実装する必要があります。**プロセスが短く、問題のトラブルシューティングが容易です。** | 開発者は次の 4 つの機能を実装する必要があります。1) 一時認可コードのプッシュを受信する、2) 一時認可コードを永続認可コードに交換する、3) アプリを有効化する、4) アプリを有効化した組織の権限付与情報を取得する。プロセスが長く、問題のトラブルシューティングが困難です。 |
| 組織のリアルタイムデータ変更の監視 | 開発者は、アプリ/スイートの詳細ページで監視するデータを選択し、プッシュを受信するデータベーステーブルをポーリングして読み取る必要があります。**単一のアクションで、実行が簡単です。** | 開発者は、組織ごとに監視アドレスを登録する必要があります。プッシュを受信した後、最終データを取得するために DingTalk Open Platform を再度照会する必要があります。これには複数回の API 呼び出しが必要となり、API のデバッグが複雑になります。 |
