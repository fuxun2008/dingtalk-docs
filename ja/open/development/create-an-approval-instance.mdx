この API を呼び出して、OA承認インスタンスを開始します。勤怠・休暇、人事、財務・税務、法務、出張などのスイートでは、この API で承認インスタンスを開始できません。

## API 呼び出し説明

### 重要なお知らせ

Open API に無効なデータが渡されるのを防ぐため、この API では受け取ったデータをより厳格に検証します。

- 単一選択コントロールと複数選択コントロールでは、渡すすべての選択肢の値が、設定済みの選択肢リストに存在している必要があります。
- 社内連絡先コントロールでは、渡すすべての userID が、現在の組織に在籍中のユーザーのものである必要があります。
- 部門コントロールでは、すべての部門 ID が、現在の組織で有効な部門 ID である必要があります。
- 関連承認フォームコントロールでは、渡すすべてのインスタンス ID が、現在の組織に存在する承認インスタンス ID である必要があります。

これらのルールに違反して開始した承認フォームは、フォームデータの検証が厳格化された後、開始に失敗する可能性があります。

### ユースケース

<Note>
承認インスタンスの開始後は、API でその情報を変更できません。
</Note>

承認インスタンスの開始方法は、承認者を指定するかどうかによって 2 通りあります。新しい承認フローを設定するか、承認管理コンソールで設定済みの承認フローを再利用します。

- 承認者を指定せず、承認管理コンソールで設定済みの承認フローを再利用する場合は、次の点に注意してください。

  - 承認者と CC受信者は、いずれも承認管理コンソールで設定済みのユーザーを再利用します。
  - いずれか承認、全員承認、条件付き承認、申請者による承認者の選択など、承認管理コンソールでサポートされているすべてのワークフロー設計を利用できます。

    承認テンプレートエディターには、**基本設定** > **フォーム設計** > **ワークフロー設計** > **高度な設定** の 4 つの設定ステップがあります。**ワークフロー設計** では、次のノードタイプを組み合わせてフローを構築します。**申請者**、**承認者**（申請者による選択、全員承認、いずれか承認など）、フィールド値に応じて振り分ける条件分岐（金額が 100 以上か 100 未満か など）、**CC受信者** です。
- 承認者を指定し、OA 管理コンソールで設定済みの承認フローを再利用しない場合は、次の点に注意してください。

  - 承認テンプレートの高度な設定はサポートされません。たとえば、手書き署名やフォーム操作権限は利用できません。承認テンプレートの **高度な設定**（ステップ 4）には次のフローオプションがありますが、この API で承認者を割り当てる場合はいずれも適用されません。**自動重複排除**（同じ承認者がフロー内に複数回登場する場合、1 回だけ承認し、残りは自動的に承認されます）、**自動承認**（承認者と申請者が同一人物の場合、承認が自動的に完了します）、**承認者の追加を許可**（フォームに一時的な承認者を追加します）、**承認の取り消し**（申請者がフォームを取り消せます）、**期限付き承認**、**手書き署名**、**承認コメント**、**代理申請を許可** です。
  - 承認者を指定する場合、この API で承認者を「申請者による選択」に設定することはできません。

### 使用方法

シナリオ 1：承認者を指定せず、承認管理コンソールで設定済みの承認フローを再利用する。

### 注意

- approvers パラメータは空のままにしてください。デフォルトで、承認管理コンソールで設定済みの承認フローが再利用されます。
- API で設定した ccList パラメータと ccPosition パラメータは反映されません。承認管理コンソールで設定済みの CC受信者が再利用されます。

- 承認フローに申請者による選択ノードが含まれるかどうかで、次の 2 つのケースに分かれます。

  - 申請者による選択ノードがある場合：[承認フォームのフローのノード情報を取得](/ja/open/development/approval-process-prediction) API を呼び出します。返されるすべてのノードの isTargetSelect の値は true です。

### 注意

  この API を呼び出して承認インスタンスを開始する際は、approvers と targetSelectActioners の両方を空のままにしてください。

  - 申請者による選択ノードがない場合：[承認フォームのフローのノード情報を取得](/ja/open/development/approval-process-prediction) API を呼び出します。返されるノードの一部で isTargetSelect の値が false になります。

### 注意

  この API を呼び出して承認インスタンスを開始する際は、approvers を空のままにし、targetSelectActioners を渡して申請者による選択ノードの情報を指定してください。

シナリオ 2：承認者を指定し、OA 管理コンソールで設定済みの承認フローを再利用しない。approvers パラメータで新しい承認者を指定します。
