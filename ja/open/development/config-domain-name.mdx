サードパーティ社内アプリでは、プライベート Server Load Balancer（SLB）サービスを DingTalk 安全ドメインにバインドし、バインドした安全ドメインをミニプログラムまたはマイクロアプリのサーバーサイドドメインとして使用する必要があります。

**重要** 

- ドメインゲートウェイのアーキテクチャアップグレードに伴い、DingTalk 安全ドメインは DingTalk Cloud または Jushita からのプライベート SLB アクセスをサポートしなくなります。
- 関連付けを作成する前に、開発者コンソールで関連付けた Alibaba Cloud アカウント（Compute Nest デプロイ）でプライベート SLB を購入済みであること、プライベート SLB に HTTP リスナーポートが設定されていること、HTTP から HTTPS へのリダイレクトが設定されていないことを確認してください。現在は CLB のみをサポートし、ALB はサポートしていません。
- バインドする有効な SLB とドメインを選択します。重複を避けるため、ドメインには「app」+ appId を使用することを推奨します。
- 安全ドメインをバインドすると、デフォルトでクラウドアカウント配下に PrivateLink エンドポイントサービスノードが作成され、DingTalk 安全ドメインゲートウェイからクラウドアカウント配下の関連付けられた SLB へのプライベートチャンネルが確立されます。PrivateLink エンドポイントサービスノードは ISV 側では無料です。
- プッシュタイプが SyncHttp の場合、コールバック URL のプッシュアドレスには DingTalk 安全ドメインを使用する必要があります。
- アプリのサーバー API ドメインには DingTalk 安全ドメインを使用する必要があります。
- Compute Nest デプロイ方式でプライベート SLB がサポートする地域とゾーンは次のとおりです。

  |  |  |
  | --- | --- |
  | **地域** | **ゾーン** |
  | 華東 1（杭州） | ゾーン B、ゾーン E、ゾーン F、ゾーン G、ゾーン H、ゾーン I、ゾーン J、ゾーン K |
  | 華東 2（上海） | ゾーン B、ゾーン E、ゾーン F、ゾーン G、ゾーン L、ゾーン M、ゾーン N、ゾーン I、ゾーン H |
  | 華北 2（北京） | ゾーン B、ゾーン C、ゾーン D、ゾーン E、ゾーン F、ゾーン G、ゾーン H、ゾーン I、ゾーン K、ゾーン L |
  | 華北 3（張家口） | ゾーン A、ゾーン B、ゾーン C |
  | 華南 1（深圳） | ゾーン D、ゾーン E、ゾーン F |

## 手順

1. [開発者コンソール](https://open-dev.dingtalk.com/) にログインします。
2. 作成したアプリを検索します。アプリ詳細ページで **DingTalk 安全ドメイン** をクリックします。
3. 関連付けるプライベート SLB と使用するドメインを選択し、権限付与契約を選択して、**関連付け** をクリックします。

   **注記** 

   安全ドメインのバインドリクエストを送信した後、DingTalk のセキュリティ審査をお待ちください。通常は 1〜2 営業日かかります。承認されると、プライベート SLB を安全ドメインに自動的にバインドする処理が行われ、1〜2 営業日以内に有効になります。ステータスの更新を確認してください。リクエストが辞退された場合は、修正して再送信してください。

   - プライベート SLB：Jushita、DingTalk Cloud、または Compute Nest にバインドされた Alibaba Cloud アカウントでプライベート SLB を購入済みであること。

     **注記** 

     SLB には HTTP リスナーポートが設定されている必要があります。443 や 8443 などの一般的な HTTPS ポートは使用しないでください。
   - 安全ドメイン：重複を避けるため、ドメインには「app」+ appId を使用することを推奨します。

## DingTalk 安全ドメイン有効化の検証基準

- サードパーティ社内アプリのプッシュタイプが **HTTP** または **syncHTTP** の場合、プッシュアドレスのドメインは DingTalk 安全ドメインである必要があります。
- サードパーティ社内アプリがミニプログラムの場合、ミニプログラムがリクエストするサーバー API は DingTalk 安全ドメインを使用する必要があります。
- サードパーティ社内アプリがフロントエンドとバックエンドを分離したアーキテクチャの H5 マイクロアプリの場合、サーバー API は安全ドメインを使用する必要があります。フロントエンドとバックエンドが一体化したアプリの場合、アプリのホームページアドレスは DingTalk 安全ドメインを使用する必要があります。

## FAQ

### 1. SLB は購入済みだが、「1 SLB の関連付け」段階で SLB 情報が表示されない

**回答：** まず、次のセルフチェックを実施してください。

- 開発者コンソールでクラウドアカウントが関連付けられていることを確認します。
- 購入したプライベート SLB がサポート対象の地域範囲内にあることを確認します。Compute Nest デプロイは華東 1（杭州）、華北 3（張家口）、華北 2（北京）、華東 2（上海）、華南（深圳）をサポートします。Jushita デプロイは華北 3（張家口）のみをサポートし、DingTalk Cloud デプロイは華東 1（杭州）のみをサポートします。
- ALB ではなく CLB を購入したことを確認します。
- SLB リスナーポートが TCP プロトコルではなく HTTP プロトコルで設定されていることを確認します。

上記のすべてを確認しても SLB 情報が表示されない場合は、チケットを送信してフィードバックしてください。

### 2. 「2 ドメイン設定」段階で、現在のステータスが「ドメイン審査中です。しばらくお待ちください」と表示される

**回答：** この場合、安全ドメインは審査および設定中です。通常、設定の完了には 1 営業日かかります。1 営業日待ってから再度確認してください。

**注記** 

本番環境以外のアプリの安全ドメインリクエストは拒否されます。DingTalk 側のコスト上の理由により、テストアプリやステージングアプリなどの本番環境以外のアプリには安全ドメインを提供しなくなりました。安全ドメインをテストする必要がある場合は、まず本番環境アプリの安全ドメインをリクエストし、それをテスト環境またはステージング環境にバインドします（SLB がトラフィックを転送する ECS グループを置き換えてバインドを切り替えます）。検証後、バインドを本番環境アプリに切り替えます。

### 3. 「3 アプリでの使用」段階で、安全ドメインの現在のステータスが「ドメインのバインドに失敗しました。DingTalk 管理者が処理中です」と表示される

**回答：** この場合、安全ドメインの設定が失敗しています。チケットを送信して DingTalk テクニカルサポートに連絡し、手動介入を依頼できます。手動介入後、処理の完了には通常 1 営業日かかります。

### 4. 「3 アプリでの使用」段階で、安全ドメインの現在のステータスは「ドメインのバインドに成功しました」だが、ドメインの有効化ステータスが「安全ドメイン未有効化」と表示される

**回答：** この場合、DingTalk は安全ドメインの審査と設定を完了しています。**有効化の検証基準** に従って、開発者側で安全ドメインの設定を完了する必要があります。設定完了後、1 営業日以内に有効として検出されます。

### 5. 元々バインドしていた SLB を使用しなくなり、新しい SLB をバインドする必要がある

**回答：修正 をクリックし**、バインドする新しい SLB を選択します。

- 再バインドが必要な SLB 情報が表示されない場合は、最初の FAQ を参照して対処してください。
- 再バインドする SLB 情報が表示される場合は、修正できます。通常、SLB の変更操作はロスなしの切り替えをサポートしますが、再バインドの過程で軽微なサービスの揺らぎが発生する場合があります。変更操作後も安全ドメインのアドレスは変わりません。

### 6. 安全ドメインの設定後、アプリへのユーザートラフィックはすぐに安全ドメインにルーティングされますか？

**回答：** いいえ。安全ドメインの設定が有効になった後、アクセストラフィックはデフォルトでは安全ドメインに切り替わりません。必要に応じてアプリ側でトラフィックを安全ドメインにルーティングするよう設定し、FAQ 7、8、9 の有効化基準に従ってドメインを有効化する必要があります。

### 7. 安全ドメインの有効化検証：プッシュアドレスに安全ドメインを使用する

**回答：** アプリ機能の **イベントとコールバック > コールバックリクエストアドレス** のドメインに安全ドメインを使用します。

### 8. 安全ドメインの有効化検証：アプリのホームページに安全ドメインを使用する

**回答：** ベーシック情報の **開発管理** ページにある **アプリホームページアドレス** と **PC ホームページアドレス** に安全ドメインを設定します。

### 9. 安全ドメインの有効化検証：ミニプログラムまたはフロントエンドとバックエンドを分離したアプリのサーバー API に安全ドメインを使用する

**回答：** アプリの nginx または tomcat の Web サービスで安全ドメインのトラフィック分配を設定します。具体的な設定方法は、オンラインで関連ドキュメントを検索してください。Open Platform はサーバー API ドメインアドレスを検出・検証し、通常は T+1 で有効になります。

### 10. 安全ドメインの HTTPS 証明書の設定方法

**回答：** 安全ドメインはデフォルトで HTTPS アクセスを提供します。安全ドメインの証明書を取得したり、開発者側で設定したりする必要はありません。クラウドの SLB で HTTP を設定するだけでよく、HTTPS を設定する必要はありません。安全ドメインゲートウェイは専用チャンネルを通じて HTTP トラフィックを開発者のプライベート SLB に転送します。

### 11. 安全ドメインへのアクセス時に継続的にリダイレクトされる

**回答：** プライベート SLB の設定を確認してください。SLB のポート 80（または他の HTTP ポート）の **HTTPS:443 へのリダイレクト** 設定をキャンセルし、トラフィックをバックエンドサーバーの Web ポートに転送して、サーバーグループにバックエンドサービスの Web サーバーを設定します。リダイレクト設定のキャンセルについては、[HTTP から HTTPS へのリダイレクト](https://help.aliyun.com/document_detail/89151.html) を参照してください。
