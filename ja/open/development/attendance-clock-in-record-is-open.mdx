この API を呼び出して、社内の社員の実際の打刻詳細を取得します。

## API 呼び出し説明

- この API では、180 日より前のデータは照会できません。
- 詳細データが不要で打刻結果のみが必要な場合は、[打刻結果の取得](/ja/open/development/open-attendance-clock-in-data) API を呼び出してください。
- 勤怠データの同期には遅延が発生する場合があります。データが見つからない場合は、時間をおいて再試行してください。
- **ユーザーにその日のシフトが設定されていても打刻していない場合、この API は空のデータを返します**。
- この API はすべての打刻詳細を返します。これには、遅刻など二次確認が必要なシナリオの打刻データも含まれます。これらのレコードは無効な打刻です。取得後、業務シナリオに応じてフィルタリングしてください。出力パラメータ `invalidRecordType`、`isLegal`、`invalidRecordMsg` に注意してください。

たとえば、組織が社員に 9:00 と 18:00 の打刻を設定しているとします。社員がその時間帯に複数回打刻した場合、この API はすべての打刻レコードを返します。

同じ打刻の生データを勤怠管理画面で確認するには、**勤怠統計** > **レポート管理** > **元のレコード** に移動します。各レコードには、**名前**、**勤怠グループ**、**部門**、**社員番号**、**役職**、**勤怠日**、**勤怠時間**（シフトの予定時刻）、**打刻時間**、**打刻結果** の列が表示されます。*打刻修正承認済み* などの結果は、そのレコードが直接の打刻ではなく、承認された修正によるものであることを示します。

## リクエスト

| **基本情報** | |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/attendance/listRecord |
| HTTP メソッド | POST |
| サポートされるアプリタイプ | appType-社内アプリ appType-サードパーティ社内アプリ |
| 必要な権限 | permission-qyapi_get_attendance_data-勤怠データ読み取り権限 |

### クエリパラメータ

| 名前 | タイプ | 必須 | 例 | 説明 |
| --- | --- | --- | --- | --- |
| access_token | String | はい | bE74xxxx | この API を呼び出すためのアプリ認証情報です。   - 社内アプリの場合は、[社内アプリの access_token の取得](/ja/open/development/obtain-orgapp-token) API を呼び出して取得します。 - サードパーティ社内アプリの場合は、サードパーティ社内アプリの access_token の取得 API を呼び出して取得します。 |

### リクエストボディ

| 名前 | タイプ | 必須 | 例 | 説明 |
| --- | --- | --- | --- | --- |
| userIds | List | はい | ["user456","user123"] | 社内の社員 ID のリストです。最大 50 件です。  **重要**  userId の値が正しいことを確認してください。正しくない場合、この API は空のデータを返します。 |
| checkDateFrom | String | はい | 2020-09-07 00:00:00 | 勤怠打刻レコードを照会する開始勤務日です。形式：yyyy-MM-dd hh:mm:ss。  たとえば「2021-12-01 10:00:00」を指定した場合、社員の 09:00 の打刻は返されません。  **重要**  workDateFrom と workDateTo の間隔は最大 7 日間（両端を含む）です。 |
| checkDateTo | String | はい | 2020-09-08 00:00:00 | 勤怠打刻レコードを照会する終了勤務日です。形式：yyyy-MM-dd hh:mm:ss。  たとえば「2021-12-01 18:00:00」を指定した場合、社員の 19:00 の打刻は返されません。  **重要**  workDateFrom と workDateTo の間隔は最大 7 日間（両端を含む）です。 |
| isI18n | Boolean | いいえ | true | 組織が海外組織かどうかを指定します。   - **true**：海外プラットフォームで使用 - **false**（デフォルト）：中国プラットフォームで使用 |

### リクエスト例

```curl
curl -X POST "https://api.dingtalk.io/attendance/listRecord" \
-H 'Content-Type:application/x-www-form-urlencoded;charset=utf-8' \
-d 'access_token=7258e1c9-af43-411c-b3f4-bcb069bfbb93' \
-d 'checkDateFrom=2018-01-01' \
-d 'checkDateTo=2018-01-01' \
-d 'isI18n=true' \
-d 'userIds=%221%22%2C%222%22'
```

Java

```text
DingTalkClient client = new DefaultDingTalkClient("https://api.dingtalk.io/attendance/listRecord");
OapiAttendanceListRecordRequest req = new OapiAttendanceListRecordRequest();
req.setUserIds(Arrays.asList("user123","user456"));
req.setCheckDateFrom("2020-11-07 08:00:00");
req.setCheckDateTo("2020-11-12 08:00:00");
req.setIsI18n(false);
OapiAttendanceListRecordResponse rsp = client.execute(req, access_token);
System.out.println(rsp.getBody());
```

Python

```python
import dingtalk.api

req=dingtalk.api.OapiAttendanceListRecordRequest("https://api.dingtalk.io/attendance/listRecord")

req.userIds="[\"1\",\"2\"]"
req.checkDateFrom="2018-01-01"
req.checkDateTo="2018-01-01"
req.isI18n=true
try:
	resp= req.getResponse(access_token)
	print(resp)
except Exception,e:
	print(e)
```

### エラーコード

この API の呼び出しに失敗した場合は、エラーメッセージをもとに [グローバルエラーコード](/ja/open/development/server-api-error-codes-1) ドキュメントで解決方法を確認してください。
