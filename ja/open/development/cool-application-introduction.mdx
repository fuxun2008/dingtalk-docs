## クールアプリとは

**クールアプリ**は、DingTalk 上でユーザーがより便利にアプリを利用できるようにし、複数のステップを 1 つにまとめます。「**人がアプリを探す**」から「**アプリが人に届く**」へ、「**人がデータを探す**」から「**データが人に届く**」へ、そして「**受動的な業務**」から「**能動的な探索**」へと転換します。まず、動画とシナリオを通じてクールアプリの概要を素早く把握し、クールアプリが DingTalk 上でアプリの利用をどのように便利にするかをご覧ください。

**シナリオ 1:** たとえば、複数の社員が出張し、異なるシステムを通じて異なる情報を提出する場合、多くの煩雑なステップが発生します。社員はまずグループを作成して個別に情報を提出し、チケット予約アプリで航空券を予約し、別のアプリに切り替えてホテルを予約し、さらに切り替えて配車を行う必要があります。旅程を報告したり費用を申請したりする場合は、企業のシステムに切り替えなければなりません。すべてのステップを完了して初めて、他の社員に通知します。

クールアプリを使えば、社員はアプリ間を切り替える必要がなくなります。グループ内で簡単にタップするだけで、航空券、ホテル、配車を素早く予約できます。旅程が先に出張した同僚と一致していれば、+1 をタップするだけで一緒に出張できます。旅程データも企業の社内システムと自動的に同期されるため、社員が手動で行う必要はもうありません。

**シナリオ 2:** 社員のシャオミンがグループチャットでプロジェクトを処理している一方で、同僚 A は他の同僚とプロジェクトについて議論しており、同僚 B はプロジェクト関連のドキュメントを書いているかもしれず、同僚 C は DingTalk のワークベンチにおり、同僚 D はカレンダーを閲覧しているかもしれません。シャオミンがグループチャットで任意のプロジェクトデータを更新するだけで、同僚 A、B、C、D は現在の画面を離れることなく、リアルタイムで確認して直接対応できます。

**クールアプリ**は、アプリ間、アプリと人の間、人と人の間でデータを同期し、社員の働き方を変革し、より多くのユーザーに価値をもたらします。クールアプリはまた、より多くの社員がデジタルなアプローチとマインドセットで働くことを促し、没入感のある印象的な体験を通じて、ユーザーが共に問題を見つけ、共に問題を解決し、共に目標を達成できるようにします。

**クールアプリ**は、没入、シナリオ指向、ネットワークコラボレーション、包摂的データという概念に基づいたまったく新しいアプリ形態です。比較的複雑な機能、フォーム、プロセス、レポートで構成される従来の B2B アプリとは異なり、クールアプリは非常に軽量なアプローチで複雑な機能、プロセス、レポートを分解、断片化、パーソナライズし、これらの機能を個別チャット、グループチャット、予定、ドキュメント、検索、ワークベンチといった高頻度のコラボレーションシナリオに取り込みます。社内アプリのクールアプリの例を以下に示します。

## クールアプリのユースケース

### OKR シナリオ

部門グループで OKR クールアプリを有効にすることで、社員が日常業務で OKR を活用できるようになります。OKR クールアプリは、ワンクリック作成、アライメントのスマートリマインダー、更新が発生した際に関連性に基づいて協働者にリマインドする機能などを提供します。また、週次の目標進捗サマリーやワンクリックの週次レポート生成も提供し、その週の主要な Objectives と Key Results の進捗を、グループメンバーが簡単に確認できる簡潔な週次レポートに変換します。

### 採用シナリオ

かつては、さまざまな採用プロセスで変更が発生した際に、多くの調整上の問題に直面していました。多くの組織は複数のシステムを使用するか、まったくシステムを使用せず、複数のロール、ステージ、システム（またはシステムなし）にまたがって並行的に採用を完了するため、コラボレーション効率が低くなっていました。採用クールアプリを使えば、特定の採用ポジション向けにグループを作成し、複数のロールが単一のグループでコラボレーションでき、構造化されたデータが蓄積され、採用効率が大幅に向上します。

### 食事注文シナリオ

食事の注文には、かつて煩雑なステップが伴っていました。まずワークベンチを開き、食事注文アプリを探し、それから適切な食べ物を探します。

クールアプリを使った食事注文はより便利です。健康的な食事をとる人など、特定のグループの人々に対して、グループを作成してお互いに健康に気を配るようリマインドできます。また、食事注文クールアプリを追加すれば、時間になったらワンタップで注文でき、前回の注文を没入的に呼び出すハーフスクリーンカードをリダイレクトなしで利用できます。クールアプリのバックエンドは食事注文リストを自動生成し、印刷して食事の準備と配布を行えます。チャットで「ご飯抜き、ミニトマト多めの牛肉定食が欲しい」と言ったり、注文するためにフォームに記入したりする必要がなくなり、レストランのスタッフも解放されます。

## クールアプリがもたらす変化

### 組織ガバナンスと社員体験のバランスをとる

近年、組織管理やガバナンスモデルについて多くの議論があり、ピラミッド型対フラット型、コントロール対エンパワーメントなど、さまざまな枠組みが提示されてきました。これらの多くは、過去と未来の組織設計を対立する視点から捉え、2 つの異なる管理またはガバナンスモデルとして扱っています。

未来の組織は、もはや単純なコントロールではありません。むしろ、明確な事業戦略の下で、トップダウンで組織の文化、メカニズム、プロセスを整え、その出発点からデジタルシステムを計画します。たとえば、財務シェアードサービスや人事シェアードサービスを構築するか、カスタマーサービスセンターをアップグレードするか、OKR、タレントレビュー、社員ポイントインセンティブプログラムを導入するか、柔軟な固定資産管理ポリシーをリリースするか、異なる事業属性に基づいて社員のインセンティブと昇進システムをアップグレードするかといったことです。これらのシステムもすべてを網羅する必要はありません。多角的な事業を展開する組織では、組織や事業の属性に応じて設計を多様化・差別化できます。

未来の組織は、もはや単純なフラット化や情報の透明化でもありません。核心は、社員を事業と組織のシステムにいかに自然に統合し、メカニズム、プロセス、ルールを効果的に実装しつつ、社員がそれらのメカニズムやルールから明らかな制約を感じないようにするかです。DingTalk の組織規模、高頻度のコラボレーション領域、シナリオ指向のクールアプリの上に構築されることで、メカニズム、プロセス、ルールは組織の効率的で柔軟な運営を支える見えざる手となり、組織が現在直面している多くの課題を解決できます。

### 高頻度のコラボレーション領域を通じて低頻度のソフトウェアを牽引し、デジタル浸透を加速する

かつて組織は、メッセージ配信、データの流れ、ビジネスの推進を加速するために多大な労力を費やし、そのために複数のサイロ化された情報システムを構築していました。DingTalk はこうした問題を解決します。DingTalk はまず、コミュニケーションとメッセージ配信の問題を解決する IM プラットフォームです。また、コラボレーションプラットフォームでもあり、コラボレーションの基盤はデータが自由に流れ、一貫性を保てることにあります。そしてローコードは DingTalk をアプリ開発プラットフォームにします。クールアプリはさらに、企業アプリの高頻度なエントリポイントを開放します。

### マイクロサービスからマイクロアプリへ移行し、スケーリングの課題を解決する

すべての論理的な計算アプローチの中には、2 つの考え方があります。1 つはトップダウン、もう 1 つはボトムアップです。トップダウンは最上位レベルから始めて層ごとに分解し、最終的に全体のブループリントを作り出します。ほとんどの複雑な B2B アプリは、ERP におけるモジュールの分割や機能プロセスの設計など、トップダウンのアプローチで設計されています。しかし、シナリオベースのアプリはボトムアップのアプローチを採用する必要があります。

真に没入感と高いアクティビティを実現するには、クールアプリはこの 2 つを有機的に組み合わせる必要があります。ミドル・バックオフィスのサービスについては、ドメインサービスを設計・蓄積するために依然としてトップダウンのアプローチが必要です。クールアプリのインタラクション設計については、ユーザーの実際のコラボレーションシナリオから始めて、ボトムアップのアプローチを採用しなければなりません。最終的に、クールアプリはミドル・バックオフィスのサービスとクライアントサイドのインタラクションのイノベーションを、まったく異なるスタイルへと牽引します。

## クールアプリとローコード/YiDA の関係

DingTalk がかつて提唱した**ローコード革命**は B2B アプリの開発方法におけるイノベーションであり、**クールアプリ**は B2B アプリの利用方法におけるイノベーションです。

クールアプリは従来のソフトウェアシステムを分解し、シナリオベースの要件を再統合することで、アプリやツールを簡単に利用できるようにし、アプリとデータの機能をすべての社員に届けます。[YiDA](https://www.aliwork.com/)（DingTalk Da）は、ローコードの観点から、業務を理解するより多くの人が低いハードルでアプリを構築できるようにします。クールアプリの概念が推進され、広く認知されるにつれ、YiDA や DingTalk Da といったローコードプラットフォームは必然的にクールアプリのファクトリーとなり、クールアプリの構築をさらに容易にします。

## クールアプリのオープン機能の概要

[グループ拡張](/zh/open/development/cool-application-overview)**はクールアプリの一種です**。これはチャット内で使用される拡張形態であり、クイックエントリポイント、チャットボット、インタラクティブカードでメインアプリを拡張します。これにより、アプリはグループチャットで複数人・複数ロールのタスクコラボレーション、共同での目標作成、商談共有、戦況レポート通知などの没入的な体験を提供できるだけでなく、技術的にクールアプリを個別チャットに統合することもできます。

- グループ拡張の一般的なサーバー API については、グループ拡張の一般的なサーバー API を参照してください。
- グループ拡張のクライアントサイド API については、クールアプリをグループにインストールする を参照してください。

## クールアプリの統合事例

### OKR クールアプリ

DingTalk のグループシナリオにおけるクールアプリの機能に基づき、推進プロセスにおけるコミュニケーションとコラボレーションの問題を解決し、組織が OKR を展開することを「より簡単に」し、OKR を真に「生きたもの」にします。詳細は OKR クールアプリの設計方法 を参照してください。

**Note**

グループ拡張の統合と開発のプロセスは、社内アプリとサードパーティ社内アプリで異なります。実際の業務ニーズに応じて開発してください。

社内アプリ向けのグループ拡張の開発プロセスについては、[グループ拡張の概要](/zh/open/development/cool-application-overview) と [グループ拡張の開発プロセス](/zh/open/development/group-application) を参照してください。

## クールアプリの設計方法

クールアプリのデザインソースファイルが利用可能になりました。これには、アプリの「クール」な体験をさらに向上させるためのクールアプリのデザイン推奨事項と一般的なスタイル仕様が含まれています。また、グループピン、アクティビティカード、ワークベンチ、個人プロフィール、モバイルのハーフスクリーンコンテナ、デスクトップのサイドバーという 6 つの領域のデザイン推奨事項とデザイン事例テンプレートも含まれています。[クールアプリのデザイン仕様](https://ding.design/#/cate/1/page/818) にアクセスして、閲覧およびダウンロードしてください。

### クールアプリのデザインガイド

1. アプリの最も核となる価値の優位性を明確にします。
2. 適切なウェルカム体験を設計します。
3. クールアプリに適したキャリアを選択し、対応するコンテンツを設計します。
4. カード情報を簡潔で閲覧しやすく保ちます。
5. インタラクションが発生するにつれて情報がリアルタイムに変化するようにします。
6. ボタン配置に関する推奨事項。
7. 複数のクライアントをカバーし、クライアント間のインタラクションを利用習慣に合わせます。
8. ダークモードに対応します。
