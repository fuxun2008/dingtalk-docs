# FAQ

## 公式 OA 承認

- **サードパーティ社内アプリでフォームスキーマを取得すると「code: 500, unknown error」が返される**

  A: [フォームスキーマの取得](/ja/open/development/obtain-the-form-schema) API が「code: 500, unknown error」を返す場合、権限の問題が原因である可能性があります。取得できるのは、ユーザーが権限付与したフォームのみです。ユーザーの権限付与がないフォームは返されません。承認インスタンスのデータ取得に必要な権限付与の詳細は、「権限付与ポップアップを呼び出す」を参照してください。
- **承認に添付ファイルを追加するにはどうすればよいですか？**

  A: 承認添付ファイルの処理には、サーバー API とフロントエンド API の両方が必要です。詳しい手順は、ユースケース「[承認添付ファイルの作業フロー](/ja/open/development/new-version-of-attachment-approval-process)」を参照してください。

### 注意

  サーバー API のみで承認添付ファイルを追加することは、現在サポートされていません。

  1. [承認用ドライブスペース情報の取得](/ja/open/development/obtains-the-information-about-approval-nail-disk) API を呼び出し、承認添付ファイル専用の承認用ドライブスペースの spaceId を取得します。
  2. ローカルリソースを選択して承認添付ファイル用のドライブスペースにアップロードする API を呼び出し、spaceId、fileId、fileName、fileSize、fileType の各パラメータを取得します。
  3. 手順 2 で取得したパラメータを、承認を開始する API の添付コンポーネントに渡します。
- **承認内の添付ファイルを取得するにはどうすればよいですか？**

  A: 承認添付ファイルの処理には、サーバー API とフロントエンド API の両方が必要です。詳しい手順は、ユースケース「[承認添付ファイルの作業フロー](/ja/open/development/new-version-of-attachment-approval-process)」を参照してください。

  1. [承認添付ファイルのプレビューの権限付与](/ja/open/development/official-authorized-preview-approval-attachment) API を呼び出します。この API は権限付与を行います。添付ファイルをプレビューできるのは、渡した userid に対応するユーザーのみです。
  2. space_id パラメータを使用して「ドライブへの添付ファイルのアップロード / ドライブからのファイル選択」を呼び出し、ドライブの添付ファイル情報を取得します。
- **承認 API の呼び出しに失敗する**

  A: 承認 API の呼び出しでエラーが返される場合は、次の点を確認してください。

  1. OA 管理コンソールの承認アプリで承認テンプレートを作成する際は、[承認インスタンスの作成](/ja/open/development/create-an-approval-instance)に記載されているコンポーネントタイプのみを選択してください。それ以外を選択すると、承認を開始する API がエラーを返します。
  2. 承認テンプレートの明細コンポーネントでサポートされるのは、入力ボックスと画像コンポーネントのみです。その他のコンポーネントタイプはサポートされていません。
  3. 1 つの承認テンプレートに追加できるコンポーネントは最大 20 個です。
- **OA承認インスタンスを開始する際、明細コンポーネントに渡せるコントロール形式は何ですか？**

  A: [承認インスタンスの作成](/ja/open/development/create-an-approval-instance) API の明細コンポーネントでは、単一行入力ボックス、複数行入力ボックス、数値入力ボックス、画像コントロールの各形式を渡せます。

## 自社 OA 承認

### テンプレートの作成または更新 API

#### errcode=15

- **問題**

  テンプレートの作成または更新 API を呼び出すと、次のエラーが返されます。

  ```json
  {
     " errcode":15,
     " sub_msg":"サービスを利用できません",
     " sub_code":isp.-1,
     " errmsg":"リモートサービスエラー"[
        subcode=isp.-1,
        "submsg=サービスを利用できません"
     ]
  }
  ```
- **原因**

  componentName パラメータにはカスタム値を指定できません。ドキュメントに記載されている固定値のいずれかを渡してください。
- **解決方法**

  componentName の値を変更してください。詳細は、[承認テンプレートの作成または更新](/ja/open/development/create-orupdate-the-approval-template-new)を参照してください。

#### errcode=810002

- **問題**

  テンプレートの作成または更新 API を呼び出すと、次のエラーが返されます。

  ```json
  {
     "errcode":810002,
     "errmsg":"コピーされた承認フローの数が上限を超えています",
     "request_id":"xsr5qth2j075"
  }
  ```
- **原因**

  テンプレート数が上限の 200 個に達しています。
- **解決方法**

  不要になったテンプレートを削除してから、再試行してください。

### インスタンスの作成 API

- **問題**

  承認フローを操作する権限がありません。承認インスタンスまたはテンプレートが正しいか確認してください。

  ```json
  {
      "errcode": 810007,
      "errmsg": "承認フローを操作する権限がありません",
      "request_id": "xxx"
  }
  ```
- **原因**

  processCode パラメータが正しくありません。
- **解決方法**

  [承認テンプレートの作成または更新](/ja/open/development/create-orupdate-the-approval-template-new) API が返した processCode を使用し、**fake_mode** を **true** に設定してください。

### インスタンスの更新 API

#### **errcode=810007** **承認フローを操作する権限がない**

- **問題**

  インスタンスの更新 API（process/workrecord/update）を呼び出すと、次のエラーが返されます。

  ```text
  承認フローを操作する権限がありません。承認インスタンスまたはテンプレートが正しいか確認してください。
  ```

  ```json
  {
      "errcode": 810007,
      "errmsg": "承認フローを操作する権限がありません",
      "request_id": "xxx"
  }
  ```
- **原因**

  インスタンス ID（process_instance_id）パラメータが正しくありません。
- **解決方法**

  インスタンス ID（process_instance_id）には、[インスタンスの作成](/ja/open/development/create-a-ticket-approval-instance) API が返した process_instance_id の値を指定する必要があります。公式承認フローのインスタンス値は使用できません。

#### errorcode=820008

- **問題**

  インスタンスの更新 API（process/workrecord/update）を呼び出すと、次のエラーが返されます。

  ```json
  {
     "errcode":810002,
     "errmsg":"承認システムエラー。原因：[承認フォームが管理者によって変更されました]",
     "request_id":"6pz3le495848"
  }
  ```
- **原因**

  result パラメータが渡されていません。
- **解決方法**

  承認フォームのフォームインスタンスを更新する際は、result の値を渡してから再試行してください。

### タスクの作成 API

#### errorcode=820008

- **問題**

  タスクの作成 API（process/workrecord/task/create）を呼び出すと、次のエラーが返されます。

  ```json
  {
     "errcode":810002,
     "errmsg":"承認システムエラー。原因：[既知のエンジンエラー:{0}",
     "request_id":"6pz3le495848"
  }
  ```
- **原因**

  URL パラメータが長すぎます。
- **解決方法**

  URL パラメータを短くしてから、再試行してください。

#### errorcode=820010

- **問題**

  タスクの作成 API（process/workrecord/task/create）を呼び出すと、次のエラーが返されます。

  ```json
  {
     "errcode":820010,
     "request_id":"6pz3le495848"
  }
  ```
- **原因**

  インスタンス内のタスク数が上限を超えています。
- **解決方法**

  1 つのインスタンスに作成できるタスクは最大 100 件です。不要になったタスクを削除してから再試行するか、新しいインスタンスを作成してください。

### その他

#### 自社 OA 承認 API が「承認フローを操作する権限がありません」を返す

この問題は、「公式 OA 承認」と「自社 OA 承認」のシナリオが混在している場合に発生します。

1. 自社 OA 承認のインスタンスの作成 API を呼び出す際は、process_code パラメータに [承認テンプレートの作成または更新](/ja/open/development/create-orupdate-the-approval-template-new) API が返した値を使用してください。承認の管理コンソールのアドレスバーからコピーした process_code は使用しないでください。
2. 自社 OA 承認のインスタンスステータスの更新 API を呼び出す際は、process_instance_id パラメータに [インスタンスの作成](/ja/open/development/create-a-ticket-approval-instance) API が返した値を使用してください。公式承認フローの承認インスタンスの作成 API が返した process_instance_id は渡さないでください。
