**注意**

ユーザーエクスペリエンス向上のため、**デザインガイドライン**はアップグレードおよび移行されました。本記事で説明するアプリロゴのガイドラインは、アップグレード前の内容を反映しています。**デザインガイドライン**ドキュメントは**2022年5月30日にアップグレード**されました。最新のコンテンツは [DingTalk App Icon Design Guidelines](https://ding.design/#/cate/1/page/802) で直接ご確認ください。

アプリのロゴは、Developer Console、DingTalk クライアントサイド、およびマーケットプレイスに表示されます。インターフェース上で洗練された完成度の高い表示を実現するために、鮮明で適切なサイズのロゴ画像をご用意ください。

## ユースケース

アプリのロゴは、DingTalk ワークベンチ、マーケットプレイス、およびアプリ詳細ページに角丸の正方形として表示されます。

注意：ワークベンチコンポーネントでは、アプリのロゴは実際のサイズ 40 × 40 px で表示されます。このサイズでもロゴが認識できるようにしてください。

## デザインガイドライン

### 1. デザイン原則

| デザイン原則 | 説明 |
| --- | --- |
| シンプルで明確 | モバイルデバイスでは、アプリのロゴは通常さまざまな程度に縮小されます。デザインの際は、グラフィックをシンプルに保つことに十分注意し、小さいサイズで認識できなくなるような不明瞭さを避けてください。シンプルなグラフィックデザインは、ロゴ全体の品質も向上させます。 |
| 正確な表現 | 優れたロゴデザインの第一の前提条件は、意味が正確であり、ユーザーが何を表しているかを瞬時に認識できることです。製品の特徴を高度に凝縮し、その属性を最もよく表すグラフィック要素を見つけ出し、デザインでこれらの要素を強調してください。 |
| 独自性 | 同じタイプの製品は数多く存在し、それらのアプリロゴは似通ったものになりがちです。多くの類似製品の中で自社アプリを際立たせるには、製品のコア機能を強調しつつ独自性を伝え、視覚的な均質化を避ける必要があります。 |
| ブランドの継続性 | ブランド認知度のある製品では、そのブランドロゴを最大限に活用してください。これらのロゴは、すでに強力なブランドイメージと影響力、そして高いブランド認知度を確立しています。アプリアイコンをデザインする際は、既存のブランドイメージを十分に活かしてください。ブランドの深い伝統を継続的に機能させ、ブランドイメージを拡張することで、ブランドにより強い活力を与えます。 |
| テキストの使用を避ける | テキストをアプリロゴとして使用することは、粗雑で単純なアプローチです。テキストが多すぎると、限られたスペース内で縮小するしかなく、アプリロゴが窮屈で読みにくくなります。大量のテキストを使用するもう一つの致命的な結果は、アプリアイコンの美的品質を大きく損なうことです。これは良い印象を与えられないばかりか、かえってユーザーの嫌悪感を引き起こします。 |
| 写真を使用しない | 写真をそのままアプリロゴとして使用しないでください。写真はビットマップであり、拡大縮小すると画質が劣化しやすく、ロゴのデザインに使用すると一連の潜在的な問題を引き起こします。写真の役割は、ロゴデザインの創造性やインスピレーションを提供することであり、ロゴ作成に直接使用することではありません。ベクターグラフィックは画質を損なわずに拡大縮小できるため、ロゴデザインに最も適した選択肢です。 |

### 2. コンテナグリッド

アプリのロゴ出力は、メイン要素の完全性を保持する必要があり、フロントエンドの円形コンテナによって切り取られてはなりません。

#### 2.1 画像の切り取り要件

アプリロゴの実際の出力サイズは 240 × 240 px で、角は直角、PNG/JPG フォーマット、単色で不透明な背景です。

#### 2.2 グリッドシステム

- アプリロゴの視覚的な重みを一定に保つため、背景コンテナ内のグラフィックが円、正方形、または長方形のグリッドエリアに収まるようにしてください。
- 単位グリッドのサイズは 8 × 8 px です。

### 3. 背景色

- セカンドパーティおよびサードパーティのアプリは、独自のブランドカラーを使用できます。
- ファーストパーティのアプリおよび機能エントリアイコンの背景色は、以下のカラーパレットから選択してください。
- グラデーション、純白、純黒は使用しないでください。背景は単一の単色にしてください。

### 4. グラフィック要件

- さまざまなシーンでアプリロゴを鮮明で目を引くものに保つため、「ソリッド/塗りつぶし」のグラフィックアプローチでメイン要素をデザインしてください。
- 純白の塗りつぶしを使用し、色付きの背景に対して十分に際立つようにしてください。
- セカンドパーティまたはサードパーティの開発者が独自のブランドグラフィックを持っている場合は、アプリロゴが縮小されても認識しやすいように、フラットまたはシルエットのスタイルで表現してください。
- 正しい例については「2.3 例」を参照してください。

テキストロゴや、面積が小さすぎるメイン要素は、実際に表示されたときに認識しづらくなります。

ライトな背景に細すぎる線状のグラフィックを使用すると、実際に表示されたときに十分な鮮明さが得られません。

## 安全リスク

1. アプリのロゴはオリジナルであり、法的リスクがないものでなければなりません。
2. アプリのロゴには、ポルノ、ギャンブル、麻薬、銃器、たばこなど、禁止・制限・下品な違法文字やパターンを含めてはなりません。また、政治的傾向や政治的含意を含んではなりません。
3. アプリのロゴには、赤いドット、NEW、HOT などのタグを含めてはなりません。
4. QRコードをミニプログラムのロゴとして使用しないでください。
