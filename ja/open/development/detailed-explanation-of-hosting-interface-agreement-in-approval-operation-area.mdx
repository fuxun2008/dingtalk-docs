## 承認操作エリアの概要

承認操作エリアは承認詳細ページの下部に表示され、操作ボタンが配置されています。例では、**コメント**、**グループディスカッションを作成**、**削除**、**元のフォームに戻る**、**却下**、**承認** のボタンが含まれています。サードパーティアプリは、このエリアのボタンをカスタマイズできます。

## 承認操作エリアの仕組み

サードパーティアプリは、承認テンプレートまたは承認インスタンスの作成時にコールバックを登録します。これにより、承認操作エリアにカスタムボタンを描画し、リクエストを送信できます。App は、ホスティング描画とユーザーリクエストの処理のために、次の 2 つの API を提供する必要があります。

- **ボタンの描画：** DingTalk がサードパーティアプリをコールバックし、操作エリアのボタン定義を取得します。
- **承認操作：** DingTalk がサードパーティの API をコールバックし、ユーザーが送信した承認操作を受け渡して処理させます。

統合フローは、**サードパーティアプリ** から **承認バックエンド：OA Open API** を経て、**承認フロントエンド** へと進みます。承認フロントエンドは、**ToDo**、**承認センター**、**IM インタラクティブカード** の 3 つの画面に結果を描画します。サードパーティアプリは、次の手順を順番に実行します。

1. テンプレートの作成
2. インスタンスの作成
3. 承認操作エリアのカスタム描画ボタンおよびリクエスト送信コールバックの登録
4. タスクの作成

描画および送信の際、承認フロントエンドは **SPI コールバック（描画 / 承認操作）** を通じてサードパーティアプリを呼び出します。このコールバックは **承認バックエンド：Open ゲートウェイ** によってルーティングされます。**ToDo** と **IM インタラクティブカード** の画面からは、承認操作のコールバックがトリガーされます。

## コアモデルの定義

- **ProcessFeatureConfig：プロセスセンター統合設定**

  プロセスセンター統合モードでは、この設定により、サードパーティアプリが一部の業務機能モジュールに独自のロジックを定義できます。承認ページのホスティングソリューションは、この設定をベースにしています。サードパーティアプリは、詳細ページの承認操作エリアにあるすべてのボタンをカスタマイズできます。次の 2 つのコールバック API を追加で設定してください。

  - CUSTOM_ACTION_DEFINITION：DingTalk がサードパーティアプリをコールバックし、操作エリアのボタン定義を取得します（ボタンの描画）。
  - CUSTOM_ACTION_APPLY：DingTalk がサードパーティの API をコールバックし、ユーザーが送信した承認操作を受け渡して処理させます（承認操作）。

  ```text
  "featureConfig":{
    "features":  [
      {
        // 操作エリア（ボタン）データを取得するためのコールバック URL（ボタンの描画）
        "name":"CUSTOM_ACTION_DEFINITION",  
        "runType":"OUTBIZ_CUSTOM",
        "callback":{
          "apiKey":"customActionDefinitionApiKey",
          "appUuid":"appUuid",
          "version":"1"
        }
      },
      {
        // 承認操作の実行時に呼び出されるコールバック URL（承認操作）
        "name":"CUSTOM_ACTION_APPLY",  
        "runType":"OUTBIZ_CUSTOM",
        "callback":{
          "apiKey":"customActionApplyApiKey",
          "appUuid":"appUuid",
          "version":"1"
        }
      }
    ]
  }
  ```

    - ##### **カスタム業務ボタン**

      連携するサードパーティシステムが定義するボタンです。簡単な設定を行うだけで、定義済みボタンと同様のスタイルを適用できます。ユーザーがこのボタンをクリックすると、DingTalk が承認操作 API を通じて連携側のシステムをコールバックします。その後、連携側のシステムがカスタム操作のロジックを実行します。

      |  |  |  |  |
      | --- | --- | --- | --- |
      | ボタン ID [actionType] | 機能 | インタラクションタイプ | 説明 |
      | CUSTOM_ACTION_xxx | カスタム業務ボタン | プラットフォームがサポートする標準インタラクションタイプ：  - link：直接リダイレクト - confirm：確認ダイアログ - modal：ダイアログを開く（ダイアログ内のコンポーネントは業務側でカスタマイズ可能） | ホスティングプラットフォームが予約している ID と重複しないようにしてください。 |
  - **ボタンの並び順と描画ルール**

    ホスティングプラットフォームは、連携側から渡されたボタンをデフォルトで並べ替え、整形します。

    - ホスティングプラットフォームは、共通ボタンを追加する必要があるかを確認し、必要に応じて追加します。
    - DingTalk がサードパーティアプリをコールバックして操作エリアのボタン定義を取得し（ボタンの描画）、返されたデータに基づいてボタンを描画します。コールバックがエラーを返した場合は、ORIGIN ホスティングソリューションの既存ボタン（共有、ダウンロード、印刷、承認、却下、コメント、グループディスカッションを作成、削除、元のフォームに戻る）にフォールバックします。
    - すべてのボタンの並び順：

      - 共通ボタンが先頭に、固定の順序で表示されます。
      - 続いて、定義済みボタンとカスタムボタンが渡された順に表示されます。

  上記のボタン分類とインタラクションタイプに基づく操作ボタンのモデルは次のとおりです。

  | actions | list | 承認操作ボタン |  |

  | ∟actionKey | 文字列 | 業務側が定義する操作キー。ApplyAction API がそのまま受け渡します。設定する場合は、actions 配列内で一意にする必要があります。 | 任意。デフォルトでは省略します。 |

### ステップ 4：プロセスセンターの承認タスクを保存する

**承認タスクのデータを DingTalk に同期：** 承認インスタンス ID `processInstanceId` と ToDo リスト `tasks` を指定して、「プロセスセンター外部統合承認タスクの保存」を呼び出します。この呼び出しにより、サードパーティシステムの承認ノード情報が DingTalk OA承認に同期されます。また、各 ToDo の taskId が返され、対応する DingTalk の ToDo タスクが作成されます。

```json
{
  "processInstanceId": "snfwBxxxx392174",
  "activityId": "001",
  "tasks": [
    {
      "userId": "manager9814",
      "url": "https://www.dingtalk.io"
    },
    {
      "userId": "013xxxx639",
      "url": "https://www.dingtalk.io"
    }
  ]
}
```

### ステップ 5：プロセスセンターの承認タスクのステータスを更新する

**カスタムロジックで承認タスクを承認または却下：** 承認者が DingTalk でカスタム承認ページを開き、承認や却下などの操作を選択します。すると DingTalk は、「プロセスセンター外部統合承認テンプレートの保存」の `CUSTOM_ACTION_APPLY` モジュールに設定されたコールバック API を呼び出します。サードパーティアプリは業務ロジックを実行した後、タスクのステータスを DingTalk に同期する必要があります。自身の承認 ToDo のステータスを更新するには、承認インスタンス ID `processInstanceId` と承認 ToDo タスク ID `taskId` を指定して、[プロセスセンターのタスクステータスの更新](/ja/open/development/update-process-center-task-status) API を呼び出します。

或签（OR 署名）などのシナリオでは、[プロセスセンターの複数の保留中タスクのキャンセル](/ja/open/development/cancel-multiple-oa-approval-tasks) API を呼び出します。この API は、承認インスタンス配下で実行中のすべての ToDo を一括で CANCELED に設定します。

```json
{
  "processInstanceId": "qZpLKAxxxx43810",
  "tasks": [
    {
      "taskId": 88094338042,
      "status": "COMPLETED",
      "result": "AGREE"
    }
  ]
}
```
