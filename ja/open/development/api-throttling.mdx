本記事では、DingTalk サーバー API のレート制限のトリガー条件と解決策について説明します。

アプリのエラーによって DingTalk サーバーに異常な負荷がかかることを防ぐため、社内アプリ、または委託を受けたサービスプロバイダーが開発したカスタム社内アプリからのサーバー API 呼び出しには、デフォルトでレート制限が設定されています。いずれかのディメンションの制限を超えると、対応する API を呼び出した際に、対応するエラーコードが返されます。

## **API ごとの月間呼び出し回数制限**

**Note**

標準版の DingTalk 組織では、すべての社内アプリおよび委託を受けたサードパーティが開発したカスタム社内アプリについて、月間呼び出しクォータにカウントされない API（アクセス認証情報 API、本人確認 API、連絡先 API など。詳細は [付録 A: 月間呼び出しクォータにカウントされない API 一覧](https://open.dingtalk.com/document/orgapp/basic-interfaces-such-as-log-off-and-address-book#) を参照してください）を除き、その他すべての API を合わせて月間 10,000 回の呼び出しクォータが設定されています。

### **トリガー条件**

標準版の DingTalk 組織では、上記の月間呼び出し回数制限を超過した場合、旧サーバー API はエラーコード 90020 を返し、新サーバー API はエラーコード Forbidden.AccessDenied.ApiCountLimitForOrg を返します。

### **解決策**

- **一般:** DingTalk のアカウントマネージャー、DingTalk のシティマネージャー、または DingTalk の地域サービスプロバイダーにお問い合わせいただき、[DingTalk Pro](dingtalk://dingtalkclient/page/link?spm=ding_open_doc.document.0.0.2cfb309498qOzp&url=https%3A%2F%2Fn.dingtalk.com%2Fdingding%2Fweb-dd-pro%2Fmobile_microApp%2Findex.html%3FcorpId%3D%26channel%3Dopenpf_web_devdoc&web_wnd=general&width=480&height=800) または [DingTalk 専用版](https://partner.dingtalk.com/opportunity_web.html?channel=openpf_web_devdoc_trial&templateId=092b3722b3fd4dd08fb641a194a90691#/consultingService) にアップグレードし、その拡張特典を利用して問題を解決してください。

## **API ごとの IP 単位のレート制限**

**Note**

DingTalk の API セキュリティ保護ポリシーにより、各 IP には指定時間内における DingTalk API 呼び出し回数の制限があります。現在の IP が指定時間内にこの呼び出し制限を超えると、DingTalk は対応する情報を返し、呼び出しをブロックします。

### **トリガー条件**

各 IP について、いずれかの DingTalk API を 20 秒以内に 10,000 回を超えて呼び出すとレート制限がトリガーされ、現在の IP は 5 分間呼び出しがブロックされます。このレート制限がトリガーされた場合はエラーコードは返されず、代わりに HTML ページが返されます。返される情報の例は次のとおりです。

```
{
   "status":1111,
   "wait":5,
   "source":"x5",
   "punish":"deny",
   "uuid":"xxx"
}
```

### **解決策**

- **一般:** OpenAPI の呼び出し量に応じて、十分な数の送信元 IP を用意してください。

## **API ごとのアプリ単位の QPS レート制限**

**Note**

標準版の DingTalk 組織が DingTalk API を呼び出す場合、1 秒あたりの呼び出し回数は 20 回を超えてはなりません。現在の 1 秒間の呼び出し回数が 20 回を超えると、対応するエラーがトリガーされます。呼び出しレートが 1 秒あたり 20 回を超えないようにしてください。

### **トリガー条件**

各アプリについて、各 API をその最大レートを超えて呼び出すとレート制限がトリガーされます。旧サーバー API はエラーコード 90018 を返し、新サーバー API はエラーコード Forbidden.AccessDenied.QpsLimitForAppkeyAndApi を返します。

### **解決策**

- **一般**

  - QPS レート制限のウィンドウは 1 秒であるため、レート制限のエラーが発生した場合は、プログラム内で 1 秒間スリープしてから実行を継続してください。
  - **キューによる呼び出し**: 単一アプリの API に対する QPS レート制限は、キューを通じて呼び出しを行うことで解決できます。
- **能動的な単一マシンのレート制限**: これはレート制限を解決する基本的な方法です。単一のサーバーが DingTalk サーバー API を呼び出す場合は、**Guava RateLimiter** などのレート制限 SDK を使用して、呼び出しレートを自由に制御してください。
- **能動的な分散レート制限**: 複数のサーバーが DingTalk サーバー API を呼び出す場合は、キャッシュキーを現在の秒単位のタイムスタンプ、値を呼び出し回数とする分散キャッシュを使用してください。

## **API ごとのグローバル単位の QPS レート制限**

**Note**

DingTalk の API セキュリティ保護ポリシーにより、1 秒あたりの呼び出し回数が制限されています。すべての DingTalk 組織アプリが特定の API を同時に呼び出し、その API の 1 秒あたりの呼び出し制限を超えると、対応するエラーがトリガーされます。

### **トリガー条件**

すべての DingTalk 組織のすべてのアプリが同じ API をその最大レートを超えて呼び出すと、レート制限がトリガーされます。旧サーバー API はエラーコード 90002 を返し、新サーバー API はエラーコード Forbidden.AccessDenied.QpsLimitForApi を返します。

### **解決策**

- **一般**: QPS レート制限のウィンドウは 1 秒であるため、レート制限のエラーが発生した場合は、プログラム内で 1 秒間スリープしてから実行を継続してください。
- **オフピーク戦略**: DingTalk API をスケジュールに従って呼び出すプログラムでは、毎正時などの DingTalk のピーク時間を避けてください。たとえば、毎時 10 分に実行をスケジュールするなどが有効です。
