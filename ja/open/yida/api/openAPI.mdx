YiDA は、HTTP ベースの非同期インターフェースを呼び出すためのリモート API 機能を提供しています（詳細は[リモート API ドキュメント](/ja/open/yida/guide/concept/datasource)を参照してください）。加えて YiDA プラットフォームでは、YiDA データを操作するための標準搭載リモート API を複数用意しています。

<Warning>
YiDA Open API は認証を必要とするため、サイレントログインページから直接呼び出すことはできません。これらの呼び出しは、FaaS 関数または自社構築のバックエンドサービスを経由させてください。
</Warning>

## API 使用上の注意

### リクエストパス

YiDA はアプリ単位で API を提供しています。アプリ内では、次の URL 形式でリモート API を呼び出します（クロスアプリ呼び出しにも対応しています）。

```bash
# アプリコードは、App Settings の Deployment & Operations ページで確認できます。
# インターフェースパスは以下のドキュメントを参照してください。API ごとに異なるパスを使用します。
"/dingtalk/web/${appCode}/${interfacePath}"
```

<Tip>
YiDA プラットフォーム上で API リクエストのコードを記述する際は、以下のように相対パスを使用してください。組織のサブドメインが変更されてもコードを更新する必要がなくなります。

```bash
/dingtalk/web/APP_X1X2X3X4/v1/form/searchFormDatas.json
```

</Tip>

### レスポンス構造

YiDA リモート API が返すレスポンス構造は次のとおりです。

```typescript
interface IResponse {
  success: boolean; // リクエストが成功したかどうか
  result?: object | array | string; // リクエスト成功時のレスポンス内容
  errorMsg?: string; // エラーメッセージ
  errorCode?: string; // エラーコード
  errorLevel?: number; // エラーレベル
}
```

## フォーム API

YiDA プラットフォームは、フォームデータを収集するためのフォーム型ページを提供しています。フォーム API を利用すると、フォームデータの作成、参照、更新、削除が可能です。ここでいう「フォームインスタンス」とは、フォームのデータセット内の 1 件のレコードを指します。

### フォームインスタンスの作成

- インターフェースパス：`/v1/form/saveFormData.json`
- リクエストメソッド：`POST`
- パラメータ：（`formDataJson` は `JSON.stringify()` でシリアライズする必要があります。）

| パラメータ    | 説明        | 必須 | 例                                                                     | 備考                                                                                     |
| :----------- | :---------- | :--- | :--------------------------------------------------------------------- | :--------------------------------------------------------------------------------------- |
| formUuid     | フォーム ID  | はい | FORM-NJYJZELV8YZRDEI2N5IQ7L6VEDMR1VE9GMPCJB                            |                                                                                          |
| appType      | アプリ ID    | はい | APP_DR4OK27ZKL5N22B907E8                                               |                                                                                          |
| formDataJson | フォームデータ | はい | `{"textField_jcpm6agt": "1行入力", "employeeField_jcos0sar": ["workno"]}` | [付録 1：保存 / 更新時のフォームデータ形式](#保存-更新時のフォームデータ形式)を参照してください。 |

- レスポンス例：

```json
{
  "result": "FINST-EF6Y93URN2UZ1SBPLIP9NAV6HR2GEO1Z4ZCHSCJ0",
  "success": true
}
```

### フォーム内コンポーネント値の更新

- インターフェース：`/v1/form/updateFormData.json`
- リクエストメソッド：`POST`
- パラメータ：

| パラメータ          | 説明                                        | 必須 | 例                                            | 備考                                                                                                                                                                                                                                                    |
| :----------------- | :----------------------------------------- | :--- | :--------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| formInstId         | 更新対象のフォームレコード ID              | はい | FINST-NJYJZELVVYZRVGJHR7M6FJW3ESJN1P1TCNPCJ9   |                                                                                                                                                                                                                                                         |
| updateFormDataJson | 更新するフォームコンポーネントの値（必須項目） | はい | `{"employeeField_jcpm5gy2": ["xxxxx", "yyyyy"]}` | [付録 1：保存 / 更新時のフォームデータ形式](#保存-更新時のフォームデータ形式)を参照してください。リクエストに含まれるコンポーネントのみ更新され、含まれないコンポーネントは変更されません。サブフォームの値は一括更新が必須で、サブフォーム内の 1 行内の単一コンポーネントを個別に更新することはできません。 |
| useLatestVersion   | 最新のフォームバージョンで更新する         | いいえ | y                                              | [付録 1：保存 / 更新時のフォームデータ形式](#保存-更新時のフォームデータ形式)内の「重要な注意事項」を参照してください。                                                                                                                                          |

- レスポンス例：

```json
{
  "success": true
}
```

## ワークフロー API

## 付録

### 保存 / 更新時のフォームデータ形式

- フォーム内の各コンポーネントは一意の ID を持ち（ページデザイナーでコンポーネントの右側にある「高度な使い方」パネルで確認できます）、コンポーネントごとに固定のデータ形式を使用します。対応するフォームコンポーネントは次のとおりです：1 行入力、複数行入力、数値、ラジオボタン、ドロップダウン選択、複数選択、ドロップダウン複数選択、日付、日付範囲、ユーザー選択、地域選択、部門選択、カスケード選択、サブフォーム。
- フォームデータを保存または更新する際は、フォーム値を `Map<String, Object>` 形式の JSON 文字列として渡します。キーがコンポーネント ID、値がコンポーネントの値となります。各コンポーネントの値の形式は以下のとおりです。

| コンポーネントの種類 | データ型       | データ形式                                                                                                                | 備考                                                                                                                       |
| :------------------ | :------------- | :------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| 1 行入力            | 文字列          | "danhang"                                                                                                                  |                                                                                                                            |
| 複数行入力          | 文字列          | "duohang"                                                                                                                  |                                                                                                                            |
| 数値入力            | 数値            | 1                                                                                                                          |                                                                                                                            |
| ラジオボタン        | 文字列          | "選択肢 1"                                                                                                                 |                                                                                                                            |
| ドロップダウン選択  | 文字列          | "選択肢 1"                                                                                                                 |                                                                                                                            |
| 複数選択            | 文字列配列       | ["選択肢 1", "選択肢 2"]                                                                                                   |                                                                                                                            |
| ドロップダウン複数選択 | 文字列配列    | ["選択肢 1", "選択肢 2"]                                                                                                   |                                                                                                                            |
| 日付コンポーネント  | タイムスタンプ  | 日付コンポーネント                                                                                                          |                                                                                                                            |
| 日付範囲            | 文字列配列       | ["1514736000000", "1517328000000"]。終了時刻のみ指定する場合は ["", "1517328000000"] とします。                            | 1 つ目の値が開始時刻のタイムスタンプ文字列、2 つ目の値が終了時刻のタイムスタンプ文字列です。                                |
| ユーザー選択        | 文字列配列       | ["xxxxx", "yyyyy"]                                                                                                         |                                                                                                                            |
| 都市選択            | 文字列配列       | ["110000", "110100", "110101"]                                                                                             | 1 つ目は省 ID、2 つ目は市 ID、3 つ目は区 ID である必要があります。                                                            |
| 部門選択            | 文字列配列       | ["1123456"]                                                                                                                | ["xxx"] には部門 ID を含めます。                                                                                             |
| カスケード選択      | 文字列配列       | ["part", "part_b"]                                                                                                         | カスケードの順序に従って値を配列に格納する必要があります。                                                                    |
| 画像アップロード    | 文字列配列       | `[{"downloadUrl":"ファイルのダウンロード URL", "name": "添付名称"}]`                                                       |                                                                                                                            |
| 添付                | 文字列配列       | `[{"downloadUrl":"ファイルのダウンロード URL", "name": "添付名称"}]`                                                       |                                                                                                                            |
| ハイパーリンク      | 文字列配列       | `[{"link":"http://www.yidaapps.com", "text":"YiDA"}]`                                                                      |                                                                                                                            |

### 条件検索時のコンポーネント値の形式

- フォーム内の各コンポーネントは一意の ID を持ち（ページデザイナーでコンポーネントの右側にある「高度な使い方」パネルで確認できます）、コンポーネントごとに独自の検索形式があります。検索を利用できるフォームコンポーネントは次のとおりです：1 行入力、複数行入力、数値、ラジオボタン、ドロップダウン選択、複数選択、ドロップダウン複数選択、日付、日付範囲、ユーザー選択、地域選択、部門選択、カスケード選択、サブフォーム。
- 検索を行う際は、各コンポーネントの検索条件を `Map<String, Object>` 形式で指定します。キーがコンポーネント ID、値がそのコンポーネントの検索値です。各コンポーネントの検索タイプと値の形式は以下のとおりです。

| コンポーネントの種類 | データ型      | データ形式                                                                | 備考                                                                                                                                     |

| 数値入力            | 文字列配列    | ["1", "10"]                                                                | 範囲検索。1 つ目が最小値、2 つ目が最大値です。                                                                                              |
