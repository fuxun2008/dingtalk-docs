## 三、基本操作

プロセス設計には、以下4種類の基本操作があります。

| 基本操作 | 説明 |
| --- | --- |
| ノードの追加 | フローに申請者・承認者・CC受信者・処理担当者などのノードを追加 |
| ノード属性の設定 | ノードの操作者タイプを選択し、タイプに応じた設定を実施 |
| ノード権限の設定 | 各ノードのフォームフィールドに対する操作権限を調整 |
| 分岐の追加 | 分岐条件の設定、階層別条件フローの設定 |

### 一）ノードの追加

**+** をクリックすると、承認者・CC受信者・処理担当者・条件分岐などを追加できます。

<Frame>

![プロセス設計でプラス記号をクリックしてノードを追加](https://img.alicdn.com/imgextra/i1/O1CN01rzDmSqUAZpF5bBcY_!!6000000001097-2-tps-2758-1732.png)
</Frame>

| 承認ノードタイプ | 説明 | 詳細 |
| --- | --- | --- |
| 申請者 | 申請者ノードは承認フローの起点です。誰がこの承認フォームを送信できるか、申請者がフォーム入力時にどのフィールドを記入できるかなどを設定できます | デフォルトノード<br />ノード名は変更不可<br />送信後、フローセンターの「私が申請した」カテゴリで確認可能<br />フォーム内フィールドの操作権限（編集可能・閲覧のみ・非表示）を設定可能 |
| 承認者 | 承認フォームに対して「承認」「拒否」「転送」「差戻し」「リクエスト署名」などの操作を実行可能 | オプションノード<br />ノード名は変更可能<br />承認前はフローセンターの「処理待ち」カテゴリで確認可能。承認後はフローセンターの「私が処理した」カテゴリで確認可能<br />フォーム内フィールドの操作権限（編集可能・閲覧のみ・非表示）を設定可能 |
| CC受信者 | このノードに到達しても審査機能はなく、該当する承認フォームを受け取って閲覧・コメント操作が可能 | オプションノード<br />ノード名は変更可能<br />このノードに到達後、フローセンターの「CC受信」カテゴリで確認可能<br />フォーム内フィールドの表示権限（閲覧のみ・非表示）を設定可能 |
| 処理担当者 | 承認フォームに対して「送信」「転送」「差戻し」「リクエスト署名」「コメント」などの操作を実行可能 | オプションノード<br />ノード名は変更可能<br />処理前はフローセンターの「処理待ち」カテゴリで確認可能。処理後はフローセンターの「私が処理した」カテゴリで確認可能<br />フォーム内フィールドの操作権限（編集可能・閲覧のみ・非表示）を設定可能 |
| 条件分岐 | このノードを利用して、異なる状況に応じて異なる承認分岐を実現可能<br />詳細な操作は [条件付き承認の設定方法](/ja/approval/set-conditional-approval) を参照 | オプションノード<br />分岐名は変更可能<br />分岐のコピーに対応<br />条件の追加に対応：異なる条件間は「かつ」の関係<br />条件グループの追加に対応：異なる条件グループ間は「または」の関係<br />実行時は**優先度順に順次実行**<br />いずれか1つの分岐ルールが通過すると、他の分岐は試行を継続せず、**条件分岐は1つのみ実行される** |
| 並列分岐 | 有料オプション。このノードを利用して、複数の承認分岐を同時に流すことが可能 | オプションノード<br />分岐名は変更可能<br />分岐のコピーに対応<br />条件の追加に対応：異なる条件間は「かつ」の関係<br />条件グループの追加に対応：異なる条件グループ間は「または」の関係<br />複数の分岐を設定されたルールに従って**同時実行**可能 |
| コネクタ | 有料オプション。このノードを利用して、「マイインテグレーション」で設定されたコネクタを呼び出し可能 | オプションノード |
| 自動化 | 有料オプション。このノードを利用して、自動化タスクを設定可能 | オプションノード |

### 二）ノード属性の設定

#### 1、申請者

申請者は業務事項の申請者であり、承認フローの起点として、フォーム内容の記入と送信を行います。

| 属性 | 説明 |
| --- | --- |
| 申請者タイプ | デフォルトは組織内ユーザー |
| 送信できる人 | ベーシック設定の「申請できる人」と一致します。ここで調整すると、ベーシック設定も連動して変更されます |

<Frame>

![申請者ノードの属性設定パネル](https://img.alicdn.com/imgextra/i1/O1CN01qxtcZQlYcRE5bwRq_!!6000000003621-2-tps-2764-1730.png)
</Frame>

#### 2、承認者

承認者は業務事項の審査・承認者であり、承認フォームに対して「承認」「拒否」「転送」「差戻し」「リクエスト署名」などの操作を実行できます。

**1）承認者属性設定**

| 属性 | 説明 |
| --- | --- |
| ノード名 | 承認詳細ページに表示される、承認ノードに対応する名称。デフォルトは「承認者」<br />ノードに対応する役職（例：「財務総監」）や、具体的な審査内容（例：「契約コンプライアンス審査」）に設定可能 |
| 承認タイプ | 手動承認・自動承認・自動拒否に対応<br />デフォルトは手動承認<br />自動承認と自動拒否は通常、条件分岐と組み合わせて使用し、自動承認を実現します |
| ノード承認者 | ノード承認者は複数のタイプに対応しており、異なる承認フローのニーズに柔軟に応えられます |
| 複数人承認時の承認方式 | 複数人が同一ノードに参加する場合、順次承認・共同署名・または署名・投票に対応<br />順次承認：複数人が順次承認し、全員が承認した場合のみ承認が通過<br />共同署名：複数人が同時に承認し、全員が承認した場合のみ承認が通過<br />または署名：複数人が同時に承認し、いずれか1名が承認すれば通過。いずれか1名が拒否した場合、承認は通過しない<br />投票：有料オプション。複数人が同時に承認し、要件を満たす承認人数に達した場合に承認が通過 |
| 承認者が不在の場合の処理方式 | 承認者を上司・部門責任者・ロールなどのタイプに設定した場合、連絡先の設定が不完全でマッチする人員が見つからない状況が発生する可能性があるため、承認者が不在の場合のフロールールを設定する必要があります<br />自動承認：このノードで承認者が見つからない場合、承認フォームは自動的に承認されます<br />自動拒否：このノードで承認者が見つからない場合、承認フォームは自動的に拒否されます<br />管理者に自動転送：デフォルトでテンプレート管理者に転送。テンプレート管理者が存在しない場合は承認管理者に転送<br />指定メンバー承認：ロールまたは上司が不在の場合、承認フォームは自動的に指定メンバーに転送されます。最大1名まで指定可能 |

    ノード承認者で「複数レベルの上司」を選択した場合、申請者から何階層上の上司まで承認するかを設定できます。この設定後、フローは部門マネージャーの階層に従って自動的に流れ、まず申請者の第1階層の部門マネージャーを識別し、続いて第2階層の部門マネージャーを識別し……申請者からN階層上の上司まで続きます。

#### 3、CC受信者

CC受信者は業務事項の関係者であり、事項を把握する必要はあるものの、意思決定は不要な立場です。このノードに到達しても審査機能はなく、該当する承認フォームを受け取って閲覧・コメント操作が可能です。

| 属性 | 説明 |

| ノード名 | 承認詳細ページに表示される、CCノードに対応する名称。デフォルトは「CC受信者」<br />ノードに対応する役職やロールタイプ（例：「財務総監」「その他プロジェクトメンバー」）に設定可能 |
| ノードCC受信者 | ノードCC受信者は複数のタイプに対応しており、異なるCC受信者への通知ニーズに柔軟に応えられます |

#### 4、処理担当者

処理担当者は業務事項の具体的な実行者であり、審査・承認権限はなく、承認フォームに対して「送信」「転送」「差戻し」「リクエスト署名」「コメント」などの操作が可能です。

| 属性 | 説明 |
| --- | --- |
| ノード名 | 承認詳細ページに表示される、処理ノードに対応する名称。デフォルトは「処理担当者」<br />ノードに対応する役職（例：「出納」）や、具体的な処理事項（例：「契約押印」）に設定可能 |
| ノード処理担当者 | ノード処理担当者は複数のタイプに対応しており、異なる処理担当者のフローニーズに柔軟に応えられます |
| 複数人処理時の処理方式 | 複数人が同一ノードに参加する場合、順次処理・全員同時処理・1名の処理担当者による処理に対応 |
| 処理担当者が不在の場合の処理方式 | 処理担当者をロールや上司に設定した場合、連絡先の設定が不完全でマッチするユーザーが見つからない状況が発生する可能性があるため、処理担当者が不在の場合のフロールールを設定する必要があります<br />自動承認：このノードで処理担当者が見つからない場合は自動的にスキップ<br />管理者に自動転送：デフォルトでテンプレート管理者に転送。テンプレート管理者が存在しない場合は承認管理者に転送<br />指定メンバー処理：ロールまたは上司が不在の場合、指定メンバーに転送して処理 |

### 三）ノード操作権限の設定

ノード属性パネルで「**フォーム操作権限**」タブに切り替えると、そのノードのフォーム内各フィールドに対する操作権限を設定できます。

<Frame>

![ノード属性でのフォーム操作権限設定](https://img.alicdn.com/imgextra/i3/O1CN01ZT9h8G4eFgB5cC3e_!!6000000005395-2-tps-2766-1732.png)
</Frame>

| フォーム操作権限 | 説明 | 詳細 |
| --- | --- | --- |
| 編集可能 | フォーム内の「編集可能」コンテンツを記入・修正可能 | 申請者・承認者・処理担当者ノードに対応<br />申請者のデフォルトのフォーム操作権限は編集可能 |
| 閲覧のみ | フォーム内の「閲覧のみ」コンテンツは閲覧のみ可能。記入・修正は不可 | 申請者・承認者・処理担当者・CC受信者ノードに対応<br />承認者・処理担当者・CC受信者のデフォルトのフォーム操作権限は閲覧のみ<br />申請者ノードを閲覧のみに設定した場合、現在のノードは申請者に対して非表示になる |
| 非表示 | フォーム内の「非表示」コンテンツは閲覧不可 | 申請者・承認者・処理担当者・CC受信者ノードに対応 |
