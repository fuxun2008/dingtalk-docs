<Note>
- YiDAのシンプルなワークフロー設計ツールでは、最大100個の設計ノード（開始ノードと終了ノードを含む）に対応します。この上限を超えるとエラーが発生し、作業フローを保存できません。
- YiDA専用版のワークフロー設計ツールでは最大150個のノードに対応しており、業務プロセスをより柔軟に設計できます。
</Note>

## 機能概要

フォームに対してユーザーによるレビューと確認が必要な場合は、ワークフローフォームを使用する必要があります。ワークフローフォームと通常フォームの主な違いは、ワークフローフォームではワークフロー設計が必要になる点です。

![](https://gw.alicdn.com/imgextra/i3/O1CN015rE7r9OCQTH5pXJi_!!6000000001029-2-tps-2872-1610.png)

## ユースケース

従来の紙ベースの承認は時間がかかり、非効率です。複雑な業務プロセスにおいては、申請者は承認を得るために各所を回らなければならず、承認者も業務を頻繁に中断させられます。YiDAはオンラインでの作業フロー承認を可能にすることでこの問題を解決し、さまざまな複雑な業務プロセスの承認を効率的に処理し、チームの生産性を高めます。

## 操作手順

1. YiDAワークベンチにログインします。
2. 対象のアプリを選択し、ページ管理ページを開きます。
3. 編集したいワークフローフォームを選択し、クリックしてフォーム設計ページに入ります。
4. フォーム設計ページ上部の「ワークフロー設計」をクリックします。

<Frame>
  ![](https://gw.alicdn.com/imgextra/i3/O1CN016TEXcEjy5wE7HPvI_!!6000000005773-2-tps-3586-1994.png)
</Frame>

5. 右上の「作業フローの作成」をクリックします。

<Note>
有効な作業フローは閲覧のみ可能で、直接編集することはできません。ワークフローフォームを作成すると、承認者として自分自身、バージョン番号としてV0が設定されたデフォルトの作業フローが自動的に生成されます。
</Note>

## FAQ

**Q: 新しいシンプルなワークフロー設計ツールを作成するにはどうすればよいですか？アプリ内の通常のワークフローエディターが新しいシンプルなワークフロー設計ツールに更新されないのはなぜですか？**

現在、新しいシンプルなワークフロー設計ツールは、アップデート後に作成されたワークフローページにのみ適用されます。アップデート前に作成された作業フローは、引き続き従来のワークフロー設計ツールを使用します。

**Q: YiDA 2.0は新しいシンプルなワークフロー設計ツールに対応していますか？**

はい、対応しています。ページ上の青枠でハイライトされた箇所をクリックすると、ワンクリックでアップグレードできます。

アップグレード後、従来のワークフロー設計ツールにロールバックすることはできません。設定済みの作業フローの設定はすべて新バージョンに移行されます。

**Q: 承認を送信する際に「承認者が無効です。組織管理者にお問い合わせください」というエラーが表示されます。どうすればよいですか？**

**原因**: フローノードで設定した承認者が存在しません。YiDAは、シンプルな作業フローが起動されたときに、ワークフロー設計に照らして承認者を検証します。

**解決策**:

- このエラーは、通常、承認者が上長に設定されている場合に発生します。DingTalkの連絡先で申請者の部門に対応する上長が設定されているか確認してください。設定されていない場合は追加してください。
- または、フローノードで承認者を「承認者が空でも許可する」に設定します。例えば、二次上長が存在しない可能性がある場合は、二次上長を空にすることを許可する必要があります。設定手順は以下のアニメーションを参照してください。

**Q: 承認結果を申請者に通知するにはどうすればよいですか？**

現在、この機能はモバイルクライアントのみで対応しています。モバイルで承認する際、承認者は「承認」または「却下」をタップした後、下部の「申請者に通知」を選択できます。PCクライアントはこの機能に対応していません。

このオプションをチェックして送信すると、以下のように申請者のDingTalkのプライベートチャットにメッセージ通知が表示されます。

**Q: モバイルで承認を送信する際に、承認者への通知をオフにするにはどうすればよいですか？**

モバイルでワークフローフォームを送信すると、デフォルトで「現在の担当者：XX。チャットで通知しますか？」というダイアログが表示されます（PCクライアントではこのプロンプトは表示されません）。この機能をオフにするには、**こちら**をクリックしてフォームに記入し、リクエストを送信してください。YiDAは3営業日以内に対応します。

ヒント：この機能は組織単位でオフになります。慎重にご検討ください。

**Q: ワークフローフォームを通常フォームに素早く変換するにはどうすればよいですか？**

フォームの種類を直接変換することはできません。以下の回避策をご利用ください。

<Frame>
  ![](https://gw.alicdn.com/imgextra/i4/O1CN01j0pwUH4NUnJ0uWWF_!!6000000005854-2-tps-449-926.png)
</Frame>

ワークフローフォームの設計ページを開く >> Ctrl（Windows）またはCommand（Mac）を長押し >> フォーム設計ページ上のすべてのコンポーネントを選択、または左側のアウトラインツリーをクリックしてすべてのコンポーネントを選択 >> キーボードショートカットでコピー >> 新規作成した通常フォームに貼り付け >> 保存

**注意：この方法では、フォームの設定のみが通常フォームにコピーされます。JSコードやページ設定は、新しい通常フォームで再設定する必要があります。**

**Q: 作業フローが起動された後、承認フローから承認者が欠落しているのはなぜですか？**

**考えられる原因**: 作業フローの起動後に申請者の部門構成が変更されたため、新しい部門のワークフローが有効になっていません。

**Q: 承認タスクが生成された後、業務通知が届かなかったのはなぜですか？**

A: 承認タスクの生成から業務通知の送信までにはネットワーク遅延があります。業務通知を送信する前に、システムはタスクのステータスを確認します。タスクがすでに完了している場合、承認通知は送信されません。

例えば、承認タスクが生成され、承認者が即座に承認を完了した場合、業務通知はまだ送信されていない可能性があります。この場合、対応する業務通知は送信されません。

**Q: 作業フローの分析のデータ範囲をカスタマイズするにはどうすればよいですか？**

- ワークフローフォーム > 作業フロー分析の作成からデフォルトレポートを作成した場合、デフォルトレポートは現在のフォームのフィルターを適用し、デフォルトでは現在の作業フローのみをクエリします。
- レポートに手動でコンポーネントを追加して組み込みデータセットを選択した場合、**フィルター**で自分で作業フローをバインドする必要があります。そうしないと、デフォルトではアプリレベルの詳細データ全体が対象になります。

**Q: メッセージ通知を設定しましたが、機能しません。なぜですか？**

ワークフローフォーム内でメッセージテンプレートを追加、変更、または削除した場合、ページ上の青いテキスト**[こちらをクリック]**をクリックしてください。これにより、新しい作業フローのバージョンが自動的に作成され、変更が有効になります。

**Q: YiDAのインスタンス詳細リンクの形式は何ですか？**

- ワークフローインスタンスの詳細リンク形式

```text
https://www.yidaapps.com/APP_xxx/processDetail?procInsId=7e03d424-xxxx-8080
```

```text
YiDAドメイン/アプリのappType/固定パラメータ (processDetail)?procInsId=データのインスタンスID
```

```javascript
`${location.origin}/${window.pageConfig.appType || window.g_config.appKey}/processDetail?procInsId=${procInsId}`
```

- フォームインスタンスの詳細リンク形式

```text
https://www.yidaapps.com/APP_xxx/formDetail/FORM-xxx?formInstId=FINST-xxx
```

```text
YiDAドメイン/アプリのappType/固定パラメータ (formDetail)/データが存在するテーブルのformUuid?formInstId=データのインスタンスID
```

```javascript
`${location.origin}/${window.pageConfig.appType || window.g_config.appKey}/formDetail/${formUuid}?formInstId=${formInstId}`
```

**Q: 作業フローが起動された後、申請者が組織を離れたり部門を異動したりした場合はどうなりますか？実行中に発生したエラーはどのように対処すればよいですか？**

- 申請者と申請部門は作業フローが起動された時点で固定され、部門異動や委任による再送信に関わらず、作業フローのライフサイクル全体を通じて変更されません。
- 作業フロー内のユーザーが組織を離れ、そのユーザーの組織構成情報に依存する承認ノード（例えば上長承認）がある場合、作業フローは承認者を見つけられません。これによりエラーが発生し、作業フローは進行できなくなります。この場合、管理者が別のノードにジャンプすることで問題を解決する必要があります。
