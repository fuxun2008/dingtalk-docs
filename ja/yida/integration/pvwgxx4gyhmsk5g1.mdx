DingTalk 標準のコネクタでは要件を満たせず、DingTalk アプリ、自社構築システム、またはサードパーティアプリと迅速に連携する必要がある場合は、YiDA コネクタファクトリーでカスタムデータコネクタを構築できます。

| **認証方法** | **説明** |
|---|---|
| 認証なし | 認証情報を必要とせず、API を直接呼び出せる方式です。通常はパブリック API へのアクセスに使用します。 |
| Basic 認証 | Basic 認証は、HTTP リクエストの Authorization リクエストヘッダーに基づく方式です。リクエストヘッダーには、サーバーがユーザーエージェントの身元を検証するための認証情報が含まれます。<br />• **形式**：`Authorization: Basic <ciphertext>`。<br />たとえば、ヘッダーに `Authorization: Basic YWxhZGRpbjpvcGVuc2VzYW1l` を追加します。これは Base64 でエンコードされたアカウントとパスワードの情報です。<br />認証情報の登録時にユーザーが入力すべき内容が分かるよう、アカウントとパスワードのプロンプトラベルを設定するだけで済みます。<br />例：<br />• **ユーザー名ラベル**<br />• **パスワードラベル** |
| API Key | **APIKey** 認証方式を指します。APIKey は長期間有効です（厳重に保管してください）。訪問者は対象システムでシークレットキーを作成し、開発者はこの認証情報を使用して、この認証タイプに対応するパブリック API を呼び出せます。<br />• **パラメータラベル**：認証情報を設定する際のプロンプトとして使用します。<br />• **パラメータ名**：システムが必要とする apiKey の名前です。<br />• **パラメータの位置**：対象システムの要件に応じて、認証情報をクエリパラメータとヘッダーのどちらに付加するかを選択します。 |
| Alibaba Cloud API Gateway | コネクタ作成後に認証テンプレートを追加し、テンプレートに App Code を入力すると、対応する Alibaba Cloud API を呼び出せます。<br />詳細は [App Code 認証による API 呼び出し](https://help.aliyun.com/document_detail/115437.html) を参照してください。 |
| DingTalk Open Platform 認証 | コネクタ作成後に認証テンプレートを追加し、テンプレートに `App Key` と `App Secret` を入力すると、DingTalk Open Platform の API（一部の YiDA API を含む）を呼び出せます。<br />認証テンプレートを追加すると、YiDA が認証パラメータ `access_token` を自動生成し、リクエスト時に `Header` の `x-acs-dingtalk-access-token` パラメータに追加します。再生成は不要です。<br />詳細は [DingTalk アプリ開発プロセス](https://open.dingtalk.com/document/orgapp/overview-of-development-process) を参照してください。 |
| DingTalk Zero Trust Gateway | DingTalk Zero Trust Gateway の使用方法は、[DingTalk Open Platform - Zero Trust Gateway 認証](https://open.dingtalk.com/document/connector/untitled-document-4) を参照してください。 |

## ステップ 2：実行アクションの作成

実行アクションページで **実行アクションを作成** をクリックし、以下の説明に従ってアクションを設定します。

| **名前** | **説明** |
|---|---|
| 基本情報 | 現在の実行アクションの基本情報を設定します。<br />• **固定値識別子**：異なるアクションを区別するために使用します。<br />• アクション名：実行アクションの名前です。<br />• アクションの説明：実行アクションの説明です。 |
| API リクエスト | 現在の実行アクションがトリガーされた際に、どの API を呼び出すかを設定します。<br />• **リクエスト URL**：API のリクエストリンクです。リクエストドメインにはコネクタのドメインが自動的に入力されます。<br />• **HTTP メソッド**：GET、POST、DELETE、PUT、HEAD、OPTIONS、PATCH などのメソッドに対応しています。<br />• **Query**：リクエストパラメータで、通常は URL のクエスチョンマーク `?` 以降に付加するパラメータを指します。プラス記号をクリックして追加します。<br />• **Body**：POST リクエストなどでは、Body フィールドが含まれる場合があります。リクエスト JSON を使ったパースに対応しています。<br />• **Headers**：追加のリクエストヘッダーをここでカスタマイズできます。現在は静的な設定のみに対応しています。<br />• **Path**：URL 内の中括弧で囲まれた変数を指します。たとえば `{pathParam}` の `pathParam` が変数名になります。<br />**注意**：リクエストパラメータには、ログインユーザーのユーザー ID や組織 ID などのシステムフィールドを設定できます。 |
| API レスポンス | API 呼び出しが成功した後の想定レスポンスを設定します。JSON を使ったパースに対応しています。<br />**注意**：API レスポンスが JSON オブジェクトでない場合、統合と自動化で直接使用することはできません。スクリプトノードで手動でパースする必要があります。 |

## ステップ 3：認証の設定

すべてのカスタムデータコネクタには、対応するリクエスト認証スキームが必要です（「**認証なし**」であっても同様です）。

1. アカウントの作成

設定済みのコネクタで「テスト」をクリックすると、認証アカウントの選択を求められます。このタイミングで新しい認証アカウントを作成することもできます。

2. アカウントの表示名、AppKey、AppSecret などの情報を入力し、「確認」をクリックします。
