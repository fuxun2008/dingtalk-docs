周期的にフォームの記入をリマインドしてデータを収集する場合、収集したデータに対して周期分割機能を適用できます。当期に該当しないデータを、設定したサイクルに沿って複数の**履歴期間データテーブル**に分けて保存できます。クローズ済みの注文、完了した巡回点検、終了済みの打刻など、テーブル分割で保存することにより、データを読み取り専用で表示・検索でき、データ計算空間の使用量を抑えられます。

## 基本操作

1. フォームビューに入り、右上の**設定**をクリック
2. **周期的なリマインド**をオン
3. 設定パネルで**周期分割**をオンにする

![](/ja/aitable/forms/form-rotation/images/image_I7-jepgTlJ.png)

各サイクルの終了後、AI テーブルの一覧に当該サイクルの履歴期間テーブル統計が表示されます。クリックすると詳細結果を確認できます。

## 履歴期間テーブルの対応 / 非対応操作

| 機能 | 課題と解決策 |
| ------------ | ---------------------------------------------------------------- |
| 編集 | - 履歴期間テーブルは編集できません |
| 検索 / フィルター / グループ化 / 並べ替え | - 履歴期間テーブル内で内容の検索が可能 - 履歴期間テーブル内でのフィルターは不可 - 履歴期間テーブル内でのグループ化は不可 - 履歴期間テーブル内での並べ替えは不可 |
| 片方向 / 双方向リレーション・参照リレーション | - 当期テーブル内の既存リレーションデータは分割後も維持されます - 履歴期間テーブルでの新規リレーション作成は不可。他テーブルから履歴期間テーブルへのリレーションも不可 |
| 数式 | - 履歴期間テーブル内のレコードの数式は更新されなくなります - 当期レコードで数式を計算する際、履歴期間テーブルのレコードを参照・リレーションすることはできません |
| ダッシュボード | - 履歴期間テーブルのデータはダッシュボードに表示できます - 当期サイクルが終了し、データが履歴期間テーブルに分割されると、ダッシュボードのデータは新しいサイクルの当期データに変わります |
| 高度な権限 | - データが分割された後は、履歴期間にアクセスできるよう、ユーザー側で高度な権限設定を手動で変更する必要があります |
| 自動化 | - 履歴期間テーブルでは自動化フローがトリガーされず、自動化によるデータ変更、参照、検索のいずれにも対応していません |
| OpenAPI | - 履歴データテーブルのデータ取得が可能です |
| 履歴 | - 履歴期間テーブルでは履歴の復元に対応していません |
| エクスポート | - 履歴期間テーブルのダウンロードが可能です |
| コピー & ペースト | - 行データのコピーは可能ですが、テーブル全体のコピーはできません - 切り取りと貼り付けには対応していません |
| モバイル端末 | - 履歴期間テーブルのデータを閲覧できます |
| 共有 | - 高度な権限が無効の場合、閲覧権限を持つユーザーは履歴期間テーブルのデータにアクセスできます |
