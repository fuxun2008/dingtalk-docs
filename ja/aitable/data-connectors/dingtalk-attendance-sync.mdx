## 概要

- 勤怠の**日次統計レポート**は、AI Tableのデータ同期センターを通じてAI Tableに同期できます。リアルタイム更新に対応し、手動更新と1時間ごとの自動同期が利用できます。
- インポートされたフィールドは編集できませんが、カスタムフィールドの追加は可能です。さらに、AI Tableの自動化、高度な使い方の権限、ダッシュボードなども利用できます。
- 同期テーブルを自由に編集したい場合は、いつでも同期を解除できます。または同期テーブルを複製することもできます。複製したテーブルはソースとの関連がなくなります。

## よくあるシナリオ

- マネージャーがチームの勤怠状況をリアルタイムに把握し、人材管理の効率を高めるのに役立ちます。勤怠記録、休暇情報、欠勤データなどを同期し、AI Tableのダッシュボード、データ分析、自動化と組み合わせることで、異常の追跡、出勤率の分析、業績評価などに活用できます。

## 勤怠データの同期

1. AI Table左サイドバーの下部で、**+ 追加 / インポート**をクリックし、**データ同期センター**を選択します。

2. データソースを選択します。**勤怠**コネクタを選択または検索し、**使用**をクリックして設定画面に進みます。

3. データソース設定 — 勤怠グループ単位で勤怠データを同期します。

   1. **データソースの選択**：利用可能なソースは1つのみで、デフォルトで選択されています。
   2. **パラメータ**
      1. 対応するメンバーフィルター：勤怠グループ単位で同期します。1つまたは複数のグループを選択します。
      2. 同期する期間を設定します。2つのモードがあります。
         注：手動更新・自動更新ともに、現在は直近1年分のデータのみ取得できます。より長い期間への対応は今後予定しています。
         | **モード** | **対応範囲** | **説明** |
         | --- | --- | --- |
         | 期間指定（注：手動更新・自動更新ともに、現在は直近1年分のデータのみ取得します） | 開始日 — 終了日 | **自動更新では、システムが現在の日付を基準に更新の要否を判断します。現在の日付が終了日を過ぎている場合、同期は自動停止します。自動更新を継続するには、期間を手動で調整するか、終了時間を削除してください。** |
         |  | 開始日 — 終了日なし | 終了日を設定しない場合、自動更新は停止しませんが、デフォルトでは直近1年分のみ取得されます。 |
         | 最近 | 直近7日間 / 直近30日間 / 直近1年 | 直近の範囲を自動同期します。**範囲外の過去データは自動的に消去されます。** |
   3. **フィールド**：ソースから同期するフィールドをすべて選択 / 一部選択します。すべて選択した場合、ソースに新しく追加されたフィールドも自動的にテーブルへ同期されます。
   4. **同期設定**：同期するフィールドと、1時間ごとに自動同期するかどうかを選択します。完了したら「保存して同期」をクリックします。
4. **作成**設定：作成をクリックすると、勤怠グループ名を冠した同期テーブルが自動的に追加され、稲妻のバッジが付きます。

同期ルール

| **同期を作成するユーザーのロール** | **同期可能なデータのスコープ** |
| --- | --- |
| 勤怠グループのメンバー | 自分自身の勤怠データのみ |
| 主管理者 | 組織内のすべての勤怠データ。すべての勤怠グループを閲覧可能 |
| 部門責任者 + 権限を付与されたサブ管理者  注：管理可能なスコープを設定する必要があります | グループ内で管理可能なメンバーの勤怠データ。管理可能なメンバー：部門責任者として管理する対象範囲の人員と、自分自身。 |
| 勤怠グループの管理権限を持つユーザー | **管理可能なスコープにグループのいずれかのメンバーが含まれていれば、グループ全体の勤怠データを同期できます** |
| 勤怠グループの主所有者 / 副所有者（グループ設定で指定） | 管理可能なグループ内の全メンバーの勤怠データ |

#### 同期作成後の権限変更

既存の勤怠同期の作成者が管理権限を失った場合、同期は直ちに終了し、同期エラーの通知が表示されます。勤怠の管理権限を持つ別のユーザーで同期を再作成してください。

### AI Table同期用の勤怠権限の設定方法

[DingTalk管理コンソール](https://oa.dingtalk.io/index.htm#/welcome "DingTalk admin console")

1. **主管理者**として設定：安全と権限 → 権限管理 → 主管理者 → 主管理者を追加

1. **勤怠グループの管理権限**を設定：安全と権限 → 権限管理 → サブ管理者 → サブ管理者 / 管理グループを追加 → 管理可能なスコープ

## データ同期の管理

**保存して同期**をクリックすると、選択したソースビューがデータテーブルとしてAI Tableの左ナビに表示されます。

同期されたテーブルには**稲妻のバッジ**が付き、名前を変更できます。また、テーブルの**複製** / **削除**や、フィールドの追加を行ってデータ管理のニーズに対応できます。注：同期されたフィールドにも稲妻のバッジが付いており、その内容はAI Tableで直接編集できず、フォールド種類も変更できず、これらのフィールドは削除できません。

<strong>注：</strong>同期テーブルを複製すると、複製は通常のテーブルになります。内容は自由に編集できますが、ソースとの同期関係はなくなります。**同期設定を編集**するには、同期されたテーブルを開き、テーブル名の横にある**その他**アイコンをクリックして、**データ同期設定**をクリックします。**データを手動で同期**するには、**データを更新**をクリックして手動同期を行います。

## 同期関係の解除

**同期を解除**をクリックすると、テーブルは通常のテーブルになり、既存のデータは保持されます。この操作は取り消せません。

注：解除のエントリを表示し、解除を正常に行うには、同期テーブルに対する**管理権限**が必要です。

## FAQ

#### Q：勤怠グループのデータをAI Tableに同期するには、どのような権限が必要ですか？

A：

勤怠グループのデータを正常に同期するには、次のいずれかが必要です。

- グループのメンバーであること。自分自身のデータのみ同期されます。
- **主管理者**であること。組織内のすべての勤怠データが同期されます。
- 管理可能なスコープにグループのいずれかのメンバーが含まれる**サブ管理者**であること。グループ全員のデータが同期されます。

#### Q：データが突然自動更新されなくなったのはなぜですか？

A：

まず同期設定を確認してください。

- 可能性1：**終了日が設定**されており、現在の日付がそれを過ぎている場合。このとき同期は自動停止します。
- 可能性2：**終了日が設定されていない**が、同期範囲が1年を超えている場合。現在、自動同期は**直近1年分のデータ**のみに対応しており、それを超える分は自動更新されません。

#### Q：過去のデータがなくなったのはなぜですか？

A：同期設定で**最近**（直近7日 / 30日 / 365日）を使用している場合、**範囲より古い履歴は自動的に消去**され、直近のデータのみが保持されます。

#### Q：データソースを削除すると同期に影響しますか？

A：データソースを削除した後も、すでに同期されたデータは保持されますが、それ以降の同期は行われません。

#### **Q：勤怠データ同期に行数の上限はありますか？**

A：はい。最大20,000行です。1つのAI Tableには最大100個のデータテーブルを作成できます。

#### Q：同期されたデータを編集できますか？

A：いいえ。閲覧のみです。レコードの編集・削除・追加はできず、フォームビューの作成もできません。
