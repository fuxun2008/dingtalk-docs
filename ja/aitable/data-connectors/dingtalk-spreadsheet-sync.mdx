## 概要

**閲覧／ダウンロードまたは編集権限**があれば、DingTalk Spreadsheet のデータを AI Table のデータ同期センター経由で AI Table に同期できます。

同期したフィールドは AI Table では編集できませんが、カスタムフィールドは引き続き追加できます。さらに、AI Table の自動化、高度な権限、ダッシュボードなども利用できます。

同期テーブルを自由に編集したい場合は、いつでも同期を解除したり、同期テーブルを複製したりできます。複製しても元の DingTalk Spreadsheet には影響しません。

## ⚠️ 同期前に必読：DingTalk Spreadsheet の書式要件

同期を確立する際、システムは両者の間でフィールドとコンテンツをマッピングします。同期を正確に保つため、まずスプレッドシートの書式を確認・調整してください。

[同期前にこれらの書式要件を守る必要があるのはなぜですか？](/aitable/data-connectors/dingtalk-spreadsheet-sync/format-requirements)

| **スプレッドシートの先頭行** | **スプレッドシートの先頭列** |
| --- | --- |
| ⚠️ 空のセルがないこと   ⚠️ 重複した名前がないこと   ⚠️ 同期後、先頭行の最初のセルを変更しないこと   ⚠️ 同期後、できるだけ先頭行を変更しないこと | ⚠️ 重複がないこと   ⚠️ 複数の空セルがないこと   ⚠️ 同期後、先頭列を削除・移動できないこと |

### 必読 1：スプレッドシートの先頭行

スプレッドシートの先頭行は、同期時に AI Table のフィールドになります。AI Table では空または重複したフィールド名を許可しないため、同期前に先頭行を確認・調整してください。

#### 先頭行のセルは空にしないことが望ましい

先頭行に空のセルがあっても**同期は続行されます**が、AI Table では空のフィールドが自動的に **Unnamed Column_X** という名前に変更されます。

#### 先頭行のセルは重複しないことが望ましい（結合セルを含む）

先頭行に重複があっても**同期は続行されます**が、AI Table では重複が自動的に **field-name_X** という名前に変更されます。

DingTalk Spreadsheet（同期前）

AI Table（同期後）

#### 同期後は先頭行のコンテンツを変更しないことが望ましい

同期を確立した後は、先頭行のフィールド名（AI Table のフィールドになります）を変更しないでください。フィールド名の変更は、削除して再作成するのと同じ扱いになり、以降の同期では新しいフィールドにデータが書き込まれます。**これにより、元のフィールドに依存するダッシュボードや自動化などが壊れる場合があります。**

### 必読 2：スプレッドシートの先頭列

#### 同期後は先頭列を削除・変更できない

スプレッドシートの**先頭列のデータを削除したり、列名を変更したり、先頭列の前に新しい列を挿入したり**すると、AI Table 同期テーブルのメインキーを削除するのと同じ扱いになり、同期が失敗して AI Table に赤色のエラーが表示されます。

#### 先頭列のデータは重複させないこと（複数の空セルを含む）

先頭列のコンテンツが重複している場合、各重複の最初のレコードのみが保持され、AI Table に黄色のお知らせが表示されます。

DingTalk Spreadsheet（同期前）

AI Table（同期後）

先頭列に複数の空セルがある場合（重複コンテンツとして扱われます）、最初のレコードのみが保持され、AI Table に黄色のお知らせが表示されます。

DingTalk Spreadsheet（同期前）

AI Table（同期後）

### 必読 3：列数の上限

1 つのデータソースで、元のスプレッドシートから AI Table へ同期できるのは最大 **300 列**までです（**空の列を含みます**）。元のスプレッドシートに空の列が多い場合、それらも上限にカウントされ、最初の 300 列のみが同期され、AI Table に黄色のお知らせが表示されます。

**そのため、同期前に不要な空の列を削除し、上限内に収めてください。**

### 必読 4：スプレッドシートのロック領域

元の DingTalk Spreadsheet に閲覧できないロック領域がある場合、それらは同期できません。確認のうえ再試行してください。（操作：元のファイルを開き、使用上の注意を確認します。）

## AI Table での同期の利用

| 同期が完了すると、新しい AI Table が生成されます | 同期したフィールドは編集できませんが、管理のためにフィールドやコンテンツを追加でき、ダッシュボード、自動化、高度な権限なども利用できます。   注：同期テーブルを複製すると、複製は通常のテーブルになります。コンテンツは自由に編集でき、元のファイルとの関係はありません。 |
| --- | --- |
| 同期設定を編集する | 同期テーブルを開く → テーブル名の横にある ⋮ その他アイコンをクリック → **データ同期設定**。同期するフィールドや同期の仕組みを変更し、自動同期のオン／オフを切り替えます。 |
| 手動で更新する | **データを更新**をクリックして手動で同期します。 |
| 同期を解除する | **同期を解除**をクリックすると、同期テーブルが編集可能になり、元のファイルに従わなくなります。 |

## FAQ

#### Q：同期が「先頭列が削除または移動されました」という赤色のエラーで失敗したのはなぜですか？

A：同期後に、スプレッドシートの先頭列に対して次のいずれかの操作を行ったことを意味します。

- 先頭列を削除した。
- 先頭列の名前を変更した。
- 先頭列の前に別の列を挿入した。

#### Q：一部のデータが同期されず、「元のファイルの先頭列に重複（複数の空セルを含む）がないか確認してください」という黄色のお知らせが表示されるのはなぜですか？

A：これは、スプレッドシートの**先頭列にコンテンツの重複または複数の空セルがある**ために発生します。スプレッドシートを調整してください。

#### Q：スプレッドシートに先頭行／先頭列の書式要件が必要なのはなぜですか？

[同期前にこれらの書式要件を守る必要があるのはなぜですか？](/aitable/data-connectors/dingtalk-spreadsheet-sync/format-requirements)

#### Q：スプレッドシートを AI Table に同期した後、フィールド名が変わったのはなぜですか？

A：スプレッドシートの先頭行に**空のフィールド名**または**重複**があることが原因と考えられます。

- 空のフィールド名は自動的に **Unnamed Column_X** に変換されます。
- 重複したフィールド名は自動的に **field-name_X** に変更されます。

#### Q：DingTalk Spreadsheet の同期に列数の上限はありますか？

A：あります。1 つのデータソースで最大 **300 列（空の列を含む）**までサポートします。

#### Q：DingTalk Spreadsheet のデータを AI Table に同期するには、どのような権限が必要ですか？

A：次の両方が必要です。

- DingTalk Spreadsheet の複製可能権限（閲覧／ダウンロード以上）。
- 同期先の AI Table の管理権限（管理者または所有者）。

#### **Q：AI Table 間の同期に行数の上限はありますか？**

A：あります。最大 20,000 行までです。1 つの AI Table には最大 100 個のデータテーブルを持てます。

#### Q：同期したデータを編集できますか？

A：いいえ、閲覧のみです。レコードの編集、削除、追加はできず、フォームビューの作成もできません。

#### Q：データソースを削除すると同期に影響しますか？

A：データソースを削除した後も、すでに同期されたデータは保持されますが、それ以降の同期は行われません。

#### Q：「元の DingTalk Spreadsheet ファイルが大きすぎます」と表示されるのはなぜですか？どうすればよいですか？

このメッセージは、元のスプレッドシートの全体的なコンテンツが大きすぎて、今回の同期で処理しきれないことを意味します。

通常は単一のセルが原因ではなく、元のファイルに以下が多すぎることが原因です。

- シートが多い。
- 行／列が多い。
- 空だが占有されている行／列が多い。
- 複雑なコンテンツが多く、ファイルが大きくなっている。

同期を成功させるには、まず元のスプレッドシートを軽量化してください。

1. 同期する必要のないシートを削除します。
2. 無効な空の行／列を削除します。
3. 同期に必要なデータ範囲のみを残します。
4. 大きなシートを複数の小さなシートに分割し、それぞれを同期します。

軽量化しても同期が失敗する場合は、コンテンツをさらに分割して再試行してください。
