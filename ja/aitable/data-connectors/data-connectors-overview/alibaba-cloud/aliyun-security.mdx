AI Table は **Aliyun Security Center コネクタ**に対応しており、Aliyun アカウント配下の**セキュリティアラートデータ**を同期できます。これにより、クラウドのセキュリティリスク、アラートイベント、対応状況を一元管理できます。

このガイドでは、次の手順を説明します。

- Aliyun コンソールにログインします。
- AccessKey ID と AccessKey Secret を取得します。
- AI Table で Aliyun Security Center のデータソースを作成します。
- パラメータとフィールドを設定し、同期を完了します。

## 1. 事前準備

開始する前に、次の点を確認してください。

- ログインできる登録済みの Aliyun アカウント。
- そのアカウントで **セキュリティセンター** が有効になっていること。
- そのアカウントに少なくとも閲覧のみの Security Center 権限があること。
- AI Table へのアクセス権があること。

> ⚠️ メインアカウントのキーではなく、**RAM サブアカウント + AccessKey** の使用を推奨します。

## 2. Aliyun AccessKey の取得

AI Table は AccessKey を使って Aliyun Security Center API を呼び出します。まず Aliyun コンソールで作成してください。

### 1. Aliyun コンソールにログイン

1. Aliyun を開きます。[https://www.aliyun.com](https://www.aliyun.com "https://www.aliyun.com")。
2. 右上の **サインイン** をクリックします。
3. Aliyun アカウントでログインします。

### 2. AccessKey の作成または取得（RAM ユーザー推奨）

1. ログイン後、**RAM（アクセス制御）**を開きます。
2. 左メニューで **ユーザー** を選択します。
3. RAM ユーザーを作成するか、既存のユーザーを選択します。
4. Security Center 権限（少なくとも閲覧のみ）を付与します。
   - 例：Security Center の閲覧のみ。
5. **認証管理**を開きます。
6. AccessKey を作成します。
7. 以下をコピーして保存します。
   - **AccessKey ID**
   - **AccessKey Secret**

> ⚠️ AccessKey Secret は作成時に一度だけ表示されます。必ず保存してください。

## 3. AI Table で Aliyun Security Center のデータソースを作成

### 1. Data sync center を開く

1. AI Table を開きます。
2. 上部の **データ同期センター** をクリックします。
3. **Aliyun** を検索します。
4. **Aliyunセキュリティセンター** を選択します。

## 4. データソース設定

現在サポートされているデータソースタイプ：

- **アラートリスト**

  現在の Aliyun アカウント配下の Security Center アラートレコードを同期します。

これを選択して続行します。

## 5. アカウント設定

Aliyun アカウントを連携します。

### フィールド参照

| フィールド | 説明 |
| --- | --- |
| アカウント名 | AI Table で複数の Aliyun アカウントを区別するためのカスタムラベル |
| AccessKey ID | Aliyun コンソールから取得 |
| AccessKey Secret | Aliyun コンソールから取得 |

完了したら **確認** をクリックします。

> 🔒 AI Table は AccessKey 情報を保存時に暗号化し、このデータソースでのみ使用します。

## 6. パラメータ

### 1. 地域（必須）

Security Center データの地域を指定します。

- 例：`Domestic regions`。
- 地域によって、Security Center のデータ範囲が異なります。

### 2. 開始時間（必須）

同期ウィンドウの開始ポイントです。

オプション：

- 最近の時間。
- 特定の時点。

### 3. 時間範囲（必須）

アラートを同期する時間スパンです。

- 例：過去 7 日間／過去 30 日間。
- 範囲が広いほど、データ量が増えます。

## 7. フィールド

AI Table に同期するアラートフィールドを選択します。

### 一般的なアラートのベーシックフィールド

| フィールド | 説明 |
| --- | --- |
| アラート ID | セキュリティアラートの固定値識別子 |
| メインアカウント ID | Aliyun メインアカウント ID |
| イベント UUID | アラートイベントの固定値識別子 |
| アラート記録時間 | アラートが生成された時間 |
| アラート発生元プロダクト | アラートを生成したクラウドプロダクト |
| アラートタイトル | アラートのタイトル |
| アラートタイプ | アラートのタイプ |
| アラート名 | アラートルール名 |
| 脅威レベル | アラートのリスクレベル |
| アラートステータス | 現在の対応状況 |

### アラートの時間関連フィールド

| フィールド | 説明 |
| --- | --- |
| アラート発生時間 | アラートが最初に発生した時間 |
| アラート初回発生時間 | 初めてトリガーされた時間 |
| アラート終了時間 | アラートの終了時間 |
| アラート最終更新時間 | 直近の更新時間 |

### アラートの詳細・拡張フィールド

| フィールド | 説明 |
| --- | --- |
| アラート説明 | アラートの詳細情報 |
| アラート英語説明 | 英語の説明 |
| アラート説明コード | 説明に対応するコード |
| アラート詳細 | イベントの詳細情報 |
| アラートログ UUID | アラートログ識別子 |
| エンティティ詳細 | アラートに関連付けられた資産情報 |
| ATT\\&CK 戦術・技術タグ | MITRE ATT\\&CK タグ |
| 防御済み | 防御アクションが実行されたかどうか |

### アカウント・資産関連フィールド

| フィールド | 説明 |
| --- | --- |
| サブユーザー ID | RAM サブアカウント ID |
| サブユーザー名 | RAM サブアカウント名 |
| クラウドベンダーコード | クラウドベンダー識別子 |
| プロダクト ID | 関連付けられたクラウドプロダクト ID |
| クラウドコード | クラウドリソースコード |
| 検出ルール ID | アラート検出ルール識別子 |
|         |            |

次の操作が可能です。

- **すべて選択** をチェックして、すべてのフィールドを同期します。
- または、セキュリティ分析で必要なフィールドのみを選択します。

## 8. 同期設定

### モード

- **オフ（デフォルト）**

  データは作成時または手動トリガー時にのみ更新されます。
- **オン**

  システムが設定した間隔で最新のアラートデータを自動同期します。

> セキュリティ監視やオンコール体制での運用に推奨します。

## 9. 完了 — データの表示

1. 右下の **作成** をクリックします。
2. AI Table が Security Center のアラートデータの取得を開始します。
3. 完了すると、AI Table でアラートリストを表示できます。
4. このデータは次の用途に活用できます。
   - セキュリティリスクの統計。
   - アラートの追跡と対応。
   - 複数アカウントのセキュリティ分析。

## 10. FAQ

#### Q1：権限が拒否される、または同期に失敗する場合は？

- RAM ユーザーに Security Center 権限があるか確認します。
- AccessKey が正しく入力されているか確認します。

#### Q2：アラート件数がコンソールと異なるのはなぜですか？

- 時間範囲の設定を確認します。
- 地域によってアラートデータが異なります。

#### Q3：AccessKey は安全ですか？

- AI Table は AccessKey 情報を保存時に暗号化します。
- このデータソースでのみ使用され、外部に公開されることはありません。
