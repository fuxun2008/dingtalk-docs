AI Table は **Aliyun Resource Access Management (RAM) コネクタ**に対応しており、Aliyun アカウント配下の **RAM ロール情報**と **RAM ユーザー情報**を同期できます。クラウドアカウントの権限、メンバー、ロールを一元管理できます。

本ガイドでは、次の手順を説明します。

- Aliyun コンソールへのログイン。
- AccessKey ID と AccessKey Secret の取得。
- AI Table での Aliyun RAM データソースの作成。
- パラメータとフィールドの設定、同期の完了。

## 1. 事前準備

開始する前に、次の点を確認してください。

- ログイン可能な登録済みの Aliyun アカウント。
- アカウントで **RAM** が有効になっていること。
- RAM の読み取り以上の権限を保有していること。
- AI Table へのアクセス権を保有していること。

> ⚠️ プライマリアカウントのキーではなく、**RAM サブアカウント + AccessKey** の使用を推奨します。

## 2. Aliyun AccessKey の取得

AI Table は AccessKey 経由で Aliyun RAM API を呼び出します。まず Aliyun コンソールで AccessKey を作成してください。

### 1. Aliyun コンソールへのログイン

1. Aliyun を開きます。[https://www.aliyun.com](https://www.aliyun.com "https://www.aliyun.com")。
2. 右上の **サインイン** をクリックします。
3. Aliyun アカウントでログインします。

### 2. AccessKey の作成または取得（RAM ユーザー推奨）

1. ログイン後、**RAM（アクセス制御）** を開きます。
2. 左メニューで **ユーザー** を選択します。
3. RAM ユーザーを作成するか、既存のユーザーを選択します。
4. 権限を付与します（少なくとも RAM の閲覧のみ）。
   - 例：`AliyunRAMReadOnlyAccess`。
5. **認証管理** を開きます。
6. AccessKey を作成します。
7. 次の情報をコピーして保存します。
   - **AccessKey ID**
   - **AccessKey Secret**

> ⚠️ AccessKey Secret は作成時に一度だけ表示されます。必ず保存してください。

## 3. AI Table での Aliyun RAM データソースの作成

### 1. データ同期センターを開く

1. AI Table を開きます。
2. 上部の **データ同期センター** をクリックします。
3. **Aliyun** を検索します。
4. **Aliyun RAM** を選択します。

## 4. データソースの設定

同期するデータ型を選択します。

### 対応するデータソースのタイプ

- **Aliyun RAM ロールリスト**

  現在のアカウント配下のすべての RAM ロールを同期します。
- **Aliyun RAM ユーザーリスト**

  現在のアカウント配下のすべての RAM ユーザーを同期します。

いずれかを選択します（複数のデータソースを作成することもできます）。

## 5. アカウント設定

Aliyun アカウントを連携します。

### フィールド参照

| フィールド | 説明 |
| --- | --- |
| アカウント名 | AI Table で複数の Aliyun アカウントを区別するためのカスタムラベル |
| AccessKey ID | Aliyun コンソールから取得 |
| AccessKey Secret | Aliyun コンソールから取得 |

完了したら **確認** をクリックします。

> 🔒 AI Table は AccessKey 情報を保存時に暗号化します。同期にのみ使用されます。

## 6. パラメータ

### エンドポイント（必須）

Aliyun RAM サービスの API エンドポイントです。

- デフォルト：`ram.aliyuncs.com`。
- 通常は変更不要です。

## 7. フィールド

AI Table に同期するフィールドを選択します。

### 1. RAM ロールフィールド

| フィールド | 説明 |
| --- | --- |
| ロール ID | RAM ロールの固定識別子 |
| ロール名 | RAM ロール名 |
| ロールの説明 | ロールの説明 |
| 作成日時 | ロールの作成時間 |
| 更新日時 | 最終更新時間 |
| 最大セッション継続時間 | ロールの最大セッション長 |
| リソース記述子 | ロールのリソース識別情報 |
| タグ | ロールに紐づくタグ |

### 2. RAM ユーザーフィールド

| フィールド | 説明 |
| --- | --- |
| RAM ユーザー ID | ユーザーの固定識別子 |
| RAM ユーザー名 | ユーザー名 |
| ログイン名 | ユーザーのログイン名 |
| ユーザーメール | 紐づくメールアドレス |
| 電話番号 | 紐づく電話番号 |
| 作成日時 | ユーザーの作成時間 |
| ユーザー更新日時 | 最終更新時間 |
| 備考 | ユーザーの備考 |

次の操作が可能です。

- **すべて選択** をチェックして、すべてのフィールドを同期します。
- または、業務に関連するフィールドのみを選択します。

## 8. 同期設定

### モード

- **オフ（デフォルト）**

  作成時または手動トリガー時のみデータが更新されます。
- **オン**

  設定したサイクルでシステムが自動的に RAM データを同期します。

> 権限の変更が頻繁に発生するシナリオで推奨されます。

## 9. 完了 — データの確認

1. 右下の **作成** をクリックします。
2. AI Table が Aliyun RAM データの取得を開始します。
3. 完了後、AI Table でロールリストまたはユーザーリストを確認できます。
4. このデータをフィルタ、権限の棚卸し、メンバー管理、監査分析などに活用します。

## 10. よくある質問

#### Q1: 権限が拒否される、または取得に失敗する場合は？

- RAM ユーザーが RAM 権限を保有しているか確認してください。
- AccessKey が正しく入力されているか確認してください。

#### Q2: 一部のユーザー / ロールが表示されないのはなぜですか？

-
- 該当のリソースがアカウント配下に実際に存在するか確認してください。
- 正しい AccessKey を使用しているか確認してください。

#### Q3: AccessKey は安全ですか？

- AI Table はキーを保存時に暗号化します。
- このデータソースのみで使用され、外部に公開されることはありません。
