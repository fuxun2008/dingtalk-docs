## 1 リクエストヘッダー（Header）と例

| **名称**​       | **タイプ**​ | **必須**​ | **説明**​                                                                                                                                                                                                                                                                                |
| ------------- | ------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authorization | string  | いいえ       | 認証情報の検証（Bearer token）はリクエストヘッダー（Header）経由で AI テーブル自動化に渡す必要があります。Header の形式（大文字・小文字を区別）は以下のとおりです。  \--header 'Authorization: Bearer \\[実際の Bearer token]'  シングルクォートは実際の Header に必ず入力してください。角括弧 \\[] は変数を示すもので、実際の Header には入力不要です。  ここで Header の Key（キー）は固定で Authorization、Value（値）は固定の接頭辞 Bearer を持ちます。  なお、Bearer の接頭辞と実際の Bearer token の間には、必ず半角スペースを 1 つ入れてください。 |
| Client-Token  | string  | いいえ       | 冪等の Header では、Key（キー）は固定で Client-Token、Value（値）はユーザーが生成し、通常は uuid を使用します。  この値が空の場合、新しいリクエストを発行することを意味します。空でない場合、冪等的な更新操作を意味し、同じ値の場合 3 時間以内には 1 回しかトリガーされません。                                                                                                                                                    |

Bearer token のサンプルコードは以下のとおりです（角括弧は置換が必要な変数を示すもので、実際のコードに記述する必要はありません）。

```bash 
curl --location --request POST '[実際の webhook アドレス]' \
--header 'Authorization: Bearer [実際の Bearer token]' \
--header 'Content-Type: application/json' \
--data-raw '{[実際のリクエスト本文]}'
```


## 2 リクエストボディ

必要に応じて設定します。形式は JSON 仕様に準拠する必要があります。

## 3 レスポンスボディと例

レスポンスボディの code が 0 でない場合、失敗を示します。

code が 0 でない場合、後述の「関連エラー」表のエラーコードと文言を参照して問題を切り分けられます。

webhook が正常に受信された場合のレスポンスボディの例：

```json 
{
"msg": "",
"data": { },
"code": 0
}
```


webhook がエラーになった場合のレスポンスボディの例：

```json 
{
"data": { },
"code": 800004509,
"msg": "webhook trigger workflow is disabled"
}
```


## 4 エラーコード

webhook トリガーでエラーが発生した場合、リクエスト送信側でエラー状況を確認し、下表のエラーコードと文言に従って問題を切り分けてください。

| **エラーコード**​  | **エラー文言**​                             | **エラー原因**​                                                                                                                                                            | **解決方法**​                              |
| --------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 800005649 | 認証情報の検証に失敗しました                               | 認証情報の検証が有効化されていますが、HTTP リクエストに含まれる認証情報が自動化フローで必要な認証情報と一致せず、フローを実行できません。                                                                                                                       | 認証情報を再確認して入力し直してください。                             |
| 800005650 | IP アドレスがホワイトリストにありません。確認してください。                       | IP ホワイトリストが有効化されており、リクエストの送信元 IP がホワイトリストに含まれていません。                                                                                                                         | 該当 IP をホワイトリストに追加するか、IP アドレスを変更して再送信してください。            |
| 800005647 | リクエスト内容のサイズが上限を超えています。内容を減らしてください                      | webhook が受信した HTTP リクエストのサイズが 4 MB を超えました。                                                                                                                                       | 内容を減らしてください。                                 |
| 800005646 | 自身を呼び出す HTTP ノードがあり、無限ループが発生しています。HTTP ノードのリクエストアドレスを変更してください | 自動化フローのトリガー条件が「webhook トリガー時」、実行アクションが「HTTP リクエストの送信」で、HTTP のリクエスト URL が現在のフローの webhook アドレスと同一のため、フローがループトリガーになっています。                                                                           | 「HTTP リクエストの送信」内の URL を変更し、webhook アドレスと一致しないようにしてください。 |
| 800005652 | リクエストの頻度が高すぎます。しばらくしてから再試行してください                          | webhook が受信する HTTP リクエストの頻度が制限を超え、レート制限されました。  \-   AI テーブル全体の webhook トリガー頻度の上限は 50 回／秒です。  \-   単一の自動化フローの webhook トリガー頻度の上限は 5 回／秒です。  \-   認証情報の検証（Bearer token）が無効な自動化フローでは、各フローの頻度上限は 1 回／秒です。 | しばらくしてから再試行してください。                                  |
| 800006003 | リクエストボディが JSON 形式仕様に準拠していません。修正後に再リクエストしてください             | 通常、「リクエスト送信で出力を設定」する方法を使用する際に、受信したリクエストボディの JSON 形式に誤りがあると発生します。                                                                                                                     | リクエストボディの JSON を再確認し、修正後に再試行してください。                  |
