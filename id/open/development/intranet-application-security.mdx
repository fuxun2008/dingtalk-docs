Artikel ini menjelaskan apa itu enterprise app gateway, tantangan dalam mengakses aplikasi intranet, solusi untuk mengakses aplikasi intranet, serta cara mengaktifkan dan mengonfigurasi enterprise app gateway.

## Apa itu enterprise app gateway

Enterprise app gateway memungkinkan organisasi mengakses aplikasi intranet secara aman melalui Internet. Gateway ini menggantikan solusi VPN tradisional dan meningkatkan kecepatan akses aplikasi berdasarkan kemampuan akselerasi jaringan Alibaba Cloud. Dibangun di atas prinsip zero-trust, gateway ini menyediakan validasi akses yang berkelanjutan dan dinamis untuk memaksimalkan keamanan informasi digital organisasi.

## Tantangan dalam mengakses aplikasi intranet

Organisasi biasanya menempatkan sistem aplikasi inti di intranet atau DMZ dan membangun isolasi batas jaringan dengan firewall. Ketika karyawan mengakses aplikasi intranet dari Internet melalui perangkat seluler atau PC, mereka menggunakan salah satu dari dua metode: dial-up VPN dan pemetaan port. Namun, perangkat VPN mungkin memiliki kerentanan, atau port mungkin dipetakan ke alamat IP atau URL eksternal. Akibatnya, peretas dapat mengakses atau menyerang aplikasi secara langsung, yang menyebabkan kebocoran data inti organisasi.

Berikut ini menjelaskan empat tantangan utama yang dihadapi pengguna saat mengakses aplikasi intranet dengan metode lama.

| Tantangan | Deskripsi |
| --- | --- |
| Biaya finansial tinggi | Solusi VPN tradisional mahal untuk diterapkan, dan jalur khusus menimbulkan biaya besar setiap tahun. |
| Pengalaman pengguna buruk | - Karyawan harus menginstal dan mengonfigurasi klien VPN terlebih dahulu, yang merepotkan. - Mereka harus melakukan dial-up VPN sebelum digunakan, dan VPN terputus pada jaringan lemah serta memerlukan penyambungan ulang. |
| Data tidak aman | Port firewall masuk harus tetap terbuka, yang memungkinkan peretas memindai port aplikasi intranet dan meluncurkan serangan. |
| Pengiriman perangkat sulit | Proses dari mengajukan permintaan pembelian hingga menerima, menginstal, dan mengonfigurasi perangkat biasanya memakan waktu beberapa bulan dan melibatkan debugging yang rumit. |

## Solusi untuk mengakses aplikasi intranet

### Solusi yang direkomendasikan

Enterprise app gateway DingTalk menghubungkan aplikasi intranet organisasi ke lingkungan public cloud Alibaba secara aman melalui platform identitas DingTalk, gateway keamanan DingTalk, dan Konektor. Ini memungkinkan karyawan mengakses aplikasi internal dengan mudah dalam skenario kantor, operasi dan pemeliharaan, serta cabang, mendukung transformasi digital dan kolaboratif organisasi.

Berikut ini menjelaskan lima solusi yang direkomendasikan bagi pengguna untuk mengakses aplikasi intranet.

| Solusi | Deskripsi |
| --- | --- |
| Menetapkan kebijakan akses untuk aplikasi tertentu | Tetapkan kebijakan akses untuk aplikasi tertentu berdasarkan organisasi, departemen, peran, atau individu. |
| Konfigurasi sederhana dan pengiriman cepat | Terapkan hanya Konektor di dalam organisasi Anda (yang membangun koneksi persisten terbalik ke server DingTalk). Skrip instalasi satu baris disediakan. Setelah instalasi, admin menyelesaikan pengiriman dengan konfigurasi sederhana di konsol gateway. |
| Enkripsi jalur penuh | Onboarding aplikasi intranet ke DingTalk dengan cepat. Setelah Anda menginstal dan menerapkan Konektor di server intranet, saluran transmisi terenkripsi yang aman dibangun antara gateway dan intranet. Permintaan dari klien DingTalk karyawan dikirim ke server intranet melalui saluran ini, dan respons server dikembalikan ke klien DingTalk karyawan melalui saluran yang sama. |
| Memblokir identitas ilegal | Berdasarkan autentikasi identitas DingTalk, autentikasi gateway melindungi sumber daya intranet dan memblokir akses berbahaya dari pihak eksternal. Hanya permintaan yang lolos autentikasi identitas DingTalk yang diteruskan ke server organisasi. |
| Dukungan untuk rewrite | Dengan aturan rewrite kustom, gateway mendukung penulisan ulang Header permintaan, Isi permintaan, Header respons, dan Isi respons. |

### Rekomendasi desain produk

| Produk | Deskripsi desain produk |
| --- | --- |
| Sisi klien | - Klien DingTalk terutama memverifikasi informasi identitas pengguna untuk memastikan keabsahan pengguna yang mengakses. - Klien mengikat identitas karyawan berdasarkan akun DingTalk untuk mencapai verifikasi identitas yang aman dan pemeliharaan status. - Klien memastikan keamanan akun melalui logika kontrol risiko akun bawaan DingTalk. - Klien mencegah serangan berbahaya seperti credential stuffing, pencurian akun, dan brute-force cracking. |
| Gateway keamanan | - Sebagai komponen inti dari solusi keamanan zero-trust DingTalk, gateway ini adalah proksi yang sadar identitas. - Gateway bekerja di Layer 7 (lapisan aplikasi) model OSI dan menerapkan reverse proxy untuk protokol HTTP(S) sekaligus memverifikasi keabsahan setiap permintaan akses dari klien. - Karena protokol HTTP(S) mendukung koneksi singkat dan tidak memerlukan koneksi persisten, gateway memberikan akses jarak jauh yang sangat stabil, bekerja andal pada jaringan lemah, dan tidak pernah "terputus". - Gateway ini adalah layanan SaaS yang diterapkan sebagai klaster di beberapa wilayah. |
| Konektor | - Konektor diterapkan di DMZ ruang peralatan pelanggan. - Konektor membangun koneksi terbalik ke gateway keamanan enterprise app DingTalk melalui firewall, meneruskan permintaan klien ke aplikasi internal, menerima konten yang dikembalikan dari aplikasi internal, dan mengirimkannya kembali ke klien melalui gateway keamanan enterprise app DingTalk. - Dengan komponen ini, intranet disembunyikan, dan aplikasi internal tidak perlu diekspos ke Internet melalui firewall, sehingga sangat mengurangi serangan. |

## Studi kasus integrasi app gateway

Sebuah perusahaan IT keuangan sebelumnya mengakses sistem kantor internalnya melalui VPN tradisional. Karyawan harus melakukan dial-up VPN sebelum masuk ke sistem intranet, dan konfigurasi yang rumit membuat banyak karyawan tidak tahu cara menggunakannya serta harus mengonfigurasi ulang setelah berganti ponsel. Selain itu, karena VPN mengandalkan koneksi persisten, koneksi sering terputus pada jaringan lemah seperti di kereta cepat dan di lift, sehingga memerlukan dial-up berulang dan menghasilkan efisiensi kolaborasi yang rendah.

Setelah mengadopsi enterprise app gateway DingTalk, perusahaan tidak lagi membuka port firewall, sehingga virus dan peretas tidak dapat masuk. Karyawan dapat mengakses sistem internal dengan cepat, mudah, dan aman kapan saja dan di mana saja untuk kolaborasi yang efisien.
