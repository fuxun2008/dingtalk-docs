Artikel ini menjelaskan cara membuat, menghapus, mengaktifkan, menonaktifkan, mengkloning, menguji, dan mengonfigurasi templat pesan.

## Membuat dan mengonfigurasi templat pesan

1. Masuk ke [Developer Console](https://open-dev.dingtalk.com/?version=5.86.5#/appMgr/provider/eapp/57406/2).
2. Klik **App Development**, pilih **Aplikasi perusahaan pihak ketiga**, lalu buat sebuah mini program atau aplikasi mikro H5.
3. Pada halaman detail aplikasi, klik **Message Push**. Di area pengelolaan templat pesan, klik **Add**.

4. Pilih tipe templat lalu klik **Create**.

5. Konfigurasikan templat pesan lalu klik **Save**.

   **Catatan**

   Jika parameter templat dikonfigurasi dalam templat, parameter templat akan dimuat secara otomatis di bawah, dan Anda kemudian dapat mengonfigurasi deskripsi parameter dinamis.

   Beberapa nilai dalam konten pesan berubah secara dinamis, seperti nomor pesanan, nomor ponsel, dan nama produk. Nilai-nilai ini tidak dapat ditentukan saat Anda menyiapkan templat, jadi Anda dapat menggunakan parameter templat untuk menggantikannya.
6. Klik **Test**, lalu klik **Send Test Message** untuk memverifikasi bahwa templat pesan telah dikonfigurasi dengan benar.

## Mengonfigurasi templat Markdown

Templat Markdown menggunakan sintaks Markdown untuk mengonfigurasi dan mengirim pesan, yang cocok untuk pesan notifikasi murni yang tidak memerlukan tindakan.

Dengan templat Markdown, Anda dapat dengan mudah mendukung format tampilan seperti teks, gambar, dan tautan.

**Deskripsi konfigurasi templat pesan Markdown**

| Konfigurasi | Mendukung parameter templat | Deskripsi |
| --- | --- | --- |
| **Nama Templat** | Tidak | Menentukan nama templat. Anda dapat menamainya berdasarkan kasus penggunaan dan tipe templat, misalnya, Templat Notifikasi Tiket Baru. |
| **Kasus Penggunaan** | Tidak | Menjelaskan kasus penggunaan templat. |
| **Gambar** | Tidak | Gambar dalam pesan, dalam format tautan gambar atau media\_id. Dikonfigurasi secara terpisah melalui item konfigurasi ini, satu pesan hanya mendukung satu gambar. Gambar disematkan di bagian atas. |
| **Judul Pesan** | Tidak | Judul pesan dan konten yang ditampilkan di layar pertama obrolan. |
| **Konten Pesan** | Ya | Konten pesan dalam format Markdown. Kami menyarankan agar tetap dalam 1.000 karakter. Untuk sintaks Markdown yang didukung, lihat tabel berikut. **Catatan** - Sintaks Markdown pada templat pesan tidak mendukung judul, artinya format judul "# + teks judul" tidak didukung. Masukkan judul pesan secara terpisah di kotak input judul. Hanya judul tingkat pertama yang didukung. - Sintaks Markdown pada templat pesan tidak mendukung gambar, artinya format "" tidak didukung. Masukkan gambar pesan secara terpisah di kotak input gambar. Satu pesan hanya mendukung satu gambar. |

**Sintaks Markdown**:

```
Kutip
> Seseorang yang tidak memperjuangkan apa pun akan terjebak pada apa saja.
 
Tebal dan Miring
**tebal**
*miring*
 
Tautan
[ini adalah tautan](http://name.com)
 
Daftar Berpoin
- item1
- item2
 
Daftar Bernomor
1. item1
2. item2

Ganti Baris
 Cukup tampilkan ganti baris di kotak input. \n tidak didukung.
```

## Templat ActionCard

Templat ActionCard mengirim pesan menggunakan tipe pesan ActionCard. Templat ini mendukung pesan yang menggabungkan konten dengan poin tindakan, yang cocok untuk skenario di mana pesan perlu diproses dengan cepat melalui satu atau beberapa poin tindakan.

Templat ActionCard dibangun di atas templat Markdown dan mendukung gaya pengalihan keseluruhan maupun pengalihan independen.

**Deskripsi konfigurasi templat ActionCard**

| Konfigurasi | Mendukung parameter templat | Deskripsi |
| --- | --- | --- |
| **Nama Templat** | Tidak | Menentukan nama templat. Anda dapat menamainya berdasarkan kasus penggunaan dan tipe templat, misalnya, Templat Notifikasi Tiket Baru. |
| **Kasus Penggunaan** | Tidak | Menjelaskan kasus penggunaan templat. |
| **Gambar** | Tidak | Gambar dalam pesan, dalam format tautan gambar atau media\_id. Dikonfigurasi secara terpisah melalui item konfigurasi ini, satu pesan hanya mendukung satu gambar. |
| **Judul Pesan** | Tidak | Judul pesan dan teks yang ditampilkan dalam daftar obrolan dan notifikasi, maksimal 64 karakter. |
| **Konten Pesan** | Ya | Konten pesan dalam format Markdown. Kami menyarankan agar tetap dalam 1.000 karakter. Untuk sintaks Markdown yang didukung, lihat tabel berikut. **Catatan** - Sintaks Markdown pada templat pesan tidak mendukung judul, artinya format judul "# + teks judul" tidak didukung. Masukkan judul pesan secara terpisah di kotak input **Judul**. Hanya judul tingkat pertama yang didukung. - Sintaks Markdown pada templat pesan tidak mendukung gambar, artinya format "" tidak didukung. Masukkan gambar pesan secara terpisah di kotak input **Gambar**. Satu pesan hanya mendukung satu gambar. |
| **Poin Tindakan** | Ya | Pesan kartu mendukung gaya ActionCard pengalihan keseluruhan dan gaya ActionCard pengalihan independen: - Gaya ActionCard pengalihan keseluruhan mendukung satu Tindakan yang dapat diklik. Meneruskan satu konfigurasi menghasilkan gaya pengalihan keseluruhan. - Gaya ActionCard pengalihan independen mendukung beberapa Tindakan yang dapat diklik. Meneruskan beberapa konfigurasi menghasilkan gaya pengalihan independen. |
| **Tautan Poin Tindakan** | Ya | Alamat tautan yang menjadi tujuan pengalihan pesan saat diklik. Ketika pesan dikirim sebagai mini program, tautan pengalihan mini program didukung, maksimal 500 karakter. |
| **Judul Poin Tindakan** | Ya | Judul tombol pengalihan, maksimal 20 karakter. |

## Templat Formulir

Templat Formulir mengirim pesan berdasarkan tipe pesan OA. Templat ini cocok untuk menampilkan pesan seperti pesanan dan mendukung pengalihan untuk melihat detail pesan.

**Deskripsi konfigurasi templat pesan Formulir**

| Konfigurasi | Mendukung parameter templat | Deskripsi |
| --- | --- | --- |
| **Nama Templat** | Tidak | Menentukan nama templat. Anda dapat menamainya berdasarkan kasus penggunaan dan tipe templat, misalnya, Templat Notifikasi Tiket Baru. |
| **Kasus Penggunaan** | Tidak | Menjelaskan kasus penggunaan templat. |
| **Konten Header Kotak Pesan** | Ya | Judul header pesan, dibatasi maksimal 10 karakter. Ini berlaku saat mengirim ke obrolan biasa. Saat mengirim ke obrolan organisasi, judul ini digantikan dengan nama aplikasi mikro. |
| **Warna Latar Header Kotak Pesan** | Ya | Warna latar belakang header pesan. Panjangnya dibatasi 8 karakter Inggris, di mana 2 karakter pertama mewakili transparansi dan 6 karakter terakhir mewakili nilai warna. Jangan menambahkan 0x. Contoh: FFBBBBBB |
| **Judul Pesan** | Tidak | Judul isi pesan. Kami menyarankan agar tetap dalam 50 karakter. |
| **Konten Pesan** | Ya | Konten isi pesan, menampilkan hingga 3 baris. |
| **Gambar dalam Isi Pesan** | Tidak | Gambar dalam pesan, dalam format tautan gambar atau media\_id. Dikonfigurasi secara terpisah melalui item konfigurasi ini, satu pesan hanya mendukung satu gambar. |
| **Konten Formulir** | Ya (judul dan nilai variabel) | Formulir isi pesan, menampilkan hingga 6 item. Kotak input kiri dan kanan masing-masing mewakili key isi pesan dan value yang sesuai dengan key tersebut. |
| **Tautan Mobile** | Ya | Alamat tautan yang menjadi tujuan pengalihan pesan saat diklik. Ketika pesan dikirim sebagai mini program, tautan pengalihan mini program didukung. |
| **Tautan PC** | Ya | Alamat tujuan pengalihan saat pesan diklik pada PC. |

## Mengonfigurasi parameter templat

Beberapa nilai dalam konten pesan berubah secara dinamis, seperti nomor pesanan, nomor ponsel, dan nama produk. Nilai-nilai ini tidak dapat ditentukan saat Anda menyiapkan templat, jadi Anda dapat menggunakan parameter templat untuk menggantikannya.

Saat mengirim Notifikasi Kerja, teruskan nilai aktual untuk menggantikan parameter templat. Parameter templat tidak wajib, dan Anda dapat mengonfigurasinya berdasarkan kebutuhan aktual Anda.

**Format parameter templat**

Parameter templat menggunakan format `${parameter name}`. Parameter harus mematuhi aturan berikut.

- Harus diawali dengan huruf atau garis bawah.
- Bagian selanjutnya setelah awal dapat terdiri dari huruf, garis bawah, dan angka.
- Kami menyarankan untuk tidak menetapkan terlalu banyak parameter dinamis dalam satu pesan. Kami menyarankan tidak lebih dari 5.

Misalnya, jika konten pesan adalah:

```
Produk ${product} yang Anda ikuti kini tersedia. Segera dapatkan!
```

Di sini, `${product}` adalah parameter templat, dengan nama parameter `product`. Teruskan nilai parameter ini saat mengirim pesan. Misalnya, teruskan `product` sebagai "Masker Sekali Pakai" saat mengirim pesan. Maka "Masker Sekali Pakai" akan menggantikan parameter templat $&#123;product&#125;, dan konten pesan yang diterima pengguna akhir adalah:

```
Produk Masker Sekali Pakai yang Anda ikuti kini tersedia. Segera dapatkan!
```

Sebuah templat pesan dapat dikonfigurasi dengan beberapa parameter templat, atau tanpa parameter sama sekali. Atur berdasarkan kebutuhan aktual Anda.

**Penerjemahan ID**

Saat meneruskan parameter dinamis, penerjemahan ID didukung. Saat ini, konversi ID departemen menjadi nama departemen dan userId menjadi username didukung.

Sintaks penerjemahan ID adalah sebagai berikut:

```
$departmentName=DEPARTMENT_ID$
$userName=USERID$
```

Di mana:

- DEPARTMENT\_ID adalah ID departemen numerik.
- USERID adalah user ID pengguna.

Contoh:

- Ganti $departmentName=100$ dengan nama departemen yang sesuai dengan ID departemen "100", seperti "DingTalk Open Platform".
- Ganti $userName=zhangsan01$ dengan username yang sesuai dengan ID pengguna "zhangsan01", seperti "John".

## Mengirim untuk peninjauan

Setelah membuat templat pesan, klik **Submit** untuk mengirim templat untuk ditinjau.

## Mengaktifkan templat

Setelah templat lolos peninjauan, templat akan diaktifkan secara otomatis. Ketika templat pesan diaktifkan, Anda dapat mengirim pesan templat dengan memanggil API. Untuk detailnya, lihat [Menggunakan templat untuk mengirim Notifikasi Kerja](/zh/open/development/work-notification-templating-send-notification-interface).

## Menonaktifkan templat

Ketika Anda tidak lagi memerlukan templat, matikan tombol aktifkan untuk berhenti menggunakannya.

## Menghapus templat

Klik **Delete** untuk menghapus templat.

## Mengkloning templat

Klik **Clone** untuk menyalin templat dengan konfigurasi yang sama.

## Menguji templat

Setelah mengklik **Edit**, masuk ke antarmuka pengeditan templat, lalu klik tombol **Test** pada halaman pengeditan templat untuk menjalankan pengujian. Pengujian akan mengirim Notifikasi Kerja kepada diri Anda sendiri.
