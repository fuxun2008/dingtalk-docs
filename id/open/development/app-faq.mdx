Artikel ini membahas pertanyaan yang sering diajukan seputar aplikasi internal, proses pengembangan, dan izin.

## **Apa itu aplikasi berotorisasi organisasi**

Aplikasi berotorisasi organisasi adalah aplikasi pada tingkat organisasi. Ini adalah format aplikasi dari versi awal DingTalk. Untuk menggunakan tipe aplikasi ini, Anda perlu membuat Kredensial API khusus berdasarkan identifier unik organisasi Anda (ID Organisasi, yaitu CorpId) dan kunci keamanan (Organization Secret, yaitu CorpSecret). Dengan Kredensial API yang dibuat, Anda dapat mengakses dan menggunakan kemampuan pengembangan seperti OpenAPI, Webhook, dan Stream.

**Catatan**

Hanya Admin Organisasi yang dapat melihat dan mengelola panggilan berotorisasi organisasi. Anggota lain tidak dapat melakukan operasi tersebut.

## **Apa itu panggilan berotorisasi organisasi**

Masuk ke [DingTalk Developer Console](https://open-dev.dingtalk.com/), lalu klik **Lainnya** > **Informasi Dasar** > [Development Information (Legacy)](https://open-dev.dingtalk.com/fe/old#/corpAuthInfo). Di sana, Anda dapat menemukan dan mencatat ID Organisasi (CorpId) dan Organization Secret (CorpSecret). Dengan kedua nilai ini, Anda dapat membuat Kredensial API khusus untuk mengakses OpenAPI. Proses ini disebut panggilan berotorisasi organisasi.

> Ini adalah produk lawas dari Open Platform versi awal. Jika diperlukan, kami menyarankan untuk memanggil OpenAPI melalui aplikasi internal. Untuk informasi lebih lanjut, lihat [Memperoleh access_token aplikasi internal](/id/open/development/obtain-the-access-token-of-an-internal-app).

## **Cara menghentikan panggilan berotorisasi organisasi**

Ketika Anda perlu menonaktifkan fitur panggilan berotorisasi organisasi, Anda tidak dapat menghapus Organization Secret (CorpSecret) secara langsung. Jika Anda ingin berhenti menggunakan panggilan berotorisasi, Super Admin dengan izin pengembangan dapat melakukannya. Secara spesifik, ubah alamat IP yang terikat menjadi alamat yang tidak valid untuk menonaktifkan panggilan berotorisasi organisasi.

## Tidak dapat menemukan aplikasi internal di Workbench

Jawaban: Jika Anda tidak dapat menemukan aplikasi terkait di Workbench, atasi masalah ini dengan mengikuti langkah-langkah berikut:

1. Konfirmasi bahwa organisasi Workbench saat ini cocok dengan organisasi tempat aplikasi berada.
2. Konfirmasi bahwa aplikasi telah dipublikasikan. Minta Admin untuk membuka [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi target > Manajemen Versi dan Rilis** guna memastikan apakah aplikasi berada dalam status terpublikasi.
3. Konfirmasi cakupan ketersediaan aplikasi. Minta Admin untuk membuka [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi target > Manajemen Versi dan Rilis** guna memastikan apakah pengguna yang tidak dapat menemukan aplikasi berada dalam cakupan ketersediaan.

## Melakukan debug aplikasi internal di Mini Program IDE menampilkan pesan "Maaf, Anda tidak berada dalam cakupan ketersediaan aplikasi ini. Hubungi Admin untuk mengubah konfigurasi"

Jawaban: Kemungkinan penyebab munculnya pesan ini saat melakukan debug aplikasi internal mencakup, tetapi tidak terbatas pada, hal-hal berikut:

1. Orang yang melakukan debug aplikasi internal tidak ada dalam daftar developer. Atur developer di [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi target > Manajemen Pengguna**.
2. Tidak ada versi yang diunggah untuk aplikasi internal. Pastikan untuk mengunggah versi aplikasi di Mini Program IDE, lalu rilis versi tersebut di [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi target > Manajemen Versi dan Rilis**.
3. Pengguna belum diatur di [Developer Console](https://open-dev.dingtalk.com/#/) **> aplikasi target > Manajemen Versi dan Rilis > Cakupan Ketersediaan**.

   **Catatan**

   Untuk mini program aplikasi internal, cakupan ketersediaan hanya ditampilkan setelah Anda mengunggah versi di Mini Program IDE dan merilis versi tersebut di Manajemen Versi dan Rilis.

## Aplikasi mikro internal atau mini program tidak memiliki App Key atau App Secret

Jawaban: Alasan mengapa aplikasi yang dibuat tidak menampilkan App Key dan App Secret mungkin sebagai berikut:

- Saat Anda membuat aplikasi internal di Developer Console, seperti yang ditunjukkan pada gambar di bawah, Anda memilih **Development by an entrusted service provider** sebagai metode pengembangan, yang menyebabkan nilai tidak muncul di Kelola Aplikasi.

  **Catatan**

  Jika Anda sebenarnya tidak memerlukan pengembangan yang didelegasikan, pilih **In-house development**.

- Anda bukan pembuat aplikasi dan tidak memiliki izin terkait untuk melihat App Key dan App Secret. Hubungi Super Admin untuk menambahkan izin Kelola Aplikasi yang sesuai di halaman [DingTalk Admin Console](https://oa.dingtalk.com/#/welcome) **> Keamanan dan Izin > Kelola izin**.
