Panggil API ini untuk memperbarui status instans secara massal.

## Deskripsi panggilan API

Sebagai contoh, Pengguna A mengirimkan tugas yang memiliki tiga tingkat node penanganan, dengan pelaksana B1, B2, dan B3. B1 sudah menerima, tugas saat ini berada di B2, dan B3 belum menerima tugas tersebut.

Setelah memanggil API ini, periksa status tugas di **Pusat Persetujuan** dengan berpindah antara tab **Menunggu**, **Diproses**, **Diajukan**, dan **Diterima**. Setiap baris menampilkan **Judul**, **Ringkasan**, **Pengaju**, **Waktu Mulai**, **Waktu Selesai**, dan **Status Proses** (misalnya, **Disetujui**). Tabel berikut menjelaskan perubahan statusnya.

Dalam contoh alur kerja persetujuan ini, jika status diatur ke **COMPLETED**, status alur kerja persetujuan menjadi seperti berikut:

| Pengirim/Pelaksana tugas | Sebelum pembaruan | Setelah pembaruan |
| --- | --- | --- |
| Pengguna A | Workbench > Tugas > Diajukan, Dalam persetujuan | Workbench > Tugas > Diajukan, Disetujui |
| Node persetujuan B1 | Workbench > Tugas > Diproses, Disetujui | Workbench > Tugas > Diproses, Disetujui |
| Node persetujuan B2 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |
| Node persetujuan B3 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |

Dalam contoh alur kerja persetujuan ini, jika status diatur ke **TERMINATED**, status alur kerja persetujuan menjadi seperti berikut:

| Pengirim/Pelaksana tugas | Sebelum pembaruan | Setelah pembaruan |
| --- | --- | --- |
| Pengguna A | Workbench > Tugas > Diajukan, Dalam persetujuan | Workbench > Tugas > Diajukan, Dibatalkan |
| Node persetujuan B1 | Workbench > Tugas > Diproses, Disetujui | Workbench > Tugas > Diproses, Dibatalkan |
| Node persetujuan B2 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |
| Node persetujuan B3 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |

## Permintaan

### Informasi dasar

| Bidang | Nilai |
| --- | --- |
| URL HTTP | https://api.dingtalk.io/v1.0/workflow/processCentres/instances/batch |
| Metode HTTP | PUT |
| Tipe aplikasi yang didukung | appType-Aplikasi internal　appType-Aplikasi perusahaan pihak ketiga |
| Izin yang diperlukan | permission-Workflow.Instance.Write-Izin tulis instans alur kerja |

### Header permintaan

| Nama | Tipe | Wajib | Deskripsi |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Ya | Kredensial akses untuk memanggil API ini. Cara mendapatkannya:   - Aplikasi internal: Panggil API [Dapatkan access token aplikasi internal](/id/open/development/obtain-the-access-token-of-an-internal-app). - Aplikasi perusahaan pihak ketiga: Panggil API untuk mendapatkan access token organisasi yang telah mengotorisasi Aplikasi pihak ketiga. |

### Isi permintaan

| Nama | Tipe | Wajib | Deskripsi |
| --- | --- | --- | --- |
| updateProcessInstanceRequests | Array | Tidak | Daftar instans. Maksimum: 50. |
| processInstanceId | String | Ya | ID instans. Panggil API [Buat instans](/id/open/development/create-a-ticket-approval-instance) untuk mendapatkannya. |
| status | String | Ya | Status instans.   - **COMPLETED**: Mengakhiri alur kerja persetujuan. - **TERMINATED**: Menghentikan alur kerja persetujuan. |
| result | String | Ya | Hasil instans.   - Jika status instans adalah **COMPLETED**, atur parameter ini ke salah satu nilai berikut.    - **agree**: Terima   - **refuse**: Tolak - Jika status instans adalah **TERMINATED**, parameter ini wajib diisi. Baik agree maupun refuse akan membatalkan alur kerja persetujuan. |
| notifiers | Array | Tidak | Daftar userId penerima CC. Maksimum: 30. |
| userId | String | Ya | userId penerima CC. |
