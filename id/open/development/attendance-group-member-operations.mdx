# Menetapkan anggota absensi: penambahan massal dan pengelolaan presisi

## Ikhtisar

### Latar belakang

Organisasi terus berubah. Karyawan bergabung, keluar, berganti peran, atau pindah departemen. Setiap perubahan mengharuskan HR atau Admin memperbarui anggota grup absensi satu per satu di Admin Console DingTalk. Karyawan baru harus ditambahkan ke grup absensi, karyawan yang keluar harus dihapus, dan karyawan yang dimutasi harus dipindahkan ke grup absensi lain. Organisasi dengan 1.000 karyawan atau lebih dapat mengalami puluhan hingga ratusan perubahan setiap bulan. Pembaruan manual memakan banyak waktu dan tenaga. Selain itu, proses manual rentan terlewat dan salah, sehingga menimbulkan kesalahan absen dan data absensi yang tidak akurat.

### Manfaat utama

Solusi ini mengotomatiskan seluruh siklus hidup anggota grup absensi. Penambahan massal, kueri, pembaruan, dan penghapusan yang semula manual diubah menjadi operasi standar berbasis API. Hasilnya, operasional sistem HR menjadi lebih efisien dan data tetap konsisten.

- **Pengelolaan anggota massal secara otomatis**: Tambahkan, kueri, perbarui, dan hapus anggota melalui API tanpa intervensi manual.
- **Pemilihan API yang tepat**: Pilih API kueri terbaik untuk anggota individu, departemen, atau campuran guna mendapatkan data yang lengkap dan akurat.
- **Verifikasi real-time**: Periksa apakah pengguna termasuk dalam grup absensi tertentu, lalu verifikasi hasil segera setelah setiap pembaruan agar data tetap konsisten.
- **Data lintas sistem yang terpadu**: Sinkronkan data anggota grup absensi secara real-time antara sistem HR, sistem OA, dan DingTalk untuk menghilangkan silo data.

### Kasus penggunaan

Solusi ini cocok untuk skenario bisnis umum berikut:

- **Orientasi karyawan baru**: Setelah HR memasukkan data karyawan baru ke sistem HR, tambahkan karyawan tersebut ke grup absensi departemen terkait secara otomatis.
- **Karyawan keluar**: Setelah persetujuan pengunduran diri di OA disetujui, hapus karyawan dari semua grup absensi secara otomatis.
- **Mutasi peran**: Saat karyawan dimutasi, hapus karyawan dari grup absensi asal dan tambahkan ke grup absensi departemen baru secara otomatis.
- **Penyesuaian anggota secara massal**: Setelah Struktur Organisasi berubah, perbarui daftar anggota beberapa grup absensi secara massal.

## Skenario bisnis umum

### Skenario 1: Menambahkan karyawan baru ke grup absensi secara otomatis

#### Kendala

Dalam proses tradisional, HR harus masuk ke Admin Console DingTalk pada hari pertama setiap karyawan baru, mencari grup absensi departemen terkait, lalu menambahkan setiap karyawan baru secara manual. Jika 5 hingga 10 karyawan bergabung setiap hari, HR harus mengulang tugas ini berkali-kali. Karyawan sering terlewat atau dimasukkan ke grup yang salah, sehingga karyawan baru tidak dapat absen sebagaimana mestinya.

#### Nilai

- **Alur otomatis**

  Alur otomatis berjalan dalam lima langkah:

  1. HR memasukkan data **Karyawan** baru (nama, **Departemen**, jabatan).
  2. Cocokkan **grup absensi** target berdasarkan ID departemen karyawan, lalu cari **groupKey**-nya.
  3. Panggil API **batch-add-employees** untuk menambahkan **userId** karyawan baru ke **grup absensi**.
  4. Panggil API **query-members-by-id** untuk memverifikasi bahwa karyawan berhasil ditambahkan.
  5. Izin **absen** berlaku pada hari yang sama dan pencatatan absensi dimulai.
- **Keunggulan utama**

  - **Pemicu sepenuhnya otomatis**: Setelah HR memasukkan data karyawan baru, sistem HR memanggil API untuk menambahkan karyawan ke grup absensi. Tidak perlu tindakan manual.
  - **Pencocokan presisi**: Sistem mencocokkan grup absensi dengan departemen karyawan secara otomatis sehingga mencegah kesalahan pemilihan.
  - **Langsung berlaku**: Sistem memverifikasi hasil segera setelah penambahan sehingga karyawan baru dapat absen pada hari pertama.
  - **Jejak audit**: Setiap tindakan mencatat operator, stempel waktu, dan ID grup absensi untuk memenuhi persyaratan kepatuhan.

### Skenario 2: Menghapus karyawan yang keluar dari grup absensi secara otomatis

#### Kendala

Saat karyawan keluar, HR harus menghapus karyawan tersebut secara manual dari setiap grup absensi terkait. Jika karyawan termasuk dalam beberapa grup absensi (misalnya, departemen utama dan tim proyek), penghapusan manual mudah terlewat. Karyawan yang sudah keluar mungkin masih dapat absen, data absensi menjadi tidak akurat, dan perhitungan penggajian bisa keliru.

#### Nilai

- **Alur otomatis**

  Alur otomatis berjalan dalam lima langkah:

  1. Permintaan pengunduran diri di **Persetujuan OA** disetujui, lalu sistem menangkap peristiwa tersebut untuk memicu Otomatisasi.
  2. Panggil API **queries-a-user-attendance-group** untuk mendapatkan ID semua grup absensi tempat Karyawan terdaftar.
  3. Lakukan iterasi pada grup-grup tersebut dan panggil API **batch-delete-employees** untuk menghapus Karyawan secara massal.
  4. Panggil API **query-members-by-id** untuk memverifikasi satu per satu bahwa Karyawan telah dihapus dari setiap grup absensi.
  5. Izin absen Karyawan dicabut dan pencatatan absensi dihentikan.
- **Keunggulan utama**

  - **Pemicu sepenuhnya otomatis**: Setelah persetujuan pengunduran diri di OA disetujui, penghapusan berjalan otomatis tanpa intervensi manual.
  - **Cakupan menyeluruh**: Kueri dan hapus karyawan dari semua grup absensi dalam satu kali proses untuk menghindari kelalaian.
  - **Langsung berlaku**: Sistem memverifikasi hasil segera setelah penghapusan sehingga karyawan yang keluar tidak dapat lagi absen.
  - **Log audit lengkap**: Setiap penghapusan mencatat informasi terperinci untuk memenuhi persyaratan audit kepatuhan dan keterlacakan.

## Panduan implementasi

### Arsitektur teknis

Solusi ini dibangun di atas Server API DingTalk Open Platform. Komponen teknis utamanya meliputi:

- **Lapisan autentikasi**: Dapatkan `access_token` menggunakan `Client ID` dan `Client Secret` untuk mengamankan panggilan API.
- **Lapisan pengelolaan anggota**: Menyediakan kemampuan API lengkap untuk menambahkan, mengueri, memperbarui, dan menghapus anggota grup absensi secara massal.
- **Lapisan perutean cerdas**: Memilih API kueri terbaik berdasarkan tipe anggota (individu, departemen, atau campuran) untuk mendapatkan data lengkap.
- **Lapisan penanganan error**: Sistem kode error yang lengkap dan mekanisme coba-lagi membantu Anda menemukan dan menyelesaikan masalah dengan cepat.

**Catatan versi API**: Server API memiliki versi baru dan versi lama. Prioritaskan versi baru untuk performa dan dukungan fitur yang lebih baik.

### Langkah 3: Dapatkan kredensial akses (access_token)

Gunakan Client ID dan Client Secret dari Langkah 1 untuk mendapatkan Kredensial akses. Untuk detailnya, lihat [Mendapatkan access_token Aplikasi internal](/id/open/development/obtain-orgapp-token).

```java
public void getAccessToken() throws ApiException {
  DingTalkClient client = new DefaultDingTalkClient("https://api.dingtalk.io/gettoken");
  OapiGettokenRequest req = new OapiGettokenRequest();
  req.setAppkey("dingxxxxxxxxxhgn");
  req.setAppsecret("9G_xxxxxxxxxxxxxxx1JDf0Qq3nexxxxxxxxGIO");
  req.setHttpMethod("GET");
  OapiGettokenResponse rsp = client.execute(req);
  System.out.println(rsp.getBody());
}
```

**Praktik terbaik**:

- **Caching**: `access_token` berlaku selama 2 jam. Simpan di memori atau Redis, lalu muat ulang 5 menit sebelumnya masa berlakunya habis.
- **Kontrol konkurensi**: Cegah konflik akibat beberapa thread memuat ulang token secara bersamaan. Gunakan distributed lock.
- **Coba lagi saat error**: Coba lagi secara otomatis saat jaringan tidak stabil, maksimal 3 kali, dengan interval yang meningkat (1s → 2s → 4s).

## FAQ

- **T1: Apa perbedaan ketiga API kueri anggota?**

  J: Setiap API sesuai untuk skenario tipe anggota yang berbeda:

  - [Mendapatkan ID pengguna anggota absensi](/id/open/development/query-attendance-group-personnel-information-in-batches): Hanya mengembalikan daftar ID pengguna. Gunakan API ini jika Anda hanya perlu memeriksa keberadaan anggota di grup absensi.
  - [Mendapatkan anggota absensi](/id/open/development/batch-query-of-attendance-group-members): Mengembalikan informasi anggota terperinci (nama, departemen, dan lainnya). Gunakan API ini jika Anda perlu menampilkan detail anggota.
  - [Mengueri daftar anggota absensi](/id/open/development/batch-query-of-employees-in-the-attendance-group): Mendukung kueri dengan paginasi. Gunakan API ini untuk mengambil anggota secara bertahap jika grup absensi memiliki banyak anggota.

  Jika grup absensi menyertakan anggota departemen, perhatikan hal berikut: kueri berdasarkan ID pengguna individu mengembalikan informasi karyawan tersebut. Kueri berdasarkan ID departemen tidak langsung mengembalikan detail karyawan di departemen tersebut. Panggil API kueri anggota departemen secara terpisah.
- **T2: Bagaimana cara menangani kegagalan sebagian saat menambahkan anggota secara massal?**

  J: API penambahan massal menggunakan strategi "best effort" dan mengembalikan anggota yang berhasil dan gagal secara terpisah. Ikuti langkah berikut:

  1. Uraikan respons untuk mengambil ID pengguna anggota yang gagal beserta alasan error-nya.
  2. Catat kegagalan dan analisis penyebabnya (misalnya, pengguna tidak ada atau sudah terdaftar di grup absensi).
  3. Coba lagi untuk error yang dapat dipulihkan (misalnya, pengguna yang baru dibuat belum tersinkronisasi).
  4. Lewati dan catat error yang tidak dapat dipulihkan (misalnya, pengguna sudah keluar dari organisasi).
- **T3: Bagaimana cara memastikan karyawan yang keluar terhapus sepenuhnya?**

  J: Ikuti langkah berikut untuk memastikan penghapusan tuntas:

  1. Setelah persetujuan pengunduran diri di OA disetujui, panggil API [Mendapatkan grup absensi pengguna](/id/open/development/queries-a-user-attendance-group) untuk mendapatkan ID semua grup absensi tempat karyawan terdaftar.
  2. Lakukan iterasi pada semua grup absensi dan panggil API [Menghapus anggota absensi secara massal](/id/open/development/batch-delete-employees-under-the-attendance-group) untuk menghapus karyawan.
  3. Panggil API [Memeriksa apakah pengguna ada di grup absensi](/id/open/development/query-members-by-id) untuk memastikan karyawan telah dihapus dari semua grup absensi.
  4. Catat tindakan tersebut, termasuk daftar ID grup absensi, waktu tindakan, dan operatornya.
