Panggil API ini untuk memperbarui status instans Persetujuan OA.

## Deskripsi panggilan API

Misalnya, Pengguna A mengirim tugas dengan tiga level penanganan: B1, B2, dan B3. B1 telah menerima tugas tersebut. Tugas kini berada di B2, dan B3 belum menerimanya.

Setelah memanggil API ini, periksa status tugas di konsol **Persetujuan** DingTalk. Tabel berikut menunjukkan perubahan statusnya.

Konsol menampilkan catatan persetujuan dalam empat tab: **Perlu ditangani**, **Diproses**, **Dimulai**, dan **Diterima**. Setiap catatan menampilkan progresnya di kolom **Status alur**, misalnya **Disetujui**.

Pada alur persetujuan di atas, jika status diatur ke **COMPLETED**, alur persetujuan berubah sebagai berikut:

| Pengirim/Pelaksana tugas | Sebelum pembaruan | Setelah pembaruan |
| --- | --- | --- |
| Pengguna A | Workbench > Tugas > Dimulai, Dalam persetujuan | Workbench > Tugas > Dimulai, Disetujui |
| Node persetujuan B1 | Workbench > Tugas > Diproses, Disetujui | Workbench > Tugas > Diproses, Disetujui |
| Node persetujuan B2 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |
| Node persetujuan B3 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |

Pada alur persetujuan di atas, jika status diatur ke **TERMINATED**, alur persetujuan berubah sebagai berikut:

| Pengirim/Pelaksana tugas | Sebelum pembaruan | Setelah pembaruan |
| --- | --- | --- |
| Pengguna A | Workbench > Tugas > Dimulai, Dalam persetujuan | Workbench > Tugas > Dimulai, Diurungkan |
| Node persetujuan B1 | Workbench > Tugas > Diproses, Disetujui | Workbench > Tugas > Diproses, Diurungkan |
| Node persetujuan B2 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |
| Node persetujuan B3 | Tidak ada tugas tersebut | Tidak ada tugas tersebut |

## Permintaan

### Informasi dasar

| Bidang | Nilai |
| --- | --- |
| URL HTTP | https://api.dingtalk.io/v1.0/workflow/processCentres/instances |
| Metode HTTP | PUT |
| Tipe aplikasi yang didukung | appType-Aplikasi internal　appType-Aplikasi perusahaan pihak ketiga |
| Izin yang diperlukan | permission-Workflow.Instance.Write-Izin tulis instans alur kerja |

### Header permintaan

| Nama | Tipe | Wajib | Deskripsi |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Ya | Kredensial akses untuk memanggil API ini. Dapatkan dengan cara berikut:   - Aplikasi internal: Panggil API [Dapatkan access token aplikasi internal](/id/open/development/obtain-the-access-token-of-an-internal-app). - Aplikasi perusahaan pihak ketiga: Panggil API Dapatkan access token organisasi yang diotorisasi oleh Aplikasi pihak ketiga. |

### Isi permintaan

| Nama | Tipe | Wajib | Deskripsi |
| --- | --- | --- | --- |
| processInstanceId | String | Ya | ID instans persetujuan. Panggil API [Buat instans](/id/open/development/create-a-ticket-approval-instance) untuk mendapatkan nilai `processInstanceId`. |
| status | String | Ya | Status instans.   - **COMPLETED**: Menyelesaikan alur persetujuan. - **TERMINATED**: Menghentikan alur persetujuan. |
| result | String | Ya | Hasil instans:   - Jika status instans adalah COMPLETED, tetapkan salah satu nilai berikut.    - **agree**: Terima   - **refuse**: Tolak - Jika status instans adalah **TERMINATED**, nilai ini juga wajib diisi. Baik agree maupun refuse akan mengurungkan alur persetujuan. |
| notifiers | Array | Tidak | Daftar ID pengguna penerima CC. Maksimum: 30. |
| userId | String | Ya | ID pengguna penerima CC. Panggil API [Dapatkan daftar ID pengguna di departemen](/id/open/development/query-the-list-of-department-userids) untuk mendapatkannya. |
