Artikel ini menjelaskan cara membeli, mengaktifkan, dan mengonfigurasi Data Security Center untuk melindungi data sensitif organisasi, termasuk data Kontak.

## **Informasi Latar Belakang**

Data Security Center menyediakan kemampuan seperti identifikasi otomatis data sensitif, klasifikasi dan penilaian tingkat, audit keamanan big data, serta penyamaran data (data masking). Layanan ini memberikan solusi terintegrasi lintas domain untuk pencegahan kebocoran data dan keamanan data di cloud.

## **Prosedur**

1. Pada halaman produk [Data Security Center](https://www.aliyun.com/product/sddp?spm=ding_open_doc.document.0.0.784366c71seamX), klik **Buy Now** untuk membuka halaman pembelian.
2. Atur spesifikasi versi pada halaman pembelian:

   - [Wajib] Product Type: Pilih **Data Security Center (Data Discovery, Classification and Grading, Masking, and Leak Prevention).**
   - [Wajib] Version: Pilih paket **Basic**. Anda dapat memilih **Business plan** dengan tingkat lebih tinggi sesuai kebutuhan keamanan Anda.
   - [Wajib] Database Management: Anda harus memilih **On**.
   - [Wajib] Number of Database Instances: Beli sesuai jumlah aktual instance database yang menyimpan data DingTalk. Beli minimal 1. Jika data yang diperoleh dari DingTalk disimpan di 2 instance database, beli 2.
   - [Opsional] OSS Data Management: Jika **tidak ada file sensitif yang disimpan**, Anda dapat memilih **Close**. Jika file sensitif seperti **foto kartu identitas atau spreadsheet daftar pengguna** disimpan, kami merekomendasikan untuk memilih **On** dan membeli sesuai penggunaan. Item ini bersifat opsional.
   - [Wajib] Subscription Duration: Pilih minimal **1 tahun** dan pilih **Auto-renew on Expiration**.

   **Penting**
   - Data Security Center mendukung identifikasi dan perlindungan produk data di region domestik berikut: Hangzhou, Shanghai, Beijing, Shenzhen, Zhangjiakou, Hohhot, dan Qingdao. Pastikan instance database Anda dibeli di region tersebut.

3. Setelah pembelian selesai, buka konsol Data Security Center dan gunakan [Configuration Guide](https://yundun.console.aliyun.com/?spm=ding_open_doc.document.0.0.784366c71seamX&p=sddp#/taskGuide/WorkBench) untuk mengonfigurasinya.
4. Klik **Sync** untuk secara otomatis menyinkronkan aset di cloud ke Data Security Center.

5. Untuk otorisasi aset, klik **Go to Configure** untuk membuka halaman konfigurasi aset.

6. Pilih data terstruktur, lalu konfigurasikan otorisasi untuk instance database yang menyimpan data yang diperoleh dari platform DingTalk (didorong melalui RDS atau dipanggil melalui OpenAPI). Anda tidak perlu mengonfigurasi otorisasi untuk instance yang menyimpan data yang dikumpulkan oleh aplikasi bisnis Anda sendiri yang tidak berada di DingTalk.

   **Catatan**

   Konfigurasi otorisasi menjadi lambat ketika terdapat banyak database. Kami merekomendasikan untuk mengatur tidak lebih dari 20 database per instance.

7. Setelah Anda menyelesaikan konfigurasi otorisasi, pada kolom Tindakan di sebelah kanan instance yang telah diotorisasi, klik **One-Click Connect** untuk mengikat aset yang telah diotorisasi.

8. Klik **Data Sorting** > **Identification Configuration**:

   - Template Configuration: Gunakan **templat klasifikasi dan penilaian tingkat keamanan bawaan dari Alibaba Group dan Ant Group**.
   - Template Details: Atur konfigurasi aturan ke status **On**.

## **FAQ**

1. Bagaimana metode deployment VPC + Data Security Center + Compute Nest melindungi data privat DingTalk? Bagaimana cara mencegah penyedia layanan mengekspor data privat internal DingTalk?

   Jawaban:

   - Compute Nest dapat mendeteksi risiko keamanan. Layanan ini mendorong peringatan untuk konfigurasi berisiko tinggi, kerentanan, atau serangan peretas.
   - Data Security Center mengidentifikasi data sensitif yang tersimpan serta mengaudit dan memberi peringatan atas operasi yang diduga menyebabkan kebocoran data, seperti ekspor data secara massal.
2. Apakah Data Security Center mengubah data asli dalam database?

   Jawaban: Tidak.
3. Apakah Data Security Center mencegat dan menyamarkan data yang di-query atau data yang sedang ditulis ke database?

   Jawaban: Tidak. Versi yang saat ini direkomendasikan hanya mengidentifikasi data sensitif. Versi ini tidak memproses data dan tidak memengaruhi bisnis Anda.
4. Bagaimana Data Security Center memantau database?

   Jawaban:

   - Pemantauan didasarkan pada otorisasi. Data sensitif hanya terdeteksi ketika otorisasi diberikan. DingTalk Security berfokus pada perlindungan data yang disinkronkan keluar dari platform. Penyedia solusi produk hanya perlu mengotorisasi instance yang menyimpan data yang diperoleh dari platform DingTalk, sesuai dengan persyaratan keamanan platform.
   - Jika penyedia solusi produk mencabut otorisasi, atau jika DingTalk Security menemukan otorisasi palsu melalui analisis audit dan penyedia menolak melakukan koreksi setelah diberi tahu, penyedia akan dikenakan pengurangan poin dan penghapusan aplikasi sesuai dengan regulasi keamanan.
5. Ketika Data Security Center memantau data dan mendeteksi risiko, bagaimana cara memberikan peringatan? Apa mekanisme penanganannya?

   Jawaban:

   - Masuk ke konsol Data Security Center untuk melihat peringatan risiko dan konten spesifiknya.
   - Penyedia solusi produk dapat menangani risiko berdasarkan peringatan risiko atau dengan berkonsultasi dengan DingTalk Security. Untuk peringatan berisiko tinggi yang sedang dipantau oleh DingTalk Security, tim ini memberikan rekomendasi penanganan.
   - DingTalk menerima notifikasi peringatan berisiko tinggi yang didorong ke sistem. DingTalk Security memutuskan apakah akan menindaklanjuti dan memberi tahu penyedia solusi produk untuk menangani risiko berdasarkan tingkat keparahan yang tertera pada notifikasi peringatan.
6. Jika issue dibiarkan tidak tertangani, apakah aplikasi akan dihapus atau apakah ada operasi penguncian yang diterapkan pada database?

   Jawaban: Tidak ada operasi yang akan dilakukan pada database. Namun, jika peringatan berisiko tinggi dibiarkan tidak tertangani dalam waktu lama atau terjadi pelanggaran keamanan (misalnya, mengekspor data dari platform DingTalk ke sistem bisnis lain), aplikasi akan dikenakan pengurangan poin dan penghapusan setelah dikomunikasikan dengan penyedia layanan aplikasi, sesuai dengan persyaratan terkait dalam regulasi keamanan platform DingTalk.
7. Jika sebuah tabel dalam database aplikasi penyedia solusi produk menyimpan rekam data pengguna yang berisi baik data sensitif yang diperoleh dari platform DingTalk maupun data pengguna yang dikumpulkan oleh aplikasi milik penyedia sendiri, apakah mengekspor rekam pengguna ini memicu peringatan audit dari Data Security Center?

   Jawaban:

   - Pada prinsipnya, mengekspor data pengguna memerlukan otorisasi dan persetujuan pengguna, dan data hanya dapat digunakan dalam cakupan yang diotorisasi. Oleh karena itu, penyedia solusi produk harus menetapkan mekanisme persetujuan dan audit untuk ekspor data pengguna guna mencegah data pengguna disalahgunakan atau bocor.
   - Identifikasi data sensitif serta pemantauan dan audit pencegahan kebocoran data pada Data Security Center tidak membedakan antara data yang disinkronkan dari platform dan data yang dikumpulkan sendiri.
   - Data Security Center mengaudit dan menghasilkan peringatan atas operasi yang diduga menyebabkan kebocoran, seperti ekspor data secara massal. Panggilan normal oleh aplikasi umumnya tidak memicu peringatan.
8. Jika Anda tidak lagi berintegrasi dengan DingTalk di masa mendatang, apa yang perlu Anda lakukan untuk memulihkan deployment jaringan publik? Apakah Anda perlu melakukan operasi seperti audit data?

   Jawaban: Setelah Anda berhenti berintegrasi dengan DingTalk, Anda perlu memberi tahu pelanggan organisasi yang menggunakan aplikasi mitra di DingTalk untuk mengekspor data mereka sendiri. Setelah Anda menghapus data pelanggan yang diperoleh dari platform DingTalk serta data pelanggan organisasi DingTalk yang dikumpulkan, dan staf DingTalk memverifikasi serta mengonfirmasi penghapusan tersebut, Anda dapat membatalkan pengikatan otorisasi dan keluar dari platform Compute Nest.

## **Langkah Berikutnya**

Setelah Anda mengintegrasikan Data Security Center, Anda perlu [mengimpor sumber daya ke Compute Nest](/id/open/development/import-resources-compute-nest).
