DingTalk mengirim event callback berlangganan ke aplikasi Anda, seperti perubahan Kontak dan perubahan Otorisasi App. Developer dapat menyinkronkan data secara real-time untuk mengintegrasikan sistem bisnis mereka dengan lebih baik.

## Apa itu RDS Push

RDS push adalah versi yang ditingkatkan untuk menggantikan push protokol HTTP. Ini adalah solusi push yang dikembangkan secara mandiri oleh DingTalk Open Platform bersama Alibaba Cloud.

Selain menjamin keamanan data, RDS push sangat menyederhanakan protokol push, mengurangi jumlah transfer data, meningkatkan kecepatan transfer data, dan meningkatkan stabilitas push. RDS push mendukung transfer data tidak hanya antara DingTalk dan ISV, tetapi juga antara DingTalk dan developer perusahaan. RDS push mendukung pengembangan dan debugging lokal maupun deployment serta operasional online, sehingga sangat menyederhanakan proses integrasi ISV dan organisasi dengan DingTalk.

## Perbandingan kemampuan antara RDS Push dan HTTP Push

|  |  |
| --- | --- |
| **RDS Push** | **HTTP Push** |
| Mendukung protokol sinkronisasi, memastikan data ditulis secara andal ke RDS developer. Jika RDS developer gagal, data disimpan secara permanen di DingTalk. | Tidak mendukung protokol sinkronisasi. Kehilangan data dapat terjadi saat jaringan tidak normal atau layanan developer gagal. |
| Mengirim status akhir dari data bisnis, sehingga developer dapat langsung menggunakan data yang dikirim oleh DingTalk Cloud. Hal ini juga mengurangi jumlah panggilan yang dilakukan developer ke DingTalk Open Platform, sehingga menghindari batas Pembatasan laju. | Mengirim ID bisnis. Setelah menerima push, developer masih perlu memanggil API DingTalk Open Platform untuk mengueri status akhir data, yang rentan terhadap batas Pembatasan laju. |
| Mengirim data dengan laju yang berbeda berdasarkan spesifikasi RDS dan kapabilitas developer yang menerima push. | Push dapat menciptakan lonjakan permintaan HTTP secara instan, yang dapat meningkatkan beban pada server developer dan menyebabkannya crash. |
| Data yang dikirim berupa plaintext, tidak memerlukan verifikasi tanda tangan atau logika enkripsi/dekripsi. | Data yang dikirim berupa ciphertext, sehingga developer harus memverifikasi tanda tangan dan melakukan enkripsi/dekripsi sendiri, serta mengimplementasikan logika verifikasi tanda tangan dan enkripsi/dekripsi dalam berbagai bahasa pemrograman. |
| Saluran data merupakan saluran jaringan internal tanpa biaya trafik, dengan tingkat keamanan tinggi dan efisiensi tinggi. | Saluran data merupakan saluran jaringan publik dengan biaya trafik, tingkat keamanan rendah, dan efisiensi rendah. |

## Perbandingan proses antara RDS Push dan HTTP Push

|  |  |  |
| --- | --- | --- |
| **Tahap pengembangan** | **RDS Push** | **HTTP Push** |
| Buat App/suite | Developer perlu menyiapkan instance RDS untuk menerima push (pada tahap pengembangan, instance MySQL apa pun dengan IP publik dapat digunakan). | Developer perlu menyiapkan program dengan alamat publik untuk memverifikasi push. (Untuk peluncuran resmi, program harus di-deploy di DingTalk Cloud.) |
| Organisasi mengotorisasi dan mengaktifkan App/suite | Developer perlu mengimplementasikan fungsi yang melakukan polling dan membaca tabel database yang menerima push untuk memperoleh informasi otorisasi dari organisasi yang telah mengaktifkan aplikasi. **Prosesnya singkat dan masalah mudah untuk ditelusuri.** | Developer perlu mengimplementasikan empat fungsi berikut: 1) Menerima push authorization_code sementara, 2) Menukar authorization_code sementara dengan authorization_code permanen, 3) Mengaktifkan aplikasi, dan 4) Memperoleh informasi otorisasi dari organisasi yang telah mengaktifkan aplikasi. Prosesnya panjang dan masalah sulit untuk ditelusuri. |
| Pantau perubahan data organisasi secara real-time | Developer perlu memilih data yang akan dipantau di halaman detail App/suite, lalu melakukan polling dan membaca tabel database yang menerima push. **Satu tindakan, sederhana untuk dilakukan.** | Developer perlu mendaftarkan alamat pemantauan untuk setiap organisasi. Setelah menerima push, mereka harus mengueri DingTalk Open Platform lagi untuk memperoleh data akhir. Hal ini memerlukan beberapa panggilan API dan membuat debugging API menjadi rumit. |
