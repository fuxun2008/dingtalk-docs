---
title: "Konfigurasikan URL entri pintasan (group plugin)"
description: "Pelajari cara mengonfigurasi URL entri pintasan group plugin di DingTalk — mencakup pengalihan ke halaman biasa, aplikasi mikro H5, dan mini program, serta mengambil informasi grup sumber dari tautan."
---

Lihat dokumen ini jika Anda perlu mengonfigurasi URL sebuah group plugin.

## Alihkan ke halaman

```text
dingtalk://dingtalkclient/page/link?dd_mode=present&pc_slide=true&url=https%3A%2F%2Fwww.dingtalk.io
```

| Parameter | Deskripsi |
| --- | --- |
| url | URL halaman. Encoding URL diperlukan. |
| dd_mode | Hanya untuk iOS.   - push: Mendorong container dari kiri ke kanan pada iOS. - present: Memunculkan container dari bawah ke atas pada iOS. |
| pc_slide | Saat `pc_slide=true`, halaman terbuka di panel samping pada PC. |

## Alihkan ke aplikasi web (aplikasi mikro H5)

```text
dingtalk://dingtalkclient/action/openapp?corpid=$CORPID$&container_type=work_platform&app_id=0_1234&redirect_type=jump&redirect_url=https%3A%2F%2Fwww.dingtalk.io
```

| Parameter | Deskripsi |
| --- | --- |
| container_type | Container tempat menampilkan halaman:   - browser: Browser. - slide_panel: Panel samping. - work_platform: Workbench. |
| corpid | ID organisasi. |
| app_id | - Aplikasi perusahaan pihak ketiga: Masukkan `appId`. Lihat appId untuk detailnya.   - Aplikasi internal: Masukkan `0_agentId`, yang terdiri dari angka `0`, sebuah Garis Bawah, dan `agentId`. Anda dapat menemukan `agentId` di halaman detail aplikasi. |
| redirect_type | Tipe pengalihan:   - jump: Membuka `redirect_url` secara langsung. - emit_params: Memancarkan sebuah event. |
| params | Parameter. Saat membuka untuk pertama kali, tambahkan parameter ini ke daftar parameter URL pengalihan. |
| redirect_url | URL pengalihan. Encoding URL diperlukan. |
| slide_panel_option | Parameter untuk panel samping. Tersedia hanya pada PC. Contoh: `{"width":500,"showAppPage":true}` (`width` adalah lebar panel samping; `showAppPage` menunjukkan apakah halaman web ditampilkan). |

## Alihkan ke mini program

| Parameter | Wajib | Deskripsi |
| --- | --- | --- |
| appId | Salah satu dari `appId` atau `agentId` wajib diisi. Jika keduanya diisi, `appId` diutamakan. | ID aplikasi. Perhatikan bahwa ini bukan `miniAppId` mini program. Gunakan ID ini untuk aplikasi perusahaan pihak ketiga. |
| agentId | Salah satu dari `appId` atau `agentId` wajib diisi. Jika keduanya diisi, `app_id` diutamakan. | ID aplikasi. |
| corpid | Ya | ID organisasi. |
| page | Tidak | Alamat halaman mini program. Anda dapat menambahkan parameter GET. Default ke halaman beranda mini program. |
| query | Tidak | Parameter peluncuran mini program. Anda dapat mengambilnya di callback `onLaunch` atau `onShow` pada App. Saat meluncurkan mini program, Sisi klien menambahkan parameter `corpId` secara default, sehingga pihak bisnis tidak boleh mengatur `corpId`, jika tidak nilainya akan ditimpa. |
| containerType | Tidak | Parameter khusus PC. Nilai yang tersedia:   - browser: Browser. - slide_panel (default): Panel samping. - work_platform: Workbench. - mobile: Mengalihkan ke perangkat mobile. |
| title | Tidak | Parameter khusus PC yang digunakan untuk menampilkan judul. |
| source | Tidak | Sumber (digunakan hanya ketika paket perlu diambil dari Sisi server):   - debug: Versi Debug perangkat. - trial: Versi uji coba. |
| version | Tidak | Nomor Versi. |
| ddMode | Tidak | Gaya transisi peluncuran mini program.   - push: Gaya push. - present: Gaya pop-up. - float: Gaya lapisan mengambang. - pop: Gaya pop view.   Jika tidak ditentukan, Sisi klien meluncurkan dengan gaya transisi default. Tersedia pada klien v4.5.8 dan yang lebih baru sebagai peluncuran bertahap. `float` dan `pop` tersedia pada v4.6.35 (20190624) dan yang lebih baru sebagai peluncuran bertahap. |
| mainTask | Tidak | Wajib hanya untuk **klien Android**. Atur ke `true` atau `false`. Default adalah `false`. Saat diatur ke `true`, mini program berbagi Task yang sama dengan Task utama DingTalk dan tidak lagi dipertahankan tetap aktif. Didukung pada klien v4.6.3 dan yang lebih baru. |
| ddJointNavi | Tidak | Mengonfigurasi gaya bilah navigasi. Saat diatur, ini menimpa logika `ddMode`. Android & iOS: `0`, `1`, atau `1001`.   - 0: Bilah navigasi lama. - 1: Bilah navigasi baru. - 1001: Bilah navigasi dengan hanya tombol Kembali dan Judul. |
| keepAlive | Tidak | Atur ke **true** atau **false**. Default adalah **true**. Diabaikan saat `mainTask` diatur ke `true`. |
| ddFocus | Tidak | Atur ke **true** atau **false**. Default adalah **true**. Saat diatur ke **true**, container mencegah elemen internal mendapatkan fokus selama inisialisasi. |
| ddEnableWX | Tidak | Apakah mendukung rendering Weex. Saat rendering Weex didukung dan halaman dikonfigurasi untuk menggunakan mode rendering Weex, Weex dapat diluncurkan untuk memuat halaman. |
| ddForceAsync | Tidak | Apakah memaksa peluncuran asinkron. Saat dipaksa meluncur secara asinkron, jika paket offline lokal ada, pembaruan sinkron tidak dipicu. Pembaruan asinkron dipaksa (untuk mengatasi masalah peluncuran di lingkungan offline). |
| animated | Tidak | Atur ke **0** atau **1**. Menunjukkan apakah animasi transisi diputar selama peluncuran asinkron (diabaikan dalam skenario peluncuran sinkron). Default adalah **1**. Tersedia pada v4.6.36 dan yang lebih baru. |

1. **Parameter yang didukung saat `ddMode=float` (jendela mengambang)**

   | Parameter | Wajib | Deskripsi |
   | --- | --- | --- |
   | panelHeight | Tidak | Tinggi jendela mengambang. Dapat berupa nilai Persentase layar atau tinggi tetap.  - `percent50` berarti 50% dari layar. Angka harus berada di antara (0, 100]. Nilai di luar batas akan dijepit ke batas. - `1000` berarti tinggi tetap 1000 pt (bukan px). - Jika tidak diatur atau diatur ke 0, jendela mengambang ditampilkan secara layar penuh. |
   | containerType | Tidak | Dua nilai tambahan tersedia dalam skenario ini:  - miniApp (default): Mini program. - online: H5 online. |
   | miniAppId | Ditentukan oleh `containerType` | `appId` mini program. |
   | page | Ditentukan oleh `containerType` | Alamat halaman yang di-encode URL. Untuk mini program, ini adalah `page` mini program. Untuk H5 online, ini adalah alamat URL. |
   | coverVisible | Tidak. Ditampilkan secara default. Atur ke `false` untuk menyembunyikan. | - true (default): Menampilkan lapisan overlay. - false: Menyembunyikan lapisan overlay. Ditampilkan secara default. |

### Parameter yang didukung saat `ddMode=pop` (lapisan pop-up)

   | Parameter | Wajib | Deskripsi |
   | --- | --- | --- |
   | width | Ya | Lebar lapisan pop-up. |
   | height | Ya | Tinggi lapisan pop-up. |
   | clear | Tidak | Apakah latar belakang transparan. Default adalah tidak tembus pandang (opaque). |
   | containerType | Tidak | Dua nilai tambahan tersedia dalam skenario ini:  - miniApp (default): Mini program. - online: H5 online. |
   | miniAppId | Ditentukan oleh `containerType` | `appId` mini program. |
   | page | Ditentukan oleh `containerType` | Alamat halaman yang di-encode URL. Untuk mini program, ini adalah `page` mini program. Untuk H5 online, ini adalah alamat URL. |
2. **Skema open app (skema khusus untuk mini program perusahaan)**

   Skema: `dingtalk://dingtalkclient/action/open_micro_app`

   `The basic parameters are the same as the general parameter list.`

   Logika kontrol peluncuran bertahap harus ditempatkan di handler skema ini.

   | Parameter | Wajib | Deskripsi |
   | --- | --- | --- |
   | corpId | Ya | ID organisasi.  **Penting**  Ini memiliki prioritas lebih tinggi dan menimpa `corpId` di query. |
   | appId | Salah satu dari `appId` atau `agent_id` wajib diisi. Jika keduanya diisi, `appid` diutamakan. | ID Aplikasi mikro. Perhatikan bahwa ini bukan ID mini program. Gunakan ID ini untuk aplikasi ISV. |
   | agentId | Salah satu dari `app_id` atau `agent_id` wajib diisi. | `agent_id` dari aplikasi internal. |
   | fallbackUrl | Tidak. Tidak diperlukan untuk aplikasi mikro yang tidak mendukung H5. Wajib selama fase peluncuran bertahap dari H5 ke mini program. | Alamat H5. Untuk aplikasi mikro yang tidak mendukung mini program, alamat ini digunakan secara langsung. |
   | ddFocus | Tidak | Saat diatur ke `true`, container mencegah elemen internal mendapatkan fokus selama inisialisasi. Default adalah `false`. |
   | ddForceAsync | Tidak | Apakah memaksa peluncuran asinkron. Saat dipaksa meluncur secara asinkron, jika paket offline lokal ada, pembaruan sinkron tidak dipicu. Pembaruan asinkron dipaksa (untuk mengatasi masalah peluncuran di lingkungan offline). |

   Kasus uji untuk PC:

   - Buka URL di panel samping tanpa judul.

     ```text
     dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io&container_type=slide_panel
     ```
   - Buka URL di panel samping tanpa judul.

     ```text
     dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io
     ```
   - Buka URL di browser.

     ```text
     dingtalk://dingtalkclient/action/open_micro_app?corpId=11233&app_id=123&fallback_url=https%3A%2F%2Fwww.dingtalk.io&container_type=browser
     ```
   - Buka URL di panel samping dengan judul.

     ```text
     https://www.dingtalk.io?micro_app_scheme=dingtalk%3A%2F%2Fdingtalkclient%2Faction%2Fopen_micro_app%3F%0AcorpId%3D11233%26app_id%3D123%26container_type%3Dslide_panel%26title%3Dtest_title
     ```
   - Buka URL di browser.

     ```text
     https://www.dingtalk.io?micro_app_scheme=dingtalk%3A%2F%2Fdingtalkclient%2Faction%2Fopen_micro_app%3F%0AcorpId%3D11233%26app_id%3D123%26container_type%3Dbrowser%26title%3Dtest_title
     ```
3. Skema open mini program (skema khusus untuk mini program pribadi)

   Skema: `dingtalk://dingtalkclient/action/open_mini_app`

   Parameter dasarnya sama dengan daftar parameter umum.

   | Parameter | Wajib | Deskripsi |
   | --- | --- | --- |
   | miniAppId | Ya | ID mini program. |
4. **Skema debug mini program**

   Skema: `dingtalk://dingtalkclient/action/dev_mini_app`

   Utamanya digunakan untuk men-debug mini program dan untuk pengembangan framework appx. Mini program yang dibuka dengan cara ini meluncurkan dokumen utama secara langsung melalui URL. Mereka tidak masuk ke proses manajemen paket dan tidak memicu logika keep-alive. `miniAppId` digunakan hanya untuk verifikasi API dan tujuan serupa.

### Penting

   Semua parameter sudah di-encode. Pastikan untuk men-decode-nya.

   | Parameter | Deskripsi |
   | --- | --- |
   | url | URL dokumen utama mini program yang di-encode. Sisi klien memanggil nebulaSDK untuk membuka Tautan ini. |
   | miniAppId | `appId` mini program. |
   | isTinyApp | Apakah ini sebuah mini program. Harus diatur ke `YES` saat membuka melalui HTTP. |
   | enableDSL | Apakah menggunakan mini program. Atur ke `YES` atau `NO`. |
   | enableWK | Apakah menggunakan WK. Atur ke `YES` atau `NO`. |
   | packageManager | Layanan manajemen paket.  - Default: DingTalk API. - alipay_online: Lingkungan produksi Alipay. - alipay_dev: Lingkungan pengembangan Alipay. |
   | keepAlive | Apakah dipertahankan tetap aktif. Default adalah `true`. |

## Mengambil informasi grup sumber melalui tautan

- Tentukan metode pembukaan khusus.

  Entri pintasan (group plugin) adalah Tautan `dingtalk` dengan kemampuan bisnis. Developer perlu menyusun Tautan group plugin berdasarkan skenario nyata Aplikasi mikro mereka dan kebutuhan spesifik pengguna dalam grup. Nama plugin mendukung hingga 4 karakter. Tautan menawarkan kemampuan yang luas, tetapi developer harus menyusunnya melalui parameter Tautan. Misalnya, metode pembukaan pada perangkat mobile (halaman push, halaman pop-up, dan sebagainya) dan logika pengalihan halaman pada PC (membuka container baru atau menggunakan panel geser) semuanya diimplementasikan melalui konfigurasi parameter Tautan.

  Berikut ini menggunakan entri pintasan sebuah grup proyek sebagai contoh untuk menjelaskan secara rinci bagaimana Tautan entri pintasan disusun.

  dingtalk://dingtalkclient/page/link?url=https%3a%2f%2fding-doc.dingtalk.io%2fdoc%23%2fpqkq0u%2feluagw%2f$CORPID$%2f$DOUBLE_ENCCID$

  - **Alamat halaman target developer**: https%3a%2f%2fding-doc.dingtalk.io%2fdoc%23%2fpqkq0u%2feluagw

    - Saat Anda menggunakan protokol pengalihan terpadu DingTalk, bagian ini diteruskan sebagai parameter input ke alamat "protokol pengalihan terpadu DingTalk" dan oleh karena itu harus di-encode URL.
    - Saat Anda tidak menggunakan protokol pengalihan terpadu DingTalk, Anda dapat menggunakan URL asli secara langsung sebagai alamat entri pintasan. Encoding URL tidak diperlukan.
  - **Protokol pengalihan terpadu DingTalk (opsional)**: dingtalk://dingtalkclient/page/link?url=

    - Bagian ini menentukan bagaimana halaman yang ditentukan dibuka. Opsi yang saat ini didukung mencakup "Buka di browser" dan "Buka di panel samping". Path dari protokol pengalihan terpadu berbeda untuk setiap opsi.
    - Beberapa path protokol pengalihan terpadu hanya tersedia pada platform tertentu. Misalnya, "Buka di panel samping" hanya tersedia pada PC dan Mac.
  - **Parameter dinamis alamat entri pintasan (opsional)**: $CORPID$ $DOUBLE_ENCCID$

    - Saat parameter dinamis diatur, bagian URL ini digantikan dengan informasi Konteks grup (seperti `corpId` dan `openConversationId`) ketika pengguna mengklik entri pintasan untuk mengakses alamat developer.

      Parameter dinamis yang saat ini didukung adalah sebagai berikut:

      > Parameter dinamis berikut hanya dikenali saat dibuka melalui entri pintasan (group plugin).

      | Parameter | Deskripsi |
      | --- | --- |
      | $CORPID$ | Digantikan secara dinamis dengan ID Organisasi (`corpId`). |
      | $ENCCID$ | Digantikan secara dinamis dengan ID percakapan terbuka (`openConversationId`). Gunakan parameter dinamis ini hanya ketika protokol pengalihan terpadu DingTalk tidak digunakan. |
      | $DOUBLE_ENCCID$ | Digantikan secara dinamis dengan ID percakapan terbuka (`openConversationId`). Perbedaannya adalah bahwa ini di-encode URL dua kali, digunakan untuk decoding URL di beberapa pengalihan pass-through protokol. Gunakan parameter dinamis ini hanya ketika protokol pengalihan terpadu DingTalk digunakan. |

      `$DOUBLE_ENCCID$` di-encode dan di-decode URL dua kali karena DingTalk memiliki lapisan protokol internal yang dimulai dengan `dingtalk://`, yang membutuhkan satu putaran encoding saat parsing. Protokol HTTPS bisnis yang diteruskan melalui parameter URL ke container hilir juga membutuhkan satu putaran encoding dan decoding. Karena konsumen membutuhkan dua putaran parsing, dua putaran encoding diperlukan saat menghasilkan URL.

      Contoh pembuatan URL: urlencode(DingTalk URL?xxx=xxx & url = urlencode(business URL))

      Contoh parsing URL: a. urldecode(DingTalk URL) -> Dapatkan business URL; b. urldecode(business URL) -> Dapatkan parameter yang dapat digunakan.
