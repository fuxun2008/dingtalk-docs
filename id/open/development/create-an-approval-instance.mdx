Panggil API ini untuk memulai instans Persetujuan OA. Paket seperti Kehadiran & Cuti, HR, Keuangan & Pajak, Hukum, dan Perjalanan Dinas tidak mendukung pembuatan instans persetujuan melalui API ini.

## Deskripsi panggilan API

### Pemberitahuan penting

API ini menerapkan validasi yang lebih ketat terhadap data masuk untuk mencegah data tidak valid diteruskan ke Open API.

- Untuk kontrol pilihan tunggal dan pilihan banyak, setiap nilai opsi yang dikirim harus ada dalam daftar opsi yang telah dikonfigurasi.
- Untuk kontrol kontak internal, setiap userID yang dikirim harus milik pengguna aktif di organisasi saat ini.
- Untuk kontrol departemen, setiap ID departemen harus berupa ID departemen yang valid di organisasi saat ini.
- Untuk kontrol formulir persetujuan terkait, setiap ID instans yang dikirim harus berupa ID instans persetujuan yang sudah ada di organisasi saat ini.

Formulir persetujuan yang dimulai dengan melanggar aturan ini dapat gagal dimulai di kemudian hari setelah validasi data formulir yang lebih ketat diberlakukan.

### Kasus penggunaan

<Note>
Setelah instans persetujuan dimulai, informasinya tidak dapat diubah melalui API.
</Note>

Instans persetujuan dapat dimulai dengan 2 cara, tergantung apakah Anda menentukan penyetuju. Tetapkan proses persetujuan baru atau gunakan ulang proses persetujuan yang telah dikonfigurasi di admin console persetujuan.

- Jangan tentukan penyetuju, dan gunakan ulang proses persetujuan yang telah dikonfigurasi di admin console persetujuan. Perhatikan hal berikut:

  - Penyetuju dan penerima CC menggunakan ulang pengguna yang dikonfigurasi di admin console persetujuan.
  - Semua desain alur kerja yang didukung di admin console persetujuan dapat digunakan, seperti persetujuan atau (or-sign), persetujuan bersama (countersign), persetujuan bersyarat, dan penyetuju yang dipilih oleh pengaju.

    Editor templat persetujuan memiliki empat langkah konfigurasi: **Pengaturan Dasar** > **Desain Formulir** > **Desain Alur Kerja** > **Pengaturan Lanjutan**. Di **Desain Alur Kerja**, susun alur dari jenis node berikut: **pengaju**, **penyetuju** (misalnya dipilih oleh pengaju, countersign, atau or-sign), cabang bersyarat yang mengarahkan alur berdasarkan nilai kolom (misalnya jumlah ≥ 100 vs. < 100), dan **penerima CC**.
- Tentukan penyetuju, dan jangan gunakan ulang proses persetujuan yang dikonfigurasi di admin console OA.

  - Pengaturan lanjutan templat persetujuan tidak didukung. Misalnya, Tanda tangan dan izin operasi formulir tidak tersedia. **Pengaturan Lanjutan** templat persetujuan (langkah 4) mencakup opsi proses berikut, dan tidak ada satu pun yang berlaku saat Anda menetapkan penyetuju melalui API ini: **Deduplikasi Otomatis** (jika seorang penyetuju muncul lebih dari sekali dalam alur, ia hanya menyetujui sekali dan sisanya lolos otomatis), **Persetujuan Otomatis** (jika penyetuju dan pengaju adalah orang yang sama, Persetujuan lolos otomatis), **Izinkan Penambahan Penyetuju** (menambahkan penyetuju sementara ke formulir), **Penarikan Persetujuan** (pengaju dapat menarik formulir), **Persetujuan Berbatas Waktu**, **Tanda Tangan**, **Komentar Persetujuan**, dan **Izinkan Pengajuan atas Nama Orang Lain**.
  - Saat menentukan penyetuju, API ini tidak dapat digunakan untuk menetapkan penyetuju sebagai dipilih oleh pengaju.

### Petunjuk

Skenario 1: Jangan tentukan penyetuju, dan gunakan ulang proses persetujuan yang dikonfigurasi di admin console persetujuan.

### Catatan

- Kosongkan parameter approvers. Proses persetujuan yang dikonfigurasi di admin console persetujuan akan digunakan ulang secara default.
- Parameter ccList dan ccPosition yang ditetapkan melalui API tidak berlaku. Penerima CC yang dikonfigurasi di admin console persetujuan akan digunakan ulang.

- Ada 2 kasus, tergantung apakah proses persetujuan berisi node yang dipilih oleh pengaju.

  - Dengan node yang dipilih oleh pengaju: panggil API [Dapatkan informasi node dalam proses formulir persetujuan](/id/open/development/approval-process-prediction). Nilai isTargetSelect dari setiap node yang dikembalikan adalah true.

### Catatan

  Saat memanggil API ini untuk memulai instans persetujuan, kosongkan approvers dan targetSelectActioners.

  - Tanpa node yang dipilih oleh pengaju: panggil API [Dapatkan informasi node dalam proses formulir persetujuan](/id/open/development/approval-process-prediction). Sebagian node yang dikembalikan memiliki nilai isTargetSelect false.

### Catatan

  Saat memanggil API ini untuk memulai instans persetujuan, kosongkan approvers dan kirimkan targetSelectActioners untuk menentukan informasi node yang dipilih oleh pengaju.

Skenario 2: Tentukan penyetuju, dan jangan gunakan ulang proses persetujuan yang dikonfigurasi di admin console OA. Gunakan parameter approvers untuk menentukan penyetuju baru.
