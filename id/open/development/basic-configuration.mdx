Setelah membuat aplikasi perusahaan pihak ketiga, selesaikan konfigurasi dasar seperti alamat IP keluar server, dan tentukan metode push data.

## Prosedur

1. Masuk ke [Developer Console](https://open-dev.dingtalk.com/) dan klik App yang dituju.
2. Pada halaman detail App, klik **Development Management** untuk mengonfigurasi informasi dasar App.

   |  |  |  |
   | --- | --- | --- |
   | Konfigurasi | Wajib | Deskripsi |
   | Mode pengembangan | Wajib untuk Aplikasi mikro H5 | Pilih mode pengembangan:  - **Develop app**: Mengembangkan Aplikasi mikro H5 baru. - **Quick link**: Menambahkan Aplikasi mikro H5 yang sudah ada. Sebuah organisasi dapat mengintegrasikan Aplikasi internalnya ke DingTalk melalui quick link, sehingga karyawan internal dapat menggunakannya di DingTalk Workbench. |
   | IP keluar server | Ya | Masukkan alamat IP yang digunakan saat memanggil DingTalk Server API, yaitu alamat IP publik dari server organisasi. Pisahkan beberapa alamat IP dengan koma (,). Format IP dengan satu wildcard (\*) didukung. |
   | URL beranda App | Wajib untuk Aplikasi mikro H5 | Masukkan URL beranda App. Mengetuk ikon App pada Workbench versi seluler akan mengalihkan ke halaman ini.  Masukkan alamat IP atau domain server tempat layanan backend di-deploy. Contoh: `https://public-IP:8080`. |
   | URL beranda PC | Tidak | Masukkan URL untuk membuka App di DingTalk Workbench pada PC. Tautan harus diawali dengan http atau https.  **Catatan**  Jika dikosongkan, mengetuk ikon App di DingTalk Workbench pada PC akan menampilkan pesan: "The PC version is not supported yet. Scan the QR code below with DingTalk on your phone to view." App hanya dapat digunakan pada DingTalk Sisi klien di perangkat seluler. |
   | URL Admin Console | Tidak | Masukkan URL bagi admin untuk mengakses App di [DingTalk Admin Console](https://oa.dingtalk.com/). |
   | Tipe push | Ya | Aplikasi perusahaan pihak ketiga **wajib** mendaftarkan callback untuk menerima peristiwa aktivasi App saat sebuah organisasi mengotorisasi App. Peristiwa ini memberi tahu App organisasi mana yang telah mengaktifkannya. Setelah backend aplikasi pihak ketiga menerima peristiwa ini, backend harus menginisialisasi informasi organisasi untuk menyelesaikan aktivasi. Untuk detailnya, lihat [Activate an authorized app](https://open.dingtalk.com/document/isvapp/activate-authorized-applications#).  Selain peristiwa aktivasi App, DingTalk juga melakukan push pesan peristiwa lainnya, seperti perubahan Otorisasi App dan perubahan Departemen. Dengan berlangganan peristiwa callback ini, developer dapat berintegrasi lebih baik dengan DingTalk. Untuk detailnya, lihat [Data Push Overview](https://open.dingtalk.com/document/isvapp/callback-events-overview#).  DingTalk mendukung dua metode berikut untuk menerima peristiwa callback:  - RDS data push - SyncHTTP push |
