Dokumen ini menjelaskan cara mengalihkan ke aplikasi mikro DingTalk dengan mengeklik Notifikasi Kerja yang telah terkirim.

## Prasyarat

Selesaikan prosedur [Buat aplikasi](/id/open/dingstart/create-application).

## Prosedur

1. Pilih aplikasi target, buka halaman detail aplikasi, lalu klik **Basic Information** > **Credentials and Basic Information**.
2. Dapatkan Client ID dan Client Secret aplikasi.
3. Aplikasi internal telah mengaktifkan Izin API Notifikasi Kerja secara default. Anda tidak perlu mengajukan permohonan secara manual.
4. Dapatkan kredensial akses untuk memperoleh access_token dari aplikasi internal. Saat Anda memanggil API, identitas pemanggil diautentikasi menggunakan access token.
5. Panggil API [Kirim Notifikasi Kerja](/id/open/development/asynchronous-sending-of-enterprise-session-messages) untuk mengirim Notifikasi Kerja kepada pengguna target. Pengguna perlu mengeklik pesan untuk memicu pengalihan, sehingga tipe pesan yang sesuai adalah pesan tautan, pesan OA, dan Pesan kartu. Untuk detailnya, lihat [Tipe notifikasi pesan](/id/open/development/message-types-and-data-format).

## Alihkan ke aplikasi web (aplikasi mikro H5) dengan mengeklik Notifikasi Kerja

1. Panggil API [Kirim Notifikasi Kerja](/id/open/development/asynchronous-sending-of-enterprise-session-messages). Pilih pesan tautan, pesan OA, atau Pesan kartu sebagai format Notifikasi Kerja. Ketiga tipe pesan ini mendukung pengalihan.
2. Untuk cara membangun tautan alih, lihat [Deskripsi tautan pesan](/id/open/development/message-link-description). Contoh berikut menunjukkan cara membangun tautan untuk masing-masing dari ketiga tipe pesan tersebut. Untuk format pengiriman pesan yang lengkap, lihat [Tipe notifikasi pesan](/id/open/development/message-types-and-data-format).

   | **Parameter** | Deskripsi |
   | --- | --- |
   | corpid | - Untuk aplikasi web (aplikasi mikro H5) aplikasi internal, parameter ini adalah nilai corpid dari organisasi tempat aplikasi mikro saat ini berada. - Untuk aplikasi web (aplikasi mikro H5) aplikasi perusahaan pihak ketiga, parameter ini adalah nilai corpid dari organisasi yang telah mengotorisasi aplikasi saat ini. |
   | container_type | Metode yang digunakan untuk membuka tautan (nilai tetap): - **work_platform**: Buka tautan di workbench. |
   | app_id | - Untuk aplikasi mikro H5 aplikasi internal, atur parameter ini ke 0_agentId, yang terdiri dari angka 0, garis bawah, dan agentId. Untuk melihat agentId, lihat Agent ID. - Untuk aplikasi mikro H5 aplikasi perusahaan pihak ketiga, atur parameter ini ke nilai appId dari aplikasi mikro pihak ketiga saat ini. Untuk melihat appId, lihat App ID. |
   | redirect_type | Dalam skenario ini, atur ke **jump** (nilai tetap). |
   | redirect_url | URL target yang dituju untuk pengalihan. URL ini **harus di-urlEncoded**. |

### Contoh

```text
dingtalk://dingtalkclient/action/openapp?corpid=corpidOfEnterprise&container_type=work_platform&app_id=appId&redirect_type=jump&redirect_url=redirectUrl
```

### Contoh membangun tautan alih untuk pesan tautan

```text
"messageUrl": "dingtalk://dingtalkclient/action/openapp?corpid=corpidOfEnterprise&container_type=work_platform&app_id=appId&redirect_type=jump&redirect_url=redirectUrl"
```

### Contoh membangun tautan alih untuk pesan OA

```text
"message_url": "dingtalk://dingtalkclient/action/openapp?corpid=corpidOfEnterprise&container_type=work_platform&app_id=appId&redirect_type=jump&redirect_url=redirectUrl"
```

### Contoh membangun tautan alih untuk Pesan kartu

Pesan kartu mendukung gaya ActionCard alih seluruh kartu dan gaya ActionCard alih tombol independen:

- Gaya ActionCard alih seluruh kartu

  ```text
  "single_url": "dingtalk://dingtalkclient/action/openapp?corpid=corpidOfEnterprise&container_type=work_platform&app_id=appId&redirect_type=jump&redirect_url=redirectUrl"
  ```
- Gaya ActionCard alih tombol independen

  ```text
  "action_url": "dingtalk://dingtalkclient/action/openapp?corpid=corpidOfEnterprise&container_type=work_platform&app_id=appId&redirect_type=jump&redirect_url=redirectUrl"
  ```
