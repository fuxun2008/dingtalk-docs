Dokumen ini memperkenalkan berbagai jenis dan kasus penggunaan notifikasi pesan, kemampuan API notifikasi pesan, serta cara mengintegrasikannya.

## Jenis notifikasi pesan

DingTalk menyediakan jenis notifikasi pesan berikut:

- **Kirim Notifikasi Kerja menggunakan templat:**

  Templat pesan adalah peningkatan dari cara Aplikasi perusahaan pihak ketiga melakukan Push pesan melalui Notifikasi Kerja. Templat pesan menyediakan kemampuan pengembangan dan konfigurasi yang lebih sederhana dan terstandardisasi untuk templat pesan, sekaligus menawarkan kemampuan notifikasi pesan yang lebih aman, terkelola, dan terkontrol di sisi pelanggan. Untuk informasi lebih lanjut, lihat [Ikhtisar Templat Pesan](/zh/open/development/message-template-overview).

  **Catatan**

  Templat pesan hanya didukung untuk Aplikasi perusahaan pihak ketiga, tidak untuk Aplikasi internal.

- **Pesan Notifikasi Kerja**:

  Ini adalah pesan notifikasi yang di-push kepada karyawan atas nama Aplikasi mikro dalam obrolan Notifikasi Kerja organisasi Anda, seperti ucapan ulang tahun dan pengingat onboarding.

## Kemampuan API notifikasi pesan

### Daftar API notifikasi pesan terbuka

Notifikasi pesan menawarkan kemampuan API yang kaya. Melalui API, developer dapat mengintegrasikan notifikasi pesan dengan sistem bisnis organisasinya.

**Notifikasi Kerja**

| API | Deskripsi | Spesifikasi Baru (New Server API) | Spesifikasi Lama (Server API) |
| --- | --- | --- | --- |
| Kirim Notifikasi Kerja | Mengirim pesan Notifikasi Kerja. | - | [Kirim Notifikasi Kerja](/zh/open/development/asynchronous-sending-of-enterprise-session-messages) |
| Perbarui Batang Status Notifikasi Kerja | Memperbarui status pesan Notifikasi Kerja OA. | - | [Perbarui Batang Status Notifikasi Kerja](/zh/open/development/update-work-notification-status-bar) |
| Dapatkan Progres Pengiriman Pesan Notifikasi Kerja | Mendapatkan progres pengiriman pesan Notifikasi Kerja. | - | [Dapatkan Progres Pengiriman Pesan Notifikasi Kerja](/zh/open/development/obtain-the-sending-progress-of-asynchronous-sending-of-enterprise-session) |
| Dapatkan Hasil Pengiriman Pesan Notifikasi Kerja | Membuat kueri hasil pengiriman pesan Notifikasi Kerja. | - | [Dapatkan Hasil Pengiriman Pesan Notifikasi Kerja](/zh/open/development/gets-the-result-of-sending-messages-asynchronously-to-the-enterprise) |
| Tarik Kembali Pesan Notifikasi Kerja | Menarik kembali pesan Notifikasi Kerja. | - | [Tarik Kembali Pesan Notifikasi Kerja](/zh/open/development/notification-of-work-withdrawal) |

## Cara mengintegrasikan kemampuan API notifikasi pesan

DingTalk menyediakan contoh alur integrasi untuk API notifikasi pesan.

- Alihkan ke Mini Program DingTalk dari Notifikasi Kerja
- [Alihkan ke Aplikasi Mikro DingTalk dari Notifikasi Kerja](/zh/open/development/redirect-micro-applications-to-work-messages)

## Glosarium

### task_id

`task_id` adalah bidang pengidentifikasi unik dari pesan Notifikasi Kerja. Bidang ini dikembalikan saat Anda memanggil API [Kirim Notifikasi Kerja](/zh/open/development/asynchronous-sending-of-enterprise-session-messages).

Gunakan `task_id` untuk memanggil API [Dapatkan Progres Pengiriman Pesan Notifikasi Kerja](/zh/open/development/obtain-the-sending-progress-of-asynchronous-sending-of-enterprise-session) dan API [Dapatkan Hasil Pengiriman Pesan Notifikasi Kerja](/zh/open/development/gets-the-result-of-sending-messages-asynchronously-to-the-enterprise) untuk membuat kueri progres dan hasil pengiriman pesan Notifikasi Kerja.
