## Ikhtisar area tindakan persetujuan

Area tindakan persetujuan berada di bagian bawah halaman detail persetujuan dan berisi tombol-tombol tindakan. Dalam contoh, area ini mencakup **Komentar**, **Buat diskusi grup**, **Hapus**, **Kembali ke formulir asli**, **Tolak**, dan **Setujui**. Aplikasi pihak ketiga dapat mengustomisasi tombol di area ini.

## Cara kerja area tindakan persetujuan

Saat membuat templat persetujuan atau instans persetujuan, Aplikasi pihak ketiga dapat mendaftarkan callback untuk merender tombol kustom di area tindakan persetujuan dan mengirim permintaan. Aplikasi wajib menyediakan dua API untuk rendering ter-hosting dan untuk memproses permintaan pengguna:

- **Rendering tombol:** DingTalk memanggil kembali Aplikasi pihak ketiga untuk mendapatkan definisi tombol pada area tindakan.
- **Operasi persetujuan:** DingTalk memanggil kembali API pihak ketiga untuk menerima dan memproses tindakan persetujuan yang dikirim pengguna.

Alur integrasi berjalan dari **Aplikasi pihak ketiga** ke **Backend persetujuan: OA Open API**, lalu ke **Frontend persetujuan**. Frontend persetujuan merender hasilnya di tiga tampilan: **To-do**, **Pusat Persetujuan**, dan **Kartu interaktif IM**. Aplikasi pihak ketiga menyelesaikan langkah-langkah berikut secara berurutan:

1. Buat templat
2. Buat instans
3. Daftarkan callback Tombol render kustom & Kirim permintaan pada area tindakan persetujuan
4. Buat tugas

Selama proses rendering dan pengiriman, Frontend persetujuan memanggil Aplikasi pihak ketiga melalui **SPI callback (render / operasi persetujuan)**. **Backend persetujuan: Open gateway** merutekan callback ini. Tampilan **To-do** dan **Kartu interaktif IM** memicu callback operasi persetujuan.

## Definisi model inti

- **ProcessFeatureConfig: Konfigurasi integrasi Pusat Proses**

  Dalam mode integrasi Pusat Proses, konfigurasi ini memungkinkan Aplikasi pihak ketiga mendefinisikan logika kustom untuk modul fitur bisnis tertentu. Solusi hosting halaman persetujuan dibangun di atas konfigurasi ini. Aplikasi pihak ketiga dapat mengustomisasi setiap tombol di area tindakan persetujuan pada halaman detail. Konfigurasikan dua API callback tambahan:

  - CUSTOM_ACTION_DEFINITION: DingTalk memanggil kembali Aplikasi pihak ketiga untuk mendapatkan definisi tombol pada area tindakan (rendering tombol).
  - CUSTOM_ACTION_APPLY: DingTalk memanggil kembali API pihak ketiga untuk menerima dan memproses tindakan persetujuan yang dikirim pengguna (operasi persetujuan).

  ```text
  "featureConfig":{
    "features":  [
      {
        // URL callback untuk mendapatkan data area tindakan (tombol) (rendering tombol)
        "name":"CUSTOM_ACTION_DEFINITION",  
        "runType":"OUTBIZ_CUSTOM",
        "callback":{
          "apiKey":"customActionDefinitionApiKey",
          "appUuid":"appUuid",
          "version":"1"
        }
      },
      {
        // URL callback yang dipanggil saat tindakan persetujuan dilakukan (operasi persetujuan)
        "name":"CUSTOM_ACTION_APPLY",  
        "runType":"OUTBIZ_CUSTOM",
        "callback":{
          "apiKey":"customActionApplyApiKey",
          "appUuid":"appUuid",
          "version":"1"
        }
      }
    ]
  }
  ```

      | INSTANCE_PRINT | Cetak Formulir persetujuan | Klik untuk membuka grup tombol. | Implementasi default mendefinisikan interaksi. Sisi bisnis dapat mengonfigurasi apakah tombol ditampilkan. |
      | INSTANCE_DING | Pengingat: pengaju Proses persetujuan mengirim pengingat kepada penyetuju di node saat ini | Klik untuk membuka komponen DING. | Implementasi default mendefinisikan interaksi. Sisi bisnis dapat mengonfigurasi apakah tombol ditampilkan. |
      | INSTANCE_IM_GROUP | Buat diskusi grup berdasarkan instans | Klik untuk membuka pemilih pengguna. Dialog konfirmasi muncul setelah pemilihan. | Implementasi default mendefinisikan interaksi. Sisi bisnis dapat mengonfigurasi apakah tombol ditampilkan. |
      | INSTANCE_COMMENT | Beri komentar pada Formulir persetujuan | Klik untuk membuka dialog konfirmasi komentar. | Implementasi default mendefinisikan interaksi. Sisi bisnis dapat mengonfigurasi apakah tombol ditampilkan. |
    - ##### **Tombol bawaan**

      Hosting formulir menyediakan tombol tindakan persetujuan ini secara bawaan dan mengimplementasikan mekanisme interaksi umum untuknya secara otomatis. Sisi bisnis mengirim tombol-tombol ini sesuai kebutuhan, berdasarkan proses dan pengguna saat ini. Pihak yang berintegrasi mengimplementasikan kemampuan sebenarnya, sehingga perilakunya dapat sedikit berbeda antar-mesin proses.

      |  |  |  |
      | --- | --- | --- |
      | ID tombol [actionType] | Kemampuan | Deskripsi |
      | TASK_APPROVE | Terima tugas persetujuan | Interaksi tetap. Teks tombol dan logika callback dapat dikustomisasi. |
      | TASK_REJECT | Tolak tugas persetujuan | Interaksi tetap. Teks tombol dan logika callback dapat dikustomisasi. |
      | TASK_FORWARD | Alihkan tugas persetujuan | Interaksi tetap. Teks tombol, daftar pengguna yang dapat dipilih, dan logika callback dapat dikustomisasi. |
      | TASK_APPEND | Tanda tangani permintaan | Interaksi tetap. Teks tombol, penyetuju yang dapat dipilih untuk tanda tangan permintaan, metode tanda tangan permintaan, dan logika callback dapat dikustomisasi. |
      | INSTANCE_REVERT | Kembalikan | Interaksi tetap. Teks tombol, daftar node tujuan pengembalian, dan logika callback dapat dikustomisasi. |
      | INSTANCE_MODIFY | Ubah Formulir persetujuan | Interaksi tetap. Teks tombol, status nonaktif (abu-abu), alasan nonaktif, dan properti serupa dapat dikustomisasi. |
      | INSTANCE_TERMINATE | Batalkan Formulir persetujuan | Interaksi tetap. Teks tombol, teks prompt konfirmasi, dan logika callback dapat dikustomisasi. |
      | INSTANCE_DELETE | Hapus Formulir persetujuan | Interaksi tetap. Teks tombol, teks prompt konfirmasi, dan logika callback dapat dikustomisasi. |
      | INSTANCE_EXTERNAL_DETAIL | Kembali ke formulir asli: menampilkan tombol di halaman detail persetujuan yang membuka halaman detail eksternal | Interaksi tetap. Teks tombol dan visibilitas dapat dikustomisasi. |
    - ##### **Tombol bisnis kustom**

      Sistem pihak ketiga yang berintegrasi mendefinisikan tombol-tombol ini. Terapkan konfigurasi sederhana agar tombol memiliki gaya yang mirip dengan tombol bawaan. Saat pengguna mengklik salah satu tombol ini, DingTalk memanggil kembali sistem pihak yang berintegrasi melalui API operasi persetujuan. Sistem tersebut kemudian menjalankan logika tindakan kustom.

      |  |  |  |  |
      | --- | --- | --- | --- |
      | ID tombol [actionType] | Kemampuan | Tipe interaksi | Deskripsi |
      | CUSTOM_ACTION_xxx | Tombol bisnis kustom | Tipe interaksi standar yang didukung platform:  - link: langsung dialihkan - confirm: dialog konfirmasi - modal: membuka dialog (sisi bisnis dapat mengustomisasi komponen di dalam dialog) | Tidak boleh sama dengan ID apa pun yang dicadangkan oleh platform hosting. |
  - **Aturan pengurutan dan rendering tombol**

    Secara default, platform hosting mengurutkan dan memformat tombol yang dikirim oleh pihak yang berintegrasi.

    - Platform hosting memeriksa apakah tombol umum perlu ditambahkan dan menambahkannya jika diperlukan.
    - DingTalk memanggil kembali Aplikasi pihak ketiga untuk mendapatkan definisi tombol pada area tindakan (rendering tombol), lalu merender tombol berdasarkan data yang dikembalikan. Jika callback mengembalikan error, DingTalk kembali menggunakan tombol yang sudah ada pada solusi hosting ORIGIN: Bagikan, Unduh, Cetak, Terima, Tolak, Komentar, Buat diskusi grup, Hapus, dan Kembali ke formulir asli.
    - Pengurutan semua tombol:

      - Tombol umum ditampilkan lebih dahulu, dengan urutan tetap.
      - Tombol bawaan dan tombol kustom menyusul, sesuai urutan pengirimannya.

## Contoh langkah integrasi

### Langkah 1: Daftarkan callback tombol tindakan kustom

1. Daftarkan callback untuk tombol tindakan persetujuan kustom, seperti pada contoh berikut.

   ```json
   {
     // URL callback untuk mendapatkan data area tindakan (tombol) (rendering tombol)
     "name": "CUSTOM_ACTION_DEFINITION",
     "runType": "OUTBIZ_CUSTOM",
     "callback": {
       "apiKey": "getIntegratedCustomActionDefinitions",
       "appUuid": "dingecxxxx97fcb1e09",
       "version": "1"
     }
   },
   {
     // URL callback yang dipanggil saat tindakan persetujuan dilakukan (operasi persetujuan)
     "name": "CUSTOM_ACTION_APPLY",
     "runType": "OUTBIZ_CUSTOM",
     "callback": {
       "apiKey": "applxxxxction",
       "appUuid": "dingecxxxxb1e09",
       "version": "1"
     }
   }
   ```
2. Pusat Proses mendapatkan daftar tombol kustom untuk area tindakan persetujuan.

   - apiKey: getIntegratedCustomActionDefinitions
   - URL: https://connector.dingtalk.io/webhook/flow/d8c375d76acb7eb01019fe0b
   - Parameter: corpId,processInstanceId,activityId,taskId,operator,platform,locale,context,customData
   - apiSecret: getIntegratedCustomActionDefinitions

### Langkah 5: Perbarui status tugas persetujuan Pusat Proses

**Terima atau tolak tugas persetujuan dengan logika kustom:** Penyetuju membuka halaman persetujuan kustom di DingTalk dan memilih tindakan seperti Terima atau Tolak. DingTalk kemudian memanggil API callback yang dikonfigurasi pada modul `CUSTOM_ACTION_APPLY` di Simpan Templat Persetujuan Integrasi Eksternal Pusat Proses. Setelah Aplikasi pihak ketiga menjalankan logika bisnisnya, Aplikasi wajib menyinkronkan status tugas ke DingTalk. Untuk memperbarui status item To-Do persetujuannya, panggil API [Perbarui status tugas Pusat Proses](/id/open/development/update-process-center-task-status) dengan ID instans persetujuan `processInstanceId` dan ID tugas To-Do persetujuan `taskId`.

Dalam skenario seperti OR-sign, panggil API [Batalkan beberapa tugas tertunda Pusat Proses](/id/open/development/cancel-multiple-oa-approval-tasks). API ini mengubah semua item To-Do yang sedang berjalan dalam satu instans persetujuan menjadi CANCELED sekaligus.
