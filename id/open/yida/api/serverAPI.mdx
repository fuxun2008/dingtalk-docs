Selain Open API untuk panggilan sisi klien, platform YiDA juga menyediakan Open API yang mendukung panggilan sisi server. Untuk detailnya, lihat [dokumentasi DingTalk Open Platform](https://open.dingtalk.com/document/orgapp-server/yida-overview).

## Panduan Pengguna

Ikuti langkah-langkah berikut untuk menggunakan Open API sisi server YiDA:

<Tip>
DingTalk Open Platform menyediakan beberapa jenis Aplikasi, dan cara penggunaan Open API sisi server berbeda-beda menurut jenis Aplikasi. Untuk detailnya, lihat [Pengenalan Jenis Aplikasi DingTalk](https://open.dingtalk.com/document/orgapp/untitled-document-1689231271995).
</Tip>

### Langkah 1: Buat Aplikasi DingTalk

- Untuk membuat Aplikasi internal, lihat [Ikhtisar Proses Pengembangan Aplikasi Internal](https://open.dingtalk.com/document/orgapp/overview-of-development-process).
- Untuk membuat Aplikasi perusahaan pihak ketiga, lihat [Ikhtisar Aplikasi Perusahaan Pihak Ketiga](https://open.dingtalk.com/document/isvapp/isv-cooperation-guide).

### Langkah 2: Tambah Izin Panggilan API

Setelah Aplikasi dibuat, hanya API masuk (sign-in) dan notifikasi pesan yang aktif secara default. Tambahkan Izin API yang diperlukan sesuai kebutuhan pengembangan Anda.

- Untuk Aplikasi internal, lihat [Tambah Izin Panggilan API](/id/open/development/add-api-permission).
- Untuk Aplikasi perusahaan pihak ketiga, lihat [Tambah Izin Panggilan API](https://open.dingtalk.com/document/isvapp-server/add-interface-call-permissions?#topic-2149187).

### Langkah 3: Dapatkan access_token untuk Aplikasi

access_token berfungsi sebagai kredensial identitas. Saat memanggil API, gunakan access_token untuk mengautentikasi identitas pemanggil.

- Untuk Aplikasi internal, lihat [Dapatkan access token dari Aplikasi internal](https://open.dingtalk.com/document/orgapp-server/obtain-the-access_token-of-an-internal-app#topic-2056397).
- Untuk Aplikasi perusahaan pihak ketiga, lihat [Dapatkan access token dari perusahaan yang diotorisasi](https://open.dingtalk.com/document/isvapp-server/obtain-the-access_token-of-the-authorized-enterprise?#topic-2056409).
