Panduan ini menjelaskan cara berkontribusi pada **YiDA Pusat Pengembang**. Kami menyediakan dua cara untuk berkontribusi: Issue dan Pull Request.

## Issue

Kami menggunakan [GitHub Issues](https://github.com/dingtalk-yida/developer-site/issues) untuk melacak masalah dokumentasi di Pusat Pengembang. Jika Anda menemukan masalah pada dokumentasi, kirim issue menggunakan templat berikut. Kami meninjau kiriman secara berkala dan memperbarui dokumentasi sesuai kebutuhan:

```
- Document link: https://yida-developer.gitee.io/docs/api/yidaAPI
- Description: Deskripsi this.setState() tidak tepat—setState tidak mendukung fungsi callback.
- Suggested fix: Hapus penggunaan callback dari API setState.
```

Sebelum melaporkan issue, telusuri terlebih dahulu daftar issue yang ada untuk menghindari duplikasi.

## Pull Request

Kami menyarankan Anda berkontribusi melalui Pull Request untuk membantu meningkatkan YiDA Pusat Pengembang. Klik tombol **Edit halaman ini** di bagian bawah dokumen mana pun untuk mulai berkontribusi. Langkah-langkahnya sebagai berikut:

* Klik **Edit halaman ini** untuk membuka halaman GitHub (daftarkan akun GitHub terlebih dahulu jika Anda belum memilikinya).

* Fork repositori Pusat Pengembang ke ruang GitHub pribadi Anda (langkah ini hanya perlu dilakukan sekali; pengeditan berikutnya akan melewati langkah ini):

* Buka halaman pengeditan dokumen, lakukan perubahan, lalu kirim commit:

* Konfirmasi perubahan dan kirim Pull Request:

Itulah proses pengiriman Pull Request yang sederhana. Tim YiDA memantau semua Pull Request. Kami akan meninjau dan menggabungkan perubahan Anda, atau meminta Anda melakukan revisi maupun menjelaskan alasan suatu perubahan tidak dapat diterima. Kami merilis versi patch dari cabang master setiap minggu.

<Tip>
Anda juga dapat mem-fork repositori Pusat Pengembang ke lingkungan lokal, mengedit dokumen secara lokal, lalu mengirim Pull Request. Jika ini adalah Pull Request pertama Anda di GitHub, lihat artikel berikut:

[Cara Berkontribusi Kode di GitHub dengan Elegan](https://segmentfault.com/a/1190000000736629)

Cabang utama kami adalah master, jadi kirim Pull Request ke cabang master.
</Tip>

<Tip>
Saat mengirim konten dokumentasi baru, jelaskan secara singkat latar belakang dan kasus penggunaannya di dalam Pull Request Anda agar kami dapat meninjau dan menambahkannya secara efisien.
</Tip>

## Alur kerja pengembangan lokal

YiDA Pusat Pengembang dibangun dengan [Docusaurus 2](https://docusaurus.io/). Setelah meng-clone repositori Pusat Pengembang dan memasang dependensi dengan npm install, Anda dapat menjalankan perintah umum berikut:

### Menjalankan secara lokal

```
$ npm start
```

Setelah dijalankan, akses situs secara lokal di `http://localhost:3000/`.

> Catatan: Pencarian global tidak tersedia dalam mode pengembangan lokal.

### Build

```
$ npm run build
```

Hasil build ditulis ke direktori build.

### Pratinjau build Produksi secara lokal

```
$ npm run serve
```

Jalankan perintah ini hanya setelah `npm run build` selesai. Perintah ini memulai server statis lokal berbasis direktori build, yang dapat diakses di `http://localhost:3000/`. Perilakunya identik dengan Produksi dan mendukung pencarian global.
