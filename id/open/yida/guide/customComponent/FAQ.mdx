## 1. Tidak dapat menemukan fungsi Hapus

Selama masa beta, fungsi penghapusan tidak disediakan dan mungkin tetap belum tersedia bahkan setelah peluncuran resmi. Penghapusan menimbulkan masalah dependensi yang kompleks dan saat ini belum menjadi kebutuhan esensial. Pendekatannya akan serupa dengan [https://www.npmjs.com/](https://www.npmjs.com/).

## 3. Struktur komponen

Sebuah komponen terdiri dari tampilan (view) dan atribut. Di sisi consumer, Anda dapat mengubah atribut komponen agar komponen menampilkan tampilan yang berbeda.
Tampilan dapat dibagi lagi menjadi tampilan desain (design view) dan tampilan runtime. Pada umumnya, keduanya dapat digunakan kembali.

Di sisi producer, tampilan komponen dan atributnya perlu dibangun secara terpisah.

## 4. Apakah aplikasi dengan komponen kustom dapat didistribusikan ke organisasi lain dan dibuka secara normal?

Ya.
Setelah aplikasi dengan komponen kustom didistribusikan ke organisasi lain, organisasi tersebut dapat menggunakan komponen secara normal, tetapi tidak dapat memperbaruinya. Untuk memperbarui komponen, penyedia layanan perlu memasang ulang versi baru komponen di aplikasi terdistribusi melalui pemeliharaan jarak jauh. Jika komponen diabstraksi dengan baik, hal ini dapat sebagian mengatasi kebutuhan untuk memperbarui aplikasi setelah didistribusikan.

## 5. Bagaimana mengakses atribut komponen kustom di halaman?

Komponen kustom bekerja sama seperti Komponen dasar. Gunakan this.$('fieldId').get('propName') untuk memperoleh atribut komponen terkait.

## 6. Bagaimana memperbarui atribut komponen kustom di halaman?

Komponen kustom bekerja sama seperti Komponen dasar. Gunakan this.$('fieldId').set('propName', propValue) untuk memperbarui atribut komponen terkait.
Atau, gunakan metode pengikatan variabel Sumber Data.

## 7. Bagaimana mendapatkan komponen halaman di dalam komponen dan menghubungkannya dengan komponen lain di halaman?

Tambahkan atribut bertipe fungsi ke komponen kustom, yang berfungsi sebagai Callback peristiwa.
Di halaman, gunakan Callback peristiwa ini untuk terhubung dengan komponen lain di halaman.
Di dalam komponen, eksekusi Callback ini pada waktu yang tepat dengan memanggil this.props.xxx(), misalnya saat terjadi Peristiwa komponen atau di dalam DidMount komponen.
Tip: Atribut bertipe fungsi dapat memiliki nilai default dan dapat diatur menjadi tersembunyi.

## 8. Bagaimana menghapus komponen kustom?
Saat ini, penghapusan komponen belum didukung. Penghapusan menimbulkan masalah dependensi yang kompleks. Pendekatannya akan serupa dengan [https://www.npmjs.com/](https://www.npmjs.com/).

## 9. Bagaimana mencopot pemasangan komponen kustom?
Saat ini, pencopotan pemasangan komponen belum didukung karena akan memengaruhi aplikasi yang sudah ada. Fitur ini akan dipertimbangkan pada iterasi mendatang.

## 10. Apakah komponen kustom mendukung pemasangan paket NPM pihak ketiga?

Belum. Sebagai gantinya, gunakan pemuatan sumber daya CDN secara dinamis.

function loadScript(src, callback) {
  if (!src) {
    return;
  }
  const node = document.createElement('script');
  node.src = src;
  node.addEventListener('load', callback, false);
  document.head.appendChild(node);
}
function loadCss(url) {
  const linkElement = document.createElement('link');
  linkElement.rel = 'stylesheet';
  linkElement.href = url;
  document.body.appendChild(linkElement);

## 12. Bagaimana mengirim data pada formulir menggunakan komponen kustom?

A: Saat ini, komponen kustom YiDA tidak mendukung komponen formulir. Untuk mengirim data, isi komponen formulir yang sudah ada. Contohnya: deklarasikan sebuah atribut dengan pengidentifikasi unik, lewatkan pengidentifikasi unik formulir yang sudah ada saat menggunakannya, lalu isi kembali data yang diperlukan ke formulir yang sudah ada melalui Peristiwa di sisi komponen.

## 13. Deskripsi versi komponen

Komponen dibagi menjadi **versi pengembangan** dan **versi resmi**.
Penomoran versi komponen kustom YiDA mengikuti [semantic versioning](https://semver.org/lang/zh-CN/) dengan konvensi tambahan.

1. 0.1.0 adalah versi pengembangan default. Versi pengembangan dapat tetap tersinkronisasi dengan desainer komponen secara real-time untuk keperluan debugging.
1. 1.x.x adalah versi resmi setelah rilis, yang mengunci fungsionalitas versi saat ini untuk memastikan stabilitas penggunaan online. **Oleh karena itu, aplikasi produksi harus memasang versi resmi 1.x.x setelah dirilis.**
