"Knowledge Base" adalah platform manajemen pengetahuan perusahaan yang profesional dan efisien di dalam DingTalk Docs. Platform ini dapat digunakan untuk membangun pustaka pengetahuan perusahaan sekaligus mendukung kolaborasi dokumen internal organisasi. Pengoperasiannya sederhana dan praktis. Setelah Admin menambahkan pengguna, dokumen dapat langsung dibagikan ke banyak orang dan disinkronkan secara real-time. Seluruh konten hasil kolaborasi internal dapat dicatat di dalam Knowledge Base.

## 01 Peningkatan manajemen pengetahuan: kelola dokumen secara efisien, WYSIWYG

Pengelolaan dokumen perusahaan dan organisasi yang baik tidak hanya terbatas pada penyimpanan dan pengategorian pengetahuan, tetapi juga harus mencakup manajemen siklus hidup penuh dari produksi, sirkulasi, hingga konsumsi pengetahuan internal. Untuk mendukung manajemen pengetahuan yang efisien, kali ini kami menghadirkan tiga peningkatan fitur utama: **Manajemen dokumen, Tampilan Peta Pikiran, dan Templat tim**.

### 1. Manajemen dokumen: dari "Buku Pengetahuan" menjadi "Folder", pengelolaan dokumen jadi lebih mudah

Konsep "Folder" kini ditambahkan sehingga Anda dapat mengategorikan dokumen menggunakan folder. Anda juga dapat menampilkan semua dokumen dalam satu pohon direktori. Selain itu, tersedia pula fitur logo dan sampul Kustom sehingga setiap ruang dapat memiliki identitasnya sendiri.

### 2. Templat Knowledge Base: simpan dan kutip dengan satu klik untuk membantu tim membuat dokumen secara efisien

Untuk meningkatkan efisiensi dan standar penggunaan dokumen, Admin dapat menyimpan dokumen Rapat, proposal, dan laporan yang sering digunakan sebagai templat tim. Dengan begitu, pengguna Knowledge Base dapat menerapkan templat tim dengan satu klik dan menyusun dokumen secara efisien dan sesuai standar.

## 02 Peningkatan kelola izin: dokumen lebih aman, pengaturan izin lebih efisien

Mengelola dokumen internal tim dan organisasi secara aman merupakan kebutuhan inti pelanggan perusahaan. Kali ini Knowledge Base menghadirkan tiga peningkatan utama pada kelola izin: **pewarisan izin secara default, dokumen privat, dan watermark keamanan.**

### 1. Peningkatan efisiensi: subdokumen secara default memiliki izin yang sama dengan dokumen induk sehingga pemberian izin lebih efisien

| **Sebelum (Knowledge Base lama)** | **Sesudah (Knowledge Base ditingkatkan)** | **Contoh 🌰** |
| --- | --- | --- |
| Setiap subdokumen perlu diberi izin secara terpisah. Jika terdapat banyak subdokumen dalam satu folder, dibutuhkan banyak tindakan berulang | Setelah dokumen atau folder diberi izin, subdokumen secara default memiliki izin, dan tetap mendukung penyesuaian secara terpisah | Dulu, setiap kali menulis laporan mingguan, staf operasional harus menambahkan izin dokumen untuk atasannya. Kini cukup menambahkan izin satu kali pada folder laporan mingguan. |

Di Knowledge Base yang telah ditingkatkan, semua subdokumen secara default mewarisi izin dokumen induk. Artinya, ketika pengguna Knowledge Base memperoleh izin dokumen atau folder tingkat atas (kelola, edit, lihat, unduh), izin yang sesuai atas dokumen tingkat bawah pun otomatis diperoleh. Hal ini sangat meningkatkan efisiensi pemberian izin oleh Admin Knowledge Base.

### 2. Peningkatan fitur: kelola izin mendukung penambahan dan pengurangan sehingga dokumen penting tim dapat diatur agar hanya terlihat oleh orang tertentu

| **Sebelum (Knowledge Base lama)** | **Sesudah (Knowledge Base ditingkatkan)** | **Contoh 🌰** |
| --- | --- | --- |
| Pengaturan kelola izin dokumen di Knowledge Base hanya mendukung penambahan izin, tidak mendukung pengurangan, sehingga kelola izin dokumen kurang fleksibel | Izin dokumen dapat diatur secara fleksibel, ditambah atau dikurangi dengan bebas, dan dapat diatur agar hanya terlihat oleh orang tertentu | Ketika staf berpindah dari tim produk ke tim operasional, atasannya perlu menghapus sebagian Izin Lihat dokumen. Sebelumnya penghapusan tidak didukung; setelah ditingkatkan, izin dokumen dapat disesuaikan dan diperbarui secara fleksibel. |

Izin dokumen mendukung pengaturan mandiri; rentang izin pengguna pada satu dokumen dapat diubah dengan bebas (kecuali Admin). Meskipun izin Knowledge Base atau dokumen tingkat atas kemudian diubah, pengaturan izin dokumen tersebut tidak akan ikut berubah dan menjadi "dokumen privat" tim, sehingga meningkatkan manajemen keamanan informasi tim.

### 3. Peningkatan keamanan: watermark keamanan diperkuat hingga mencakup seluruh antarmuka Knowledge Base, perlindungan informasi lebih menyeluruh

| **Sebelum (Knowledge Base lama)** | **Sesudah (Knowledge Base ditingkatkan)** | **Contoh 🌰** |
| --- | --- | --- |
| Watermark keamanan lama hanya muncul di antarmuka konten dokumen, tidak mencakup struktur dokumen Knowledge Base maupun antarmuka informasi pengguna | Mencakup seluruh antarmuka Knowledge Base; pohon direktori dan antarmuka manajemen pengguna semuanya diberi watermark | Manajer penjualan biasa mencantumkan nama pelanggan pada nama dokumen agar mudah dicari. Setelah ditingkatkan, struktur dokumen dan informasi Knowledge Base dapat diberi watermark untuk melindungi keamanan informasi. |

"Watermark keamanan" dan "Larang salin" pada Knowledge Base lama tetap dipertahankan dalam peningkatan kali ini. Selain itu, kemampuan watermark diperkuat sehingga cakupannya meliputi seluruh antarmuka Knowledge Base. Dengan begitu, struktur dokumen dan informasi ruang ikut terlindungi watermark, sehingga tercapai perlindungan keamanan informasi yang menyeluruh.

## 03 Publikasi publik: membantu perusahaan mempublikasikan informasi ke luar secara aman dan efisien

Fitur **"Publikasi publik + Persetujuan"** di Knowledge Base membantu pengguna DingTalk membagikan dokumen ke kontak dan pelanggan di luar organisasi. Anda juga dapat membuat tautan dokumen untuk dipublikasikan ke luar sehingga konten dokumen dapat dilihat tanpa perlu masuk. Hal ini sangat meningkatkan efisiensi sirkulasi informasi perusahaan.

Bersamaan dengan itu, fitur inovatif **"Persetujuan atasan"** turut diluncurkan, menjadikannya produk dokumen pertama di dalam negeri yang mengembangkan dan menghadirkan fitur ini. Fitur ini tidak hanya menjamin kontrol keamanan konten, tetapi juga meningkatkan efisiensi tinjauan publikasi konten. Fitur ini menghadirkan pengalaman inovatif yang menjadi tonggak penting ketika pengguna membagikan dan mempublikasikan DingTalk Docs ke luar, sehingga "efisiensi" dan "keamanan" benar-benar terwujud sekaligus.

▲ Panduan penggunaan publikasi publik: masuk ke DingTalk Docs — pilih Knowledge Base — klik Bagikan

▲ Manajer departemen perusahaan dapat mengunggah petunjuk penggunaan perangkat beserta status perawatannya ke "Knowledge Base" untuk dipublikasikan ke luar, lalu membuat Kode QR dan menempelkannya pada perangkat. Jika ada masalah, pengguna dapat memindai kode di perangkat bengkel kapan saja untuk melihatnya; pembaruan konten harus melalui tinjauan atasan untuk mencegah kebocoran informasi.

▲ Membuat Panduan Pengguna produk untuk membantu pengguna memahami fitur produk dengan cepat. Gambar menunjukkan DingTalk resmi yang menggunakan DingTalk Docs dan kemampuan publikasi publik untuk membangun panduan bantuan penggunaan. Dengan mengaksesnya melalui browser, pengguna dapat melihat isi panduan dengan mudah dan praktis, tanpa memerlukan insinyur untuk membangun halaman.

## Bagaimana cara menggunakan Knowledge Base?

*   Akses di PC: Buka DingTalk — klik navigasi kiri untuk masuk ke "DingTalk Docs" — klik "Knowledge Base".

*   Perangkat seluler: Buka aplikasi DingTalk — menu "Lainnya" di bagian bawah — buka "Docs" — klik — "Knowledge Base" — klik — \[+\] untuk membuat baru.
