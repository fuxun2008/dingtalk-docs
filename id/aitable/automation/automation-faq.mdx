  <Accordion id="q1" title="Siapa yang dapat mengonfigurasi atau mengubah otomatisasi?">
    Pemilik, admin, atau editor AI Table (dengan izin lanjutan dinonaktifkan, atau dengan izin kelola-semua-tabel melalui izin lanjutan) dapat mengaktifkan atau mengubah otomatisasi. Jika seorang pengguna kehilangan izin ini, otomatisasi yang mereka aktifkan akan berhenti berjalan — pemilik, admin, atau editor dapat mengaktifkannya kembali.
  </Accordion>
  <Accordion id="q2" title={`Mengapa pemicu "Saat sebuah rekaman dibuat" tidak menyala?`}>
    **Catatan:** klik **Baru** untuk membuat baris kosong, dengan setiap bidang kosong. Jika sebuah tindakan hilir mereferensikan bidang non-sistem apa pun (yaitu selain Dibuat oleh, Terakhir diubah oleh, Waktu pembuatan, atau Waktu modifikasi terakhir) dari rekaman yang baru dibuat, nilainya sebenarnya kosong dan tindakan akan menghasilkan kesalahan.
  </Accordion>

    - Anda memiliki izin edit otomatisasi, tetapi izin lanjutan memblokir akses Anda ke kelola-semua-tabel.
    - Anda tidak berada di organisasi saat ini.
  </Accordion>

  <Accordion id="q6" title="Berapa batas jumlah run pada otomatisasi?">
    Lihat tautan di bawah untuk detailnya. Setelah batas bulanan tercapai, run berhenti dan dilanjutkan pada tanggal 1 bulan berikutnya pukul 0:00 GMT+0.

    [Model penagihan — DingTalk Open Platform](https://open.dingtalk.com/document/connector/connection-platform-billing-model#5adcd8504dk8w "Model penagihan — DingTalk Open Platform")

    **Tips penggunaan node connection-flow:**

    - Hapus node eksekusi yang tidak digunakan, atau gunakan cabang untuk menghindari panggilan yang tidak perlu.
    - Dalam perulangan, tambahkan pemeriksaan kondisi untuk melewati iterasi yang tidak diperlukan.
    - Gunakan langganan peringatan platform agar mendapat notifikasi saat terjadi kegagalan.
    - Nonaktifkan connection flow yang tidak valid untuk menghentikan pemborosan run.
  </Accordion>
  <Accordion id="q7" title="Bagaimana jumlah run otomatisasi dihitung?">
    **Dihitung**

    - Node tindakan yang berhasil — 1.
    - Panggilan node **Delay** — 1.
    - Panggilan node **HTTP request** — 1.
    - Node **Branch** — 1 per evaluasi.
    - Node **Loop** yang beriterasi dalam satu run alur kerja — sebuah loop dengan satu node yang beriterasi 200 kali dihitung sebagai 200.
    - Ketika sebuah kueri tidak mengembalikan apa pun, tetap dihitung sebagai run yang berhasil (mis. kueri direktori tanpa kecocokan tetap dihitung sebagai 1).

    **Tidak dihitung**

    - Eksekusi acara pemicu.
    - Node yang dilewati; node yang gagal.
    - Run debug.
  </Accordion>
  <Accordion id="q8" title="Bagaimana cara memeriksa jumlah run bulan ini?">
    Buka **Manajemen alur kerja** untuk melihat akumulasi run node organisasi pada bulan berjalan.
  </Accordion>
