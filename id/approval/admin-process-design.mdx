## 3. Tindakan dasar

Desain proses mencakup empat kategori tindakan dasar berikut:

| Tindakan dasar | Keterangan |
| --- | --- |
| Tambah node | Tambahkan node pengaju, pemberi persetujuan, penerima CC, pelaksana, dan lainnya ke dalam proses |
| Atur atribut node | Pilih tipe operator node, lalu selesaikan pengaturan sesuai tipe tersebut |
| Atur izin node | Sesuaikan izin tindakan setiap node terhadap Bidang formulir |
| Tambah cabang | Atur kondisi cabang dan konfigurasikan alur bertingkat berbasis kondisi |

### 1) Tambah node

Klik **+** untuk menambahkan pemberi persetujuan, penerima CC, pelaksana, cabang kondisional, dan lainnya.

<Frame>

![Klik tanda plus di desain proses untuk menambahkan node](https://img.alicdn.com/imgextra/i1/O1CN01rzDmSqUAZpF5bBcY_!!6000000001097-2-tps-2758-1732.png)
</Frame>

| Tipe node persetujuan | Penjelasan | Detail |
| --- | --- | --- |
| Pengaju | Node pengaju adalah titik awal proses persetujuan. Di node ini, Anda dapat mengonfigurasi siapa yang dapat mengirim Formulir persetujuan ini, Bidang mana yang dapat diisi pengaju saat mengisi formulir, dan lainnya | Node default<br />Nama node tidak dapat diubah<br />Setelah diajukan, dapat dilihat di kategori "Diajukan oleh saya" di Pusat Proses<br />Dapat mengatur izin tindakan atas Bidang formulir: dapat diedit, Hanya Baca, atau disembunyikan |
| Pemberi persetujuan | Dapat melakukan tindakan "Terima", "Tolak", "alihkan", "Kembalikan", "Tanda tangani permintaan" atas Formulir persetujuan | Node opsional<br />Nama node dapat diubah<br />Sebelum diproses, dapat dilihat di kategori "Perlu diproses" di Pusat Proses; setelah diproses, dapat dilihat di kategori "Diproses oleh saya"<br />Dapat mengatur izin tindakan atas Bidang formulir: dapat diedit, Hanya Baca, atau disembunyikan |
| Penerima CC | Saat proses mengalir ke node ini, tidak ada fungsi meninjau; penerima menerima Formulir persetujuan dan dapat melihat serta memberikan Komentar | Node opsional<br />Nama node dapat diubah<br />Setelah proses mengalir ke node ini, dapat dilihat di kategori "Di-CC ke saya" di Pusat Proses<br />Dapat mengatur izin lihat atas Bidang formulir: Hanya Baca atau disembunyikan |
| Pelaksana | Dapat melakukan tindakan "Kirim", "alihkan", "Kembalikan", "Tanda tangani permintaan", "Komentar" atas Formulir persetujuan | Node opsional<br />Nama node dapat diubah<br />Sebelum diproses, dapat dilihat di kategori "Perlu diproses" di Pusat Proses; setelah diproses, dapat dilihat di kategori "Diproses oleh saya"<br />Dapat mengatur izin tindakan atas Bidang formulir: dapat diedit, Hanya Baca, atau disembunyikan |
| cabang kondisional | Melalui node ini, kondisi berbeda dapat diarahkan ke cabang persetujuan berbeda<br />Detail operasi dapat dilihat di >>>[Cara mengatur persetujuan bersyarat](/id/approval/set-conditional-approval) | Node opsional<br />Nama cabang dapat diubah<br />Mendukung Salin cabang<br />Mendukung penambahan kondisi: antar kondisi merupakan hubungan "DAN"<br />Mendukung penambahan Grup kondisi: antar Grup kondisi merupakan hubungan "ATAU"<br />**Dijalankan berdasarkan prioritas secara berurutan**<br />Begitu satu aturan cabang berhasil dijalankan, cabang lain tidak akan dicoba lagi. **Hanya satu cabang kondisional yang dijalankan** |
| Cabang paralel | Memerlukan berlangganan berbayar. Melalui node ini, beberapa cabang persetujuan dapat berjalan secara bersamaan | Node opsional<br />Nama cabang dapat diubah<br />Mendukung Salin cabang<br />Mendukung penambahan kondisi: antar kondisi merupakan hubungan "DAN"<br />Mendukung penambahan Grup kondisi: antar Grup kondisi merupakan hubungan "ATAU"<br />Beberapa cabang dapat **berjalan bersamaan** sesuai aturan yang ditetapkan |
| Konektor | Memerlukan berlangganan berbayar. Melalui node ini, Konektor yang telah dikonfigurasi di "Integrasi Saya" dapat dipanggil | Node opsional |
| Otomatisasi | Memerlukan berlangganan berbayar. Melalui node ini, tugas Otomatisasi dapat dikonfigurasi | Node opsional |

### 2) Atur atribut node

#### 1. Pengaju

Pengaju adalah pemohon pekerjaan bisnis sekaligus titik awal proses persetujuan. Pengaju dapat mengisi konten formulir lalu mengirimkannya.

| Atribut | Keterangan |
| --- | --- |
| Tipe pengaju | Default adalah anggota di dalam Organisasi |
| Siapa yang dapat mengirim | Sinkron dengan "Siapa yang dapat mengajukan" di Pengaturan Dasar. Perubahan di sini juga akan otomatis memperbarui Pengaturan Dasar |

<Frame>

![Panel pengaturan atribut node pengaju](https://img.alicdn.com/imgextra/i1/O1CN01qxtcZQlYcRE5bwRq_!!6000000003621-2-tps-2764-1730.png)
</Frame>

#### 2. Pemberi persetujuan

Pemberi persetujuan adalah pihak yang meninjau dan menyetujui pekerjaan bisnis, serta dapat melakukan tindakan "Terima", "Tolak", "alihkan", "Kembalikan", "Tanda tangani permintaan" pada Formulir persetujuan.

**1) Pengaturan atribut pemberi persetujuan**

| Atribut | Keterangan |
| --- | --- |
| Nama node | Ditampilkan di halaman detail persetujuan sebagai nama node persetujuan bersangkutan; default adalah "Pemberi persetujuan"<br />Dapat diatur menjadi posisi terkait, misalnya "Direktur Keuangan", atau konten peninjauan spesifik, misalnya "Tinjauan Kepatuhan Kontrak" |
| Tipe persetujuan | Mendukung persetujuan manual, persetujuan otomatis, dan penolakan otomatis<br />Default adalah persetujuan manual<br />Persetujuan otomatis dan penolakan otomatis biasanya digunakan bersama cabang kondisional untuk mencapai persetujuan otomatis |
| Pemberi persetujuan node | Pemberi persetujuan node mendukung beberapa tipe untuk memenuhi berbagai kebutuhan alur persetujuan secara fleksibel |
| Metode persetujuan multi-orang | Ketika beberapa orang terlibat dalam satu node, mendukung persetujuan berurutan, tanda tangan bersama, tanda tangan salah satu, dan Voting<br />Persetujuan berurutan: beberapa orang menyetujui secara berurutan; persetujuan lolos hanya bila semua Terima<br />Tanda tangan bersama: beberapa orang menyetujui bersamaan; persetujuan lolos hanya bila semua Terima<br />Tanda tangan salah satu: beberapa orang menyetujui bersamaan; jika salah satu Terima, persetujuan lolos; jika salah satu Tolak, persetujuan tidak lolos<br />Voting: memerlukan berlangganan berbayar. Beberapa orang menyetujui bersamaan; persetujuan lolos jika jumlah yang Terima memenuhi syarat |
| Cara menangani pemberi persetujuan kosong | Ketika pemberi persetujuan diatur sebagai atasan, penanggung jawab Departemen, Peran, dan sejenisnya, pengaturan Kontak yang tidak lengkap dapat menyebabkan tidak ada Pengguna yang cocok. Anda perlu mengatur aturan alur saat pemberi persetujuan kosong<br />Persetujuan otomatis: jika node ini tidak menemukan pemberi persetujuan, Formulir persetujuan otomatis lolos<br />Penolakan otomatis: jika node ini tidak menemukan pemberi persetujuan, Formulir persetujuan otomatis ditolak<br />Alihkan otomatis ke Admin: default dialihkan ke Admin template; jika tidak ada Admin template, dialihkan ke Admin Persetujuan<br />Persetujuan oleh Pengguna yang ditentukan: ketika Peran atau atasan kosong, Formulir persetujuan otomatis dialihkan ke Pengguna yang ditentukan; maksimum satu orang |

#### 4. Pelaksana

Pelaksana adalah eksekutor spesifik pekerjaan bisnis, tanpa izin meninjau maupun menyetujui, dan dapat melakukan tindakan "Kirim", "alihkan", "Kembalikan", "Tanda tangani permintaan", "Komentar" pada Formulir persetujuan.

| Atribut | Keterangan |
| --- | --- |
| Nama node | Ditampilkan di halaman detail persetujuan sebagai nama node pelaksana; default adalah "Pelaksana"<br />Dapat diatur menjadi posisi terkait, misalnya "Kasir", atau tugas spesifik, misalnya "Pembubuhan Cap pada Kontrak" |
| Pelaksana node | Pelaksana node mendukung beberapa tipe untuk memenuhi berbagai kebutuhan alur pelaksana secara fleksibel |
| Metode pelaksanaan multi-orang | Ketika beberapa orang terlibat dalam satu node, mendukung pelaksanaan berurutan, semua orang mengerjakan bersamaan, atau satu orang saja yang menangani |
| Cara menangani pelaksana kosong | Ketika pelaksana diatur sebagai Peran atau atasan, pengaturan Kontak yang tidak lengkap dapat menyebabkan tidak ada Pengguna yang cocok. Anda perlu mengatur aturan alur saat pelaksana kosong<br />Persetujuan otomatis: jika node ini tidak menemukan pelaksana, node akan dilewati secara otomatis<br />Alihkan otomatis ke Admin: default dialihkan ke Admin template; jika tidak ada Admin template, dialihkan ke Admin Persetujuan<br />Pelaksanaan oleh Pengguna yang ditentukan: ketika Peran atau atasan kosong, dialihkan ke Pengguna yang ditentukan |

### 3) Atur izin tindakan node

Pada panel atribut node, beralih ke tab "**Izin tindakan formulir**" untuk mengatur izin tindakan node atas setiap Bidang di dalam formulir.

<Frame>

![Pengaturan izin tindakan formulir dalam atribut node](https://img.alicdn.com/imgextra/i3/O1CN01ZT9h8G4eFgB5cC3e_!!6000000005395-2-tps-2766-1732.png)
</Frame>

| Izin tindakan formulir | Penjelasan | Detail |
| --- | --- | --- |
| Dapat diedit | Dapat mengisi dan mengubah konten "dapat diedit" di dalam formulir | Mendukung node pengaju, pemberi persetujuan, dan pelaksana<br />Izin tindakan formulir default pengaju adalah dapat diedit |
| Hanya Baca | Hanya dapat melihat konten "Hanya Baca" di dalam formulir; tidak dapat mengisi atau mengubah | Mendukung node pengaju, pemberi persetujuan, pelaksana, dan penerima CC<br />Izin tindakan formulir default pemberi persetujuan, pelaksana, dan penerima CC adalah Hanya Baca<br />Ketika node pengaju diatur sebagai Hanya Baca, node saat ini tidak terlihat oleh pengaju |
| Sembunyikan | Tidak dapat melihat konten "sembunyi" di dalam formulir | Mendukung node pengaju, pemberi persetujuan, pelaksana, dan penerima CC |
