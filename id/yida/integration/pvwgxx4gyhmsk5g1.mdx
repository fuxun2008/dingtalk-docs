Jika konektor DingTalk resmi tidak memenuhi kebutuhan Anda dan Anda perlu segera menghubungkan aplikasi DingTalk, sistem internal, atau sistem pihak ketiga, buat konektor kustom melalui YiDA Connector Factory.

## Langkah 1: Buat konektor

<Steps>
  <Step title="Langkah 1">
    Masuk ke [YiDA workbench](https://www.yidaapps.com/workPlatform) sebagai admin.
  </Step>
  <Step title="Langkah 2">
    Klik tombol **Manajemen platform** di pojok kanan atas untuk membuka halaman manajemen platform.
  </Step>
  <Step title="Langkah 3">
    Pada menu di sisi kiri, klik **Connector Factory**, klik **Buat konektor**, lalu pilih HTTP Connector.
  </Step>
</Steps>

| **Tipe autentikasi** | **Deskripsi** |
|---|---|
| Tanpa autentikasi | Tidak memerlukan informasi verifikasi apa pun, dan API dapat langsung dipanggil. Umumnya digunakan untuk mengakses API publik. |
| Autentikasi dasar | Autentikasi dasar bergantung pada header permintaan Authorization dari permintaan HTTP. Header permintaan berisi kredensial yang digunakan server untuk memverifikasi identitas agen pengguna.<br />• **Format**: `Authorization: Basic <ciphertext>`.<br />Misalnya, tambahkan `Authorization: Basic YWxhZGRpbjpvcGVuc2VzYW1l` ke header, yaitu informasi akun dan kata sandi yang dienkode Base64.<br />Cukup konfigurasikan label prompt untuk akun dan kata sandi agar pengguna mengetahui apa yang harus diisi saat mendaftarkan informasi autentikasi.<br />Contoh:<br />• **label nama pengguna**<br />• **label kata sandi** |
| API key | Merujuk pada metode autentikasi **APIKey**. APIKey berlaku dalam jangka waktu long (simpan dengan aman). Pengunjung membuat kunci rahasia di sistem target, lalu developer dapat menggunakan kredensial ini untuk memanggil API publik yang mendukung tipe autentikasi ini.<br />• **Label parameter**: digunakan sebagai prompt saat mengonfigurasi informasi autentikasi.<br />• **Nama parameter**: nama apiKey yang dibutuhkan sistem.<br />• **Lokasi parameter**: pilih untuk menyertakan informasi autentikasi pada Parameter kueri atau header, sesuai kebutuhan sistem target. |
| Alibaba Cloud API Gateway | Setelah konektor dibuat, tambahkan templat autentikasi. Setelah App Code dimasukkan pada templat, Anda dapat memanggil API Alibaba Cloud yang sesuai.<br />Untuk informasi lebih lanjut, lihat [Call an API by using App Code authentication](https://help.aliyun.com/document_detail/115437.html). |
| Autentikasi DingTalk Open Platform | Setelah konektor dibuat, tambahkan templat autentikasi. Setelah `App Key` dan `App Secret` dimasukkan pada templat, Anda dapat memanggil API DingTalk Open Platform (termasuk sebagian API YiDA).<br />Setelah templat autentikasi ditambahkan, YiDA secara otomatis menghasilkan parameter autentikasi `access_token` dan menambahkannya ke parameter `x-acs-dingtalk-access-token` pada `Header` saat permintaan dikirim. Anda tidak perlu membuatnya lagi.<br />Untuk informasi lebih lanjut, lihat DingTalk app development process. |
| DingTalk Zero Trust Gateway | Untuk informasi tentang cara menggunakan DingTalk Zero Trust Gateway, lihat DingTalk Open Platform - Zero Trust Gateway authentication. |

## Langkah 2: Buat execute action

Pada halaman Execute Action, klik **Buat execute action**, lalu konfigurasikan tindakan sesuai penjelasan di bawah.

| **Nama** | **Deskripsi** |
|---|---|
| Informasi dasar | Konfigurasikan informasi dasar dari execute action saat ini.<br />• **Pengenal unik**: digunakan untuk membedakan tindakan yang berbeda.<br />• Nama tindakan: nama execute action.<br />• Deskripsi tindakan: deskripsi execute action. |
| Permintaan API | Konfigurasikan API yang akan dipanggil saat execute action ini dipicu.<br />• **URL permintaan**: tautan permintaan API. Domain permintaan otomatis terisi dengan domain konektor.<br />• **Metode HTTP**: mendukung GET, POST, DELETE, PUT, HEAD, OPTIONS, PATCH, dan metode lainnya.<br />• **Query**: parameter permintaan, biasanya parameter yang ditambahkan setelah tanda tanya `?` di URL. Klik tanda plus untuk menambahkan parameter baru.<br />• **Body**: untuk permintaan POST dan sejenisnya, bidang Body juga dapat disertakan. Mendukung parsing menggunakan JSON permintaan.<br />• **Headers**: header permintaan tambahan dapat dikustomisasi di sini. Saat ini hanya mendukung konfigurasi statis.<br />• **Path**: variabel yang diapit kurung kurawal dalam URL, seperti `{pathParam}`, di mana `pathParam` digunakan sebagai nama variabel.<br />**Catatan**: Parameter permintaan mendukung konfigurasi bidang sistem seperti ID pengguna yang masuk dan ID organisasi. |
| Respons API | Konfigurasikan respons yang diharapkan setelah API berhasil dipanggil. Mendukung parsing menggunakan JSON.<br />**Catatan**: Jika respons API bukan object JSON, respons tersebut tidak dapat langsung digunakan dalam integrasi & otomatisasi. Anda perlu menguraikannya secara manual pada node skrip. |

## Langkah 3: Konfigurasikan autentikasi

Semua konektor kustom memerlukan skema autentikasi permintaan yang sesuai, bahkan untuk "**Tanpa autentikasi**".

1. Buat akun

<Frame>
  ![](https://gw.alicdn.com/imgextra/i1/O1CN01HbUbFpqWghJ5pXJy_!!6000000001301-2-tps-2872-1626.png)
</Frame>

Untuk konektor yang telah dikonfigurasi, klik Uji, lalu Anda akan diminta memilih akun autentikasi. Anda juga dapat membuat akun autentikasi baru pada tahap ini.

2. Masukkan nama tampilan akun, App Key, App Secret, dan informasi lainnya, lalu klik Konfirmasi.
