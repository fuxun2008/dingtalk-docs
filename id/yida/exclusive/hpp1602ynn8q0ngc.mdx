YiDA Edisi Dedicated mendukung penyimpanan data bisnis YiDA dalam database cloud khusus di akun Alibaba Cloud pelanggan. Saat ini YiDA Dedicated mendukung database yang kompatibel dengan sintaks PostgreSQL.

Opsi yang direkomendasikan: Alibaba Cloud RDS PostgreSQL dan ADB PostgreSQL.

## Langkah konfigurasi

Buka YiDA [Workbench](https://www.yidaapps.com/workPlatform) > **Manajemen platform** > **Kustomisasi platform dedicated** > **Konfigurasi penyimpanan** untuk mengonfigurasi informasi penyimpanan database.

## Database bisnis utama

Setelah dikonfigurasi, data bisnis yang dikirimkan di YiDA akan otomatis membuat tabel dan indeks yang diperlukan, sehingga data formulir, alur kerja, dan data bisnis lainnya tersimpan dalam database ini. Sebaiknya gunakan database yang benar-benar baru dan hindari berbagi koneksi dengan sistem non-YiDA agar pemeliharaan data tetap konsisten.

- Alamat database cloud yang dapat diakses melalui internet publik: biasanya berupa nama domain ditambah nomor port.
- Nama database: sesuai dengan nama database.
- Tipe database: PostgreSQL. Alibaba Cloud RDS PostgreSQL direkomendasikan. Untuk performa yang lebih tinggi, pilih ADB (analitis) PostgreSQL.
- Akun: akun yang digunakan untuk mengakses database.
- Kata sandi: kata sandi yang digunakan untuk mengakses database.

## Database ekstensi

- Dengan otomatisasi yang memisahkan skenario pengiriman data (database bisnis utama) dari skenario kueri data (database ekstensi), desain ini menyediakan strategi sharding untuk beban tinggi dan menghadirkan performa kueri yang lebih cepat untuk pencarian bisnis, laporan BI, serta kasus penggunaan pencarian data lainnya.
- Untuk skenario kueri bervolume besar seperti Quick integration, pelanggan dapat memilih konfigurasi yang sesuai dengan kebutuhan aktual.

## Aktivasi sesuai kebutuhan (level aplikasi)

### 1. Aktivasi opsional saat membuat aplikasi baru

Saat membuat aplikasi baru, pilih apakah data bisnis aplikasi disimpan di public cloud (default) atau di database dedicated hybrid cloud (untuk data inti dan sensitif).

### 2. Aktivasi manual untuk aplikasi yang sudah ada

- Admin aplikasi dapat mengaktifkan penyimpanan dedicated di backend aplikasi melalui **Pengaturan aplikasi** > **Pengaturan dasar** > **Penyimpanan dedicated aplikasi**.
- Setelah diaktifkan, baik data yang sudah ada maupun data baru pada aplikasi akan disimpan dalam database dedicated (PostgreSQL) dan OSS lampiran dedicated yang dikonfigurasi di manajemen platform.

### 3. Konfigurasi global level platform

Admin platform dapat menerapkan kebijakan penyimpanan secara massal ke aplikasi yang baru dibuat melalui konfigurasi aplikasi global, sekaligus mengelola perilaku default aplikasi di seluruh organisasi.

- Menyederhanakan konfigurasi premium massal untuk aplikasi dan memastikan setiap aplikasi baru mengikuti kebijakan seluruh organisasi dengan pengaturan default yang konsisten.
- Memungkinkan admin menetapkan sekumpulan pengaturan operasi dasar yang diterapkan sebagai default ke setiap aplikasi yang dibuat di platform.

## Daftar tabel database

Berikut adalah tabel database inti utama. Untuk deskripsi field yang lebih detail, pelanggan yang sudah ada dapat menghubungi account manager untuk informasi lebih lanjut.

- odin_open_application_data: tabel data instans formulir (dibagikan oleh formulir dan laporan).
- tianshu_form_data_operation_log: tabel log aktivitas data formulir.
- tianshu_proc_inst_carbon: tabel penerima CC instans alur kerja.
- tianshu_data_form_version: tabel pemetaan data instans ke versi formulir.
- tianshu_form_data_stash: tabel cache formulir.
- tianshu_form_remark: fitur komentar.

- tianshu_instance_relation: tabel relasi instans formulir. Digunakan oleh penyimpanan YiDA Dedicated versi lama. Tidak digunakan lagi.
- yida_entity_instance: tabel data instans formulir. Digunakan oleh penyimpanan YiDA Dedicated versi lama. Tidak digunakan lagi.
- tianshu_form_data: tabel data formulir. Digunakan oleh penyimpanan YiDA Dedicated versi lama. Tidak digunakan lagi.
- ecds_xxxx: tabel sistem internal YiDA. Setiap tabel dengan prefiks ecds merupakan tabel runtime internal. Jangan lakukan operasi apa pun pada tabel tersebut.
- yida_app_data_xxx: tabel daftar fisik. Strukturnya sama dengan odin_open_application_data, tetapi field JSON diratakan. Setiap formulir memiliki tabelnya sendiri, dan sub-tabel juga merupakan tabel independen.

## FAQ

<AccordionGroup>
<Accordion title="T: Setelah mengaktifkan penyimpanan dedicated untuk aplikasi yang sudah ada, apakah data historis akan disinkronkan? Apa yang perlu diperhatikan?">
  - Data historis akan disinkronkan. Waktu sinkronisasi bergantung pada volume data aplikasi dan spesifikasi database: semakin besar volume data, semakin lama waktunya. Sinkronisasi selesai ketika indikator pemuatan pada tombol toggle berhenti.
  - Selama sinkronisasi, database membatasi penulisan. Cegah pengguna mengakses atau mengirimkan data di aplikasi selama sinkronisasi berlangsung untuk menghindari error atau data kotor.
</Accordion>
<Accordion title="T: Setelah mengonfigurasi penyimpanan object OSS milik organisasi sendiri, apakah masih ada batas atas untuk unggahan lampiran?">
  - Lampiran yang diunggah dalam aplikasi dengan penyimpanan dedicated aktif akan disimpan langsung di penyimpanan dedicated organisasi. (Kuota lampiran keseluruhan untuk aplikasi yang menggunakan penyimpanan public cloud tetap berlaku, tetapi lampiran yang disimpan di OSS dedicated tidak dihitung terhadap batas sisi platform.) Hal ini melindungi keamanan data organisasi, dan batas atas total lampiran untuk aplikasi yang menggunakan penyimpanan dedicated hanya dibatasi oleh kapasitas OSS organisasi.
</Accordion>
<Accordion title="T: Dengan penyimpanan dedicated aktif, data disimpan di database Alibaba Cloud atau OSS milik organisasi sendiri. Apakah platform YiDA akan mencadangkan data ini?">
  Tidak. Data bisnis disimpan langsung di ruang database atau OSS organisasi. YiDA tidak menyimpan atau mencadangkan data ini. Pelanggan bertanggung jawab menjaga keamanan data.
</Accordion>
<Accordion title="T: Apakah tabel tampilan disimpan dalam tabel data terpisah?">
  Tidak. Tabel tampilan tidak disimpan secara terpisah. Tabel tersebut dihitung sesuai kebutuhan dari tabel entitas dasar dan tidak melibatkan penyimpanan persisten. (Catatan: persiapan data melibatkan pemrosesan data terdistribusi, dan tabel perantara serta data yang telah diproses tetap disimpan di lingkungan cloud.)
</Accordion>

<Accordion title="T: Apakah biaya YiDA Dedicated mencakup biaya media penyimpanan dan operasinya?">
  - Biaya YiDA Dedicated hanya mencakup fungsionalitas produk YiDA itu sendiri. Biaya tersebut tidak mencakup biaya media penyimpanan atau operasinya. Platform hanya memerlukan layanan penyimpanan dedicated yang valid, andal, dan dapat diakses secara publik untuk dikonfigurasi.
  - Layanan YiDA Dedicated juga tidak mencakup implementasi dan pengiriman database atau OSS yang diperlukan untuk penyimpanan dedicated, operasi stabilitas DevOps berkelanjutan, operasi firewall dan jaringan, atau biaya penyimpanan dedicated itu sendiri.
  - Sebelum deployment, evaluasi kemampuan Anda untuk mengoperasikan penyimpanan dedicated secara andal. Sebaiknya penyimpanan dedicated dipelihara oleh profesional yang berkualifikasi di organisasi guna menghindari gangguan bisnis akibat masalah pada media atau lingkungan penyimpanan.
</Accordion>
<Accordion title="T: Bisakah saya memodifikasi data DB langsung di database?">
  - Penyimpanan dedicated dirancang untuk memenuhi persyaratan keamanan data dan kebutuhan analitik BI berskala besar. Saat menggunakan penyimpanan dedicated, Anda dapat melakukan kueri yang diperlukan pada data lokal. Namun, karena fitur platform saling terkait erat serta melibatkan sinkronisasi antar tabel dan cache sistem, platform sangat menyarankan untuk tidak memanipulasi data langsung di database.
  - Jika Anda perlu mengubah data, gunakan operasi resmi yang disediakan platform, seperti pengeditan manual, OpenAPI, integrasi & otomatisasi, Impor, dan pengeditan massal.
</Accordion>
