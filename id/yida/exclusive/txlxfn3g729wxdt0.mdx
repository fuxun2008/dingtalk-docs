Pada pembaruan produk V4.4.5 di bulan Oktober 2023, database **Dedicated Storage** YiDA mendapatkan peningkatan struktur penyimpanan yang ditujukan untuk Aplikasi yang baru dibuat dalam suatu Organisasi.

Penyimpanan data bisnis yang dikumpulkan melalui Formulir kini ditingkatkan dari mode JSON ke mode baris-kolom fisik data relasional yang lebih terstruktur. Dengan Aplikasi sebagai unit, kolom penyimpanan fisik menghadirkan arsitektur penyimpanan data yang lebih mudah diperluas dan dianalisis.

Untuk database dedicated storage Organisasi, setiap Formulir disediakan satu Tabel dasar fisik, dan setiap Bidang Komponen Formulir disediakan satu (atau lebih) kolom fisik. Hal ini memudahkan integrasi lebih lanjut atas data yang terakumulasi dari bisnis inovatif low-code ke dalam middle platform data dan data lake analitik Organisasi.

Untuk mengaktifkan fitur ini, hubungi account manager Anda.

## FAQ

**T: Dalam mode kolom fisik, setiap Komponen Formulir berkorespondensi dengan setidaknya satu (atau lebih) kolom fisik. Apakah ada batas maksimum jumlah Bidang?**

- Database mendukung hingga 1.000 Bidang kolumnar. Setelah Model dasar melampaui batas ini, penambahan Komponen baru ke Formulir akan diblokir dari penyimpanan.

**T: Jenis Tabel apa saja yang dicakup oleh peningkatan ini?**

- Data Formulir. YiDA mendukung berbagai jenis dataset; peningkatan ini mencakup data pengisian Formulir pada Formulir biasa maupun Formulir alur kerja.

**T: Apakah Aplikasi yang menggunakan mode penyimpanan kolom fisik dapat disalin?**

- Penyalinan didukung, tetapi penyimpanan data bisnis dari Aplikasi hasil salinan secara default menggunakan mode JSON. (Saat ini, hanya Aplikasi baru yang kosong yang mendukung mode kolom fisik. Kemampuan salin untuk Aplikasi yang sudah ada akan ditingkatkan secara bertahap.)

**T: Apa perbedaan antara Tabel `yida_entity_instance` dan `odin_open_application_data` pada database dedicated? Data suatu instans formulir muncul di kedua Tabel tersebut. Apa hubungan antara keduanya, dan dengan mekanisme apa data dijaga tetap sinkron?**

- `yida_entity_instance` menyimpan Konten detail data Formulir. Semua permintaan database yang melibatkan operasi data dalam Aplikasi ditangani oleh Tabel ini. `odin_open_application_data` digunakan untuk tampilan laporan; semua kueri dan agregasi laporan pada lapisan data ditangani oleh Tabel ini. Saat ini, kedua Tabel diperbarui secara bersamaan dan sebagian besar konsisten dalam hal penyimpanan data Formulir. Namun, `yida_entity_instance` berisi Bidang bisnis tambahan, seperti status alur kerja dan informasi Versi.
