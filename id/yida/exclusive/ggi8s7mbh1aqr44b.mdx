YiDA Dedicated mendukung tiga opsi penyimpanan object: Alibaba Cloud OSS, Huawei Cloud OBS, dan Inspur Cloud OSS.

## Konfigurasi produk

Di konsol admin YiDA, buka **Manajemen platform > Konfigurasi penyimpanan** untuk mengatur penyimpanan database dan penyimpanan file.

## Penyimpanan object file

**Tipe penyimpanan**: Pilih Alibaba Cloud OSS, Huawei Cloud OBS, atau Inspur Cloud OSS sesuai kebutuhan Organisasi Anda.

**Endpoint penyimpanan**: Secara default mengikuti format `bucket.endpoint`.

**AccessKey (AK)**: AccessKey yang diterbitkan oleh penyedia penyimpanan.

**SecretKey (SK)**: SecretKey yang diterbitkan oleh penyedia penyimpanan.

### Mode proxy jaringan DingTalk Dedicated

YiDA Dedicated dapat digunakan bersama mode jalur jaringan sewa DingTalk Dedicated. Melalui proxy jaringan yang dikustomisasi, OSS terhubung langsung ke penyimpanan pribadi Organisasi Anda sekaligus mewujudkan transmisi yang lebih aman pada lapisan jaringan.

### Pemeriksaan mandiri lingkungan Dedicated

- Sebelum menggunakan database dan penyimpanan object OSS secara resmi, jalankan uji ketersediaan.

## FAQ

<AccordionGroup>
<Accordion id="q1" title="T: Setelah mengonfigurasi penyimpanan object OSS file milik organisasi, apakah masih ada batas volume unggahan lampiran?">
  J:

  - Lampiran yang diunggah dari aplikasi dengan penyimpanan dedicated aktif langsung disimpan di penyimpanan dedicated organisasi. (Total volume lampiran untuk aplikasi yang menggunakan penyimpanan cloud tetap dibatasi, tetapi unggahan ke OSS dedicated dikecualikan dari perhitungan kuota di sisi platform.) Hal ini melindungi data organisasi. Total volume lampiran untuk aplikasi yang menggunakan penyimpanan dedicated hanya dibatasi oleh kapasitas OSS milik organisasi.
</Accordion>
<Accordion id="q2" title="T: Ketika penyimpanan dedicated diaktifkan dan data disimpan di database atau OSS Alibaba Cloud milik organisasi, apakah platform YiDA mencadangkan data ini?">
  Tidak. Data bisnis langsung disimpan di database atau ruang OSS milik organisasi. YiDA tidak menyimpan atau mencadangkan data ini. Pelanggan bertanggung jawab atas penyimpanan data secara aman.
</Accordion>
<Accordion id="q3" title="T: Apakah item konfigurasi OSS dedicated dapat diedit atau dihapus?">
  OSS menangani penyimpanan file bisnis yang penting. Penggantian media penyimpanan OSS setelah berhasil dikonfigurasi saat ini tidak didukung. Konfigurasikan OSS dedicated yang valid dengan hati-hati untuk menghindari ketidakkonsistenan sinkronisasi data akibat perubahan endpoint penyimpanan OSS yang sering.
</Accordion>
<Accordion id="q4" title="T: Setelah mengaktifkan OSS dedicated, mengapa unggahan lampiran mengembalikan error URL tidak valid?">
  J: Periksa apakah domain penyimpanan dedicated valid. Konfigurasi OSS dedicated hanya mendukung format `bucket + domain`. Menggunakan `bucket + IP` akan menyebabkan kegagalan unggah lampiran.
</Accordion>
