## **Ikhtisar fitur**

Setelah data dikirim melalui halaman proses YiDA, data tugas dihasilkan di pusat tugas, baik pada tingkat aplikasi maupun tingkat organisasi. Tugas dikategorikan berdasarkan status menjadi "Dibuat oleh saya", "Untuk diproses oleh saya", "Diproses oleh saya", dan "CC untuk saya". Seiring proses berjalan, data ini disimpan, diperbarui, dan dikueri oleh layanan YiDA.

Organisasi pada YiDA Edisi Dedicated dapat menggunakan fitur integrasi pesan tugas persetujuan perusahaan di Integration Center untuk menghubungkan layanan YiDA ke pusat tugas atau sistem tugas milik sendiri. Ketika proses Aplikasi menghasilkan atau memperbarui tugas, YiDA memanggil layanan Organisasi untuk mengirim (push) datanya.

Setelah Konektor terkonfigurasi, setiap tugas Persetujuan (semua tugas) dari setiap Aplikasi YiDA di dalam Organisasi otomatis dikirim ke alamat layanan terdaftar yang ditampilkan di bawah. Melalui Callback layanan terkait, Organisasi dapat memproses dan mengonsumsi Peristiwa Persetujuan YiDA secara selektif sesuai kebutuhan.

## **Cara menggunakan**

### **Prasyarat**

1. Organisasi menggunakan YiDA Edisi Dedicated.
2. Organisasi memiliki sistem layanan sendiri yang dapat mengekspos layanan berbasis HTTP untuk dipanggil YiDA.
3. Layanan memenuhi persyaratan Format Callback YiDA.
4. Layanan dapat diakses melalui jaringan.

### **Alur integrasi**

#### **Buat Konektor HTTP**

Buat Konektor HTTP di Organisasi target dan Konfigurasikan layanan yang akan dihubungkan, seperti ditampilkan di bawah:

Anda dapat membuat Konektor terpisah untuk setiap layanan antarmuka dengan satu Tindakan per Konektor, atau membuat beberapa Tindakan dalam satu Konektor untuk mewakili layanan antarmuka yang berbeda.

- Konfigurasikan lima Tindakan Konektor yang bersesuaian dengan pembuatan, penyelesaian, pembatalan, penghapusan, dan CC tugas Persetujuan. Serupa dengan Webhook, ketika Peristiwa ini terpicu, sistem YiDA otomatis melakukan Callback ke alamat terdaftar www.yourCorpService.com/xx-interface.

#### **Proses penandatanganan**

Tanda tangan antarmuka Callback layanan mengenkripsi Parameter permintaan menggunakan MD5. Hasil enkripsi diteruskan ke Penyedia layanan melalui parameter sign. systemToken Aplikasi YiDA diperlukan sebagai kunci penandatanganan.

1. Urutkan semua kunci Parameter permintaan menggunakan String.CASE_INSENSITIVE_ORDER.
2. Gabungkan nilai parameter yang bersesuaian sesuai urutan kunci untuk membentuk string yang akan dienkripsi.
3. Tambahkan systemToken ke string hasil langkah 2.
4. Enkripsi string dari langkah 3 dengan algoritma MD5 menggunakan set karakter UTF-8.

<Warning>
⚠️ Catatan: systemToken adalah App Secret. Temukan di Pengaturan Aplikasi > Deployment dan Operasi > App Secret.
</Warning>

## FAQ

**T: Setelah Integration Center dikonfigurasi, apakah berlaku untuk data historis?**

J: Tidak. Konfigurasi hanya berlaku untuk data baru.

**T: Jika layanan yang di-push oleh Integration Center mengembalikan Kesalahan karena kegagalan pada sistem pelanggan, apakah YiDA menyediakan cara untuk mengueri log terkait? Apakah tersedia Mekanisme coba-lagi cadangan saat push gagal?**

J: YiDA Integration Center digerakkan oleh Peristiwa. Saat ini tidak disediakan mekanisme cadangan, dan sistem belum menyertakan logika coba-lagi.
