**Fitur ini eksklusif untuk laporan Premium Data.**

Database Isolasi saat ini merupakan "database perluasan" yang **dirancang khusus untuk pelanggan yang telah mengaktifkan Premium Data Workbench Yida** (kapabilitas analisis Premium Data). Tujuannya adalah **menyinkronkan secara real-time dari database dedicated asli ke Database Isolasi ini** — Daftar Kolom fisik Formulir beserta Data instansinya dari Aplikasi di bawah suatu Organisasi yang telah ditingkatkan ke Database Isolasi (**Aplikasi harus terlebih dahulu mengaktifkan penyimpanan dedicated dan kapabilitas Kolom fisik**), sehingga berfungsi sebagai Sumber Data utama untuk kueri dan analisis Data pada Ruang Aplikasi tersebut, serta **mengurangi tekanan kueri pada database dedicated asli dan dampak performa pada bisnis penyimpanan dedicated asli Yida.**

#### Skenario Penerapan

Database Isolasi Data cocok untuk situasi berikut:

- Kebutuhan analisis Premium Data: Ketika Organisasi perlu melakukan kueri kompleks dan analisis Data, penggunaan Database Isolasi dapat meningkatkan efisiensi dan performa.
- Pemrosesan Data skala besar: Untuk Aplikasi dengan volume Data yang besar, Database Isolasi dapat mendistribusikan tekanan kueri secara efektif dan mencegah beban berlebih pada database asli.
- Optimalisasi pengalaman Pengguna: Dengan memindahkan tugas kueri dan analisis ke Database Isolasi, Pengguna dapat memperoleh kecepatan respons yang lebih cepat saat mengakses Aplikasi pada database asli.

#### Deskripsi Fitur

<Note>
1. Database Isolasi saat ini hanya tersedia secara eksklusif bagi pelanggan yang telah mengaktifkan Premium Data Workbench (kapabilitas analisis Premium Data).
2. Aplikasi hanya dapat ditingkatkan dengan kapabilitas Database Isolasi setelah konfigurasi Database Isolasi selesai di bawah penyimpanan dedicated Organisasi.
3. Peningkatan Aplikasi ke kapabilitas Database Isolasi serupa dengan Kolom fisik; keduanya memerlukan migrasi Data yang sudah ada, yang membutuhkan waktu.
4. Terdapat 3 tempat di mana Aplikasi dapat ditingkatkan ke Database Isolasi:

(1) Database Isolasi dapat dipilih saat Buat Aplikasi;

(2) Terdapat opsi peningkatan pada Pengaturan Aplikasi;

(3) Saat pertama kali masuk ke Premium Data Workbench, akan ditampilkan Tips untuk meningkatkan ke Database Isolasi.

5. Database Isolasi Organisasi saat ini mendukung PostgreSQL dan MySQL.
</Note>

#### FAQ

- T: Waktu migrasi Data - Berapa lama peningkatan Aplikasi ke Database Isolasi? J: Peningkatan ke Database Isolasi melibatkan migrasi Data yang sudah ada, dan waktunya bergantung pada volume Data. Disarankan untuk merencanakan lebih awal dan mengalokasikan Waktu yang cukup untuk migrasi.
- T: Pengalihan instansi database - Bagaimana cara mengubah Connection string, Tipe, atau nama database? J: Jika perlu mengubah informasi ini, dapat dilakukan melalui fitur pengalihan migrasi otomatis. Perhatikan bahwa setiap pengalihan memicu migrasi Data yang sudah ada, jadi harap perkirakan Waktu yang dibutuhkan terlebih dahulu.
- T: Perubahan username dan password - Bagaimana cara mengubah username dan password database? J: Saat ini perubahan username dan password secara langsung tidak didukung. Jika diperlukan, Buat nama database baru pada instansi database, ubah hanya nama database dan kata sandi akun, kemudian picu pengalihan migrasi otomatis. Jika perubahan mutlak diperlukan, hubungi dukungan teknis Yida.
- T: Dampak performa - Apakah Database Isolasi berdampak pada performa sistem? J: Tujuan utama Database Isolasi adalah mengurangi tekanan kueri pada database dedicated asli, dan secara teori tidak akan berdampak negatif pada performa sistem secara keseluruhan. Sebaliknya, hal ini membantu meningkatkan stabilitas dan kecepatan respons sistem.
