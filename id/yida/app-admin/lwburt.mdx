## Tipe penyimpanan Aplikasi berbeda

Tipe penyimpanan dasar Yida terus berkembang seiring waktu. Tipe penyimpanan yang lebih baru menawarkan performa lebih tinggi dan kemampuan parsing yang lebih kuat. Pada sebagian besar kasus, Aplikasi lama diupgrade secara otomatis ke penyimpanan baru. Namun, kombinasi tipe tertentu tidak dapat diupgrade secara otomatis, sehingga beberapa fitur untuk sementara tidak didukung.

## Beralih ke penyimpanan berperforma tinggi

Untuk meningkatkan performa laporan Yida dan mengatasi masalah timeout Permintaan yang dijelaskan di atas, batas maksimum asosiasi multi-Tabel pada Tabel Tampilan telah dinaikkan.

Modul Data terkait laporan Yida saat ini sedang dimigrasikan ke penyimpanan berperforma tinggi. Setelah migrasi, efisiensi kueri Data laporan akan meningkat beberapa kali lipat, dan kemampuan Tabel Tampilan juga akan ditingkatkan. Pada sebagian besar kasus, Pengguna diupgrade secara otomatis tanpa perlu melakukan Tindakan apa pun (termasuk pada Edisi Gratis).

Namun, upgrade otomatis tidak akan berlangsung jika Anda mengalami salah satu Kesalahan berikut.

### CASEWHEN ERROR

- argument of CASE/WHEN must be type boolean, not type integer
- CASE types text and integer cannot be matched

Penyebab: Tipe kondisi caseWhen tidak sesuai dengan Tipe yang diharapkan. Setelah upgrade ke penyimpanan berperforma tinggi, argumen setelah WHEN harus bertipe boolean.

Solusi: Sesuaikan Tipe argumen berdasarkan Pesan error.

### numeric ERROR

- invalid input syntax for type numeric: "750D"

Penyebab: Perhitungan mengandung karakter ilegal, yang tidak lagi didukung setelah upgrade ke penyimpanan berperforma tinggi.

Solusi: Gunakan Formula VAL() untuk mengonversi Teks menjadi Tipe Numerik.

### Math Formula ERROR

- function sum(text) does not exist
- function avg(text) does not exist

Penyebab: Nilai Teks tidak dapat dijumlahkan, dirata-ratakan, atau digunakan dalam operasi Numerik lainnya. Hal ini tidak lagi didukung setelah upgrade ke penyimpanan berperforma tinggi.

Solusi: Gunakan VAL untuk mengonversi nilai menjadi Angka sebelum melakukan penjumlahan.

### Logical Formula ERROR

- operator does not exist: boolean = integer

Penyebab: Formula mengandung operator kesetaraan. Hal ini tidak lagi didukung setelah upgrade ke penyimpanan berperforma tinggi.

Solusi: Tipe Data di kedua sisi tidak cocok. Ubah menjadi Tipe yang sama.
