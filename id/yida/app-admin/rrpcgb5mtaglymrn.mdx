Artikel ini membahas pertanyaan umum yang mungkin Anda temui saat menggunakan YiDA Data Factory.

<AccordionGroup>
<Accordion title="T: Apakah nama tabel database mendukung bahasa Mandarin dan Inggris?">
  - Hanya nama tabel dalam bahasa Inggris yang didukung.
</Accordion>
<Accordion title="T: Bagaimana cara mengatasi Error Sumber Data (daftar sebagian)?">
  | Pesan error | Solusi |
  |---|---|
  | data source validate failed.connectionInfo isn't correct | YiDA hanya mendukung jaringan publik. Jika database tidak mengekspos endpoint jaringan publik, YiDA tidak dapat mengaksesnya. |
  | ORA-00972: identifier is too long | Alias bidang terlalu panjang. Untuk database Oracle, pertahankan panjang alias maksimal 64 karakter sesuai standar kami. |
  | Saat Sumber Data mengambil data SQL Server dan laporan menggunakan agregasi, muncul Error "concat ws is not a recognized built-in function name". | Untuk mendukung `concat_ws`, tingkatkan versi ke SQL Server 2017 atau yang lebih baru. |
</Accordion>
</AccordionGroup>

### T: Saat membuat Sumber Data, muncul Error "Connection test timed out. Check the connection information and firewall, then try again"

- Saat mengintegrasikan Sumber Data dengan sistem Anda sendiri, pastikan database atau sistem tersebut dapat diakses melalui jaringan publik. Jika tidak, Error akan muncul.

### T: Saat menggunakan SQL Server (versi lebih lama dari 2012), muncul Error "xxx field is not a recognized built-in function name"

- Hal ini terjadi karena YiDA saat ini tidak kompatibel dengan SQL Server versi lebih lama dari 2012. Meskipun data terkadang dapat ditampilkan dengan benar, kami tidak menyarankan penggunaan versi tersebut.

### T: Aturan Pemicu antara pengiriman Formulir, impor massal (Pemicu saat pemilihan), Sumber Data OPEN API / Halaman, serta aturan Asosiasi bisnis atau Integrasi & Otomatisasi

| Tindakan | Dapat memicu aturan Asosiasi bisnis | Dapat memicu Integrasi & Otomatisasi |
|---|---|---|
| Pengiriman Formulir | ✅ | ✅ |
| Impor massal (Pemicu saat pemilihan) | ✅ | ✅ |
| OPEN API / Sumber Data Halaman | ✅ | ✅ |
| Aturan bisnis | ❌ | ❌ |
| Integrasi & Otomatisasi | ❌ | ❌ |

### T: Kapan dataset kehadiran akan tersedia?

J: Fitur ini ada dalam roadmap dan akan dipertimbangkan untuk perilisan pada iterasi mendatang.

### T: Mengapa saya tidak dapat melakukan Pratinjau Data terbaru dalam dataset resmi yang saya hubungkan?

J: Saat ini Anda perlu mengklik tombol Uji secara manual untuk Muat Ulang Data. Tombol Muat Ulang untuk Pratinjau Data akan ditambahkan kemudian.

### T: Apakah Data bersifat Real-Time atau diperbarui keesokan harinya?

J: Saat ini, hanya Data [Persetujuan OA] yang bersifat Real-Time. Metrik umum, daftar Karyawan, Smart HR (onboarding, transfer, promosi, pengunduran diri), dan dataset serupa diperbarui secara default pada pukul 00:00 keesokan harinya.

### T: Setelah Admin yang memiliki Izin Data untuk Aplikasi pihak pertama membuat dataset melalui Data Factory, bagaimana Izin Data dapat dikonfigurasi lebih lanjut?

J: Data yang diproses melalui Data Preparation menghasilkan dataset independen baru berdasarkan Izin Data dari penerbit terbaru. Izin baris dan Kolom default dataset ini bergantung pada Izin penerbit terakhir. Atas dasar ini, Anda dapat Konfigurasikan Izin dataset independen tersebut.

<Accordion title="T: Apakah ada masalah presisi saat menggunakan pembagian di Data Preparation?">
  Saat ini, konversi floating-point diperlukan. fungsi formula floating-point akan disediakan di masa mendatang.
</Accordion>
<Accordion title="T: Dataset tidak diperbarui setelah menambahkan Komponen baru?">
  Setelah menambahkan Komponen baru, klik Uji sekali lagi atau seret ulang dataset ke dalam untuk Perbarui.
</Accordion>
<Accordion title="T: Hasil pratinjau node Data Preparation tidak sesuai dengan hasil Hitung lokal?">
  Jumlah baris Data yang ditampilkan pada pratinjau Data di Data Preparation hanya bersifat referensi. Angka tersebut tidak dapat dijadikan dasar untuk menilai jumlah baris dataset output akhir, karena kemungkinan adanya caching akselerasi menengah.
</Accordion>
<Accordion title="T: Dalam kondisi apa modifikasi Tipe bidang pada node Data Preparation berlaku?">
  Misalnya, jika node terstruktur sebagai A - B - C, modifikasi Tipe bidang pada node A hanya memengaruhi node B dan C. Modifikasi Tipe bidang pada node B hanya memengaruhi node C.
</Accordion>
<Accordion title="T: Mengapa ID Bidang dari node output berubah?">
  Dalam penggunaan Harian, hindari tindakan Hapus atau Atur Ulang yang tidak dapat dibatalkan pada node operasi data.

  - Jika Konten node pemrosesan sebelumnya berubah (misalnya, mengandung bidang A dengan ID Bidang = xxx001), termasuk menghapus dan menambahkannya kembali, ID Bidang yang sepenuhnya baru akan dihasilkan secara dinamis untuk bidang berikutnya (sebagai ilustrasi, ID bidang A mungkin dibuat ulang secara acak menjadi yyy789). Hal ini menyebabkan konfigurasi ID node yang ada pada skenario konsumsi bisnis hilir seperti laporan dan dasbor menjadi Gagal.
</Accordion>
<Accordion title="T: Saat Data Preparation mengambil data kehadiran DingTalk, 'waktu check-in pertama dalam sehari' menampilkan null untuk beberapa Pengguna meskipun mereka memiliki catatan check-in. Mengapa?">
  Di YiDA, bidang yang diekspos "waktu check-in pertama" menggunakan format: `yyyy-MM-dd HH:mm:ss`.

  Aturan tampilan:

  - Jika Pengguna memiliki jadwal shift dan melakukan check-in untuk shift kerja pertama, waktu tersebut dicatat sebagai waktu check-in pertama dalam sehari.
  - Untuk formulir Persetujuan, catatan di luar kantor, cuti, check-in tambahan, dan kerja lapangan tidak dihitung.
  - Untuk catatan check-in, catatan kerja lapangan dan yang dimodifikasi Admin tidak dihitung.
</Accordion>
