Dokumen ini menjelaskan kondisi pemicu dan solusi Batas laju Yida Server API di DingTalk Open Platform.

## Kondisi pemicu

Untuk mencegah beban abnormal pada server Yida akibat kesalahan aplikasi, secara default setiap endpoint Yida Server API memiliki Batas laju yang berbeda sesuai kompleksitasnya (untuk detailnya, Kirim tautan dokumen API kepada tim dukungan teknis). Melampaui salah satu dimensi batas tersebut akan memicu Batas laju. Kode Kesalahan Respons yang umum: `failure.operation.requestTooFast`, `failure.operation.tooManyVisitors`.

- Batas QPS per Aplikasi: untuk setiap Aplikasi, Batas laju terpicu ketika Panggilan ke suatu endpoint melampaui frekuensi maksimum.
- Batas QPS per Organisasi: untuk setiap Organisasi, Batas laju terpicu ketika Panggilan ke suatu endpoint melampaui frekuensi maksimum.
- Batas QPS global per endpoint: karena kebijakan proteksi Keamanan endpoint Yida, Jumlah panggilan per detik dibatasi. Kesalahan Respons akan terpicu ketika seluruh Aplikasi Organisasi Yida secara bersama-sama memanggil suatu endpoint melebihi Jumlah panggilan per detik yang diizinkan.

Solusi

- Umum: karena jendela Batas laju QPS adalah 1 detik, saat mengalami Kesalahan Batas laju, program dapat tidur selama 1 detik, lalu Lanjutkan eksekusi.
- Strategi off-peak: untuk program yang memanggil Yida API secara terjadwal, hindari waktu puncak tepat pada jam bulat, misalnya jadwalkan eksekusi 10 menit setelah jam bulat.

## FAQ

<AccordionGroup>
<Accordion title="T: DingTalk Open Platform mengenakan biaya untuk Panggilan OpenAPI. Apakah endpoint terkait Yida dikenakan biaya ganda?">
  J: Tidak, tidak akan dikenakan biaya ganda. Rinciannya sebagai berikut:

  Panggilan business API terkait Yida terbagi menjadi 2 skenario penggunaan:

  1. Yida bertindak sebagai Aplikasi SaaS dan memanggil endpoint DingTalk melalui fitur yang telah diproduksi (yaitu Connector resmi Yida, misalnya mengambil Data absensi DingTalk). Panggilan ini tidak tunduk pada batasan kebijakan.
  2. Pelanggan telah membangun Aplikasi internal di DingTalk Open Platform dan langsung memanggil Konten dalam [daftar endpoint Yida] dari sistem eksternal mereka sendiri (misalnya, sistem pelanggan memanggil endpoint openAPI Yida untuk menyinkronkan Data Aplikasi yang dibangun di Yida ke sistem pelanggan). Panggilan ini mengikuti kebijakan terpadu DingTalk Open Platform.

  
</Accordion>
<Accordion title="T: Apakah Jumlah panggilan endpoint Yida mengonsumsi Jumlah panggilan DingTalk Open Platform?">
  J: Tidak, tidak mengonsumsi Jumlah panggilan DingTalk Open Platform, karena Panggilan business API terkait Yida tidak tunduk pada batasan [kebijakan](https://open.dingtalk.com/document/orgapp-server/descriptions-about-adjusting-limit-and-frequency-of-api-calls).

  1. Skenario 1: Yida bertindak sebagai Aplikasi SaaS dan memanggil endpoint DingTalk melalui fitur yang telah diproduksi (yaitu Connector resmi Yida, misalnya mengambil Data absensi DingTalk). Panggilan ini tidak tunduk pada batasan kebijakan.
</Accordion>
<Accordion title="T: Apakah batas QPS yang dipublikasikan DingTalk Open Platform juga berlaku untuk endpoint Yida?">
  J: Batas QPS yang dipublikasikan DingTalk Open Platform membedakan antara Aplikasi internal dan Aplikasi perusahaan pihak ketiga. Yida, sebagai Aplikasi perusahaan pihak ketiga, juga tunduk pada batas QPS tersebut. Untuk setiap endpoint DingTalk yang dipanggil Yida sendiri, frekuensi maksimumnya adalah 40 Panggilan/detik. Untuk detailnya, lihat [Batas laju](https://open.dingtalk.com/document/isvapp-server/invocation-frequency-limit-1).

  
</Accordion>
<Accordion title="T: Jika saya telah membeli DingTalk Edisi Professional dan Yida sekaligus, Standar Batas laju QPS mana yang berlaku?">
  J: Karena Panggilan business API terkait Yida tidak tunduk pada batasan [kebijakan](https://open.dingtalk.com/document/orgapp-server/descriptions-about-adjusting-limit-and-frequency-of-api-calls), Standar QPS tetap 40 Panggilan/detik sebagai frekuensi maksimum, terlepas dari edisi dasar DingTalk yang dibeli pelanggan Yida.

  1. Skenario 1: Yida bertindak sebagai Aplikasi SaaS dan memanggil endpoint DingTalk melalui fitur yang telah diproduksi (yaitu Connector resmi Yida, misalnya mengambil Data absensi DingTalk). Panggilan ini tidak tunduk pada batasan kebijakan.
</Accordion>
<Accordion title="T: Apakah Batas laju QPS Yida mendukung ekspansi kapasitas individual? Bagaimana penagihannya?">
  J: Selain Edisi Dedicated, saat ini pelanggan tidak dapat melakukan ekspansi kapasitas individual.
</Accordion>
