# Self-Built OA Approval: Third-Party Workflow and Page Integration

## Overview

### Background

Organizations often develop their own OA systems or purchase third-party ones. These systems usually have their own approval processes and pages. Employees must switch between multiple systems to handle approvals, which fragments their work and lowers efficiency. Connect your self-built approval process to the DingTalk OA Approval Center. Users can then open business system pages and approve directly in DingTalk, for a one-stop experience.

Organizations commonly face the following pain points:

- **Scattered approval entry points:** Employees handle approvals separately in multiple systems. DingTalk To-Do reminders do not cover approval tasks from self-built systems, so approvers can easily miss tasks.
- **Inconsistent approval experience:** Approval pages in self-built systems do not match the DingTalk style. Users must adapt to different interfaces, which increases the learning curve.
- **Low reach of To-Do notifications:** Self-built systems rely on email or SMS for approval notifications. These channels are slow and cannot use DingTalk Message push or the To-Do Center.
- **Siloed approval data:** Approval statuses and processing records are spread across systems. Managers cannot view approval progress in one place in DingTalk.

### Core Value

This solution connects third-party approval systems with in-app pages in DingTalk. It calls the Approval Process Center API on the DingTalk Open Platform to sync approval data in both directions.

- **Approval template sync:** Sync approval form templates from your self-built system to DingTalk. Users can view and manage third-party approval templates in the DingTalk OA Approval Admin Console.
- **Approval instance linkage:** When an approval starts in your self-built system, DingTalk automatically creates a matching approval instance. Users can view and act on it in the four lists of the DingTalk Approval Center: Pending, Processed, Initiated, and Received.
- **To-Do task push:** After approval node information syncs to DingTalk, DingTalk automatically generates To-Do tasks. These tasks use the unified DingTalk To-Do reminders and Message push.
- **Approval status write-back:** After users complete an approval in DingTalk, write the result (such as Accept or Decline) back to your self-built system to keep data consistent on both sides.

### Use Cases

This solution applies to the following typical business scenarios:

- **ERP procurement approval integration:** An employee submits a purchase request in the ERP system. The request syncs to DingTalk automatically. The approver completes the approval in DingTalk, and the result writes back to the ERP system to update the purchase order status.
- **HR leave approval linkage:** Leave requests from the HR system sync to DingTalk. Employees receive reminders in the DingTalk To-Do Center and handle them there. Approval results update the HR attendance module automatically.
- **Project management expense reimbursement integration:** The expense reimbursement process in the project management system connects to the DingTalk Approval Center. Project managers approve in DingTalk, and reimbursement data syncs back to the project budget module.
- **CRM contract approval collaboration:** The contract approval process in the CRM system syncs to DingTalk. The sales team completes multi-level approvals in DingTalk, and contract statuses update in the CRM system in real time.

## Implementation Guide

### Technical Architecture

This solution uses the following five core technical components to connect your self-built approval system with the DingTalk OA Approval Center:

- **Identity Authentication layer:** Based on the OAuth 2.0 protocol of the DingTalk Open Platform. It uses the App credential to obtain an access token, which provides unified identity verification for all API calls and ensures call security and legitimacy.
- **Approval template management layer:** Syncs self-built approval templates to the DingTalk OA Approval Center and obtains a globally unique template code as the identifier. It supports creating, updating, and deleting templates for unified cloud management of approval form structures.
- **Approval instance engine:** Creates approval instances in DingTalk and generates a unique instance identifier. It carries the specific approval business data, such as the applicant, approval Content, and Attachments, and supports full approval lifecycle management.
- **To-Do task sync layer:** Syncs approval tasks in batches to the DingTalk Process Center, generates task identifiers, and binds them to DingTalk Users. Approvers can view and handle approval tasks from multiple business systems in one DingTalk Task list.
- **Bidirectional status sync layer:** Syncs approval statuses in both directions. When a user completes an approval in DingTalk, the status writes back to the business system in real time. When the business system terminates or completes an approval, the DingTalk task status updates accordingly. This ensures data consistency on both sides.

### Prerequisites

- **App preparation**: Complete [App creation and configuration](/open/dingstart/create-application).
- **Permission requirements**: Hold DingTalk Organization Admin or Sub Admin permissions, and apply for the following API permissions:

  - `Workflow.Form.Write` (workflow template write permission)
  - `Workflow.Form.Read` (workflow template read permission), optional
  - `Workflow.Instance.Write` (workflow instance write permission)
  - `Workflow.Instance.Read` (workflow instance read permission)
  - `qyapi_aflow` (approval flow data management permission)
- **Development environment**: A Java development environment (JDK 1.6 or later) and the Maven build tool are installed.
- **SDK preparation**: Download the DingTalk Server-side SDK, which supports multiple languages such as Java, Python, and Go.

### Code Implementation

Step 1: Get the App credential information, including the client ID and Client Secret.

Step 2: Apply for API permissions for the approval-related APIs.

Step 3: Get the Access credential. See [Get the access token of an Internal app](/open/development/obtain-the-access-token-of-an-internal-app). When you call an API, the access token authenticates the caller's identity.

Step 4: Call the Server-side approval APIs.

1. Call the new Server API [Create or update an approval template](/open/development/create-orupdate-the-approval-template-new) to get the unique template code `processCode`.
2. If you did not save the `processCode`, call the [Get the template code](/open/development/obtain-the-template-code) API to retrieve it.
3. After the approval template is created, users can go to the DingTalk OA Approval Admin Console to view the third-party self-built Approval form templates, view or search template data, and export or delete template data.
4. Using the template code `processCode`, call the new Server API [Create an instance](/open/development/create-a-ticket-approval-instance) to initiate an approval instance and get the approval instance ID `processInstanceId`.
5. After the approval instance is created, users can also open the DingTalk OA Approval Center to view the four approval lists (Pending, Processed, Initiated, and Received), search approval instance data, and perform approvals.
6. Using the approval instance `processInstanceId` and the To-Do list `tasks`, call the [Create pending tasks in the Process Center](/open/development/create-pending-tasks-in-process-center) API. This syncs approval node information from the third-party system to DingTalk OA Approval, returns the taskId of each To-Do item, and generates the corresponding DingTalk To-Do task.
7. After the pending task is created, call the [Query OA approval tasks integrated through the Process Center](/open/development/query-oa-approval-tasks-integrated-through-process-center) API to query a user's running approval tasks.
8. Using the approval instance `processInstanceId` and the approval To-Do taskId, call the [Update the Process Center task status](/open/development/update-process-center-task-status) API to sync status updates of your self-built approval To-Do items. In scenarios such as OR-signing (any one approver can approve), call the [Cancel multiple pending tasks in the Process Center](/open/development/cancel-multiple-oa-approval-tasks) API to set all running To-Do items under the approval instance to CANCELED in batches.
9. Using the approval instance `processInstanceId`, the instance status `status`, the instance result `result`, and other parameters, call the [Update the instance status](/open/development/update-instance-status) or [Update instance statuses in batches](/open/development/self-owned-batch-update-of-instance-status) API to update instance statuses.
10. Finally, to clean up approval template data, call the [Delete a template](/open/development/self-owned-approval-deletion-template) API. This deletes the approval template created for your Organization, along with the instances and To-Do tasks created under it.

## Implementation Steps

### **Step 1: Get the App Credentials**

1. Sign in to the [DingTalk Developer Console](https://open-dev.dingtalk.io/).
2. Select the target App to open its details page.
3. Click **Basic Information** > **Credentials and Basic Information**.
4. Record the App's `Client ID` and `Client Secret`.

### Note

   Keep the `Client Secret` secure and never share it with third parties. Store it in environment variables or a key management system instead of hardcoding it.

### Step 2: Add API Permissions

1. On the App details page, click **Manage permissions**.
2. In the permission search box, enter the following permission identifiers and apply for them:

   - `Workflow.Form.Write` (workflow template write permission): Creates, updates, and deletes approval templates.
   - `Workflow.Form.Read` (workflow template read permission): Gets the template code. Optional.
   - `Workflow.Instance.Write` (workflow instance write permission): Creates approval instances and updates instance statuses.
   - `Workflow.Instance.Read` (workflow instance read permission): Queries approval tasks and instance information.
   - `qyapi_aflow` (approval flow data management permission): Manages Approval process data comprehensively.

<Note>
Different business scenarios may require different permission combinations. Apply based on your actual needs. For example, batch Import scenarios also require permissions for batch User operations.
</Note>

### Step 3: Get the Access Credential (Access Token)

Use the Client ID and Client Secret from Step 1 to get the App's Access credential. See [Get the access token of an Internal app](/open/development/obtain-the-access-token-of-an-internal-app).

**Best practices**:

- **Caching strategy**: The `accessToken` is valid for 2 hours. Cache it in memory or Redis, and refresh it proactively 5 minutes before it expires.
- **Concurrency control**: Prevent multiple threads from refreshing the token at the same time and causing a Conflict. Use a distributed lock.
- **Error retry**: Retry automatically on network fluctuations, up to 3 times, with increasing intervals (1s → 2s → 4s).

## FAQ

- **Q1: Which parameters are required when creating an approval template?**

  A: The Required parameters are:

  - `name`: The approval template name.
  - `formComponents`: The list of form components. It must contain at least one component.
  - Optional parameters include `description` (template description) and others.
- **Q2: How do I get the processCode?**

  A: Use either of the following methods:

  - After calling the Create or update an approval template API, get `result.processCode` from the response.
  - If you did not save the processCode, call the Get the template code API and query by template name.
- **Q3: What changes in DingTalk after I create a pending task?**

  A: After you create a pending task:

  1. The Approval form details page shows the Accept and Decline Buttons.
  2. The Process Center syncs the approval task as a DingTalk To-Do task.
  3. The approver sees the approval reminder in the DingTalk To-Do Center.
- **Q4: How do I sync To-Do task data?**

  A: Follow these steps:

  1. Call the Create pending tasks in the Process Center API to sync approval node information from the third-party system to DingTalk.
  2. Call the Query OA approval tasks API to confirm that the tasks synced correctly.
  3. When the approval status changes, call the Update the Process Center task status API to sync the latest status.
- **Q5: Which permissions do I need to apply for on the DingTalk Open Platform?**

  A: Apply for the following permissions to connect to the OA Approval Process Center:

  | **Permission Scope Code** | **Permission Scope Name** | **Description** |
  | --- | --- | --- |
  | Workflow.Form.Write | Workflow template write permission | Create, update, and delete approval templates |
  | Workflow.Instance.Write | Workflow instance write permission | Create approval instances and update instance statuses |
  | Workflow.Instance.Read | Workflow instance read permission | Query approval tasks and instance information |
  | qyapi_aflow | Approval flow data management permission | Manage Approval process data comprehensively |

  Different business scenarios may require different permission combinations. Apply based on your actual needs.
