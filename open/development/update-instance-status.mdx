Call this API to update the status of an OA Approval instance.

## API Call Description

For example, User A submits a To-Do task that has three handling levels: B1, B2, and B3. B1 has accepted the task. The task is now at B2, and B3 has not yet received it.

After you call this API, check the To-Do status in the DingTalk **Approval** console. The following table shows the status changes.

The console lists approval records under four tabs: **To-Handle**, **Processed**, **Initiated**, and **Received**. Each record shows its progress in the **Flow Status** column, for example, **Approved**.

In the approval flow above, setting the status to **COMPLETED** changes the approval flow as follows:

| Submitter/To-Do Handler | Before Update | After Update |
| --- | --- | --- |
| User A | Workbench > To-Do > Initiated, In approval | Workbench > To-Do > Initiated, Approved |
| Approval node B1 | Workbench > To-Do > Processed, Approved | Workbench > To-Do > Processed, Approved |
| Approval node B2 | No such To-Do task | No such To-Do task |
| Approval node B3 | No such To-Do task | No such To-Do task |

In the approval flow above, setting the status to **TERMINATED** changes the approval flow as follows:

| Submitter/To-Do Handler | Before Update | After Update |
| --- | --- | --- |
| User A | Workbench > To-Do > Initiated, In approval | Workbench > To-Do > Initiated, Undone |
| Approval node B1 | Workbench > To-Do > Processed, Approved | Workbench > To-Do > Processed, Undone |
| Approval node B2 | No such To-Do task | No such To-Do task |
| Approval node B3 | No such To-Do task | No such To-Do task |

## Request

### Basic Information

| Field | Value |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processCentres/instances |
| HTTP Method | PUT |
| Supported app types | appType-Internal app　appType-Third-party enterprise app |
| Required permissions | permission-Workflow.Instance.Write-Workflow instance write permission |

### Request Header

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Yes | The access credential for calling this API. Obtain it as follows:   - Internal app: Call the [Get the access token of an internal app](/open/development/obtain-the-access-token-of-an-internal-app) API. - Third-party enterprise app: Call the Get the access token of an organization authorized by a third-party app API. |

### Request Body

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| processInstanceId | String | Yes | The approval instance ID. Call the [Create an instance](/open/development/create-a-ticket-approval-instance) API to obtain the `processInstanceId` value. |
| status | String | Yes | The instance status.   - **COMPLETED**: Completes the approval flow. - **TERMINATED**: Terminates the approval flow. |
| result | String | Yes | The instance result:   - If the instance status is COMPLETED, set one of the following values.    - **agree**: Accept   - **refuse**: Decline - If the instance status is **TERMINATED**, this value is also required. Both agree and refuse undo the approval flow. |
| notifiers | Array | No | The list of CC recipient user IDs. Maximum: 30. |
| userId | String | Yes | The user ID of the CC recipient. Call the [Get the list of user IDs in a department](/open/development/query-the-list-of-department-userids) API to obtain it. |
