Call this API to batch update instance statuses.

## API Call Description

For example, User A submits a To-Do task that has three levels of handling nodes, with handlers B1, B2, and B3. B1 has accepted, the task is currently at B2, and B3 has not yet received the To-Do task.

After you call this API, query the To-Do status in the **Approval Center** by switching between the **Pending**, **Processed**, **Initiated**, and **Received** tabs. Each row lists **Title**, **Summary**, **Initiator**, **Start Time**, **Completion Time**, and **Process Status** (for example, **Approved**). The following tables describe the status changes.

In this example approval workflow, when the status is set to **COMPLETED**, the approval workflow statuses are as follows:

| Submitter/To-Do Handler | Before Update | After Update |
| --- | --- | --- |
| User A | Workbench > To-Do > Initiated, In approval | Workbench > To-Do > Initiated, Approved |
| Approval node B1 | Workbench > To-Do > Processed, Approved | Workbench > To-Do > Processed, Approved |
| Approval node B2 | No such To-Do task | No such To-Do task |
| Approval node B3 | No such To-Do task | No such To-Do task |

In this example approval workflow, when the status is set to **TERMINATED**, the approval workflow statuses are as follows:

| Submitter/To-Do Handler | Before Update | After Update |
| --- | --- | --- |
| User A | Workbench > To-Do > Initiated, In approval | Workbench > To-Do > Initiated, Undone |
| Approval node B1 | Workbench > To-Do > Processed, Approved | Workbench > To-Do > Processed, Undone |
| Approval node B2 | No such To-Do task | No such To-Do task |
| Approval node B3 | No such To-Do task | No such To-Do task |

### Basic Information

| Field | Value |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processCentres/instances/batch |
| HTTP Method | PUT |
| Supported app types | appType-Internal app　appType-Third-party enterprise app |
| Required permissions | permission-Workflow.Instance.Write-Workflow instance write permission |

### Request Header

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Yes | The access credential for calling this API. Obtain it as follows:   - Internal app: Call the [Get the access token of an internal app](/open/development/obtain-the-access-token-of-an-internal-app) API. - Third-party enterprise app: Call the API for getting the access token of an organization that has authorized the third-party app. |

### Request Body

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| updateProcessInstanceRequests | Array | No | The instance list. Maximum: 50. |
| processInstanceId | String | Yes | The instance ID. Call the [Create an instance](/open/development/create-a-ticket-approval-instance) API to obtain it. |
| status | String | Yes | The instance status.   - **COMPLETED**: Ends the approval workflow. - **TERMINATED**: Terminates the approval workflow. |
| result | String | Yes | The instance result.   - If the instance status is **COMPLETED**, set this parameter to one of the following values.    - **agree**: Accept   - **refuse**: Decline - If the instance status is **TERMINATED**, this parameter is required. Both agree and refuse undo the approval workflow. |
| notifiers | Array | No | The list of userIds of CC recipients. Maximum: 30. |
| userId | String | Yes | The userId of the CC recipient. |
