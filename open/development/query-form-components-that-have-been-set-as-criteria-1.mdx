Query the form components that are set as conditions.

## API Call Description

After a solution provider creates an approval template for an organization through the Create Approval Template API, the organization can configure the approval process in the Approval Admin Console. During configuration, form components can be set as process conditions. ISVs cannot update form components that are set as process conditions. Call this API to query which form components are set as process conditions.

## Request

### Basic Information

| Field | Value |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processes/conditions/components |
| HTTP Method | GET |
| Supported app types | appType-Third-party enterprise app |
| Required permissions | permission-Workflow.Form.Read-Workflow template read permission. |

### Request Header

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Yes | The access credential for calling this API. Obtain it by calling the API for getting the access token of an organization that has authorized a third-party app. |

### Query Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| processCode | String | Yes | The unique code of the approval process. Obtain it by calling the [Create or Update an Approval Form Template](/open/development/create-an-approval-form-template) API or from [OA Approval Overview - Glossary](/open/development/workflow-overview). |
| agentId | Long | No | The agentId of the app.   - For internal apps, obtain it on the app details page in the [Developer Console](https://open-dev.dingtalk.io/#/). - For third-party enterprise apps, obtain it by calling the API for getting organization authorization information. |

### Request Example

HTTP

```http
GET /v1.0/workflow/processes/conditions/components?processCode=PROC-xxx&agentId=10 HTTP/1.1
Host:api.dingtalk.io
x-acs-dingtalk-access-token:6d1bxxxx
Content-Type:application/json
```
