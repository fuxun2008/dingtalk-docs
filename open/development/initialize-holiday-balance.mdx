Call this API to initialize multiple regular leave balances for an employee.

## API Call Description

Compensatory leave types do not require initialization through this API. Overtime duration automatically converts to compensatory leave duration. Create leave rules in either of 2 ways: by calling an API, or through the official DingTalk Attendance app:

| Leave Rule Creation Method | Leave Type Updates Supported by This API |
| --- | --- |
| Leave types created by calling the [Add Leave Rules](/open/development/add-holiday-rules) API. | Supported |
| Leave types created in the Attendance app in the Admin Console.   - Created by default by the Attendance app system. - Created through the Attendance app backend. | Not supported |

## Request

| **Basic Information** | |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/topapi/attendance/vacation/quota/init |
| HTTP Method | POST |
| Supported App Types | appType-Internal app appType-Third-party enterprise app |
| Permission Requirements | permission-qyapi_holiday_manage-DingTalk leave management permission |

### Query Parameters

| Name | Type | Required | Example | Description |
| --- | --- | --- | --- | --- |
| access_token | String | Yes | bE74xxxx | The app credential used to call this API.   - For an Internal app, obtain it by calling the [Get the access_token of an Internal App](/open/development/obtain-orgapp-token) API. - For a Third-party enterprise app, obtain it by calling the API for getting the access_token of a third-party organization. |

### Request Body

| Name | Type | Required | Example | Description |
| --- | --- | --- | --- | --- |
| op_userid | String | Yes | manager1 | The user ID of an admin in your organization who has app permissions for **OA Approval**. |
| leave_quotas | LeaveQuotas | Yes |  | The leave balance records to initialize. |
| userid | String | Yes | zhangsan | The user ID of the employee. |
| end_time | Number | Yes | 1653851001000 | The end time of the quota validity period, as a timestamp in milliseconds. |
| start_time | Number | Yes | 1553851001000 | The start time of the quota validity period, as a timestamp in milliseconds. |
| leave_code | String | Yes | f84a282xxxx | The unique identifier of the leave type.  **Note**   - Initialization is supported for leave types added by calling the [Add Leave Rules](/open/development/add-holiday-rules) API. - Initialization is not supported for the organization's built-in leave types. |
| reason | String | No | Imported by admin | The reason for the action. |
| quota_num_per_day | Number | No | 100 | The total quota, calculated in days.  **Note**  When the leave type is calculated in days, this value must not be empty and is measured in hundredths of a day.  For example, 1000 = 10 days. |
| quota_num_per_hour | Number | No | 100 | The total quota, calculated in hours.  **Note**  When the leave type is calculated in hours, this value must not be empty and is measured in hundredths of an hour.  For example, 1000 = 10 hours. |
| quota_cycle | String | No | 2019 | The cycle that the quota applies to.  **Note**  The format must be "yyyy". |
