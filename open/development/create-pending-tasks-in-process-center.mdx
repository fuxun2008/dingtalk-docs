Call this API to create a To-Do task for an OA Approval.

## Request

### Basic Information

| Field | Value |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/v1.0/workflow/processCentres/tasks |
| HTTP Method | POST |
| Supported app types | appType-Internal app　appType-Third-party enterprise app |
| Permission required | permission-qyapi_aflow-Approval flow data management permission |

### Request Header

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| x-acs-dingtalk-access-token | String | Yes | The access credential for calling this API. Obtain it as follows:   - Internal app: Call the [Obtain the access token of an internal app](/open/development/obtain-the-access-token-of-an-internal-app) API. - Third-party enterprise app: Call the API for obtaining the access token of an organization that authorized a third-party app. |

### Request Body

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| processInstanceId | String | Yes | The ID of the OA Approval workflow instance. Call the [Create an instance](/open/development/create-a-ticket-approval-instance) API to obtain the `processInstanceId` value. |
| activityId | String | No | The ID of the custom approval node. This is a custom parameter with a maximum length of 256 characters. |
| tasks | Array | Yes | The task list. Maximum: 20 elements. |
| userId | String | No | The user ID. Call the [Get the list of user IDs in a department](/open/development/query-the-list-of-department-userids) API to obtain it. |
| url | String | No | The redirect URL of the To-Do item. Maximum length: 1,024 characters.  - The url in the approval instance creation API redirects to the Approval form in the DingTalk Approval app. - The url in this API redirects from the corresponding To-Do card on the DingTalk To-Do page. - The DingTalk To-Do page supports both mobile and PC clients. Make sure the page for the url passed to this API is compatible with both mobile and PC. |
| customData | String | No | Custom user data. It is returned through URL parameters on page redirection. Maximum length: 500 characters. |
| dueTimestamp | Long | No | The task due time, as a Unix timestamp in milliseconds. When set, the DingTalk To-Do center displays the due time of the approval task, supports sorting by due time, and supports filtering by tags such as Due Today and Overdue. |
| featureConfig | Object | No | The Process Center integration configuration. Configure, per task, the shortcut action button entry in To-Do items and Card notifications. |
| features | Array | No | The configuration list. |
| name | String | No | The name of the feature module that third parties can customize. Currently supported:   - **CUSTOM_SHORTCUT**: Shortcut action buttons in To-Do items and Card notifications |
| pcUrl | String | No | The third-party custom redirect link for PC. Maximum length: 1,024 characters. |
| mobileUrl | String | No | The third-party custom redirect link for mobile. Maximum length: 1,024 characters. |
| runType | String | No | The run mode.  When features.name is `CUSTOM_SHORTCUT`, the following values are supported:   - **ORIGIN**: Native mode. Opening the To-Do details page redirects to the official Approval details page. - **REDIRECT**: External redirect mode. Opening the To-Do details page redirects to the address configured in pcUrl or mobileUrl. |
| callback | Object | No | The gateway callback configuration. Required when shortcut action buttons are needed. External data APIs called back through the gateway must be registered as gateways in "Data Source Management". For details, see Create a Data Source. |
| appUuid | String | No | The gateway appUuid. Required when shortcut action buttons are needed.  Pass the organization ID of the Organization that owns the Data Source. |
| apiKey | String | No | The gateway apiKey. Required when the shortcut action button entry is needed. Obtain the `apiKey` from the Data Source you created.  - When the gateway calls back an external API, DingTalk returns parameters required for business processing to the ISV based on the business scenario. To parse these parameters after receiving the callback request, the ISV must configure the corresponding parameter keys when creating the Data Source.   For example, when a callback is configured for the TASK_EXECUTE task execution module (the Accept and Decline buttons on the details page), DingTalk returns the following fixed parameters: `&#123;"outResult":"agree","processInstanceId":"xxx","activityId":"xxx","corpId":"dingxxx","data":[],"remark":"Accept","title":"Asset requisition request submitted by xxx","taskId":111,"operator":"manager0001"&#125;`. - When creating the Data Source, the ISV must configure the keys to parse based on business needs: outResult,processInstanceId,activityId,corpId,remark,title,taskId,operator |
| version | String | No | The gateway API Version.  - Required when the shortcut action button entry is needed. - Default: 1. |
| config | String | No | The configuration of the feature module customized by the third party. Maximum length: 1,024 characters. |
