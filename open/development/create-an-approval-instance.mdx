Call this API to start an OA Approval instance. Suites such as Attendance & Leave, HR, Finance & Tax, Legal, and Business Travel do not support starting approval instances through this API.

## API Call Description

### Important Notice

To prevent invalid data from being passed to Open APIs, this API will apply stricter validation to incoming data.

- For single-select and multiselect controls, every option value passed in must exist in the configured option list.
- For internal contact controls, every userID passed in must belong to an active user of the current organization.
- For department controls, every department ID must be a valid department ID in the current organization.
- For related approval form controls, every instance ID passed in must be an existing approval instance ID in the current organization.

Approval forms started in violation of these rules may fail to start later once stricter form data validation takes effect.

### Use Cases

<Note>
After you start an approval instance, you cannot modify its information through the API.
</Note>

You can start an approval instance in 2 ways, depending on whether you specify approvers. Either set a new approval process or reuse the approval process configured in the approval admin console.

- Do not specify approvers, and reuse the approval process configured in the approval admin console. Note the following:

  - Both approvers and CC recipients reuse the users configured in the approval admin console.
  - All workflow designs supported in the approval admin console are supported, such as or-sign, countersign, conditional approval, and initiator-selected approvers.

    The approval template editor has four configuration steps: **Basic Settings** > **Form Design** > **Workflow Design** > **Advanced Settings**. In **Workflow Design**, build the flow from these node types: **initiator**, **approver** (for example, initiator-selected, countersign, or or-sign), conditional branches that route by field value (for example, amount ≥ 100 vs. < 100), and **CC recipient**.
- Specify approvers, and do not reuse the approval process configured in the OA admin console.

  - Advanced settings of the approval template are not supported. For example, Signature and form operation permissions are unavailable. An approval template's **Advanced Settings** (step 4) include the following process options, none of which apply when you assign approvers through this API: **Auto Deduplicate** (if an approver appears more than once in the flow, they approve only once and the rest pass automatically), **Auto Approve** (when the approver and initiator are the same person, the Approval passes automatically), **Allow Adding Approvers** (add temporary approvers to the form), **Approval Withdrawal** (the initiator can withdraw the form), **Time-Limited Approval**, **Signature**, **Approval Comments**, and **Allow Submitting on Behalf of Others**.
  - When you specify approvers, you cannot use this API to set approvers as initiator-selected.

### Instructions

Scenario 1: Do not specify approvers, and reuse the approval process configured in the approval admin console.

### Note

- Leave the approvers parameter empty. The approval process configured in the approval admin console is reused by default.
- The ccList and ccPosition parameters set through the API do not take effect. The CC recipients configured in the approval admin console are reused.

- Whether the approval process contains initiator-selected nodes leads to 2 cases.

  - With initiator-selected nodes: call the [Get Node Information in an Approval Form Process](/open/development/approval-process-prediction) API. The isTargetSelect value of every returned node is true.

### Note

  When calling this API to start the approval instance, leave both approvers and targetSelectActioners empty.

  - Without initiator-selected nodes: call the [Get Node Information in an Approval Form Process](/open/development/approval-process-prediction) API. Some returned nodes have an isTargetSelect value of false.

### Note

  When calling this API to start the approval instance, leave approvers empty and pass targetSelectActioners to specify the information for the initiator-selected nodes.

Scenario 2: Specify approvers, and do not reuse the approval process configured in the OA admin console. Use the approvers parameter to specify new approvers.
