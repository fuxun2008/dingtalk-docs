This topic covers the OA Approval product, its open APIs, how to integrate OA Approval capabilities, and approval use cases.

## What Is OA Approval

OA Approval (Smart Workflow) is an official DingTalk app for organizations. Use it to quickly set up approval processes, such as leave requests and business trips. The OA Approval APIs let you perform actions on approval instances and other resources, which connects your organization's existing business systems with DingTalk OA Approval. For more features, see [DingTalk User Guide - OA Approval](https://alidocs.dingtalk.io/i/p/Y7kmbokZp3pgGLq2/docs/lo1YvX0prG98keM3X7aqVPw7xzbmLdEZ).

The following app types support OA Approval integration:

- Internal app
- Third-party enterprise app

## Glossary

### Approval Form

An approval form is a predefined template that can contain multiple form controls. When an employee fills in and submits the form, an approval instance is generated. DingTalk also provides a set of general approval forms, such as leave requests and business trips. Click **Create New Form** to use them directly. Admins can view all approval forms in the [OA Approval Admin Console](https://aflow.dingtalk.io/dingtalk/web/query/dashboard?dinghash=aflowSetting#/aflowSetting).

Click **Create New Form** to open a dialog with two form types: **Process Form** (for scenarios that need approval) and **Data Form** (for data collection without approval). Use one of three tabs to start from a template: **Use Classic Template**, **Other App Templates**, or **Copy Existing Template**. Built-in classic templates include leave request, shift swap, overtime, business trip, outing, recruitment request, performance self-review, transfer request, vehicle request, item requisition, and general approval.

### Approval Form Controls

DingTalk provides a wide range of approval form controls for quickly customizing approval forms. Create a new approval form or edit an existing one, then click **Form Design** to add or modify controls. The following describes the controls in the leave request form.

The approval form builder has four steps: **Basic Settings** > **Form Design** > **Process Design** > **Advanced Settings**. Under **Form Design**, open the **Control library** to add or modify controls, grouped as follows:

| Group | Controls |
| --- | --- |
| Layout | Columns |
| Basic | Single-line text, Multi-line text, Number, Radio, Checkbox, Date, Date range, Description text, ID card, Phone |
| Enhanced | Cascade/Category, Image, Detail/Table, Amount, Attachment, Handwritten signature, External contact, Contact |

The default leave request form contains the fields **Leave type**, **Start time**, **End time**, **Duration**, **Leave reason**, and **Image**.

### Approval Process

Design approval processes based on your needs, for example, by setting approvers and approval conditions.

Configure the Approval process through a four-step wizard: **Basic Settings** > **Form Design** > **Process Design** > **Advanced Settings**. On the **Process Design** canvas, add nodes between the **Initiator** and the end of the process. The available node types are:

| Node Type | Purpose |
| --- | --- |
| **Approver** | A person who approves the request |
| **CC Recipient** | A person notified of the request |
| **Action** | An assignee who handles a task |
| **Conditional Branch** | Routes the flow based on conditions |

Set the handler for each node, for example, **Initiator-selected**.

### Approval Instance

When a user in an organization initiates an approval, an approval instance is generated. Each approval instance contains data such as the form data the user entered at initiation, the approvers, and the approvers' Activity log.

### Approval Step

An Approval process can have multiple approval steps. Each step is configured with one or more approvers. Depending on the approvers of a step, there are two cases:

- **A single approval step has only one approver.** When the approver accepts or declines at this step, the step ends immediately and the approval automatically proceeds to the next level.
- **A single approval step has multiple approvers.** Each approver corresponds to one approval task. Depending on how the approvers approve, there are three cases:

  - **Sequential approval**: After one approver completes processing, the approval task is automatically sent to the next approver in order.
  - **Joint approval (all must approve)**: The process moves to the next step only after all approvers at the current step approve. Otherwise, the process is declined.
  - **Any-one approval**: Only one approver at the current step needs to take action, and the current step ends immediately.

### Approval Task

An approval step can generate one or more approval tasks. Each approval task identifies the approver. After receiving the task, the approver can accept, decline, or take other actions.

The unique code of an approval form. Find it at the bottom of the **Basic Settings** page in the approval form editor.
