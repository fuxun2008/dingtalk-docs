## Create and Configure a Message Template

1. Sign in to the [Developer Console](https://open-dev.dingtalk.com/?version=5.86.5#/appMgr/provider/eapp/57406/2).
2. Click **App Development**, select **Third-party enterprise app**, and create a mini program or an H5 micro app.
3. On the app details page, click **Message Push**. In the message template management area, click **Add**.

4. Select a template type and click **Create**.

5. Configure the message template and click **Save**.

   **Note**

   If template parameters are configured in the template, the template parameters are loaded automatically below, and you can then configure the descriptions of the dynamic parameters.

   Some values in the message content change dynamically, such as the order number, mobile number, and product name. These values cannot be determined when you set up the template, so you can use template parameters to replace them.
6. Click **Test**, then click **Send Test Message** to verify that the message template is configured correctly.

## Configure a Markdown Template

The Markdown template uses Markdown syntax to configure and send messages, which is suitable for pure notification messages that require no action.

With the Markdown template, you can easily support display formats such as text, images, and links.

**Description of the Markdown Message Template Configuration**

| Configuration | Supports Template Parameters | Description |
| --- | --- | --- |
| **Template Name** | No | Specifies the template name. You can name it based on the use case and type of the template, for example, New Ticket Notification Template. |
| **Use Case** | No | Describes the use case of the template. |
| **Image** | No | The image in the message, in the format of an image link or a media_id. Configured separately through this configuration item, a single message supports only one image. The image is pinned to the top. |
| **Message Title** | No | The title of the message and the content displayed on the first screen of the chat. |
| **Message Content** | Yes | The message content in Markdown format. We recommend keeping it within 1,000 characters. For the supported Markdown syntax, see the following table. **Note** - The Markdown syntax of the message template does not support titles, that is, the title format "# + title text" is not supported. Enter the message title separately in the title input box. Only first-level titles are supported. - The Markdown syntax of the message template does not support images, that is, the "" format is not supported. Enter the message image separately in the image input box. A single message supports only one image. |

**Markdown Syntax**:

```
Quote
> A man who stands for nothing will fall for anything.
 
Bold and Italic
**bold**
*italic*
 
Link
[this is a link](http://name.com)
 
Bulleted List
- item1
- item2
 
Numbered List
1. item1
2. item2

Line Break
 Simply show a line break in the input box. \n is not supported.
```

## ActionCard Template

The ActionCard template sends messages using the ActionCard message type. It supports messages that combine content with action points, which is suitable for scenarios where a message needs to be processed quickly through one or more action points.

The ActionCard template builds on the Markdown template and supports both overall redirect and independent redirect styles.

**Description of the ActionCard Template Configuration**

| Configuration | Supports Template Parameters | Description |
| --- | --- | --- |
| **Template Name** | No | Specifies the template name. You can name it based on the use case and type of the template, for example, New Ticket Notification Template. |
| **Use Case** | No | Describes the use case of the template. |
| **Image** | No | The image in the message, in the format of an image link or a media_id. Configured separately through this configuration item, a single message supports only one image. |
| **Message Title** | No | The title of the message and the text displayed in the chat list and notifications, up to 64 characters. |
| **Message Content** | Yes | The message content in Markdown format. We recommend keeping it within 1,000 characters. For the supported Markdown syntax, see the following table. **Note** - The Markdown syntax of the message template does not support titles, that is, the title format "# + title text" is not supported. Enter the message title separately in the **Title** input box. Only first-level titles are supported. - The Markdown syntax of the message template does not support images, that is, the "" format is not supported. Enter the message image separately in the **Image** input box. A single message supports only one image. |
| **Action Point** | Yes | Card messages support the overall redirect ActionCard style and the independent redirect ActionCard style: - The overall redirect ActionCard style supports one clickable Action. Passing in a single configuration results in the overall redirect style. - The independent redirect ActionCard style supports multiple clickable Actions. Passing in multiple configurations results in the independent redirect style. |
| **Action Point Link** | Yes | The link address that the message redirects to when clicked. When the message is sent as a mini program, mini program redirect links are supported, up to 500 characters. |
| **Action Point Title** | Yes | The title of the redirect button, up to 20 characters. |

## Form Template

The Form template sends messages based on the OA message type. It is suitable for displaying messages such as orders and supports redirecting to view message details.

**Description of the Form Message Template Configuration**

| Configuration | Supports Template Parameters | Description |
| --- | --- | --- |
| **Template Name** | No | Specifies the template name. You can name it based on the use case and type of the template, for example, New Ticket Notification Template. |
| **Use Case** | No | Describes the use case of the template. |
| **Message Box Header Content** | Yes | The header title of the message, limited to a maximum of 10 characters. This takes effect when sending to a regular chat. When sending to an organization chat, it is replaced with the name of the micro app. |
| **Message Box Header Background Color** | Yes | The background color of the message header. The length is limited to 8 English characters, where the first 2 represent transparency and the last 6 represent the color value. Do not add 0x. For example: FFBBBBBB |
| **Message Title** | No | The title of the message body. We recommend keeping it within 50 characters. |
| **Message Content** | Yes | The content of the message body, displaying up to 3 lines. |
| **Image in the Message Body** | No | The image in the message, in the format of an image link or a media_id. Configured separately through this configuration item, a single message supports only one image. |
| **Form Content** | Yes (title and variable value) | The form of the message body, displaying up to 6 items. The left and right input boxes represent the key of the message body and the value corresponding to the key, respectively. |
| **Mobile Link** | Yes | The link address that the message redirects to when clicked. When the message is sent as a mini program, mini program redirect links are supported. |
| **PC Link** | Yes | The address to redirect to when the message is clicked on a PC. |

## Configure Template Parameters

Some values in the message content change dynamically, such as the order number, mobile number, and product name. These values cannot be determined when you set up the template, so you can use template parameters to replace them.

When sending Work Notifications, pass in the actual values to replace the template parameters. Template parameters are not required, and you can configure them based on your actual needs.

**Format of Template Parameters**

Template parameters use the format `${parameter name}`. Parameters must conform to the following rules.

- Must start with a letter or an underscore.
- The remaining part after the beginning can consist of letters, underscores, and numbers.
- We recommend not setting too many dynamic parameters in a single message. We recommend no more than 5.

For example, if the message content is:

```
The product ${product} you follow is now in stock. Hurry up and grab it!
```

Here, `${product}` is the template parameter, with the parameter name `product`. Pass in the value of this parameter when sending the message. For example, pass in `product` as "Disposable Mask" when sending the message. Then "Disposable Mask" replaces the $&#123;product&#125; template parameter, and the message content that the end user receives is:

```
The product Disposable Mask you follow is now in stock. Hurry up and grab it!
```

A message template can be configured with several template parameters, or with none. Set them based on your actual needs.

**ID Translation**

When passing in dynamic parameters, ID translation is supported. Currently, converting a department ID to a department name and a userId to a username is supported.

The ID translation syntax is as follows:

```
$departmentName=DEPARTMENT_ID$
$userName=USERID$
```

Where:

- DEPARTMENT_ID is the numeric department ID.
- USERID is the user's user ID.

For example:

- Replace $departmentName=100$ with the department name corresponding to the department ID "100", such as "DingTalk Open Platform".
- Replace $userName=zhangsan01$ with the username corresponding to the user ID "zhangsan01", such as "John".

## Submit for Review

After creating a message template, click **Submit** to submit the template for review.

## Enable a Template

After the template passes the review, it is enabled automatically. When a message template is enabled, you can send template messages by calling the API. For details, see [Use a Template to Send Work Notifications](/zh/open/development/work-notification-templating-send-notification-interface).

## Disable a Template

When you no longer need a template, turn off the enable button to stop using it.

## Delete a Template

Click **Delete** to delete a template.

## Clone a Template

Click **Clone** to copy a template with the same configuration.

## Test a Template

After clicking **Edit**, enter the template editing interface, then click the **Test** button on the template editing page to run a test. The test sends a Work Notification to yourself.
