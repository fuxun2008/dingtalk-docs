Call this API to update the rules of a specified leave type.

## API Call Description

Leave rules can be created in two ways: by calling the API, or in the official DingTalk Attendance app:

| Method for Creating Leave Rules | Supports Updating the Leave Type via This API |
| --- | --- |
| Leave types created by calling the [Add Leave Rules](/open/development/add-holiday-rules) API. | Yes |
| Leave types created in the Attendance app in the Admin Console.   - Created by default by the Attendance app system. - Created in the Attendance app backend. | No |

On the **Attendance** > **Leave Management** > **Leave Rules** page, view the four existing leave rules.

- API-created leave type 1 and API-created leave type 2 were created through the API. Call this API to update their information, such as the leave name, leave request unit, leave duration calculation method, and balance scope.
- Personal Leave and Compensatory Leave are default leave types created by the Attendance app system. This API cannot update these leave types and returns the following error message: errcode:880015,errmsg:The specified leaveCode or userId does not exist.

<Note>
Call the [Query Leave Rule List](/open/development/holiday-type-query) API to check which leave rules were created through the API.
</Note>

In the DingTalk Admin Console, go to **Leave Management** > **Leave Rules** to view the list of leave rules. Click **+ Add Leave** to create a new one. Each rule shows the following columns:

| Column | Description |
| --- | --- |
| Leave name | For example, Personal Leave, Compensatory Leave, API-created leave type 1/2 |
| Leave request unit | By hour or By day |
| Leave duration calculation method | For example, Calculate by workday |
| Balance rule | For example, Unlimited balance |
| Applicable scope | For example, Entire company |
| Actions | Edit, Delete |

Default leave types such as Personal Leave and Compensatory Leave use "By hour" as the request unit, while the leave types created through the API use "By day".
