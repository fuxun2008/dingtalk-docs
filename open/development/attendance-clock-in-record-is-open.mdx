Call this API to get the actual clock-in details of employees in your organization.

## API Call Description

- This API does not support querying data older than 180 days.
- If you need only clock-in results and not detailed data, call the [Get Clock-In Results](/open/development/open-attendance-clock-in-data) API instead.
- Attendance data synchronization may be delayed. If data is missing, try again later.
- **If a user has a scheduled shift on a given day but does not clock in, this API returns empty data**.
- This API returns all clock-in details, including clock-in data for scenarios that require secondary confirmation, such as late arrivals. These records are invalid clock-ins. Filter them based on your business scenario after retrieval. Pay attention to the output parameters `invalidRecordType`, `isLegal`, and `invalidRecordMsg`.

For example, an organization schedules an employee to clock in at 9:00 and 18:00. If the employee clocks in multiple times during that period, this API returns all clock-in records.

To view the same raw clock-in data in the Attendance console, go to **Attendance Statistics** > **Report Management** > **Raw Records**. Each record lists the following columns: **Name**, **Attendance group**, **Department**, **Job number**, **Position**, **Attendance date**, **Attendance time** (scheduled shift time), **Clock-in time**, and **Clock-in result**. A result such as *makeup clock-in approved* indicates that the record came from an approved correction rather than a direct clock-in.

## Request

| **Basic Information** | |
| --- | --- |
| HTTP URL | https://api.dingtalk.io/attendance/listRecord |
| HTTP Method | POST |
| Supported app types | appType-Internal app　appType-Third-party enterprise app |
| Required permissions | permission-qyapi_get_attendance_data-Attendance data read permission |

### Query Parameters

| Name | Type | Required | Example | Description |
| --- | --- | --- | --- | --- |
| access_token | String | Yes | bE74xxxx | The app credential used to call this API.   - For an internal app, call the [Get the access_token of an Internal App](/open/development/obtain-orgapp-token) API to obtain it. - For a third-party enterprise app, call the Get the access_token of a Third-Party Enterprise API to obtain it. |

### Request Body

| Name | Type | Required | Example | Description |
| --- | --- | --- | --- | --- |
| userIds | List | Yes | ["user456","user123"] | The list of employee IDs in your organization. Maximum: 50.  **Important**  Make sure the userId values are correct. Otherwise, this API returns empty data. |
| checkDateFrom | String | Yes | 2020-09-07 00:00:00 | The start workday for querying attendance clock-in records. Format: yyyy-MM-dd hh:mm:ss.  For example, if you pass "2021-12-01 10:00:00", the employee's 09:00 clock-in is not returned.  **Important**  The workDateFrom and workDateTo parameters  can be at most 7 days apart (inclusive). |
| checkDateTo | String | Yes | 2020-09-08 00:00:00 | The end workday for querying attendance clock-in records. Format: yyyy-MM-dd hh:mm:ss.  For example, if you pass "2021-12-01 18:00:00", the employee's 19:00 clock-in is not returned.  **Important**  The workDateFrom and workDateTo parameters  can be at most 7 days apart (inclusive). |
| isI18n | Boolean | No | true | Specifies whether the organization is an overseas organization:   - **true**: Used on the overseas platform - **false** (default): Used on the China platform |

### Request Example

```curl
curl -X POST "https://api.dingtalk.io/attendance/listRecord" \
-H 'Content-Type:application/x-www-form-urlencoded;charset=utf-8' \
-d 'access_token=7258e1c9-af43-411c-b3f4-bcb069bfbb93' \
-d 'checkDateFrom=2018-01-01' \
-d 'checkDateTo=2018-01-01' \
-d 'isI18n=true' \
-d 'userIds=%221%22%2C%222%22'
```

